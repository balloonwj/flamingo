## 1. 背景与目标

在聊天里贴代码是常见需求，但现在代码只能当普通文字发出去：比例字体对不齐、Tab 缩进消失、没有任何高亮，对方几乎没法读（§2.1）。本方案让单聊、群聊可以发送「代码片段」：发出的消息在双方的消息列表里显示为一张代码卡片，等宽字体、保持原有缩进、按语言做关键字高亮，可以一键复制原文。

**不引入第三方库**：语法着色用自写的按语言表驱动的扫描器（`Common/Code/CodeLexer`），卡片排版与绘制用 `BalloonChatWnd/ChatCodeBlock`。这两个模块与效果演示程序已经完成（§2.4），本方案只需把它们接入协议、气泡、发送入口与其它显示面。

以下口径已与用户确认（2026-10-06），实现时不再另行请示：

## 2. 现状盘点（据实证，均已核对代码位置）

### 2.1 代码当普通文字发出去时的表现

- 文字气泡用界面字体（比例字体）排版：`Source/UI/BalloonChatWnd/ChatInlineText.cpp:812-821`（`CreateInlineFont` 取 `i18n::UiFontName()`）。所有文字气泡都走这一套排版：`ChatBubble.cpp:5421`（`LayoutInlineContentForStyle`）、`:5429`（`DrawInlinePlaced`）。
- 连续的空格与 Tab 合成一个折行词元（`ChatInlineText.cpp:133` 起的 `TokenizeForWrap`），折行后行首空白直接丢弃（`:567`），绘制用 `DrawTextW` 且不带 `DT_EXPANDTABS`（`:806`）。
- 效果演示程序实测（2026-10-06 截图核对）：**空格缩进**的行缩进还在，但比例字体让各行对不齐；**Tab 缩进**的行缩进完全消失；没有任何高亮。

### 2.2 协议与服务端

- 服务端把 `content` 当作 JSON 对象整体存储，不关心其中的字段；敏感词检查、会话摘要、服务端搜索都取 `content.text`；逐条转发与合并转发都保留 `content` 的其余字段（详细出处见 `docs/Markdown消息方案.md` §2.2）。
- 客户端解析时，任何 msgtype 只要 `content.text` 是字符串就按文字气泡显示（`net/MessageProtocolClient.cpp` 的文本分支），所以老客户端会忽略不认识的字段，照常显示 `text`。
- Markdown 消息已在客户端定义了 `content.format`：`net::text_format` 枚举（`net/MessageProtocolClient.h`）、`buildTextContent` 写入、`readTextFormatFromContent` 读出（均在 `MessageProtocolClient.cpp`），并约定 `format` 的其它取值留给以后的格式，当前按纯文字处理（`docs/Markdown消息方案.md` §4）。

结论：沿用 `msgtype = 1`，在 `format` 上增加取值 `"code"`，服务端不用改任何代码。

### 2.3 本地库

- 本地库按记录保存原始 JSON（`UI/BalloonHistory/V2MsgQuery.cpp:581` 的 `m_raw`），聊天窗还原消息时解析原始 JSON，新增字段不会丢失（`:595-597`）。
- `BuildContentJson`（`V2MsgQuery.cpp:254` 起）另写一份 content 列供消息记录窗使用，文字分支已写入 `format`（`:275`）；代码片段需要再写入 `lang`。

### 2.4 已完成的模块（2026-10-06）

| 模块 | 位置 | 说明 |
| --- | --- | --- |

### 2.5 已知的限制

- `DuiRichEdit` 纯文本模式下的制表位取自 balloonui 宿主的默认段落格式，只有一个半英寸的制表位（`third-party/balloonui/balloonui/Controls/Input/DuiTextHost.cpp:250-256`），`DuiRichEdit` 没有公开修改它的接口。因此「发送代码」窗口的编辑框里，一个 Tab 显示为半英寸宽，与卡片的 4 列不一致。要统一需要改 balloonui（须事先获得用户批准），本方案第一版不改，见 §8。富文本模式可以在 RTF 里写制表位，查看窗不受这项限制。

## 3. 交互设计

### 3.1 发送端

- **工具栏按钮**：单聊、群聊输入框工具栏各加一个「代码」按钮，图标由 `ChatIcons` 绘制成「</>」，悬停提示「发送代码」。
- **发送代码窗口**：可缩放的 `DuiFrameWindow`。
  - 顶部：语言下拉框（第一项「自动识别」，其后为各语言）与状态文字（自动识别的结果、行数、大小）。
  - 中间：`DuiRichEdit` 纯文本模式、Consolas、关闭自动换行、可横向滚动，只按纯文本粘贴。
  - 底部：「取消」「发送」；Ctrl+Enter 发送。超过单条消息上限（§4.2）时状态文字变红、「发送」不可用。
  - 打开时：输入框里有选中的文字就预填选中的文字。
  - 手选过的语言记在本机配置里，下次打开默认选中它；没有手选过时默认「自动识别」。
- **``` 写法**：输入框里整条消息以 ``` 开头、以 ``` 结尾（开头一行 ``` 后面可以写语言名，如 ```` ```python ````）时，按代码片段发送，语言取写明的那个，没写时自动识别。
- **粘贴识别**：往**空的**输入框粘贴文字、且 `LooksLikeCode` 判断为代码时，输入框上方出现一行提示条「看起来是一段代码」与按钮「以代码片段发送」「不用了」。点「以代码片段发送」把输入框内容移进发送代码窗口（语言按自动识别预选），输入框清空；点「不用了」或继续输入时提示条消失。不自动转换，用户照常回车时仍按普通文字发送。
- **重新编辑**：发送失败的代码片段，点「重新编辑」时打开发送代码窗口并预填原文与语言。
- **引用**：在发送代码窗口发出的代码片段可以带输入框当前的引用（与文字消息相同）。代码片段不支持 @。
- **没能发出时不丢内容**：离线或超过体积上限时提示并放弃发送；从发送代码窗口发出的，宿主随即重新打开发送代码窗口并放回这段代码；``` 写法发出的，输入框原样保留。
- **聊天窗尺寸**（用户 2026-10-06 要求，随「代码」按钮一并调整）：单聊窗默认整窗尺寸由 658×667 调为 760×720，群聊窗由 898×667 调为 1000×720；群聊窗最小宽度由 660 提到 700（工具栏加了 32 像素宽的「代码」按钮）；输入区块默认高度由 172 调为 212（两个布局的 `split-fraction` 由 0.66 改为 0.62）。

### 3.2 接收端（消息列表里的代码卡片）

- 卡片外观与效果演示一致：顶部一行写语言名与行数，右侧「复制」；正文白底、等宽字体、按语言着色，左侧行号；超过 15 行时底部「查看全部（共 N 行）」。
- 卡片画在气泡里：外面仍是与文字气泡相同的气泡底，卡片四周留 4 像素（与图片气泡每侧的内边距相同，`ChatBubble.cpp` 的 `kCodeBubblePad`）；带引用时引用块照文字气泡的内边距画在卡片上方。自己发的靠右、对方发的靠左，头像、发送者名、回执的位置与文字气泡相同。（起草时写的是「不再套一层彩色气泡底」，第 2 步实现时改为现在的样子。）
- 宽度：最大为两侧头像之间的整列宽度，按最长的行收窄，最小 240 像素。
- 长行在卡片里折行，续行保持原缩进再缩进两列。
- 交互：
  - 点「复制」：复制原文，顶部改为灰色「已复制」，1.5 秒后恢复；
  - 点卡片正文或底栏：打开代码查看窗（§3.3）；
  - 右键菜单：在文字消息原有的引用、转发、收藏、Pin、撤回、删除、多选之外，「复制」改为「复制代码」，另加「在窗口中查看」「另存为…」（按语言给扩展名）。
- 语言标识不认识（新版本客户端发来的新语言）时按纯文本显示：等宽、保持格式，不着色。

### 3.3 代码查看窗

- 可缩放的 `DuiFrameWindow`，标题为「代码 · C/C++ · 42 行」；同一条消息再次打开时调到前台，不重复创建。
- 正文是只读的 `DuiRichEdit`（富文本模式），按词元生成一段带颜色表与制表位的 RTF，一次 `LoadRTF`；默认不折行、可横向滚动；行号画在正文左侧的独立窄栏里，随正文滚动。
- 工具条：语言下拉框（只改本窗口的着色，不改消息）、「自动换行」开关、「复制全部」、「另存为…」。
- 据推测，按词元生成 RTF 一次载入比逐段选中改颜色快得多。5000 行代码的耗时**尚未实测**（第 3 步没有做这项测量），留在 §8 作为遗留项。

### 3.5 与 Markdown 消息的关系

- 两者共用 `content.format` 字段与文字消息的收发路径：`format = "markdown"` 是 Markdown 消息，`format = "code"` 是代码片段，缺省是普通文字。
- Markdown 消息里的 ``` 代码块与代码片段卡片是两回事：前者是一段 Markdown 正文中的一块，后者是整条消息。Markdown 方案第 4 期给代码块加语法着色时，可以直接调用 `CodeLexer` 与 `ChatCodeBlock`（已通知 flamingo-39）。
- 两个功能改动的文件有大量重叠（§5.7），开工顺序与分工见 §7。

## 4. 协议

### 4.1 消息格式

```json
"msgtype": 1,
"content": {
    "text": "int main()\n{\n\treturn 0;\n}",
    "format": "code",
    "lang": "cpp"
}
```

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `format` | `"code"` | 本条是代码片段；缺省为普通文字，`"markdown"` 为 Markdown 消息，其它值按普通文字处理 |
| `text` | 字符串 | 代码原文：换行统一为 `\n`，Tab 原样保留，去掉开头与末尾只含空白的行（`NormalizeCodeNewlines`）；不做表情标记转义，接收方也不解析表情标记 |
| `lang` | 字符串，可缺省 | 语言的协议标识（`CodeLanguageId`）：`text`、`cpp`、`csharp`、`java`、`python`、`javascript`、`go`、`rust`、`sql`、`shell`、`json`、`xml`、`lua`、`php`；缺省或不认识时按纯文本显示 |
| `quote` | 对象，可缺省 | 引用回复，与文字消息相同 |

代码片段不写 `font` 与 `at`。

### 4.2 体积

单条消息的 `content` 与 `quote` 合计不得超过 256 KiB（服务端 `MESSAGE_CONTENT_MAX_BYTES`，客户端 `ChatSendLimit` 按同一口径预先检查，非 ASCII 字符按 `\uXXXX` 计 6 字节）。代码以 ASCII 为主，约可容纳几千行。MySQL 列的实际上限只有 64 KiB（`bugs.md` BUG-108），在它修好之前，超过 64 KiB 的代码片段与长文字消息一样会出问题，本方案不单独处理。

### 4.3 兼容性

- 服务端不改：敏感词检查、服务端搜索照常覆盖代码正文；转发、合并转发保留 `format` 与 `lang`。
- 老版本客户端：按普通文字显示代码原文（即 §2.1 的现状）。
- `docs/协议设计-v2.md` §10.3 在 Markdown 消息写的 `format` 说明后补上 `"code"` 与 `lang`。

## 5. 客户端实现

### 5.1 网络层（`net/`）

- `net::text_format` 末尾追加 `text_format_code = 2`。
- `buildTextContent` 在 `textFormat == text_format_code` 时写 `format` 与 `lang`；为此新增一个参数 `codeLang`（`std::string`，默认空），放在现有参数之后，不影响现有调用点。
- 解析时读出 `format = "code"` 与 `lang`，存进 `net::MessageNotify` 的 `m_textFormat` 与新增的 `m_codeLang`。
- `IUSocket` 的单聊、群聊文字发送函数同样在末尾加默认参数 `codeLang`；`textContentBytes` 一并加上，保证预检体积与实际发出的 content 逐字节相同。

### 5.2 数据模型

- `ChatMessage`（`ChatMockData.h`）新增 `isCode`（是否代码片段）与 `codeLang`（`codesnippet::CodeLanguage`）；按该结构体的约定都给默认值。
- 收消息、拉历史、读本地库三条路径组装 `ChatMessage` 时据 `m_textFormat` 与 `m_codeLang` 填写。
- 本地库 `BuildContentJson` 的文字分支在代码片段时写入 `lang`。

### 5.3 气泡（`ChatBubble`）

- 文字消息分支里 `isCode` 为真时改走代码卡片：Measure 时调 `LayoutCodeBlock` 并缓存结果（宽度、消息不变时不重排），绘制时调 `PaintCodeBlock`；不再走 `ChatInlineText`、选区、@ 高亮、链接识别。
- 鼠标：悬停「复制」与底栏时加下划线；点「复制」直接写剪贴板；点卡片正文或底栏时经新的窗口私有消息请宿主聊天窗打开代码查看窗（§5.7）。
- 右键菜单按 §3.2 调整；`ChatMessageMenu.h` 新增菜单编号接在 Markdown 占用的编号之后。

### 5.4 代码查看窗

- 新建 `UI/BalloonCode/CodeViewerWindow.h/.cpp`（窗口）与 `UI/BalloonCode/CodeViewerLayout.h/.cpp`（控件树与 RTF 生成，后者可单测）。
- 行号栏：一个自绘控件，按 `DuiRichEdit` 的首个可见行与行高画行号。若 `DuiRichEdit` 取不到首个可见行，就退而不显示行号栏，并在 §8 记一笔（不为此改 balloonui）。

### 5.5 发送

- 新建 `UI/BalloonCode/CodeComposeWindow.h/.cpp`（发送代码窗口）与 `CodeComposeLayout.h/.cpp`。
- 发送代码窗口不直接发消息：把代码、语言、是否带引用交回宿主聊天窗，由宿主走现有的文字发送流程（乐观气泡、回执、失败重发都沿用），只是 `textFormat` 为代码。
- ``` 写法与粘贴识别：判断逻辑写成纯函数 `ParseCodeFence`、`TryCodeFenceSend`（Markdown 模式下不转换）、`ShouldOfferCodePaste`（输入框原本为空、不在 Markdown 模式、`LooksLikeCode` 为真），可单测。原计划另建 `ChatCodeSend.*`，实现时并入 `BalloonChatWnd/ChatCodeMessage.h/.cpp`，与 `ApplyCodeFields`、`CodeDigestFromCode`、`IsCodeTooLarge` 放在一起。
- ``` 写法的接入点在两个聊天窗的 `DoSend`：输入框内容切分后只有一段文字、没有图片时才判断。输入框里没有表情时正文是原文，不做斜杠转义（`ChatRichContentSplit.h` 对 `BuildOutgoingParts` 的说明），代码里的 `//` 不会变。
- 粘贴识别：`ChatInputRichEdit::SetPasteTextMsg` 设一个消息号（`WM_APP + 0x89`，定义在 `ChatCodeMessage.h` 的 `kMsgChatCodePaste`）。往空输入框里做一次普通粘贴（不是 Flamingo 聊天内容）后投递 wParam 为 1 的通知，内容每次变化投递 wParam 为 0 的通知；Ctrl+V、Shift+Insert 与右键「粘贴」都会触发。宿主收到 1 时判断并显示提示条、记下此刻的文字，收到 0 且文字已不同时收起。粘贴本身引起的变化通知排在粘贴通知之前，不会把刚显示的提示条收起。
- 提示条在引用条与输入框之间：外层 `DuiVBox` 负责浅蓝底与圆角（`DuiHBox` 没有底色），里面一行灰色说明文字与两个 `DuiLabel` 链接；样式由 `ChatWindowLayout.h` 的 `ApplyCodePasteBarStyle` 统一设置（单聊、群聊共用），非简体中文界面下链接按译文宽度加宽。显隐变化后对输入区块 `ForceLayout`（UI 约定第 5 条）。
- 发送代码窗口点「发送」后先给自己投 `WM_CLOSE`，再把结果投给宿主：两条消息在同一个线程的队列里按投递顺序处理，宿主没能发出而重新打开窗口时，排在后面的关闭不会把它关掉。
- 「重新编辑」：`ChatReeditData` 追加 `m_isCode`、`m_codeLang`、`m_code`，宿主据此打开发送代码窗口并预填原文与语言，不放回输入框。

## 8. 风险与遗留

- **发送代码窗口的 Tab 宽度**：见 §2.5，编辑框里一个 Tab 显示为半英寸宽。要与卡片一致，需要给 `DuiRichEdit` 增加设置宿主默认段落格式（制表位）的接口，属于 balloonui 改动，须事先获得用户批准；第一版不做。
- **近似着色**：`CodeLexer` 是按表扫描，不是语法分析；JS 正则字面量、Shell heredoc、C++ 嵌套模板等可能着色不准，不影响原文显示与复制。
- **中文与列对齐**：中文改用界面字体绘制，宽度约为两列但不精确，中文之后的列可能略有错位。
- **服务端摘要**：登录后拉取的会话列表里，最后一条是代码片段时显示代码原文第一行，没有「[代码]」前缀（§3.4）。以后愿意改服务端时，在摘要生成处按 `format` 加前缀即可，不需要改协议。
- **拖选**：第一版不支持在卡片里拖选一部分代码。以后可以用 `ChatTextSelection` 的模型接上：`ChatCodeBlock` 的文字段已带坐标，补上字符区间即可。
- **查看窗的大文件耗时**：5000 行代码在查看窗里的载入耗时尚未实测（§3.3）。
- **记录窗的多选模式**：消息记录窗进入多选后，点代码卡片仍会打开查看窗、不会勾选这一行（与文件卡片的现状相同）。

## 10. 增强：发送代码窗口的行号、格式化与批注（2026-10-06 起草）

> 用户 2026-10-06 提出：「发送代码」窗口的编辑框增加格式化、显示行号与批注（原话「批准」，经确认为「批注」）。本节标「待确认」的口径逐条与用户确认后再动代码。

### 10.1 目标与范围

- **行号**：编辑框左侧显示行号，可以关闭。
- **格式化**：把粘进来的代码整理干净（统一换行、去掉行尾空白、去掉整段多出来的缩进），对能可靠处理的语言重新缩进或美化。
- **批注**：发送前给某一行或连续几行写一段说明。说明放在代码窗口右侧可以收起的批注栏里（发送代码窗口与代码查看窗）；聊天窗、消息记录窗的代码卡片只标出被批注的行，点开代码查看窗看说明。
- **不做**：语法级的完整格式化（像 clang-format 那样调整运算符两侧空格、断长行、移动花括号），不引入第三方库；接收方回复批注、围绕批注讨论；安卓端。

### 10.2 现状（据实证）

- 编辑框是 `DuiRichEdit` 纯文本模式、不折行（`UI/BalloonCode/CodeComposeLayout.cpp:227-230`）。纯文本模式整段只有一种字符格式，**不能给某几行设底色**。
- 代码查看窗已有行号栏 `CodeLineGutter`（`UI/BalloonCode/CodeViewerLayout.h`），绘制时向编辑框的排版引擎查询每行的纵坐标（`CodeViewerLayout.cpp` 的 `CodeLineGutter::OnPaint`），不依赖编辑框是否只读，可以直接复用。
- 可撤销的整段替换：`DuiRichEdit::SetSel` / `SelectAll` 加 `ReplaceSel(text, bCanUndo = true)`（`DuiRichEdit.h:251`、`258`、`265`），Ctrl+Z 一步撤回。
- 编辑框右键菜单可以由子类追加菜单项（`AppendContextMenuItem` / `OnContextMenuCommand`，`DuiRichEdit.h:500`、`736`）。
- 代码卡片按等高的视觉行排版（`ChatCodeBlock.h` 的 `CodeBlockLayout::m_rowHeight`、`CodeBlockRun::m_row`），给被批注的行画底色只需按视觉行填充，不需要改排版模型。
- 左右分栏可以用 balloonui 的 `DuiSplitter`（聊天记录管理器的左右分栏 `kIdMgrSplitter` 就是它，`UI/BalloonHistory/HistoryWindowLayout.h`）。
- jsoncpp 的对象按键名排序存储（`third-party/jsoncpp-1.9.0/value.h:284`，`typedef std::map<CZString, Value> ObjectValues`），用它美化 JSON 会打乱键的顺序，所以 JSON 美化自己写。
- 服务端的敏感词检查只取 `content.text`（§2.2），`content` 里新增的字段不会被检查。

### 10.3 行号

- 编辑框左侧放行号栏（复用 `CodeLineGutter`），顶部工具行加「行号」勾选框，默认勾选，记在用户配置（`[ChatDlg] CodeComposeLineNumbers`）。
- 编辑框不折行，每个视觉行就是一个逻辑行。行号栏增加「按视觉行编号」的模式：直接用 `EM_GETFIRSTVISIBLELINE`、`EM_LINEINDEX`、`EM_POSFROMCHAR` 取每行位置，不必每次输入后扫描全文重算各行起点，打字时行号始终是最新的。
- 行号栏宽度按 `EM_GETLINECOUNT` 的位数算，位数变化（如 99 行到 100 行）时加宽并对所在横排 `ForceLayout`（UI 约定第 5 条）；取消勾选「行号」时隐藏行号栏并同样重排。
- 编辑框滚动、内容变化时请行号栏重画（新的编辑框子类覆写 `TxSiteScrollInfoChanged`，做法与 `CodeViewerEdit` 相同）。
- 行号栏同时画批注标记（§10.5）。

### 10.4 格式化

**入口**：顶部工具行「格式化」按钮、编辑框右键菜单「格式化」、快捷键 Ctrl+Shift+F。有选中文字时只处理选中内容覆盖到的整行，否则处理全文。结果用 `SetSel` + `ReplaceSel(…, 可撤销)` 写回，Ctrl+Z 一步撤回；状态文字显示「已格式化，调整了 N 行」或「没有需要调整的地方」。

**规则**（纯函数，新文件 `Common/Code/CodeFormatter.h/.cpp`，可单测）：

| 语言 | 处理 |
| --- | --- |
| 所有语言 | 换行统一为 LF；去掉行尾空白；去掉开头与末尾的空白行；连续三行以上的空行压成一行；去掉所有非空行共同的前导缩进（从文件中间复制出来的代码常带一整段多余缩进） |
| C/C++、C#、Java、JavaScript/TypeScript、Go、Rust、PHP | 在上面的基础上按 `{` `}` `(` `)` `[` `]` 的嵌套层数重新缩进：括号是否计数按 `CodeLexer` 的词元判断，字符串、字符、注释里的不算；以右括号开头的行少缩一级；C/C++ 的预处理行（`#` 开头）顶格；块注释内部的行保持相对缩进不变 |
| JSON | 美化：每个键值对、每个数组元素各占一行，按层缩进；键的顺序、数字与字符串的写法原样保留。不是合法的 JSON 时只做通用整理，并提示「不是合法的 JSON，只做了基本整理」 |
| XML / HTML | 按标签层数重新缩进：自闭合标签、HTML 的空元素（`br`、`img`、`input`、`meta`、`link`、`hr` 等）、注释、CDATA 不加层；不拆行，不改标签内部 |
| SQL | 美化：关键字转大写（关键字表与 `CodeLexer` 的 SQL 表相同）；`SELECT`、`FROM`、`WHERE`、`GROUP BY`、`HAVING`、`ORDER BY`、`LIMIT`、`INSERT INTO`、`VALUES`、`UPDATE`、`SET`、`DELETE FROM`，以及 `JOIN` 一族（`LEFT JOIN` 等）、`UNION` 各起一行；`AND`、`OR` 在 `WHERE` / `ON` / `HAVING` 之后另起一行并多缩一级；`SELECT` 后的字段列表超过一行宽时每个字段一行；括号里的子查询加一级缩进。字符串、带引号的标识符与注释里的内容一概不动；多条语句以 `;` 分开，各自处理 |
| Python、Shell、Lua、纯文本 | 只做通用整理（Python 的缩进有语义，不能重排） |

**缩进单位**：沿用代码原有的风格——多数缩进行以 Tab 开头就用 Tab；否则取各行缩进量的最大公约数，为 2 或 4 时用该数目的空格；判断不出时用 4 个空格。

**不做**：调整运算符两侧空格、断长行（SQL 的字段列表除外）、移动花括号位置。

**与批注的关系**：格式化可能改变行数（JSON 美化尤其明显），批注按 §10.5 的规则重新定位，找不到对应行的批注会被删除，并在状态文字里说明。

### 10.5 批注

**形式**（**已确认**，2026-10-06）：批注不画进代码里，而是放在代码窗口右侧单独的一栏「批注栏」里，与代码一一对应；批注栏可以收起。聊天窗里的代码卡片不显示说明文字，只标出被批注的行。

**数据**：一条批注是「起止行 + 说明文字」，行号从 1 起、包含两端，指发送时规范化之后的代码（去掉开头的空白行后，批注随之平移）。两条批注的行范围不能相交；在已有批注的行上再添加时改为修改那一条。

**上限**（**已确认**，2026-10-06）：每段代码最多 50 条批注，每条说明最多 200 个字（按 UTF-16 字符数）。达到 50 条时「批注」按钮与右键菜单项不可用，输入框到 200 字后不再接受输入；接收端只取前 50 条、每条截到 200 字。

**批注栏**（发送代码窗口与代码查看窗共用一套控件，新文件 `UI/BalloonCode/CodeNotesPane.h/.cpp`）：

```
┌ 发送代码 ───────────────────────────────── ☐ ✕ ┐
│ 语言[自动识别▾] ☑行号  格式化  批注   │ 批注 (2)    » │
│  1 int main()                     │┌──────────┐│
│  2 {                              ││第 3～4 行 ││
│▐ 3     char* p = get();           ││这里没有判空││
│▐ 4     *p = 0;                    ││ 修改  删除 ││
│  5     return 0;                  │└──────────┘│
│  6 }                              │┌──────────┐│
│                                    ││第 9 行 …  ││
│ Ctrl+Enter 发送        取消  发送  │              │
└───────────────────────────────────────────────┘
```

- 布局：代码区（行号栏 + 编辑框）与批注栏之间用 balloonui 的 `DuiSplitter` 左右分栏（聊天记录管理器的左右分栏用的就是它），分隔条可以拖动；批注栏默认宽 240 像素，最窄 180。
- 批注栏顶部一行写「批注 (N)」，右端「»」收起。收起后整栏隐藏、代码区占满；工具行的「批注」按钮显示为「批注 (N)」，点它重新展开。显隐变化后对分栏所在容器 `ForceLayout`（UI 约定第 5 条）。
- 展开批注栏时，窗口没有最大化、且向右加宽后仍在显示器工作区内，就把窗口加宽一个批注栏的宽度，代码区保持原宽；收起时缩回。放不下时窗口不变，代码区让出宽度。
- 批注按起始行排成一列小卡片（`DuiScrollView` 里的 `DuiVBox`，超出可滚动），每张写「第 3～4 行」与说明。点卡片时在代码里选中那几行并滚到可见；在代码里选中或把光标放到被批注的行上时，对应的卡片高亮并滚到可见。
- 被批注的行在代码里加浅黄底色、行号栏左侧画一条橙色竖条，与批注栏的卡片对应。发送代码窗口的编辑框是纯文本模式、不能设底色（§10.2）。实际做法（2026-10-06 实施时改定）：`DuiRichEdit` 让排版引擎按透明背景画文字、底色由控件自己铺，所以编辑框子类 `CodeMarkedEdit`（`CodeViewerLayout.h`，发送代码窗口与代码查看窗共用）先按常规画一遍，再裁剪到被批注的行的范围内、以浅黄底色重画一遍。整行铺满，自动换行时同样正确，文字颜色不受影响，也不需要改 RTF。

**发送端（发送代码窗口）**：

- 选中一行或几行（只放了光标时就是光标所在的行），点工具行「批注」按钮或右键「添加批注…」：批注栏自动展开，在对应位置插入一张编辑中的卡片（多行输入框 + 「确定」「取消」），Enter 换行、Ctrl+Enter 确定、Esc 取消。编辑期间代码编辑框只读、「格式化」不可用，批注的行范围在编辑期间不会变；说明为空时点「确定」，新增的放弃、修改的删除；编辑期间点「发送」先确定这条批注再发送。
- 「批注」按钮：批注栏收起且有批注时写「批注 (N)」，点它只展开；其余情况点它为选中的行添加批注。达到 50 条时（批注栏展开时）按钮与右键菜单项不可用，卡片上的「修改」照常可用。
- 卡片上「修改」把说明变回输入框，「删除」直接删除（可以撤销到上一步：删除后状态文字出现「已删除 1 条批注　撤销」）。
- 没有批注时批注栏默认收起；有批注时按上次的展开状态（记在用户配置 `[ChatDlg] CodeNotesPaneOpen`）。
- 改了代码之后批注跟着行走：新旧文字按行做最长公共子序列比较（比较时忽略行首行尾空白，所以重新缩进不影响定位），把批注的起止行映射到新位置；整段都被删掉的批注随之删除，状态文字说明「有 1 条批注所在的行已被删除」。新旧都超过 2000 行时不做比较，批注按原行号保留，超出总行数的删除。
- 带批注发送时，体积超过单条消息上限，状态文字提示，「发送」不可用。

**接收端**：

- 聊天窗与消息记录窗、聊天记录查看窗的代码卡片：被批注的行底色浅黄、行号左侧一条橙色竖条；顶部语言名后的说明加「· N 条批注」。卡片里不显示说明文字。点卡片（或底栏「查看全部」）打开代码查看窗，批注栏默认展开。
- 代码查看窗：右侧批注栏只读（没有「修改」「删除」），可以收起；工具条加「批注 (N)」按钮，点它展开或收起。没有批注时不显示批注栏与这个按钮。有批注时打开即展开，窗口与发送代码窗口一样随之加宽（放得下时）。点卡片上的「第 3～4 行」在正文里选中那几行；把光标放到被批注的行上时对应的卡片高亮。「复制全部」「另存为…」只写代码，不含批注。
- 「复制」「复制代码」只复制代码；摘要不变，仍是「[代码] 第一行」。
- 发送失败后「重新编辑」，批注随代码一起放回发送代码窗口。

**协议**（`content` 新增一个可选字段）：

```json
"content": {
    "text": "...", "format": "code", "lang": "cpp",
    "notes": [ { "from": 3, "to": 5, "text": "这里没有判空" } ]
}
```

- 按起始行升序；接收端丢弃越界、起止颠倒、与前一条相交的条目。
- `textContentBytes` 计入，发送前的体积检查与实际发出的 content 一致。
- 老客户端忽略这个字段，只看到代码原文。
- 本地库 `BuildContentJson` 一并写入，消息记录窗据此显示；逐条转发与合并转发由服务端原样保留 content（§2.2），批注随之保留。
- **敏感词**（**已确认**，2026-10-06）：改服务端，把批注说明一并纳入检查。`flamingoserver/chatserversrc/MessageProtocol.cpp` 的 `collectTextsFromContent` 在文字消息分支只收集 `text`，追加收集 `notes` 数组里每一项的 `text`；命中时与正文命中一样拒发（`error_code_sensitive_word`）。合并转发的记录也经同一个函数递归收集，转发出去的批注同样会被检查。服务端单测在 `flamingoserver/tests/test_messageprotocol.cpp` 追加。这是本方案唯一的服务端改动，需要重新部署 chatserver；老服务端不检查批注，但照常存储与转发。

### 11.1 已确认的口径

| 决策点 | 取值 | 状态 |
| --- | --- | --- |
| 通知形式 | 加批注的人发出一条**新的代码片段消息**，带上代码与全部批注；原来的代码卡片不更新 | **已确认**（2026-10-07，用户原话「重新产生一条带批注的消息卡片，原代码卡片不必更新」） |

| 修改与删除 | 每人只能修改、删除自己写的批注 | **已确认**（2026-10-07） |
| 回复 | 不做回复；同一行可以由多人各加一条 | **已确认**（2026-10-07） |

由第一条可知，通知就是一条普通消息：计未读、闪托盘、响提示音都按会话的提醒模式处理，不需要新的推送命令，服务端也不用改。据实证，若改用接龙那样的灰色系统提示行，群聊里不计未读、不提醒（`UI/BalloonMain/NotifyModePolicy.cpp:39-41`）。

### 11.3 交互设计

**入口**（只在单聊窗、群聊窗里有）：

- 聊天里代码卡片的右键菜单「添加批注…」，排在「另存为…」之后。
- 代码查看窗工具条的「添加批注」按钮。它与已有的「批注 (N)」开关不同，后者只负责展开、收起批注栏。在查看窗正文里先选中几行再点它，直接为这几行进入批注编辑（第 12 节起在代码查看窗里编辑）。
- 代码片段还没有服务器 msgid（发送中、发送失败）时，这两个入口都不出现。
- 消息记录窗、聊天记录查看窗里打开的查看窗没有「添加批注」（**已确认**，§11.8 第 1 条）。

**批注模式**（第 12 节起在能追加批注的代码查看窗里进行，不再另开窗口）：

- 状态文字写「张三的代码 · C/C++ · 42 行。添加或修改批注后才能发送」，新增或修改之后后半句换成「已新增或修改 N 条批注」。
- 代码只读，发出的消息沿用原消息的语言（**已确认**，§11.8 第 4 条）。理由：改了代码，别人批注的行可能对不上，而别人的批注本人无权修改。
- 批注栏默认展开，列出原消息上的全部批注，每张卡片写作者名字。别人的批注只读（没有「修改」「删除」），本人的可以修改、删除。
- 在没有本人批注的行上添加时新建一条，即使这几行已有别人的批注；同一行有多人批注时，卡片按起始行、再按作者排在一起。在本人已批注的行上添加时，改为修改本人那一条。
- 本次新增或修改的批注卡片上标「新」。
- 「发送」只在本次至少新增或修改了一条本人批注时可用；只删除了本人的批注时不能单独发送（**已确认**，§11.8 第 3 条）。

**发出的消息**：

- 是一条普通的代码片段消息，发到原消息所在的会话，并自动引用原消息（**已确认**，§11.8 第 2 条）：卡片上方的引用块写「张三：[代码] 第一行」，点它定位到原消息。输入框里当时挂着的引用不使用。
- 代码、语言与原消息相同；批注是原消息上的批注，去掉本人删除的、换上本人修改的、加上本人新增的。
- 没能发出（离线、被禁言、超过体积上限）时与 §3.1 相同：重新打开代码查看窗并放回本次的批注。发送失败后的「重新编辑」同样回到代码查看窗（§12.1）。

**接收方看到的**：

- 一张新的代码卡片，顶部写「C/C++ · 42 行 · 3 条批注，其中 1 条是新的」；被批注的行照常标浅黄底色与橙色竖条。
- 会话列表摘要（本机生成的那部分）、新消息通知、托盘提示写「[批注] 」加第一条新批注的说明，截断规则与「[代码]」相同。登录后从服务端拉取的摘要仍是代码第一行（§8 已记的限制）。
- 点卡片打开代码查看窗：批注栏展开，新的批注卡片标「新」，并选中第一条新批注对应的行。
- 收到之后可以继续「添加批注」再发出下一条。每追加一轮就是会话里的一条新消息，之前的卡片都不变。

**作者名字**：单聊为对方或本人的名字；群聊与接龙的口径相同（`IRelayNameResolver`）；取不到名字时显示 userid。

### 11.4 协议

`content.notes` 的每一项追加两个可选字段：

```json
"notes": [
    { "from": 3, "to": 4, "text": "这里没有判空" },
    { "from": 3, "to": 3, "text": "get() 可能返回空指针", "userid": "100008", "new": 1 }
]
```

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `userid` | 字符串，可缺省 | 写这条批注的人；缺省时为这条消息的发送者 |
| `new` | 1，可缺省 | 本条消息的发送者在这一轮新增或修改的批注；缺省为 0 |

- 发送端只在作者不是本消息发送者时写 `userid`，因此第 10 节已有的发送格式不变。
- 整理规则改为：同一作者的批注不能相交（相交的后一条丢弃），不同作者的可以相交；总数仍最多 50 条，每条最多 200 字。
- 一条代码片段是不是「追加批注」，按「至少有一条批注带 `new`」判断，不另加字段。
- 服务端不改：照常存储与转发 `content`，敏感词检查覆盖所有批注说明。服务端不校验 `userid`（§11.9）。
- 兼容性：支持第 10 节批注的客户端还没有发布过（改动全部未提交），不存在新旧批注格式之间的兼容问题；更早的客户端按普通文字显示代码原文。

### 11.5 客户端实现要点

- **数据**：`CodeNote` 与 `CodeNoteData` 追加作者 userid 与「新」标记；`SanitizeCodeNotes` 改为只判断同一作者的批注是否相交；一轮追加时的批注组装写成纯函数（别人的原样保留并清掉「新」，本人的按修改、删除处理，新增与修改的标「新」）。`ChatMessage`、`CodeViewerOpenRequest`、`CodeComposeResult`、`ChatReeditData` 随之追加需要的字段（原消息 msgid、原消息发送者、作者名字）。
- **批注栏 `CodeNotesPane`**：卡片显示作者名与「新」；可编辑与只读的卡片可以混排（现在只有整栏只读一种模式）。
- **入口**：右键菜单新增 `kChatMsgMenuAnnotateCode = 21`。查看窗的「添加批注」与右键菜单都经已有的 `WM_APP + 0x86` 交给宿主聊天窗，`CodeViewerOpenRequest` 追加一个动作字段区分「打开查看窗」与「添加批注」，不新增消息号（开发约定文档 UI 约定第 6 条里 `0x86` 的说明随之更新）。宿主打开查看窗时告诉它能不能添加批注：单聊窗、群聊窗能，消息记录窗与聊天记录查看窗不能。
- **宿主聊天窗**：收到批注模式的结果后，按 msgid 在消息列表里找到原消息，用 `BuildQuoteFromMessage` 生成引用，走现有的代码片段发送流程。原消息已不在列表里（被删除、清理）时不带引用照常发出。代码卡片上方的引用块可以点击定位：气泡的点击处理先判断引用块、再判断代码卡片（`ChatBubble.cpp` 约第 3069 行与第 3090 行，据实证为代码顺序），界面上还没有实际点过。
- **摘要**：`CodeDigestFromCode` 一族增加带「新」批注时的「[批注] 」写法，引用块摘要同一口径。
- **卡片**：`ChatCodeBlock` 顶部说明追加「，其中 M 条是新的」。

### 11.8 待确认

以下四项**已确认**（2026-10-07，用户回复「按建议」，§11.6 的测试用例一并确认），按建议执行：

1. **消息记录窗、聊天记录查看窗里不提供「添加批注」。** 前者要先打开对应的聊天窗再发；后者的代码来自别人转发的聊天记录，应该发回哪个会话不明确。建议第一版只在单聊窗、群聊窗里提供。
2. **发出的批注消息自动引用原消息。** 建议引用：接收方一眼能看出批注的是哪段代码，点引用块还能定位到原消息。
3. **只删除了本人的批注、没有新增或修改时，不能发送。** 建议不能：原卡片不更新，单独发一条只是少了一条批注的消息意义不大。
4. **批注模式下代码与语言锁定。** 建议锁定，理由见 §11.3。

### 11.9 风险

- 服务端不校验批注的 `userid`，改过的客户端可以把批注写成别人写的。以后要防范的话，服务端可以按引用找到原消息，核对作者不是本人的那些批注与原消息里的一致。
- 每追加一轮就把整段代码再发一次，长代码经多轮批注会占用更多存储；单条消息仍受 256 KiB 上限约束（§4.2），超过时「发送」不可用。

## 12. 调整：在代码查看窗里直接加批注（2026-10-07 起草并确认）

### 12.2 交互

只有「能追加批注」的查看窗才有下面这些：从单聊窗、群聊窗打开，且消息已有服务器 msgid。从消息记录窗、聊天记录查看窗打开的，以及还没有 msgid 的，与现在一样只读。

- **入口**：
  - 查看窗工具条的「添加批注」：为选中的行添加批注；只放了光标时为光标所在的那一行（与发送代码窗口的「批注」按钮相同）。批注栏自动展开，在对应位置插入编辑卡片。
  - 查看窗正文的右键菜单增加「添加批注…」，作用同上。
  - 聊天里代码卡片的右键「添加批注…」：打开这条消息的查看窗并展开批注栏，不自动进入编辑（这时还没有选中的行）。
- **编辑**：与第 11 节的批注模式相同——别人的批注只读，本人的可以「修改」「删除」；在别人批注的行上添加是新建一条，在本人批注的行上添加是修改；本次新增或修改的标「新」；编辑卡片里 Ctrl+Enter 确定、Esc 取消。卡片上的「修改」「删除」「确定」「取消」先投递给窗口自己再执行（UI 约定第 13 条）。
- **底部一行**：能追加批注时显示，左边是状态文字（「张三的代码 · C/C++ · 42 行。添加或修改批注后才能发送」，有新增或修改后为「已新增或修改 N 条批注」），右边是「发送」。没有新增或修改时「发送」不可用。底部一行显隐变化后对父容器 `ForceLayout`（UI 约定第 5 条）。
- **发送**：把结果交给打开它的聊天窗（与第 11 节相同，聊天窗引用原消息发出），随后关闭查看窗。聊天窗已经关闭时提示「打开这段代码的聊天窗口已经关闭……」，不关闭查看窗。
- **语言下拉框**：只改本窗口的着色，发出的消息仍用原消息的语言（与现在相同）。

### 12.3 实现要点

- **查看窗**（`CodeViewerWindow`、`CodeViewerLayout`）：
  - 布局追加底部一行（状态文字 `kCodeViewerIdAnnotateStatus` 与「发送」`kCodeViewerIdAnnotateSend`，默认隐藏）；查看窗正文编辑框 `CodeViewerEdit` 支持追加右键菜单项「添加批注…」。
