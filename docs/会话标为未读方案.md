# 会话标为未读方案

2026-10-06 与用户确认。12 项新功能的第二批之一（同批另见 `docs/消息提醒模式与消息盒子方案.md` 的「只提醒 @我和关注的人」一节、`docs/群成员部门树方案.md`）。主面板会话列表的右键菜单里可以把一个会话「标为未读」：会话显示一个不带数字的未读小红点，打开会话或「标记已读」时清除；标记存在服务端，换电脑、重新登录都还在，本人各设备同步。

## 1. 已定事项

| 事项 | 结论 | 来源 |
| --- | --- | --- |
| 作用对象 | 整个会话（单聊、群聊都可以），不是单条消息 | 用户确认 |
| 入口 | 会话右键菜单，与现有「标记已读」二选一显示：会话有未读或已标为未读时显示「标记已读」，否则显示「标为未读」 | 默认 |
| 显示 | 会话行右下角画一个不带数字的小红点；会话本来就有未读数时照常画数字胶囊，不另画红点。提醒模式让未读胶囊变灰的会话，红点同样变灰；「屏蔽」模式不显示 | 默认 |
| 清除 | 打开这个会话（包括从消息盒子打开）、右键「标记已读」时清除 | 默认 |
| 存储 | 服务端 `t_conversation` 加一列；随会话列表（1501）下发，设置与清除走 1513，改完经 1514 推给本人所有在线设备 | 用户确认 |
| 消息盒子 | 收进消息盒子的会话被标为未读时，消息盒子那一行也画红点（盒内没有未读数时） | 默认 |

## 2. 现状（据实证）

本节记的是 2026-10-06 动手前的代码现状，行号只对当时的代码成立。

- **表**：`t_conversation` 有 `f_pinned`、`f_notify_mode`、`f_readmsgid` 等列（`flamingoserver/table_mysql.sql:396-408`），读写都在 `MessageManager.cpp`（单聊列表 `getConversationBriefs:434`、群聊列表 `getGroupConversationBriefs:2043`、`setConversation:1264`、`getConversationState:1476`、`markRead:679`）。
- **加列**：要改 `table_mysql.sql`、`MysqlManager.cpp` 的列定义，再跑 `tools/gen_table_sqlite.py`。2026-10-09 起启动时不再给已有的表补列，已有的库须手工加列（见 `docs/SQLite本地数据库模式方案.md` 第 12 节）。
- **未读位点只增不减**：`markRead` 用 `GREATEST` 更新 `f_readmsgid`，所以「标为未读」不能靠回退位点实现，要单独一列。
- **置顶的整条链路可以照搬**：1513 `cmd_set_conversation` 的 `pinned` 是可选字段（`MessageProtocol.cpp:844`），`onSetConversation`（`ChatSession.cpp:5000`）改完后读回完整状态，经 `sendToUser` 推 1514 给本人所有在线连接（含发起端）。客户端 `SetConversationPinnedState`（`BalloonMainPanel.cpp:9439`）乐观更新后发 1513，`OnConversationChanged`（`:10236`）应用 1514。
- **1506 已读上报不推 1514**（`ChatSession.cpp:2980`），客户端的已读上报还会在位点没前进时去重跳过（`MarkConversationRead`，`BalloonMainPanel.cpp:7611`、`:7646`）。所以「标为未读后再标记已读」不能靠 1506 清标记，要显式发 1513。
- **菜单**：`MainPanelConversationMenu.cpp:56` 的「标记已读」在没有未读时灰显；菜单 id 已用到 19（`MainPanelConversationMenu.h:64-81`，1、7、11 已作废）。
- **角标**：会话行 `SetItemRightStacked(id, 时间, 未读数)`（`BalloonMainPanel.cpp:6591`），未读数为 0 时不画；目前没有「只画红点」的样式（`BadgeRender.h`）。

## 3. 设计

### 3.1 服务端

- `t_conversation` 加 `f_unread_mark TINYINT NOT NULL DEFAULT 0`（1 表示本人手动标为未读）。同步改 `MysqlManager.cpp` 的列定义，跑 `tools/gen_table_sqlite.py` 重新生成 SQLite 的两份文件。
- `ConvState`、`ConversationBrief` 加 `unreadmark`；两处会话列表的 SELECT 与 `getConversationState` 读出它；1501 每个会话加 `"unreadmark":0|1`。
- 1513 请求加可选字段 `unreadmark`（bool），`setConversation` 的 UPSERT 在它出现时写这一列；1514 推送加 `unreadmark`。
- 本人发 1506 已读上报时，服务端顺带把这一列清零（另一台设备读完了也算「读过了」）；1506 仍然不推 1514，其他设备的标记要等会话列表重拉或本端显式发 1513 清除才消失，这一点与未读数现在的行为一致。
- 协议文档 §10 补字段说明。

### 3.2 客户端

- `net::ConversationItem` 与 `ConversationChangedNotify` 加 `m_unreadMark`；解析 1501、1514，构造 1513 时带上。
- **菜单**：`kConvMenuMarkUnread = 20`。模型按「未读数 > 0 或已标为未读」决定显示「标记已读」（可点），否则显示「标为未读」。
- **标为未读**：乐观更新 `m_conversations` 里的 `m_unreadMark`、刷新这一行，发 1513 `{unreadmark:true}`；收到 1514 时以推送为准。
- **清除**：`MarkConversationRead` 里，会话已标为未读时清掉本地标记并发 1513 `{unreadmark:false}`（不受已读上报去重影响）；打开会话、消息盒子打开、右键「标记已读」都走这一个函数。
- **红点**：`MainPanelTreeView` 新增「未读小红点」样式（`SetItemUnreadDot`），与数字胶囊同一位置、同一套颜色（灰色模式下也变灰），未读数大于 0 时以数字胶囊为准。消息盒子行按盒内是否有已标为未读、且没有未读数的会话决定是否画红点。
- 新增两条界面文字「标为未读」，翻译四种语言。

## 6. 实机核对

1. 右键一个没有未读的会话，菜单里是「标为未读」；点了之后会话行出现小红点。
2. 再右键，菜单里变成「标记已读」；点了之后红点消失。
3. 标为未读后双击打开会话，红点消失；关闭聊天窗后不再出现。
4. 两台电脑登录同一账号：一台标为未读，另一台的会话行随即出现红点；一台打开会话后，另一台的红点也消失。
5. 退出重新登录，标记仍在。

## 7. 实施记录（2026-10-07）

按 §3 实现，测试用例见 §5。与方案不同或方案没写到的地方：

- **服务端**：`f_unread_mark` 用 `int(2)`（与表里其它开关列一致）。`MessageManager::getConversationState` 新增带 `unreadmark` 出参的重载，原六个参数的版本保留并转调它。1513 只认布尔型 `unreadmark`；`markRead` 的 UPSERT 里加了 `f_unread_mark = 0`，位点没前进时也会清零。
- **服务端用例**：`tests/test_markunread.cpp`（MU-S1a 协议、MU-S1b 存储、MU-S2 已读清零、MU-S3 新库建表；存量库补列的部分已随 2026-10-09 删除启动时自动补列一并去掉）。MySQL 侧的列定义由 `flamingo_tests_mysql` 构建跑同一组用例时覆盖。
- **客户端协议**：`ConversationsProtocolClient::buildSetUnreadMarkRequest` 只带 `ctype` / `cid` / `unreadmark` 三个字段；1501、1514 的 `unreadmark` 同时接受 0 / 1 与布尔值。IUSocket 新增 `SendSetUnreadMark`，应答复用 1513 原有的回投路径。
- **菜单**：第二项在「标记已读」与「标为未读」之间二选一（`kConvMenuMarkUnread = 20`），原来「未读为 0 时标记已读灰显」的用例 CMENU7 随之改写。
- **清除**：`MarkConversationRead` 里用 `SetConversationUnreadMark(..., false)` 的返回值判断要不要发 1513 清除，不受已读上报去重影响；打开会话、消息盒子打开、右键「标记已读」都走这个函数。标为未读走新的 `MarkConversationUnread`，乐观更新后发 1513，以 1514 为准。
- **红点**：`MainPanelTreeView::SetItemUnreadDot`，直径 10 像素、与数字胶囊同一位置与配色（不提醒的模式下为灰），有未读数时只画数字胶囊；判定函数 `NotifyModePolicy::ShowsUnreadDot`。消息盒子一行按 `MsgBoxSummary::m_unreadMarked` 画灰色小红点。
- **客户端用例**：`Tests/MarkUnreadTests.cpp`（MU-C1a / C1b / C2 / C4a / C4b），绘制用例 MU-C3a~C3c 放在 `Tests/MainPanelRowMarkTests.cpp`，与其它行标记的绘制用例共用离屏画布。
