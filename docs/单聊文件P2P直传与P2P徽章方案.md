# 单聊文件 P2P 直传与 P2P 徽章方案

2026-10-04 用户提出：单聊发文件、且双方都在线时，也优先走 P2P；凡是用 P2P 模式传输的地方，加一个「P2P」徽章以示区别。
本文是方案与逐项确认的决定，进度在第 6 节回填。P2P 模块本身见 `docs/P2P通信方案.md`。

## 1. 现状

- **单聊发单个文件**（`flamingoclient/Source/net/FileTransfer.h`）：发送方算 MD5 → 1801 申请上传（服务器已有相同文件时秒传）→ 连 fileserver 1851 分片上传 → 上传完成后才发 1503 文件消息（`message_type_file`）；接收方收到消息只渲染气泡，点「接收」后 1802 申请下载、连 fileserver 1852 下载，存进下载缓存目录；可以点「拒绝」，结果经服务端告知发送方（文件回执）。字节经服务器走两遍，接收方要等上传全部完成才看得到文件。没有任何 P2P 代码。
- **单聊发文件夹**（`Source/Feature/FolderTransfer/`，cmd 1810～1817）：在线直传，「邀请 → 对方接收并选位置 → 1816 下发通道参数（带 `p2psessionid`）→ 传输 → 1814 结束」，传输通道已是「P2P 优先、中转兜底」（P2P 方案第 5 期），失败后 10 分钟内可续传（1817）。结束后服务器写一条 `message_type_folder` 记录，历史里不提供重新下载。服务端限额：全服同时 24 笔（`foldermaxsessions`）、每人 5 笔（`foldermaxperuser`），因为每笔都在 fileserver 上预留中转连接；邀请 30 分钟无应答作废（`folderinvitetimeout`）。

## 2. 用户确认的决定（2026-10-04）

| # | 事项 | 决定 |
| --- | --- | --- |
| 1 | 直传成功后服务器是否留副本 | **不留**。文件只在收发双方电脑上；历史里的这条文件气泡标明「在线直传，服务器未保存」，其他设备上看到这条记录时不能下载，删了本地文件后也取不回 |
| 2 | 对方在线但一直没点「接收」 | **5 分钟后自动转为离线文件**（改走现有的上传服务器路径，那一份存在服务器上）；发送方在这 5 分钟内也可以手动点「发送离线文件」提前转 |
| 3 | 徽章加在哪里 | **四处都加**：单聊文件气泡（直传）、单聊文件夹气泡、文件共享的传输界面、远程桌面 / 通话 / 屏幕共享窗口 |
| 4 | 徽章在哪些路径下显示 | **只在直连时显示**（局域网直连、公网打洞直连）；经 imgserver 一对一中转时不显示，与没有 P2P 时一样。徽章只表示「数据没经过服务器」 |

## 3. 单聊文件在线直传

### 3.1 选路（发送端）

对方在线、双方的 PC 客户端都报到了 P2P 能力、企业开关 `p2p.enabled` 打开时走「在线直传」；否则照旧上传服务器，行为与现在完全一样。是否能走以服务端判断为准（对方只有手机端在线、对方是旧客户端、企业关了 P2P，都回落到上传服务器），客户端的在线状态只用来少发一次注定失败的请求。

### 3.2 流程

1. 发送方不先上传、不先算 MD5，直接向对方发起直传邀请（带文件名、大小）。本端立即出一条文件气泡（「等待对方接收」，带「取消」与「发送离线文件」）。
2. 接收方收到推送，出现与现在一样的文件气泡（待接收态，「接收 / 拒绝」）。点「接收」后不弹保存对话框，与现在一样存进下载缓存目录；点「拒绝」与现在一样，不再上传。
3. 双方在 P2P 链路上传输（DLL 依次尝试局域网直连、公网打洞，不通时用 imgserver 一对一中转）。两端气泡显示进度；链路为直连时显示 P2P 徽章（第 4 节）。接收端边收边算 MD5，传完校验。
4. 结束后由服务器写一条普通文件消息（`message_type_file`，content 加「直传」标记、链路路径、结果），历史里照常显示为文件气泡，不显示成文件夹记录卡片。

### 3.3 回退

| 情况 | 处理 |
| --- | --- |
| 服务端判定不能直传（对方离线、不支持、企业关了 P2P） | 立即改走上传服务器 |
| P2P 链路建不起来（直连、打洞、中转都不通） | 自动改走上传服务器 |
| 对方 5 分钟没点接收 | 自动改为离线文件（上传服务器）；接收方那条待接收的直传气泡随之作废，改由随后到达的离线文件消息承载 |
| 传输中途失败（链路断开、对方下线） | 气泡给「重试」，10 分钟内续传（复用文件夹传输的续传）；对方已离线时「重试」改为发送离线文件 |
| 接收方拒绝 | 与现在相同，不再上传 |

### 3.4 实现思路

- **传输层复用文件夹传输**：复用发送 / 接收会话、续传与 P2P 通道，把单个文件当成只有一个文件的清单（`Feature/FolderTransfer/DirectFileTransfer`，单测 DFT1~7）。
- **服务端新增「单文件直传」会话**：只走 P2P 链路，不在 fileserver 上预留文件夹中转连接，因此不占文件夹传输的 24 / 5 名额，另设上限。信令扩展 1810～1817（带 `kind`，1 为单文件直传），见 `docs/协议设计-v2.md` 12.9。
- **5 分钟超时**由服务端计时（新配置项，默认 300000 毫秒），超时后通知双方，发送方客户端随即改走上传服务器。
- **历史显示**：直传记录的文件气泡在本机有文件时可「打开 / 打开所在文件夹」；本机没有文件时显示「在线直传，服务器未保存」，不提供下载。

## 4. P2P 徽章

- **显示条件**：链路实际路径为局域网直连（`p2p_link_path_lan`）或打洞直连（`p2p_link_path_punched`）时显示「P2P」；中转（`p2p_link_path_relay`）与非 P2P 传输都不显示。
- **样式**：小圆角标签，文字「P2P」（不翻译，加 `//i18n-ignore`）。样式由 `UI/BalloonMain/P2PBadge` 统一提供（单测 P2PB1~6）。
- **位置**：

| 位置 | 显示时机 | 路径从哪里来 |
| --- | --- | --- |
| 单聊文件气泡（直传） | 传输中与传完后 | 直传会话的链路；历史记录里取服务端写进 content 的路径 |
| 单聊文件夹气泡 | 传输中与传完后 | 文件夹传输的链路；结束记录由服务端把路径写进 `message_type_folder` 的 content |
| 文件共享的传输界面 | 传输中的那一行 | 文件共享传输会话的链路 |
| 远程桌面观看窗、通话窗、屏幕共享观看窗（及发起人的控制条） | 连接期间 | `RdTransport`、`CallMediaSession`、`ShareViewerReceiver` / `ShareHostStreamer` 的链路 |

- **实现**：各业务把「链路实际路径」交给界面（链路统计 `P2PLinkStats::m_path`）；文件与文件夹气泡是自绘的，徽章画在状态文字旁边；其余窗口优先用 balloonui 现成控件（按 UI 约定第 2 条）。

## 7. 转发在线直传的文件（2026-10-05 用户确认）

在线直传的文件服务器上没有副本，按消息原样转发出去，对方拿到的只是一条打不开的记录。规则（`balloonmain::DecideDirectFileForward`）：

| 转发方式 | 本机还有这份文件 | 本机已没有 |
| --- | --- | --- |
| 逐条转发（聊天窗多选、消息记录窗右键与多选） | 不按消息转发，改为把本机文件以**离线文件**发给每个目标：单聊不试在线直传（`SendLocalFileToConversation` 的 `forceOffline`），群聊传到群文件，与群聊里发文件的做法相同 | 跳过；只选了它时提示「在线直传的文件无法转发」，与别的消息一起选时选会话窗口说明「在线直传的文件无法转发：N 个」 |
| 合并转发 | 文件本身一律不发；这条照常进入合并记录，卡片预览行与查看窗里显示「[文件] 文件名（在线直传的文件，服务器未保存，无法转发）」，查看窗里这一行不能打开、下载 | 同左 |

- 聊天窗右键「转发」一条本机已没有文件的直传文件时不进入多选，直接提示「在线直传的文件无法转发」；
- 说明文字由客户端按界面语言生成（`MergedDirectFilePlaceholder`），服务端不改，合并记录里的子消息仍是原来的直传文件消息体；
- 消息记录窗要认出哪些记录是直传文件，本地库归一化 content 的 `file` 子对象从此带 `direct: 1`（`BuildContentJson` / `ParseContentBrief`）。
