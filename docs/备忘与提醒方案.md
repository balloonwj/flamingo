# 备忘与提醒方案

2026-10-03 与用户确认。个人备忘与群备忘都保存在服务端，换电脑登录也在；提醒由客户端按本机时间计算并弹出。§7 是群备忘卡片（2026-10-05），§8 是从聊天消息添加到备忘（2026-10-06）。

## 1. 功能范围

### 1.1 个人备忘

- 入口：主面板系统菜单「备忘与提醒」（排在「公告与通知」之后），打开独立的备忘窗口。2026-10-03 用户反馈后从系统设置「通用」页移到这里。
- 备忘窗口：左侧月历（上个月 / 下个月 / 今天，今天与选中日高亮，有备忘的日子带圆点），右侧选中那天的备忘卡片；「＋ 添加备忘」新建。个人备忘的卡片在鼠标悬停时显示「修改」「删除」，另可双击修改、右键弹「修改 / 删除」菜单；编辑对话框左下角也有「删除」。
- 被提醒的群备忘也出现在本人的日历与卡片里，带所属群名与创建人，只能查看。

### 1.2 群备忘

- 入口：群聊窗右侧边栏在「成员 / 群文件 / 公告」之后新增「备忘」页签，标题写成「备忘 N」（条数），另有红色角标。
- 每条备忘一张卡片：标题；备注（有才显示）；下一次提醒时间或「已结束」；重复规则 · 提醒对象（「提醒 N 人」/「提醒全体成员」）；「创建人 · 时间 创建」。群主、管理员悬停时在标题右侧看到「修改」「删除」，普通成员只能双击查看。
- 只有群主、管理员能新建、修改、删除；新建时选「提醒全体成员」或「指定成员」。
- 可见范围：被提醒的成员，以及本群群主、管理员。没被选中的普通成员看不到。
- 新建、修改群备忘时，在群里发一张备忘卡片，只有这条备忘的可见者（被提醒的成员与群主、管理员）看得到；删除不发卡片，也不留系统提示（2026-10-05 起，见第 7 节；此前三种操作都不在群里留任何消息）。被提醒的成员另在「备忘」页签上看到角标（本次登录后新到、还没点开过页签的条数）。

### 1.3 提醒

| 项目 | 取值 |
| --- | --- |
| 时机 | 到点提醒；提前 N 分钟（0～1440，0 即到点） |
| 重复 | 不重复 / 每天 / 每个工作日（周一到周五）/ 每周（可多选星期几）/ 每月 / 每年 |
| 结束 | 永不结束；提醒 N 次后结束（1～999，「不重复」即 1 次）。「N 次」是重复规则的前 N 次，与客户端开没开无关 |
| 方式 | 右下角弹窗；全屏动画。群备忘由设置的人决定，所有被提醒的人一样 |

- 每月：日期取开始那天的「几号」，当月没有这一天（如 31 号）时取当月最后一天。每年：2 月 29 日在平年取 2 月 28 日。
- 右下角弹窗：一直留着，点「知道了」才关；另有「10 分钟后再提醒」。同时有多条时合并在一个窗口里逐条列出。
- 全屏动画：盖住主面板所在的显示器（主面板收在托盘时盖主显示器）。背景渐暗淡入，标题由下往上滑入；「知道了」「稍后提醒」两个按钮，Esc 等同「知道了」。60 秒无操作收起，改为右下角弹窗继续提醒。
- 错过的提醒（客户端没开、没登录、电脑休眠）：登录或唤醒后合并成一条右下角弹窗「你有 N 条错过的提醒」，只补最近 24 小时内的，每条备忘只补最近一次。
- 「稍后提醒」只在本次运行内有效，退出客户端后不保留。
- 本期不放提示音。

## 2. 数据

时间存<u>本地</u>的年月日时分（`f_start`，十进制 `yyyymmddhhmm`，如 `202610031530`），由客户端按本机时间计算提醒。前提是企业内所有人在同一时区；跨时区部署时会出现提前或推后，本期不处理。

```sql
CREATE TABLE IF NOT EXISTS t_memo (
  f_id         bigint(20)   NOT NULL AUTO_INCREMENT COMMENT '备忘ID',
  f_ctype      int(2)       NOT NULL DEFAULT 1   COMMENT '所属:1个人 2群',
  f_owner      bigint(20)   NOT NULL             COMMENT '个人备忘为本人userid,群备忘为群id',
  f_creator    bigint(20)   NOT NULL DEFAULT 0   COMMENT '创建人userid',
  f_editor     bigint(20)   NOT NULL DEFAULT 0   COMMENT '最后修改人userid',
  f_title      varchar(256) NOT NULL DEFAULT ''  COMMENT '标题(1~50字)',
  f_note       varchar(1024) NOT NULL DEFAULT '' COMMENT '备注(0~200字)',
  f_start      bigint(20)   NOT NULL             COMMENT '首次事件的本地时间 yyyymmddhhmm',
  f_advance    int(11)      NOT NULL DEFAULT 0   COMMENT '提前分钟数 0~1440',
  f_repeat     int(2)       NOT NULL DEFAULT 0   COMMENT '重复:见 memo_repeat_type',
  f_weekdays   int(4)       NOT NULL DEFAULT 0   COMMENT '每周重复的星期掩码 bit0=周一..bit6=周日',
  f_count      int(11)      NOT NULL DEFAULT 1   COMMENT '提醒次数上限,0=永不结束',
  f_style      int(2)       NOT NULL DEFAULT 1   COMMENT '提醒方式:1右下角弹窗 2全屏动画',
  f_target_all int(2)       NOT NULL DEFAULT 0   COMMENT '群备忘是否提醒全体成员',
  f_create_time bigint(20)  NOT NULL DEFAULT 0   COMMENT '创建时间(Unix毫秒)',
  f_update_time bigint(20)  NOT NULL DEFAULT 0   COMMENT '最后修改时间(Unix毫秒)',
  PRIMARY KEY (f_id),
  KEY idx_owner (f_ctype, f_owner)
);

CREATE TABLE IF NOT EXISTS t_memo_target (
  f_memoid  bigint(20) NOT NULL COMMENT '备忘ID',
  f_userid  bigint(20) NOT NULL COMMENT '被提醒成员userid',
  PRIMARY KEY (f_memoid, f_userid),
  KEY idx_user (f_userid)
);
```

删除是真删（同 t_group_announcement）。上限：每人个人备忘 500 条，每群群备忘 200 条。

## 3. 协议（2400 段）

| cmd | 说明 |
| --- | --- |
| 2401 `cmd_memo_list` | 拉取本人可见的全部备忘；带 `groupid` 时只返回该群里本人可见的群备忘 |
| 2402 `cmd_memo_save` | 新建（`memoid` 为 `"0"`）或修改 |
| 2403 `cmd_memo_delete` | 删除 |
| 2404 `cmd_memo_notify` | 推送：`changetype` 1 新增或修改、2 删除 |

备忘对象：

```json
{ "memoid": "12", "ctype": 2, "groupid": "268435463", "creator": "5127", "editor": "5127",
  "title": "周会", "note": "带上周报", "start": "2026-10-05 09:30", "advance": 10,
  "repeat": 3, "weekdays": 1, "count": 0, "style": 1,
  "targetall": false, "targets": ["5308"], "createtime": 1790000000000, "updatetime": 1790000000000 }
```

- `repeat`：0 不重复、1 每天、2 工作日、3 每周、4 每月、5 每年。`weekdays` 只在 `repeat=3` 时有意义，至少选一天。
- 个人备忘 `ctype=1`、`groupid` 为 `"0"`、`targets` 为空。

保存请求带上述字段（不带 `creator` / `editor` / 时间戳，由服务端填）；应答 `{code, msg, memo}`。删除请求 `{memoid}`，应答 `{code, msg, memoid}`。推送 `{changetype, memo}`，删除时只带 `{changetype:2, memoid}`。

规则：
- 个人备忘只能由本人增删改查。
- 群备忘只能由本群群主、管理员增删改；保存时校验调用方是群成员且角色是群主或管理员、`targets` 都是本群成员；标题与备注要过企业敏感词（`error_code_sensitive_word`）。
- 可见：个人备忘归本人；群备忘对被提醒的成员（`targetall` 时为全体成员）与群主、管理员可见。
- 推送：个人备忘推给本人所有在线会话；群备忘推给修改后能看到它的人，修改前能看到、修改后看不到的人收到删除推送。
- 成员退群或被踢：从该群各条群备忘的 `t_memo_target` 中移除，并收到这些备忘的删除推送。解散群：删除该群全部群备忘并推送删除。角色变化：按新的可见范围补推新增或删除。

错误码 1000 段：1000 `error_code_memo_not_exist`（不存在或已删除）、1001 `error_code_memo_invalid`（字段不合法）、1002 `error_code_memo_too_many`（数量已达上限）、1003 `error_code_memo_target_invalid`（提醒对象不是本群成员）。无权限用 `error_code_permission_denied`。

## 4. 客户端

- 登录成功后发 2401 拉全部可见备忘，放在内存里（`MemoBook`），收到 2404 增量更新；断线期间已有的备忘照常提醒，重连后重新拉一次。
- 提醒计算（`MemoRule`，纯逻辑）：按规则枚举事件时间（本地分钟），减去提前分钟数得到提醒时间。
- 调度（`MemoScheduler`，纯逻辑）：
  - 每台电脑在本人配置里记每条备忘「已提醒过的最后一次事件」，避免重启后重复弹出；
  - 每次检查找出「提醒时间 ≤ 现在、且晚于已提醒记录」的那些：提醒时间在最近 5 分钟内的按备忘设定的方式提醒；更早、但在 24 小时内的归入「错过的提醒」；
  - 主面板一次性定时器设到最近一次提醒，最长 60 秒检查一次，改系统时间、休眠唤醒后都能补上。
- 窗口：备忘窗口（月历 + 当天列表）、编辑对话框（个人与群共用，群模式多「提醒对象」）、右下角提醒弹窗、全屏提醒窗口、群聊窗侧边栏「备忘」页。全部用 balloonui 现有控件组合（月历是 `DuiButton` 网格），不改 balloonui。

## 5. 测试用例（已与用户确认）

- 服务端 MEM-S1～S7：个人备忘只对本人；群备忘只有群主 / 管理员能增删改；可见范围；退群 / 被踢后删除推送与拉不到；字段校验；推送对象；敏感词。
- 提醒计算 MEM-R1～R8：不重复；各重复规则（含月末、闰日）；N 次结束；提前跨天；错过只补 24 小时并合并；稍后提醒；修改后重算；时间回拨与休眠唤醒不重复弹。
- 界面 MEM-U1～U6：月历排法；翻月与回到今天；对话框默认值与校验；群侧边栏按角色显示新建；右下角弹窗合并、知道了、稍后提醒；全屏窗口落在主面板所在显示器、60 秒转弹窗。
- 联调 MEM-L1：群主新建只提醒 B 的群备忘，B 收到推送并到点提醒，C 看不到；删除后 B 那里随之消失。

## 7. 群备忘卡片（2026-10-05 起草，同日实施，实施记录见 §7.8）

2026-10-05 与用户确认的需求：

- **新建、修改群备忘时，服务端在该群里发一张备忘卡片**，通知这条备忘的接收者。
- **只有接收者看得到**：被提醒的成员（`targetall` 时为全体成员），以及本群群主、管理员。其他成员看不到这条消息，不计未读，也搜不到。
- 修改时只发给修改之后的接收者；被移出提醒对象的人照旧只收到 2404 删除推送，不发卡片。
- **个人备忘不发卡片，删除备忘也不发卡片。**
- 只改服务端与 PC 客户端，Android 客户端不在本次范围内。

本节覆盖 §1.2 原先「新建、修改、删除都不在群里留系统提示」的约定（§1.2 已同步改写）。消息类型的接线（摘要、不可操作、右键菜单）与群公告卡片相同，见 `docs/群公告接入方案.md` §13。

### 7.1 现状（据实证）

- 保存成功后，服务端用 `MemoProtocol::collectViewers` 算出修改前后各有哪些人能看到这条备忘，再推 2404（`ChatSessionMemo.cpp:253-255`）。其中「修改之后的可见者」正好就是卡片的可见名单，不必另算。
- 服务端已有按人可见的消息机制：`MessageManager::saveMessage` 的可选参数 `audience` 非空时，把 `t_chatmsg.f_audience` 置 1 并写 `t_message_audience`，只有发送者本人与名单里的人能看到；`visibleToUserClause` 一处过滤，同时作用于消息同步、未读计数、会话摘要与消息搜索（`MessageManager.h:69-78` 的 `saveMessage` 参数说明；`docs/文件共享方案.md` 实施记录 1-6）。文件共享卡片就是这样只给部分群成员看的。
- 客户端的 `MemoBook` 在内存里持有本人可见的全部备忘，并随 2404 增量更新（§4）。点卡片时可以直接在本地判断这条备忘是否还在、本人是否还能看到，不需要再向服务端查。
- 编辑对话框支持新建、修改、只读三种打开方式（`MemoEditDialog.h:47-51`）；群聊窗「备忘」页签卡片上的操作经 `WM_APP + 0x57` 先投给自己再执行（`BalloonGroupChatWindow.h:2047` 的 `kMemoCardActionMsg`）。

### 7.2 备忘卡片 `message_type_memo = 23`

由服务端生成，客户端不得发送、撤回、置顶、转发，处理与群公告卡片相同。

- 群聊消息，`from` 为本次新建或修改备忘的人（`editor`），`to` 为群 id。
- **可见范围**：`targetall` 时全员可见（`f_audience = 0`），之后入群的成员按群的历史消息设置也能看到，他们本来就在提醒范围内；否则可见名单取 `collectViewers` 对保存后那条备忘的结果（被提醒成员加群主、管理员），发送者本人由可见机制保证能看到。
- **可见名单在发卡片那一刻确定，之后不再调整**：后来才被设为管理员的人看不到之前的卡片；被移出提醒对象的人仍能看到移出之前收到的那几张卡片，点开时提示已失效（§7.3）。
- 对可见名单里的其他人计未读，并按各人的会话提醒模式提醒，与普通消息相同。
- `clientmsgid` 为 `memo-card-<备忘id>-<updatetime>`：同一条备忘每修改一次就发一张新卡片。
- 卡片内容是发出那一刻的快照，之后备忘再被修改或删除时**不改写**已发出的卡片：每张卡片记录的就是那一次变更。

落库的 `content`：

```json
{ "memoid": "12", "groupid": "268435463", "change": 1, "title": "周会", "note": "带上周报",
  "start": "2026-10-05 09:30", "advance": 10, "repeat": 3, "weekdays": 1, "count": 0,
  "targetall": false, "targetcount": 3, "editorid": "5127", "editor": "张三",
  "text": "[群备忘] 周会" }
```

| 字段 | 说明 |
| --- | --- |
| `memoid`、`groupid` | 备忘 id 与群 id，按字符串编码 |
| `change` | 这张卡片对应的操作：1 新建、2 修改。两端 `Protocol.h` 新增枚举 `memo_card_change`，逐值注释 |
| `title`、`note`、`start`、`advance`、`repeat`、`weekdays`、`count` | 保存后那条备忘的同名字段，取值同 §3 的备忘对象 |
| `targetall`、`targetcount` | 是否提醒全体成员；不是时为被提醒的人数。卡片上只写人数，不带名单 |
| `editorid`、`editor` | 新建或修改的人的 userid 与昵称（昵称取不到时为空串，客户端按 `IMemoHost::MemoUserName` 的口径补） |
| `text` | 只给不认识本类型的老客户端兜底显示，新客户端不读 |

会话列表的 `lastmsg` 带 `digestarg`（备忘标题），客户端生成「[群备忘] 标题」。消息搜索的文字取标题与备注，由可见机制保证只有可见名单里的人搜得到。

### 7.3 客户端

- **协议层与本地库**：与群公告卡片相同（`MessageNotify` 增加卡片 `content`、三处摘要、本地库保存 `content`）。
- **卡片模型** `UI/BalloonChatWnd/ChatMemoCard.{h,cpp}`（不用预编译头，exe 与 FlamingoUnit 共用）：解析 `content`，给出卡片上各行的显示文字。重复规则与提醒对象的文字复用 `MemoViewModel.h` 里已有的 `RepeatText`（第 159 行）与 `TargetsText`（第 207 行），与群「备忘」页签卡片的措辞保持一致。这两个函数接受的是 `net::MemoItem`，卡片解析时先把快照字段填进一个 `MemoItem` 再调用。
- **卡片外观**：顶部一行「群备忘」与「新建」或「修改」标签；标题加粗；一行「开始时间 · 重复规则」；备注一行（有备注时才显示）；底部「提醒 N 人」或「提醒全体成员」。`ChatBubble` 按屏幕共享卡片的几何绘制。
- **失效状态**：`MemoBook` 已经加载完、而里面没有这个 `memoid` 时，卡片底部改为灰色的「备忘已删除，或你已不在提醒对象中」，点击只给提示。`MemoBook` 还没加载完时按正常状态显示。群聊窗收到 `FMG_MSG_MEMO_CHANGED`（C 段 4800）时一并刷新卡片的失效状态。
- **点击**：卡片经 `WM_APP + 0x84`（定义在 `ChatMessageList.h`，已登记进开发约定文档）请宿主群聊窗打开这条备忘，走「备忘」页签双击卡片的同一条路径：群主、管理员以修改方式打开，其他人只读。打开的是 `MemoBook` 里的最新版本，不是卡片上的快照。
- **右键菜单与消息记录窗**：与群公告卡片相同，没有撤回、转发、引用回复、Pin；消息记录窗预览为「[群备忘] 标题」。
- **多语言**：新增界面文字全部用 `TR` 系列，改完运行 `i18n_extract.py`。

| 哪些消息 | `kMsgText` 一类：普通文字（含内联表情、@）、Markdown、代码片段、带引用的回复（只取回复的文字，不含被引用的内容）。大表情、图片、文件、语音、卡片类都不给；发送失败的行、多选模式下不给 | 默认 |
| 谁发的消息 | 自己发的、别人发的都可以 | 默认 |
| 标题 | 消息纯文字的第一个非空行，超过 50 字时截成 49 字加「…」；纯文字为空时用「聊天消息」 | 默认 |
| 备注 | 第一行写来源，单聊为「来自 张三，10月6日 14:30」，群聊为「来自 项目群 / 张三，10月6日 14:30」（发送人是自己时写「我」）；第二行起是消息的纯文字全文。合计超过 200 字时把正文截短并以「…」结尾，来源行保留 | 默认 |
| 提醒时间等其他字段 | 用新建备忘的默认值（`DefaultMemoForDay`，当天）；群备忘的提醒对象默认全体成员，与边栏「新建」相同 | 默认 |

### 8.2 现状（据实证）

- **菜单模型**：`BuildChatMessageMenuModel`（`flamingoclient/Source/UI/BalloonChatWnd/ChatMessageMenu.h:243`，实现 `.cpp:88` 起）只拿到 `msgKind`，分不出 Markdown 与代码片段（这两种在 `ChatBubble.cpp` 建真菜单时才替换「复制」）；没有单聊 / 群聊之分的先例。菜单项枚举 `ChatMessageMenuId` 已用到 18（`ChatMessageMenu.h:45-65`），用例 CIM8 断言各项 id 互不相同。
- **编辑窗**：本人备忘与群备忘共用 `CMemoEditDialog`，靠 `m_ctype` 区分，模态；入口 `CMemoCenter::OpenEditor(owner, item, mode, members)`（`UI/BalloonMemo/MemoCenter.h:142`），`CMemoCenter` 是单例，单聊窗也能直接调用。预填只需在 `item.m_title` / `m_note`（UTF-8）里写好。
- **长度**：标题 50 字、备注 200 字，按字符计（`MemoViewModel.h:97-98`，客户端校验把代理对算 1 个）。服务端还要求标题不含换行，否则返回 1001（`flamingoserver/chatserversrc/MemoProtocol.cpp` 的 `normalizeMemo`）。编辑框的 `SetMaxLength` 只限制键盘输入、不限制 `SetText`，所以预填的内容必须事先截断，否则要到点「保存」时才报错。
- **群备忘入口**：群聊窗 `OpenGroupMemoEditor(memoid)`（`BalloonGroupChatWindow.cpp:7580`）只接受 memoid，新建时用默认值；权限用 `m_myRole` 与 `CanEditGroupMemo` 判断。
- **取纯文字**：普通文字用 `BuildClipSegmentsFromBody` + `ClipSegmentsToPlainText`（`ChatClipboardContent.h:104`、`:130`，表情转成「[表情]」）；Markdown 用 `markdown::MarkdownToPlainTextUtf8`（DLL 不可用时原样返回源文本）；代码片段的正文就是原文。
- **备忘没有「来源」字段**：`net::MemoItem` 与 `t_memo` 都没有会话、消息 id、发送人，所以来源只能写进备注，占用 200 字上限。

### 8.3 设计

- **纯逻辑** `UI/BalloonChatWnd/ChatMemoPrefill.{h,cpp}`：输入一条 `ChatMessage`、来源信息（会话名、发送人显示名、消息时间、是否本人），输出预填的标题与备注（UTF-8），按 §8.1 的规则取纯文字、截断、拼来源行。不依赖窗口，便于单测。
- **菜单**：`ChatMessageMenuId` 新增 `kChatMsgMenuAddMemo = 19`（单聊「添加到备忘」、群聊「添加到我的备忘」共用）与 `kChatMsgMenuAddGroupMemo = 20`。`BuildChatMessageMenuModel` 增加两个参数：是否文字类、是否显示「添加到群备忘」；两项放在第一组「复制」类之后。气泡建真菜单时由消息列表告知是否群聊、本人能否新建群备忘（群聊窗在同步群角色时一并设置，单聊窗不设置）。
- **投给宿主**：气泡选中这两项后，把预填结果放进堆上的结构体，投窗口私有消息 `WM_CHAT_ADD_TO_MEMO`（`WM_APP + 0x8D`，定义在 `ChatMessageList.h`，已登记进开发约定文档 UI 约定 6；起草时拟用的 `0x8C` 已被 Markdown 预览窗口占用），宿主处理后 delete。
- **宿主**：单聊窗调 `CMemoCenter::OpenEditor` 新建本人备忘；群聊窗按目标分别新建本人备忘或群备忘，后者给 `OpenGroupMemoEditor` 加一个接受预填内容的重载，权限与超时检查照旧。
