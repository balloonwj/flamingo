# 截图独立模块方案（FlamingoScreenshot.dll，托盘入口，未登录可用）

2026-10-07 起草。用户要求：截图做成独立 DLL；托盘菜单始终有「截图」入口；未登录时也能截图。

## 2. 已定的决定（2026-10-07 与用户逐项确认）

| 问题 | 决定 |
| --- | --- |
| 未登录时快捷键按哪份配置注册 | 截图快捷键与「截图时隐藏当前窗口」改为全局配置，存 `config/flamingo.ini` 的 `[screenshot]` 段，所有账号共用，程序启动就注册；升级后第一次登录时把该账号配置里的值迁移过去 |
| 未登录时「识别文字」怎么办 | OCR 改为启动时预加载、启动时接上结果窗口，登录前后截图都能识别文字 |
| 托盘菜单项的位置与文字 | 两种菜单都紧跟「打开主面板」；文字为「截图（Alt+Z）」（复用聊天窗剪刀提示的 `ScreenshotCommandText`，全角括号），括号里是当前快捷键，快捷键停用或注册失败时只显示「截图」 |

## 3. 设计

### 3.1 DLL 形态

照 `FlamingoLock.dll` 的形态：

- 目录 `flamingoclient/FlamingoScreenshot/`，产物 `FlamingoScreenshot.dll`，与其它插件 DLL 输出到同一目录。
- 静态链接自己的一份 balloonui；四个配置都定义 `WIN32`、使用静态 CRT。
- 工程文件由 `python flamingoclient/tools/gen_screenshot_vcxproj.py` 生成，子目录下的源文件自动收集。
- 标题栏图标：截图遮罩没有正式标题栏，不适用 UI 约定第 10 条。

### 3.2 接口 `FlamingoScreenshot/ScreenshotApi.h`

- `kApiVersion` 两边必须完全一致，否则工厂返回 NULL、宿主当作模块不可用。工厂函数名 `FlamingoScreenshot_Create`，由 `.def` 固定。
- 跨模块只传纯虚接口与基本类型（两边各有独立的 CRT 堆）。
- `IScreenshotHost`（exe 实现）：`Log`、`Translate`、`GetUiLanguage`、`IsOcrAvailable`、`LaunchOcrForImage(owner, bgra 像素, 宽, 高)`。
- `IScreenshotSink`（每次截图由发起方提供，可为 NULL）：`OnSend(pngPath)`、`OnStage(pngPath)`，对应现在的「发送」「发送到对话框」两个回调，路径只在回调期间有效。
- `IScreenshotModule`（DLL 实现）：`Init`、`Shutdown`、`GetApiVersion`、`IsRunning`、`Run(const ScreenshotRequest*, IScreenshotSink*)`。`ScreenshotRequest` 带 `m_cbSize`、发起窗口、要排除的窗口、是否以全屏选区开始；`Run` 仍是模态的，返回时截图已结束，返回值同现在的 `CScreenCaptureOverlay::Run`。

### 3.3 exe 侧

- 新增 `Source/Feature/Screenshot/ScreenshotHost`（单例）：程序启动时在 `AppShell` 里同步加载 DLL（与 Markdown 预加载同一处）；退出时卸载。加载失败不重试，记一条日志。
- 三个发起点改为经 `ScreenshotHost` 调用：两个聊天窗的 `DoScreenshot`、`RunClipboardScreenshot`。
- DLL 不可用时：托盘菜单不出现「截图」，聊天窗工具栏的截图按钮与下拉箭头隐藏，快捷键不注册，设置页的快捷键一行显示为不可用。

### 3.4 全局配置

- 新增 `Source/Feature/Screenshot/ScreenshotPrefs`：读写 `flamingo.ini` 的 `[screenshot] hotkey`（十进制整数，0 表示停用）与 `[screenshot] hidewindow`（0 / 1）；读不到或不是数字时取默认值（Alt+Z、隐藏）。值都是 ASCII，符合该文件只能是 ASCII 的约定。
- 迁移：登录成功后，若 ini 里还没有 `[screenshot] hotkey`，把这个账号配置里的两项写进 ini；ini 已有值时不覆盖。账号配置里的旧键保留不删，只是不再作为生效值。
- 设置页的快捷键一行与「截图时隐藏当前窗口」改为读写全局配置。

### 3.5 快捷键注册时机

- 主面板窗口建好后（启动时、未登录）就按全局配置注册截图快捷键；登出后保持注册。
- 「打开主面板」Ctrl+Alt+D 与录屏 Ctrl+Alt+R 仍在登录后注册，不变。
- 锁屏解锁后的恢复（`BalloonMainPanelLock.cpp` 的 `CBalloonMainPanel::OnScreenUnlocked`）与设置页录入结束后的恢复，要区分是否已登录：未登录时只恢复截图快捷键。

### 3.6 托盘菜单

- 两种菜单（登录前 / 面板锁定、登录后）都在「打开主面板」之后加「截图 (Alt+Z)」，图标新增一种。
- 点了之后的行为与「在聊天窗之外按快捷键」相同：不绑定会话，操作栏为「重选 / 保存 / 取消 / 完成」，结果放进剪贴板。
- 先让菜单窗口消失、桌面合成一次之后再抓屏，否则菜单会出现在截图里：菜单命令里只投递一条消息，在消息处理里先 `DwmFlush` 再发起截图。

### 3.7 OCR 改为启动时预加载

把原来在 `MainPanelSessionController.cpp` 登录成功后调用的 `balloonocr::RegisterOcrLaunchers()` 与 `COcrModuleHost::StartPreload` 移到 `AppShell` 启动时（Markdown 预加载旁），语言参数取启动时已确定的界面语言。

### 3.8 多语言与日志

- `FlamingoScreenshot/` 加入三处扫描范围：`tools/i18n_extract.py` 的 `SCAN_ROOTS`、`Source/Tests/I18nSourceScanner.cpp` 的 `kScanRoots`、`I18nGuardTests.cpp` 的 `kConvertedPaths`。
- DLL 里的 `TR` 经宿主接口转发（同 FlamingoLock 的 `i18n::InitFromHost`）；日志带 `[shot] ` 前缀，经宿主写入 exe 的日志。

## 7. 粘贴截图后点「发送」没有反应（bugs.md BUG-106，2026-10-08）

### 7.1 现象与原因

用户登录后按 Alt+Z 截图（在聊天窗之外发起，结果放进剪贴板），在单聊窗输入框里按 Ctrl+V 粘贴，图片显示在输入框里，点「发送」没有任何反应，日志里也没有发送记录。这是 2026-10-05 就记录的 BUG-106，与本方案的 DLL 拆分无关；未登录、聊天窗之外都能截图进剪贴板之后更容易碰到。

原因（据实证，实验用例 PIM0 `[.][pasteimage-repro]`，`tmp/verify7/pim0.log`）：

- 截图放进剪贴板的只有位图（`CF_BITMAP`，系统可转出 `CF_DIB`），没有文字。
- 输入框按 Ctrl+V 时，`ChatInputRichEdit::OnKeyDown` 先试 Flamingo 自己的聊天内容格式（`TryPasteChatContent`），不是这种格式就交给基类 `DuiRichEdit::OnKeyDown`，按键直接转给 RichEdit 引擎（`ForwardToEngine`），**绕过了聊天窗设置的「默认按纯文本粘贴」**（右键「粘贴」走 `DuiRichEdit::Paste()`，会遵守这项设置，剪贴板里只有图片时什么也不插入）。
- RichEdit 引擎把位图作为原生图片插入：不是 OLE 对象（实验中 `GetObjectCount()` 为 0），`EnumContent` 把它读成**一个空格**（`U+0020`）。
- 发送时 `BuildOutgoingParts` 把只有空白的文字组丢掉，`parts` 为空，`DoSend` 在 `parts.empty()` 处静默返回；图片留在输入框里，看上去就是「发送按钮失效」。

### 7.2 修法（2026-10-08 用户确认「粘贴图片走『发送到对话框』」）

1. **判定**（纯函数，`UI/BalloonChatWnd/ChatPasteImage.h`）：`DecideChatPaste(hasChatContent, hasText, hasImage)`，优先级为 Flamingo 聊天内容 > 文字 > 图片 > 交给原来的粘贴。剪贴板里有文字时照旧粘贴文字（例如从 Word 复制的内容同时带位图），只有「没有文字、只有图片」时才按图片处理。
2. **位图转 PNG**（同一文件）：`SaveDibAsPng(dib, bytes, path)` 把 `CF_DIB` 数据存成 PNG（GDI+，不碰剪贴板，可单测）；`ReadClipboardImageToPng(owner, outPath)` 打开剪贴板取 `CF_DIB`，存到临时目录 `flamingo_paste_<tick>.png`。
3. **输入框**：`ChatInputRichEdit` 新增私有方法 `TryPasteClipboardImage`。Ctrl+V、Shift+Insert 与右键「粘贴」在 `TryPasteChatContent` 之后调用它：判定为图片时把剪贴板图片存成临时 PNG，交给聊天窗已经注册的插图回调 （`SetImageStager`，单聊窗、群聊窗都注册为 `StageImageThunk` → `StageImageInInput`），不再让 RichEdit 原生粘贴。这个回调本来就用于「粘贴 Flamingo 聊天内容里的图片」，在按键处理中同步调用，路径已经验证过；因此**不需要新的窗口消息号**，聊天窗也不用新增消息处理。没有注册插图回调、或输入框只读时不拦截，照旧交给基类。剪贴板里只有图片却没能存成 PNG 时同样不交给 RichEdit（粘进去也发不出去），日志里记一条警告。
4. **聊天窗的插图路径**：`StageImageInInput` 与截图「发送到对话框」同一路径——带编号插入内嵌图、登记 `m_pendingShotPaths`，发送时 `BuildOutgoingParts` 从编号读回源文件、按图片消息发出。密聊状态同样适用（`SendSecretImagePart` 也按 `m_pendingShotPaths` 取源文件）。
6. **日志**：两个聊天窗的 `DoSend` 在「输入框不为空、但聚合不出任何可发送部分」时记一条日志，以后同类问题不再无迹可查。
