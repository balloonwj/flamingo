# 撤回后重新编辑方案

2026-10-06 与用户逐项确认。适用于 PC 客户端单聊窗、群聊窗：自己撤回一条文字类消息后，撤回提示行末尾出现可点击的「编辑」，点击后把撤回的内容放回输入框再编辑。属于 12 项新功能的第一批（另外三项见 `docs/快捷回复方案.md`、`docs/备忘与提醒方案.md` §8、`docs/群管理接入方案.md` §14）。

## 1. 已定事项

| 事项 | 结论 | 来源 |
| --- | --- | --- |
| 谁能看到「编辑」 | 只出现在**本人撤回、且本人发送**的消息的提示行上；对方和群里其他人看到的提示行不变 | 默认，用户未提异议 |
| 显示多久 | 撤回后 5 分钟内；5 分钟内关窗重开、重新登录仍然显示，超时后提示行变回普通的「你撤回了一条消息」 | 用户确认 |
| 哪些消息给「编辑」 | 文字类：文字、大表情、带 @ 的文字、Markdown、代码片段。图片、文件、语音、合并转发、接龙等都不给 | 用户确认 |
| 点击后的行为 | 与现有的「重新编辑」（发送失败的文字消息，`docs/敏感词方案.md` §8.4）完全相同：文字和表情插到输入框光标处，输入框原有内容保留；群聊里的 @ 重新登记为待发候选；Markdown 打开 Markdown 编辑器并预填源文本；代码片段打开发送代码窗口并填好原文。引用不恢复 | 默认 |
| 原文从哪里来 | 撤回的那一刻由本机保存一份快照，不依赖服务端是否还下发已撤回消息的原文（BUG-58 修复后服务端不再下发） | 默认 |
| 其他设备 | 只有执行撤回的那台电脑上有快照，所以只有它显示「编辑」 | 默认，用户未提异议 |
| 点过以后 | 「编辑」可以重复点击，每次都再插入一遍；不因点过而消失 | 默认 |

## 2. 现状（据实证）

- **撤回提示行**：在线收到撤回推送（cmd 1509）时，`ChatMessageList::RecallMessageByMsgid` 调 `ChatBubble::RecallToTip`，把这一行就地改成 `kMsgTime` 样式，正文换成提示文案（`flamingoclient/Source/UI/BalloonChatWnd/ChatBubble.cpp:2215`），**原文在内存里被覆盖**。重开窗口拉历史时，已撤回的消息由 `MakeRecalledTipRow` 换成提示行（`ChatSystemTip.h:53`，单聊调用点 `BalloonChatWindow.cpp:7647`，群聊 `BalloonGroupChatWindow.cpp:5868`）。
- **可点击提示行的先例**：接龙提示行。`RelayTipAtPoint` 按居中文字的宽度判断落点（`ChatBubble.cpp:2623`），悬停加下划线、按下与抬起、手型光标的处理同在 `ChatBubble.cpp`。
- **协议、服务端与 `t_msg` 都不记录撤回时间**：协议的撤回推送只有 ctype / cid / msgid / operator（`net/MessageProtocolClient.h` 的 `MessageRecalledNotify`），服务端消息体只带 `recalled` 与 `recalledby`（`flamingoserver/chatserversrc/MessageProtocol.cpp:249-254`），本机库对 `t_msg` 只执行 `UPDATE t_msg SET recalled=1`（`UI/BalloonHistory/V2MsgStore.cpp:168`）。
- **自己刚发出的单聊消息不一定在本机库里**：据推测，本机库只在收到推送（`BalloonMainPanel.cpp:3963`）和拉历史、拉 Pin 时写入，发送回执时不写入，所以撤回时 `MarkRecalled` 可能命中 0 行。本方案不依赖这一点，见 §3.1。
- **「重新编辑」的数据结构**：`ChatReeditData`（`ChatReedit.h`）含文字 / 表情片段、@ 候选、Markdown 源文本、代码片段的语言与原文；宿主处理 `WM_CHAT_REEDIT_REQUEST`（`WM_APP + 0x68`）时按它放回输入框或打开对应编辑窗口。

## 3. 设计

### 3.1 快照

- **何时生成**：主面板收到撤回推送、判断撤回者是本人后，把「是否本人撤回」一并交给已打开的聊天窗（`OnMessageRecalled` 增加参数）。聊天窗在 `RecallToTip` 覆盖原文**之前**，用这一行的 `ChatMessage` 判断是否符合 §1 的条件，符合就生成一份 `ChatReeditData` 作为快照。
- **为什么聊天窗一定开着**：撤回只能从聊天窗气泡的右键菜单发起，执行撤回的那台电脑上，推送到达时该聊天窗必然开着。如果用户在推送到达前的一瞬间关了窗，就拿不到快照，这种情况不显示「编辑」。
- **存到哪里**：本机消息库 `msgv2.db` 新建一张表 `t_recall_draft`，与 `t_msg` 分开，原因是 `t_msg` 里可能没有这一行（见 §2），而且同步历史时的 upsert 会改写 `t_msg`。

  | 列 | 含义 |
  | --- | --- |
  | `ctype`、`cid`、`msgid` | 主键，口径与 `t_msg` 相同 |
  | `recall_time` | 撤回推送到达本机的时间（Unix 毫秒，本机时钟） |
  | `payload` | 快照，`ChatReeditData` 序列化成的 UTF-8 JSON（片段、@ 候选、Markdown 源文本、代码语言与原文），带版本号字段 |

- **清理**：写入时与打开库时删除 `recall_time` 早于「现在减 5 分钟」的行，表里通常只有几行。

### 3.2 提示行

- 提示行文字为「你撤回了一条消息」，后面隔一个空格画「编辑」，用聊天窗超链接的颜色；整段居中，宽度按两段合计。
- 只有「编辑」两个字是可点击的：鼠标停在上面时加下划线、显示手型光标，按下并在原处抬起才算点击；多选模式下不可点。
- 点击后，气泡把快照复制一份放到堆上，投 `WM_CHAT_REEDIT_REQUEST` 给宿主聊天窗，后续处理与「重新编辑」完全相同，不新增窗口消息号。
- 提示行本身的行高、样式都不变。

### 3.3 5 分钟到期

- 气泡记下到期时刻（`recall_time + 5 分钟`）。绘制、命中测试时都检查当前时间，过期即视为普通提示行。
- 为了让链接到点就从界面上消失，聊天窗用一个定时器，定在所有可编辑提示行中最早的到期时刻；触发时调消息列表的到期处理，把到期的行重画，再按下一个到期时刻重新定时。做法参照群聊窗的接龙到期定时器（`kRelayExpiryTimerId`）。

### 3.4 重开窗口与重新登录

- 聊天窗拉历史生成撤回提示行时，对其中「本人撤回」的那些 msgid，批量到 `t_recall_draft` 查快照（经主面板，做法同 `QueryVoicePlayed`）；查到且未过期的，提示行带上快照和到期时刻。

### 3.5 代码组织

- 新增 `UI/BalloonChatWnd/RecallEdit.{h,cpp}`：纯逻辑，不依赖窗口。包括：是否给「编辑」的判定、到期判定、快照的序列化与解析、时限常量（300 秒）。
- `CV2MsgStore` 增加 `t_recall_draft` 的写入、按 msgid 批量查询、清理三个方法。
- `ChatBubble`：`RecallToTip` 增加可选的快照与到期时刻参数；新增「编辑」的命中测试、悬停、点击处理。
- `ChatMessageList`：`RecallMessageByMsgid` 在覆盖原文前取出快照并返回给调用方；新增到期处理方法。
- 单聊窗、群聊窗：撤回推送与拉历史两条路径各接一处，加到期定时器。
- 主面板：`OnMessageRecalled` 传「是否本人撤回」，把聊天窗交回的快照写入本机库。

## 5. 测试用例（标签 `[recalledit]`）

| 编号 | 内容 |
| --- | --- |
| RE1 | 判定：本人发送并本人撤回的文字、大表情、带 @ 的文字、Markdown、代码片段给「编辑」；别人发的、本人撤回别人的（群管理员）、图片、文件、语音、合并转发、接龙、发送失败的行不给 |
| RE2 | 快照序列化与解析往返：文字加表情加 @ 片段、Markdown 源文本、代码片段（含语言）各一条，解析结果与原数据逐字段相同；损坏的 JSON、版本号不认识的 JSON 解析失败且不崩溃 |
| RE3 | 到期判定：撤回后 0 秒、299.999 秒有效，300 秒起无效；撤回时间晚于当前时间（本机时钟被往回调）时按有效处理、到期时刻不超过「当前时间加 5 分钟」 |
| RE4 | 本机库：写入后按 msgid 批量查得到，跨会话同 msgid 互不影响；清理删掉过期行、保留未过期行；重复写入同一主键覆盖旧值 |
| RE5 | 气泡：带快照的撤回提示行，落点在「编辑」上命中，落在前面的提示文字上不命中，多选模式不命中，到期后不命中；不带快照的提示行与改动前行为相同 |
| RE6 | 消息列表：撤回本人的文字消息时取出的快照与撤回前的气泡内容一致；撤回图片消息时不产生快照；到期处理把过期行变成普通提示行，并返回下一个到期时刻 |
| RE7 | 点击「编辑」后宿主收到的 `WM_CHAT_REEDIT_REQUEST` 数据与原消息一致（单聊、群聊各一条） |

## 6. 实机核对清单

1. 单聊发一条带表情的文字，撤回后提示行出现「编辑」，点击后文字和表情回到输入框，输入框原有的文字还在。
2. 群聊发一条带 @ 的文字，撤回后点「编辑」，@ 回到输入框，直接发送后对方仍然收到 @ 提醒。
3. Markdown 消息、代码片段各撤回一条，点「编辑」分别打开 Markdown 编辑和发送代码窗口。
4. 撤回图片，提示行没有「编辑」。
5. 撤回后关窗重开、退出重新登录，5 分钟内「编辑」仍在；等到 5 分钟，链接在窗口开着的情况下自动消失。
6. 对方的聊天窗（另一台电脑）里，提示行只有「对方撤回了一条消息」，没有「编辑」。
