# 「我的收藏」接入方案与开发计划

> 作者：balloonwj@qq.com　起草日期：2026-08-03
> 用途：记录在主面板「联系人」Tab 增加「我的收藏」分类、支持把联系人与群组加入收藏的整体方案、分期路线与开发步骤。后续每步开工前据此细化、收尾后回填实际结果。

---

## 1. 背景与目标

主面板的「联系人」Tab 目前只有企业组织架构一棵树。企业规模上来之后，天天要找的那几个人和那几个群埋在部门树深处，每次都要展开好几层。本方案在树顶加一个「我的收藏」分类，让用户把常用的联系人和群组放进去。

最终形态：用户在联系人行、群行、会话行上右键即可加入 / 移出收藏；收藏内容存在服务端，换台机器登录仍在；「我的收藏」作为「联系人」Tab 树的第一个根节点，联系人与群组混挂其下。

## 2. 现状盘点（据实证，均已核对代码位置）

### 2.1 协议里已经埋好半个脚手架，两头都没接

`cmd_get_contacts`(1201) 的应答数据结构里本来就有 `favorites` 字段：

- `flamingoserver/chatserversrc/ContactsProtocol.h:75` —— `std::vector<int64_t> favorites; //星标好友的用户ID列表（本期恒为空）`
- `flamingoserver/chatserversrc/ContactsProtocol.cpp:78-82` —— 编码逻辑已写好，把 `data.favorites` 逐个转成字符串塞进 JSON 数组
- `flamingoserver/chatserversrc/ChatSession.cpp:953` —— 注释明写"favorites（星标好友）本期不实现"，从不填充，故恒为空数组
- `flamingoclient/Source/net/ContactsProtocolClient.h` —— `ContactsResult` 结构里<u>没有</u>这个字段，客户端压根不解析

**结论：现在改这个字段的形状是零成本的**，没有任何存量客户端依赖它。

### 2.2 UI 层也有占位，但真实数据一到就被冲掉

- `flamingoclient/Source/BalloonMain/MainPanelMockData.h:90` —— `MockFavorites()`
- `flamingoclient/Source/BalloonMain/BalloonMainPanel.cpp:652` —— `FillContactsTree()` 用它渲染了一个分组根节点（设计期占位）
- `flamingoclient/Source/BalloonMain/BalloonMainPanel.cpp:1668` —— 真实通讯录到达时 `OnContactsArrived()` 会 `tv->Clear()` 并按部门树重建，该分区随即消失

### 2.3 有个同名陷阱：1901~1903 是「收藏消息」

`flamingoclient/Source/net/Protocol.h:216-218` 已占用：

```
cmd_add_favorite    = 1901,   //收藏消息
cmd_get_favorites   = 1902,   //拉取收藏列表
cmd_delete_favorite = 1903,   //删除收藏
```

这三条是把**某条聊天记录**存起来，与本方案的"收藏联系人 / 群组"是两件事，<u>不得复用</u>，也不要把两者的数据表混在一起。

### 2.4 最合适的参照物是 `t_conversation`

`flamingoserver/table.sql:369` 的 `t_conversation` 表主键为 `(f_userid, f_ctype, f_cid)`：`f_ctype` 取 1 单聊 / 2 群聊，`f_cid` 单聊存对端 userid、群聊存 groupid，上面挂 `f_pinned` / `f_mute` 这类每用户的标志位，由 `cmd_set_conversation`(1513) 驱动写入。

**这个复合键正好能同时表达"联系人"与"群组"**，收藏沿用同一套键设计。

### 2.5 已经具备的基础

- 三处右键菜单都已成形，加一项即可：`ContactMenuId`（`BalloonMainPanel.cpp:119`）、`GroupMenuId`（同文件 `:137`）、`ConversationMenuId`（`MainPanelConversationMenu.h`）。三者都已有"文案随当前状态取反"的写法（置顶 / 取消置顶）可照抄。
- 退群清理已有挂载点：`CBalloonMainPanel::CleanupLeftGroup()`（`BalloonMainPanel.cpp:2801`）。
- 两端都有测试框架：服务端 doctest（`flamingoserver/tests/`）、客户端 Catch2（`flamingoclient/Source/Tests/`，产出 `Bin/Tests/Win32/Debug/FlamingoUnit.exe`）。

## 3. 数据库设计

### 3.1 新建 `t_favorite`

沿用 `t_conversation` 的复合键，但**不复用那张表**：`t_conversation` 的一行代表"有过会话"，仅为标记收藏就往里插行，会让一个从没聊过的同事凭空冒出一条会话记录。

```sql
CREATE TABLE IF NOT EXISTS t_favorite (
    f_userid      bigint(20) NOT NULL COMMENT '收藏归属用户userid',
    f_ctype       int(2)     NOT NULL COMMENT '收藏对象类型:1联系人 2群组',
    f_cid         bigint(20) NOT NULL COMMENT '联系人为对端userid,群组为groupid',
    f_order       int(11)    NOT NULL DEFAULT 0 COMMENT '手动排序权重,值小者靠前;0表示未手动排序',
    f_create_time bigint(20) NOT NULL DEFAULT 0 COMMENT '收藏时间,Unix毫秒',
    PRIMARY KEY (f_userid, f_ctype, f_cid),
    INDEX idx_user (f_userid)
) ENGINE=InnoDB DEFAULT CHARSET=utf8
```

`f_order` 本期不用（一律 0），排序按 `f_create_time` 倒序。留这一列是为了以后加拖拽排序时不必改表。

### 3.2 三处建表定义都要改，漏一处就有一套库跑不起来

| 文件 | 改什么 |
| --- | --- |
| `flamingoserver/table.sql` | MySQL 建表语句 |
| `flamingoserver/table_sqlite.sql` | SQLite 建表语句 |
| `flamingoserver/sqliteapi/SqliteSchema.cpp` | 内嵌建表语句（约 `:275` 一带）与表名清单（`:512` 一带）、列清单（`:709` 一带）三处 |

当前部署跑的是 SQLite（`flamingoserver/etc/chatserver.conf` 里 `dbtype=sqlite`），SqliteSchema 那处尤其不能漏。

## 4. 协议设计

### 4.1 改造既有字段：`cmd_get_contacts` 应答的 `favorites`

从"用户ID字符串数组"改成对象数组，使其能同时装下联系人与群：

```json
"favorites": [
    {"ctype": 1, "cid": "5081"},
    {"ctype": 2, "cid": "268435456"}
]
```

`ctype` 取 1 联系人 / 2 群组，与 `t_favorite.f_ctype`、`t_conversation.f_ctype` 同一口径。`cid` 沿用本协议"64 位 ID 一律以字符串编码进 JSON"的既有约定。

按 `f_create_time` 倒序排列，最近收藏的排最前。

### 4.2 新增 `cmd_set_favorite = 1215`

1200 段现状：1201~1210 已用，1211 / 1212 已废弃留空不复用，1213 / 1214 已用，**1215 空闲**。

```
请求  {"ctype":1, "cid":"5081", "favorite":1}
应答  {"code":0, "msg":"ok", "ctype":1, "cid":"5081", "favorite":1}
```

`favorite` 取 1 收藏 / 0 取消，一条命令兼管两个方向，与 `cmd_set_blacklist`(1213)、`cmd_set_conversation`(1513) 的既有写法一致。

应答回带 `ctype` / `cid` / `favorite`，便于客户端在多条请求并发时对上号。

### 4.3 服务端校验与新增错误码

| 校验 | 不通过时 |
| --- | --- |
| `ctype` 必须是 1 或 2、`cid` 为正、`favorite` 为 0/1 | `error_code_bad_request`(3) |
| `ctype==1`：对方须是同企业成员 | `error_code_not_friend` |
| `ctype==2`：自己须是该群成员 | `error_code_not_group_member` |
| 收藏总数上限 200 条 | 新增 `error_code_favorite_limit` |

上限取 200：收藏是"常用入口"，几百条就失去意义了；同时避免恶意刷表。该常量在服务端定义为具名 `constexpr`，不得写成裸数字。

### 4.4 多端同步

本期**不做**推送。A 设备收藏后，B 设备在下次拉通讯录（重登 / 重连）时同步。

后续单独一轮再加 `cmd_favorite_changed_notify = 1216`，形态照抄 `cmd_conversation_changed_notify`(1514)
这类"多端同步某属性"的推送。（本节原本写的是照抄 `cmd_friend_relation_changed_notify`(1208)，
该命令已随好友关系子系统于 2026-08-05 删除，编号作废不复用。）

## 5. 服务端行为

新增 `chatserversrc/FavoriteManager.{h,cpp}`（单例，照 `GroupManager` 的形态）：

- `getFavorites(userid, std::vector<FavoriteRecord>& out)` —— 按 `f_create_time` 倒序取该用户全部收藏
- `setFavorite(userid, ctype, cid, favorite, int& outErrorCode)` —— 收藏走 `INSERT`（已存在则幂等返回成功），取消走 `DELETE`
- `countFavorites(userid)` —— 供上限校验
- `removeFavoriteForAll(ctype, cid)` —— 群被解散 / 用户被停用时清理所有人对它的收藏

新增 `chatserversrc/FavoriteProtocol.{h,cpp}`（纯逻辑，只依赖 jsoncpp，不碰网络与数据库，照 `ContactsProtocol` 的形态）：解析 `cmd_set_favorite` 请求、构造其应答。

`ChatSession` 增加 `onSetFavorite()` 处理 1215；`onGetContacts()` 里把第 953 行那句"本期不实现"换成真正调用 `FavoriteManager::getFavorites` 填充 `ContactsData::favorites`。

清理挂载点：群解散（`cmd_dismiss_group`）与账号停用时调 `removeFavoriteForAll`。

## 6. 客户端数据流

`net/ContactsProtocolClient` 的 `ContactsResult` 增加 `std::vector<FavoriteItem> m_favorites`（`FavoriteItem` 含 `m_ctype` / `m_cid`），并在解析处填充。

新增 `net/FavoriteProtocolClient.{h,cpp}`：构造 `cmd_set_favorite` 请求、解析其应答，形态照 `ContactsProtocolClient`。

新增 `BalloonMain/FavoritesModel.{h,cpp}` —— **纯逻辑，不碰窗口不碰网络，进 FlamingoUnit 单测**：

- 持有当前收藏集合，`IsFavorite(ctype, cid)`
- `Add` / `Remove`，以及供乐观更新用的回滚
- `GetMenuLabel(bool isFavorite)` —— 返回「添加到收藏」或「取消收藏」
- `BuildRows(...)` —— 把收藏集合 + 联系人资料池 + 群列表合成"收藏分区该显示哪些行"的模型（行含显示名、副标签、是否画在线状态点、头像取自哪里）

`CBalloonMainPanel` 持有一个 `FavoritesModel`，在 `OnContactsArrived` 里灌入，在右键菜单命令里做乐观更新 + 发请求，应答失败则回滚（照抄状态胶囊 `ApplyPresenceOptimistic` / `OnChangePresenceResult` 那套写法）。

## 7. 界面与交互

### 7.1 「我的收藏」根节点

位置：「联系人」Tab 的 DuiTreeView 第一个根节点，排在企业部门树之前。

```
▼ 我的收藏  5
     苏沐辰            ●
     设计组组长         ●
     产品部周会（群）
▼ 明远科技有限公司 · 161 人
   ▼ 产品部
        ……
```

- 根节点文案 `我的收藏  N`，`SetItemSelectable(false)`（点击只展开折叠，不显示选中底色），与现有分组根节点一致
- 联系人行画在线状态点，群行不画
- 头像：联系人走现有的 monogram / 自定义头像路径；群走群头像
- **收藏为空时整个根节点不显示**（而非显示"暂无收藏"提示行）——下面紧跟着部门树，空节点很突兀
- 默认展开

### 7.2 右键菜单

三处各加一项，文案随当前状态取反：

| 菜单 | 新增项 |
| --- | --- |
| 联系人右键（`ContactMenuId`） | `kCMenuFavorite` —— 添加到收藏 / 取消收藏 |
| 群聊右键（`GroupMenuId`） | `kGMenuFavorite` —— 添加到收藏 / 取消收藏 |
| 会话右键（`ConversationMenuId`） | `kConvMenuFavorite` —— 添加到收藏 / 取消收藏 |

放在"查看资料"之后、第一条分隔线之前。

### 7.3 其它约定

- 服务号**可以**收藏（服务号本质也是联系人，`ContactInfo::usertype == 1`，拦着反而奇怪）
- 「群」Tab **不做**任何标记，保持原样
- 收藏区里的行，左键点击行为与它在原位置一致：联系人开单聊窗，群开群聊窗

## 10. 待确认与风险

- **`favorites` 字段换形状**：本方案判断"零成本"的依据是服务端恒返回空数组且客户端不解析（见 §2.1）。若另有未纳入本仓库的客户端（如 Android 端）已经在解析该字段，需先确认。`flamingoAndroid/` 当前未接入 v2 通讯录协议，初步判断不受影响，开工前再核一次。
- **收藏对象失效的时机差**：被收藏的联系人离职（被移出企业 / 账号停用）或群被解散后，服务端清理与客户端本地缓存之间有一个时间窗，期间收藏区可能出现一条查不到资料的行。`BuildRows` 的第 17 条用例即为此兜底——查不到就跳过该行。
- **上限 200 的取值**是拍的，没有实测依据。若实际使用中有人抱怨不够，改常量即可，表结构不受影响。

> **2026-08-05 更新：** 企业版删除了好友关系子系统，本文中"是好友或同企业成员"这条口径
> 已退化为"同一企业即可收藏"（`ChatSession::onSetFavorite` 里的 `isFriend` 那半个条件已去掉）；
> "被删好友时清理收藏"这个挂载点也随之消失。错误码仍沿用 `error_code_not_friend`(202)，
> 只是含义改成了"够不着该联系人（不在同一企业）"。
