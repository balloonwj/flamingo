# 「无操作自动离开」方案与实现记录

> 作者：balloonwj@qq.com　起草日期：2026-08-12
> 用途：记录 PC 客户端「电脑一段时间无操作，自动把在线状态切到离开；人回来后自动切回在线」这一特性的功能约定、触发路径、配置项、代码落点与测试情况。

---

## 1. 背景与目标

改版前，用户离开座位后在线状态不会变。同事在通讯录里看到的仍是绿色的「在线」，消息发过来以为马上有人回，实际上人已经走了半小时。反过来，靠用户自己每次离座前手动切「离开」、回来再切「在线」也不现实——没人会记得。

目标：**让在线状态自动跟上"人在不在电脑前"这件事**，同时不夺走用户自己挑状态的权利。

---

## 2. 功能约定

这四条是整个特性的骨架，实现与测试都围绕它们展开。

1. **只有「在线」会被自动切走。** 当前是「忙碌」时，无论空闲多久都不动——忙碌是用户刻意发出的「别打扰我」，降级成「离开」会把这层意思丢掉。「离线」「隐身」同样不动。
2. **只有「自动」切过去的离开，才会在检测到操作时自动切回在线。** 用户自己手动选的「离开」，回到电脑前也原样留着，否则等于剥夺了「我就想挂个离开」这个选择。
3. **任何一次手动改状态，都会清掉「这是自动切的」这个标记。** 于是「自动离开期间用户自己把状态改成忙碌」之后，人回来也不会被擅自切回在线。
4. **连接没就绪时一律不动作。** 未登录、掉线重连中、用户主动离线，都既不自动切离开、也不自动切回——此刻 `cmd_change_presence` 发不出去，改了只是本地自欺。

补充约定：**关掉总开关时，若此刻正处于自动设上的「离开」，会被切回在线**。用户关掉这个功能的本意是「别再自动摆布我的状态」，把人晾在一个自动设上的离开上最不合预期。

---

## 3. 两条触发路径

### 3.1 空闲轮询（主路径）

`CMainDlg` 起一个 30 秒一跳的定时器，每跳用 `GetLastInputInfo` 取**全系统**最后一次键鼠输入的时刻，算出空闲时长交给判定函数。

- 取全系统口径而非本进程，是因为需求说的是「电脑无操作」——用户在浏览器里忙活也不该被判成空闲。
- 30 秒的粒度：最短可选阈值是 5 分钟，最坏情况比设定时刻晚半分钟切过去，用户无感；跳得再密只是白耗电。
- 空闲时长的计算单独抽成 `ComputeIdleMs`，专为把 **tick 回绕**测到：两个值都是 32 位无符号 tick，开机约 49.7 天后回绕归零，直接用 `DWORD` 相减天然正确，但写成有符号或先转 `int64` 会在回绕当天算出一个荒谬的巨大值，把全体用户误判成长时间空闲、集体切到离开。

### 3.2 锁屏 / 解锁（快捷路径）

锁屏那一刻人肯定已经不在了，不必再等空闲满阈值，否则同事在随后的 5 分钟里看到的仍是「在线」。

- `CMainDlg::OnInitDialog` 调 `WTSRegisterSessionNotification(m_hWnd, NOTIFY_FOR_THIS_SESSION)` 订阅会话事件，`OnDestroy` 里退订。注册失败不影响主流程，只记一条警告——空闲轮询那条路照常兜底，只是锁屏后要多等一会儿。
- 消息 `WM_WTSSESSION_CHANGE` 的状态码先经 `ClassifySessionEvent` 归成三类：
  - **人走了**：`WTS_SESSION_LOCK`（锁屏）、`WTS_CONSOLE_DISCONNECT`（切换用户 / 被远程接管）、`WTS_REMOTE_DISCONNECT`（远程桌面断开）
  - **人回来了**：`WTS_SESSION_UNLOCK`、`WTS_CONSOLE_CONNECT`、`WTS_REMOTE_CONNECT`
  - **不关心**：登录、注销、远程协助等，忽略
- 判定走 `DecideAutoAwayOnSessionEvent`，它把事件**折算成空闲时长**后复用同一个状态机（离开事件视同已空闲满阈值，回来事件视同刚刚有操作）。这样第 2 节那四条约定只有一份实现，不会因为多出一条触发路径而两边走样——锁屏同样不动忙碌、同样不碰未连接的情形。

## 4. 手动与自动怎么区分

切换在线状态的漏斗只有一个：`CMainDlg::OnChangeMyPresence`。它负责乐观更新状态胶囊、刷新托盘提示，再按连接态分流（在线时发 `cmd_change_presence`，离线时记下期望状态并重新登录）。

本特性复用这个漏斗，胶囊、托盘图标、协议下发因此全都自动跟上。区分手动与自动，用的是 `FMG_MSG_CHANGE_MY_PRESENCE` 一直空着的 `lParam`：

| 取值 | 含义 | 谁传 |
| --- | --- | --- |
| `kPresenceChangeManual`(0) | 用户手动选的 | 主面板状态菜单、托盘右键菜单 |
| `kPresenceChangeAuto`(1) | 本特性自动切的 | `CMainDlg::CheckAutoAway` / `OnSessionChange` |

取值 0 表示手动是刻意的——三个既有入口传的本来就是 0，加这个字段时一行都不用改。`OnChangeMyPresence` 据它维护 `m_bAutoAway`：手动一律清掉，自动则只在目标是「离开」时置位。

**服务端无需改动**，也没有新增协议：全程复用既有的 `cmd_change_presence`。

## 5. 配置项

位置：**系统设置 → 通用**，两行挨着放，读起来就是一句话。

| 界面 | 控件 | 配置项 | 默认值 |
| --- | --- | --- | --- |
| 自动离开 | 开关 | `CUserConfig::IsEnableAutoAway` | 开 |
| 无操作多久后离开 | 下拉：5 / 10 / 15 / 30 分钟 | `CUserConfig::GetAutoAwayDelayIndex` | 5 分钟（索引 0） |

- 持久化在账号配置 ini 的 `[Settings]` 节，键名 `AutoAway` 与 `AutoAwayDelayIndex`。老账号的配置文件里没有这两项，缺省按「开启、5 分钟」处理，与设置页默认值一致。
- 存的是**下拉索引**而非分钟数，与语言 / 字体大小等下拉项同口径；索引 → 分钟的映射只写在 `SettingsBinding::AutoAwayDelayMinutesFromIndex` 一处，越界索引（配置文件被手工改坏）回落到默认档。
- **改完即时生效**：每次判定都重新读一次配置，设置窗不必往 `CMainDlg` 推送通知。

## 6. 代码落点

| 文件 | 职责 |
| --- | --- |
| `flamingoclient/Source/BalloonMain/AutoAwayPolicy.h/.cpp` | 纯逻辑：`DecideAutoAway`（状态机）、`DecideAutoAwayOnSessionEvent`（会话事件）、`ClassifySessionEvent`（WTS 状态码归类）、`ComputeIdleMs`（空闲时长，含 tick 回绕）。不读时钟、不碰窗口、不发协议，故可被 FlamingoUnit 直接断言 |
| `flamingoclient/Source/MainDlg.h/.cpp` | 定时器与会话通知的注册、`GetLastInputInfo` 探测、`BuildAutoAwayInput` / `ApplyAutoAwayAction` / `CheckAutoAway` / `OnSessionChange`，以及 `m_bAutoAway` 的维护 |
| `flamingoclient/Source/UserSessionData.h` | `PresenceChangeSource`（切换来源）与 `FMG_MSG_CHANGE_MY_PRESENCE` 的 `lParam` 契约 |
| `flamingoclient/Source/UserConfig.h/.cpp` | 两个配置项的存取与持久化 |
| `flamingoclient/Source/BalloonSettings/SettingsBinding.h/.cpp` | 时长下拉的选项表与「索引 ↔ 分钟数」映射 |
| `flamingoclient/Source/BalloonSettings/BalloonSystemSettingDlg.cpp` | 通用页两行与写回分支 |
| `flamingoclient/Source/Tests/AutoAwayPolicyTests.cpp` | 测试 |

判定与执行分开是刻意的：状态机是纯函数，边角情形（谁能被切走、谁能被切回、未连接怎么办）全部可测；`CMainDlg` 那一侧只做读时钟、读配置、发消息这些没法测的脏活。

关键路径按规范打 `LOG_INFO`，日志形如：

```
auto-away[idle-poll]: idle 300 sec (threshold 300 sec), presence 1 -> 2.
auto-away[session-lock]: idle 3 sec (threshold 300 sec), presence 1 -> 2.
```

方括号里是触发来源，便于事后区分是空闲轮询还是锁屏引起的。日志一律用英文，理由见
开发约定文档「代码规范」第 15 条：客户端日志宏的窄 / 宽字符两个重载落盘编码不同，中文混用会让
同一个日志文件里同时出现 UTF-8 与 GBK 两种编码。

## 7. 测试

`flamingoclient/Source/Tests/AutoAwayPolicyTests.cpp`，覆盖：

- **在线 → 离开**：空闲满阈值触发、不够不触发、边界（正好满阈值即触发）。
- **只有在线会被切走**：忙碌、离线、隐身下空闲再久也不动。
- **离开 → 在线**：自动离开且有操作才切回；仍空闲不动；**手动选的离开有操作也不切回**；自动离开期间改成忙碌之后不切回（标志已清与状态已变两道防线都验）。
- **连接态与开关**：未连接一律不动作（含不做「切回在线」）；关掉开关不再自动切离开、并把自动设上的离开还回去；阈值为 0 视为未配置。
- **空闲时长**：常规相减、tick 回绕、最后一次输入比当前还新（两次取值之间恰好有输入）。
- **会话事件**：状态码归类（含注销等不相关事件不能误判）；锁屏时空闲为 0 也照切；解锁只切回自动离开；锁屏同样不动忙碌 / 不碰未连接与功能关闭的情形。
- **时长下拉**：四档取值、越界索引回落默认。

## 8. 实测证据

2026-08-12 在真实登录会话（客户端连本机 `chatserver`）中实测。为便于观察，当时临时把轮询间隔改成 2 秒、阈值改成 6 秒，验完已改回 30 秒 / 设置页取值。日志：

```
15:19:19.881  自动离开：空闲 6 秒（阈值 6 秒），状态 1 → 2。
15:19:23.881  自动离开：空闲 0 秒（阈值 6 秒），状态 2 → 1。
```

状态 1 是在线、2 是离开。前一行是空闲满阈值自动切到离开，后一行是检测到键鼠操作自动切回在线，两行相隔 4 秒，正好是 2 秒轮询跳了两跳。配套的两条 `OnChangeMyPresence` 日志都带 `auto=1`，说明来源标志一路传到位。界面上状态胶囊同步从绿色实心圆的「在线」变成橙色时钟的「离开」再变回来。

## 9. 已知边界与未做的部分

- **开启「禁止机器休眠」期间，本特性一律不生效。** 日后排查「自动离开怎么不灵了」要先想到这条：

  「禁止机器休眠」（设置 → 通用）为了让系统不休眠、不关屏、不锁屏，会**周期性合成一次零位移鼠标移动**。而 `GetLastInputInfo` 统计的正是全系统最后一次输入的时刻——合成的这一下会把空闲计时器清零，空闲时长永远涨不到阈值。

  2026-08-12 与用户确认后改为**代码显式互斥**：`CAutoAwayController::BuildAutoAwayInput` 在禁止休眠开启时把 `m_enabled` 置为 false，空闲轮询与锁屏 / 解锁两条路径都经过这里，因此**都不会**切换在线状态；设置页同时把「自动离开」两行置为禁用并说明原因。自动离开自身的配置值不改，关闭禁止休眠后原样恢复。详见 `docs/禁止机器休眠方案.md` 第 4 节。

- **全屏看视频 / 看文档不动键鼠会被判成空闲**，进而切到离开。这是所有 IM 的通行行为，不做特殊处理。
- **不弹提示**。曾考虑自动切换时在托盘弹气泡告知，权衡后不做：气泡弹出来的时刻人恰恰不在电脑前，几秒钟就消失了，等人回来早没了；而人一回来状态又自动切回在线，全程不需要知道。日后若加「离开期间自动回复」之类的功能，用户才有必要知道自己刚才处于离开态，那时更合理的做法是「回来时告诉他刚才离开过多久、期间有谁找过」。
- **休眠 / 唤醒未单独处理**（`WM_POWERBROADCAST`）。实践中唤醒通常伴随锁屏解锁，会走会话事件那条路。
- **多设备**：本特性只管本机这一个客户端自己的状态，不涉及多端状态合并。
