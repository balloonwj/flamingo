# 「本地数据存储位置」与「清理本地缓存」方案与实现记录

> 作者：balloonwj@qq.com　起草日期：2026-08-12
> 用途：记录 PC 客户端「系统设置 → 存储」两项功能的约定、设计取舍、代码落点与实测依据。
> 这两项此前都是空壳：保存位置改了不生效，清理缓存点了只弹一句「开发中」。

---

## 1. 背景

改版前存储页有两行，实际情况是：

- **文件保存位置**：能弹选目录框、能写进账号配置，但**没有任何生效路径读它**。真正读自定义目录的只有 `CUserMgr::GetDefaultRecvFilePath()`，而全仓库引用它的只有老的 MFC 聊天窗 `BuddyChatDlg.cpp`。现用的 balloonui 聊天窗收文件走 `net/FileTransfer.cpp`，落地路径固定拼成 `Users\<账号>\ChatFile\<md5>\<原名>`，与该设置无关。
- **清理本地缓存**：`ApplySettingChange` 里就是一个消息框，没有任何删除动作。

目标：把这两项做成真的，并且**语义分清**——缓存是可再生的副本，删了最多重下一次；聊天记录、公告、配置是唯一副本，任何清理都不许碰。

---

## 2. 已确认的决策

以下每一条都与用户逐条确认过（2026-08-12），实现与测试围绕它们展开。

1. **存储位置管的是整棵 `Users\<账号>\`**，不只是接收到的文件。改路径后聊天记录、公告、本地设置都会从新位置从头开始。
2. **改动须重启才生效**，设置页只写配置并提示。运行期不切换。
3. **不做自动迁移**，旧数据原样留在旧位置。确认框里写清手动迁移的步骤。
4. **`Users\LoginAccountList.dat` 留在程序目录不动**。它是"这台机器登录过哪些账号"，属于机器级数据，不随账号数据搬家；否则用户改完路径连账号列表都要重输。
5. **路径这一项存在全局 `config\flamingo.ini`**，维持 ANSI 文件、由程序写入。
6. **改路径或清理缓存之后**，聊天界面与消息记录里那些本地已不在的图片 / 文件**显示"已删除"并可重新下载**，不自动下载；下载失败就在气泡上提示，不弹框。
7. **清理缓存点击时弹对话框**，让用户勾选清理哪些内容。

## 3. 数据根目录

### 3.1 为什么路径不能存在账号配置里

账号配置 `<账号>.cfg` 本身就位于 `Users\<账号>\` 之下，也就是**要搬走的那棵树里面**。若把新路径存进它，客户端下次启动会去新位置找这个文件、找不到就用默认值，于是新路径永远不可能生效。故这一项只能存在数据根目录**之外**的全局配置里。

### 3.2 flamingo.ini 能不能装中文路径

`config\flamingo.ini` 文件头写着「keep this file pure ASCII」，需要先确认它能否承载中文路径。**实测**（探针 `tools/probe_ini_unicode.ps1` 形态，用完即删；客户端是 Unicode 构建，`CIniFile` 走 `GetPrivateProfileStringW` / `WritePrivateProfileStringW`）：

| 文件编码 | 写中文路径再读回 | 结论 |
| --- | --- | --- |
| ANSI（现状） | 一致 | 中文按系统代码页写入，同机往返自洽 |
| UTF-16LE + BOM | 一致 | 文件带 `FF FE`，原有 ASCII 键照样读得到 |
| UTF-8 无 BOM | **乱码**（`D:\鎴戠殑鏂囨。\...`） | 正是文件头注释警告的情形 |

所以"ini 不支持中文"这个说法并不准确：**只要中文由客户端自己写、自己读，现状的 ANSI 文件就能原样往返**；真正会出事的是有人用 UTF-8 编辑器手改这个文件。据此维持 ANSI 不变，并把文件头那句注释改成"手写内容保持 ASCII，本地化的值交给程序写"。

已知代价：把这份 ini 拷到另一台 ANSI 代码页不同的机器（如英文系统），中文路径会乱。与用户确认后接受。

### 3.3 配置项与归一

```ini
[storage]
datapath=D:\FlamingoData
```

空表示用默认（程序目录）。取值经 `net::ResolveDataRoot`（`Source/net/StorageLocation.h`）归一后才使用，规则如下，**任何一条不满足都回落默认，绝不返回一个可疑路径**：

- 配置为空 —— 用户没改过；
- 不是绝对路径（`Data\Flamingo`、`\Users`）—— 相对路径会随进程当前工作目录漂移，数据可能写到任何地方；
- 含 `..` —— 配置文件是纯文本、可能被手工改坏；
- 只给盘符（`D:`）—— 补成 `D:\`，否则后续拼出 `D:Users\...`，那是相对于该盘当前目录的路径。

归一后保证以反斜杠结尾，与 `g_szHomePath` 的既有约定一致。

### 3.4 两个全局量的分工

新增 `g_szDataRoot`（`UserSessionData.h`），在 `Startup.cpp` 里紧接 `g_szHomePath` 之后算出，位置在日志初始化之前——各个库与缓存目录都要用它，必须比登录早。

| 全局量 | 含义 | 挂在下面的东西 |
| --- | --- | --- |
| `g_szHomePath` | 程序目录 | 皮肤、表情、`config\flamingo.ini`、`Users\LoginAccountList.dat` |
| `g_szDataRoot` | 本地数据根目录 | `Users\<登录账号>\` 整棵：`<账号>.cfg`、`ChatLog\`（`msg.db` / `announce.db` / `filelocal.db`）、`ChatFile\`、`ChatImage\`、`Avatar\`、`UserThumb\` |

改动落点：`UserMgr`（个人目录、最近会话列表）、`FlamingoClient`（账号配置读写）、`MainDlg`（头像缓存）、`BalloonMainPanel`（配置路径）、`net/FileTransfer`、`net/ImageTransfer`、`BalloonAuth/AccountRemoval`（删除边界）共 13 处改用 `g_szDataRoot`；`LoginAccountList.dat` 那 5 处保持 `g_szHomePath`。

`net::UserCacheDir(homeDir, …)` 本来就把根目录做成了入参，无需改动，只是调用方传的东西变了。

## 4. 改路径的交互

选完目录后先弹确认框，把后果与手动迁移步骤一次讲清（不能只说"重启后生效"就完事——用户多半是冲着"C 盘满了想挪到 D 盘"来的，未必预期聊天记录也跟着从头开始）：

```
更改后需要重启客户端才会生效。

新位置是空的：聊天记录、公告、本地设置都会从头开始。原有数据仍保留在
    <旧数据根>\Users\<账号>\
但不再被使用。

如需保留原有数据，请手动迁移：
  1. 退出客户端；
  2. 把上面那个目录整个复制到
       <新数据根>\Users\
  3. 再启动客户端。

是否继续？
```

确认后写 ini、刷新界面显示、提示重启。本次会话行为完全不变。

## 5. 「已删除」空态与重新下载

### 5.1 为什么只能统一文案

`filelocal.db`（文件落点登记表）也在 `ChatLog\` 下，随数据根目录一起搬走，新位置是空库。于是客户端**无法区分"下载过但本地没了"与"从没下载过"**——两者都是"查不到登记、本地也没有"。故空态文案统一为"已删除 / 点击重新下载"。代价是新收到、尚未下载过的文件也会写"已删除"，措辞略有出入但操作一致。

若要严格区分，就得把登记表留在旧位置不搬，与「整棵搬」的口径冲突，已放弃。

### 5.2 呈现

- **文件气泡**：本地没有时显示"文件已删除"加重新下载入口（改版前是一个不带说明的「下载」按钮）。
- **图片气泡**：现状是"浅灰占位块 + 斜向纹理"、占位文字为空；在占位块上补"图片已删除"，点击重新下载。
- **失败**：就在气泡上显示一行失败说明，可再次点击重试。**不弹消息框**——群里连点几个文件时会被一连串弹框治住。

清理缓存之后的空态与改路径后完全一致，复用同一套展示。

## 6. 清理本地缓存

### 6.1 清理范围

只清**当前登录账号**的四类缓存，且都在 `<数据根>\Users\<账号>\` 之下：

| 目录 | 内容 | 删了之后 |
| --- | --- | --- |
| `ChatFile\` | 聊天文件的下载缓存（按 MD5 分目录） | 气泡退回"已删除"，可重下 |
| `ChatImage\` | 聊天图片缓存 | 同上 |
| `Avatar\`、`UserThumb\` | 头像缓存 | 下次自动重新拉 |

**一律不碰**：`ChatLog\`（`msg.db` 聊天记录、`announce.db` 公告、`filelocal.db` 登记表）与 `<账号>.cfg`。

### 6.2 对话框

balloonui **没有复选框控件**（`Controls/Input` 下只有 ComboBox / EditHost / SearchBox / Slider / SpinBox / Switch）。按开发约定文档「最大化复用 balloonui」的顺序，选**直接使用现成的 `DuiSwitch`**：每项一行「名称 + 占用大小 + 右侧开关」，与系统设置页其它行观感一致，**不新增控件、不动 balloonui**。默认全部开启，底部显示合计大小。

### 6.3 安全与时序

- 路径边界复用 `BalloonAuth/AccountRemoval` 那套：账号名经 `net::SanitizeAccountForPath` 净化，拼出的路径必须落在 `<数据根>\Users\` 之下，否则拒绝执行。
- 扫描占用可能耗时几秒，扫描期间按钮置灰、文案改为"正在统计…"，不起后台线程（一次性操作）。
- 若有传输进行中，提示稍后再清理，不强行删除正在写入的文件。
- 清理后不动登记表：失效记录由 `ResolveLocalFilePath` 自然回退，下次下载时 `INSERT OR REPLACE` 覆盖。

## 7. 测试

纯逻辑用 Catch2 覆盖，碰磁盘与界面的部分实测：

| 套件 | 覆盖 |
| --- | --- |
| `StorageLocationTests.cpp`（STL1–STL7） | 数据根目录归一：空配置回落、绝对路径补齐结尾反斜杠、相对路径与含 `..` 拒绝、只给盘符补成盘根、UNC 接受、中文路径、默认根未带反斜杠时补齐 |
| `CacheCleanPlanTests.cpp`（CCP1–CCP7） | 三类计划与各自目录；`ChatLog` / `.cfg` / `msg.db` / `announce.db` / `filelocal.db` 永不出现在计划里；未登录时空计划；账号含分隔符或上跳时仍落在 `Users\` 之下；边界检查放行与拒绝（越界、`Users\` 本身、上跳段、空参数）；占用量文本分档 |

`CacheCleanExecutor`（扫描与删除）碰磁盘，不进测试工程，靠实测验收。

### 7.1 写测试时逮到的一个真问题

CCP4 第一版是红的：边界检查原本写成「路径里出现过 `..` 就拒绝」，而账号净化后可能得到 `_.._Windows` 这类**合法目录名**（里面碰巧有两个点），于是本模块自己产出的计划过不了自己的边界检查。改成判「某一段**整段**等于 `..`」才对——该拦的是真正的上跳，不是"出现过两个点"。这条若不是先写测试，多半要等某个账号名恰好触发时才在现场暴露。

### 8.2 接着做的人需要知道的

- 对话框直接架在 `BuildCacheCleanPlan` + `ScanDirSizeBytes` + `DeleteDirTree` 三支上即可，三者的职责边界与失败语义见各自头文件。
