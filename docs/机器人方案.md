# 机器人方案（企业机器人、群机器人、个人机器人）

> 作者：balloonwj@qq.com　起草日期：2026-10-07
> 用途：记录「企业管理员、群主、员工本人分别配置机器人，机器人在群聊与单聊中按条件自动应答」的整体方案、已确认事项与开发步骤。第 11 节的 9 个决策已于 2026-10-07～08 逐项与用户确认并写回正文；第 12 节为已实现的测试用例。

---

## 1. 背景与目标

用户需求（2026-10-07）：「群机器人可以在 flamingoAdmin 中配置给所有群或者指定的群，群主也可以给某个群配置机器人，用户也可以给自己配置机器人，单聊时，满足条件也可以触发机器人操作。」

按配置者拆成三种机器人：

| 种类 | 谁来配置 | 在哪里生效 | 典型用途 |
| --- | --- | --- | --- |
| 企业机器人 | 企业管理员（flamingoAdmin，平台超级管理员可代为配置） | 本企业的全部群，或所选的群 | IT 支持问答、规章制度问答、每周例行提醒 |
| 群机器人 | 只有群主（2026-10-07 用户确认，管理员不能配置） | 本群 | 本群的关键词应答、值班提醒、新人指引 |
| 个人机器人 | 员工本人 | 只在单聊里：别人发给本人的单聊消息（2026-10-07 用户确认，群里 @本人不代答） | 离开、忙碌、下班后代为回复；按关键词回复常见问题 |

`docs/群问答方案.md` 第 3 行已经写明「第五批的机器人会用这些问答自动作答」，本方案的「用问答作答」动作即对应这一点。

最终形态示例：

- 管理员在 flamingoAdmin「机器人」页新建「IT 小助手」，应用到全部群，规则为「被 @ 时用问答作答」。员工在任意群里输入「@IT 小助手 VPN 连不上」，机器人回复企业问答里「VPN 连不上怎么办」的答案。
- 群主给本群添加「值班提醒」机器人，每个工作日 9:00 在群里发「今天值班：……」。
- 员工张三给自己配置「下班后代答」：工作日 18:00 至次日 9:00 收到单聊时回复「我已下班，紧急事项请电话联系」。对方在与张三的单聊里看到这条回复，正文开头带「[机器人代答] 」标记。

### 2.2 缺口（据实证）

1. **没有机器人身份。** 客户端把 `from <= 0` 且不是系统消息的消息当成脏数据丢弃（`MessageProtocolClient.cpp:978`），所以机器人必须是一个 userid 为正数的 `t_user` 行。`t_user.f_usertype` 现有 0 普通用户、1 服务号（`Protocol.h` 的 `user_type`），但没有任何代码创建过非 0 的用户；登录也不拒绝 `usertype = 1`（`ChatSession::onLogin` 只检查版本、账号、状态、口令与企业）。
2. **机器人的名字解析不到。** 服务端下发通讯录只放部门成员（`ChatSession::onGetContacts`）；群聊气泡的发送者先查群成员表、再查通讯录，都查不到就显示「用户<id>」（`GroupSenderRefresh.cpp:45-81`）。客户端任何地方都没有「机器人」标识。
3. **@ 字段不一致。** PC 客户端把 @ 写在 `content.at = {"all":0|1, "users":[{"uid","off","len"}]}`（`MessageProtocolClient.cpp:175-202`；`buildSendRequest` 在 `:250-261`，不写顶层字段）；服务端只读顶层的 `mentions` / `mentionall`（`MessageProtocol.cpp:133-135`），从不解析 `content.at`。服务端要判断「是否 @ 了机器人」，必须自己解析 `content.at.users[].uid`。
4. **发消息的整条链路同步执行在发送者连接所在的 I/O 线程上**（`ChatSession::onSendMessage`、`sendGroupMessage`；`MessageManager::saveMessage` 同样是同步的）。机器人的判定与动作必须投递到独立线程，否则一次慢操作会拖慢这个 I/O 线程上的所有连接。
5. **没有公开的「以指定身份发消息」函数**，同类逻辑有多份副本（`ChatSession::sendGroupSystemMessage`、`ScreenShareService.cpp` 匿名命名空间里的 `saveAndPushMessage`、`GroupCallServerEnv::saveCard`、`CloudRecordServerEnv::sendCard` 等）。`docs/仓库变动通知方案.md` §5.1 设计了 `ChatServer::postMessageAs`，已由本方案第一期 1a 实现（§5.1）。
6. **服务端没有出站 HTTP / HTTPS 能力。** `chatserver.vcxproj` 与 `CMakeLists.txt` 都没有链接 curl 或 WinHTTP；Windows 上的域名解析没有实现（`net/InetAddress.cpp:49-73`）。
7. **chatserver 的 HTTP 端口有一条请求就能让进程退出的缺陷**（查询串不足两个字符的 GET 请求会抛出未捕获的异常）。接收外部系统的 Webhook 需要把这个端口开放给外部系统，因此在第一期 1j 先行修复（已修复）。
8. **客户端可以发送 `msgtype = 17`（系统提示）。** `MessageProtocol::isClientOperableMsgType` 只排除了卡片类消息，没有排除 17；客户端只要求 `from > 0` 就收下（`MessageProtocolClient.cpp:978`）。机器人消息同样存在被普通用户伪造的可能，对策见 §5.6；缺陷本身另记 `bugs.md` BUG-124。
9. **现有自动回复完全在客户端**（`AutoReplyPolicy.cpp:95-167`，触发点 `BalloonMainPanelAutoReply.cpp:95`），本人客户端不在线时不会回复；它只排除 16 / 17 / 18 三种 msgtype（`AutoReplyPolicy.cpp:48-52`），新的消息类型会触发它。
10. **服务号与机器人在概念上重叠。** 服务号分「通知型 / 助手型 / 集成型」（`ServiceAccountManager.h:21-39`；管理台 `ServiceModal.cpp:51-58`），「助手型」的注释即「可交互的自助式机器人」（`flamingoAdmin/Mock/MockData.h:61`）。但服务号没有 `t_user` 行，IM 一侧也没有接通：`cmd_get_service_accounts`（2001）没有处理函数，通讯录的 `serviceaccounts` 恒为空数组（`ChatSession::onGetContacts`），管理台的「Webhook 接收地址」只是占位（`ServicesPanel.cpp:807`）。
11. **群管理窗「入群欢迎语」的说明文字与实际不符。** 说明是「新成员加入时由机器人自动发送」（`GroupManageLayout.cpp:1869`），实际是服务端发出的系统提示（`ChatSession::sendGroupWelcomeMessage`，`from = 0`、`msgtype = 17`），与机器人无关。

## 3. 总体设计

### 3.1 机器人在服务端运行（推荐）

规则的判定与执行全部在 chatserver 内完成，客户端只负责配置界面与显示。理由：

- 个人机器人要在本人不在线时也能代答，只有服务端做得到（客户端自动回复做不到，见 §2.2 第 9 条）。
- PC 与安卓看到的行为一致；频率限制、审计、企业策略集中在一处。
- 第一至三期不需要任何出站网络，机器人读到的消息不离开服务器。

### 3.2 机器人身份

- 企业机器人与群机器人各对应一行 `t_user`：`f_usertype = 2`（新增 `user_type_bot`），`f_enterprise_id` 为所属企业，用户名为保留前缀 `__bot_` 加 16 位随机十六进制（建账号时机器人 id 还没分配），口令为随机值的哈希。个人机器人以主人的身份回复（§3.4），不建账号（`t_bot.f_user_id = 0`，§11 Q12）。登录时 `usertype != 0` 一律拒绝（同时补上服务号账号能登录的缺口）。
- 机器人不进组织架构，不计入员工列表、在线人数与仪表盘统计。
- **删除机器人只做软删除**：`t_bot` 标记为已删除，`t_user` 行保留并停用。历史消息的发送者仍是这个 userid，删掉 `t_user` 行会让历史消息的发送者名字解析不出来。群机器人消息的 `content.bot` 带 `name`，客户端查不到这个机器人时按它显示名字并带「机器人」标识，不加「（已删除）」：查不到也可能只是机器人改了范围、不再用于本群（§11 Q15）。

### 3.3 群里的机器人不写入群成员表（2026-10-07 用户确认，§11 Q6）

一个群可用的机器人 = 范围包含本群、且没有在本群被关闭的企业机器人 + 本群自己的群机器人。由服务端按需计算，不写进 `t_group_member`。理由：

- 企业机器人「应用到全部群」时，要给现有的每个群、以后新建的每个群都插一行成员；群人数、@所有人、成员管理（移出、禁言、设管理员）、退群清理、加群审批都要为它开例外。
- 机器人的消息由服务端直接落库，本来就不经过发言校验 `checkGroupSpeak`（`ChatSession.cpp:3859` 起），「仅通知模式」与禁言不影响它，成员身份对它没有作用。

代价：客户端不能从群成员列表拿到机器人资料，改由新命令 2801 下发本群机器人列表（§6.1）；群聊窗的发送者解析、@ 候选、成员页签都要加上这一来源（§8.1）。

### 3.4 单聊里的个人机器人以主人的身份回复

个人机器人回复别人发给主人的单聊消息时，消息的 `from` 是主人本人，`content` 里带机器人标记（§6.2），客户端据此在正文开头显示「[机器人代答] 」标记（§11 Q13）。

不以机器人自己的身份回复，原因是服务端推单聊消息时，收件人一侧的会话 id 就是发送者的 userid。如果 `from` 是机器人，这条回复会出现在对方「与机器人的单聊」里，而不在对方与主人的那个会话里。

### 3.5 规则模型

每个机器人有一组有序的规则。一条消息到来时按顺序判定，命中第一条后执行它的动作，后面的规则不再判定。

**触发方式**

| 编号 | 触发方式 | 适用于 | 说明 |
| --- | --- | --- | --- |
| T1 | 被 @ | 企业、群机器人 | `content.at.users[].uid` 里有机器人的 userid；@所有人不算 |
| T2 | 关键词 | 企业、群、个人机器人 | 正文命中关键词，匹配方式为「包含 / 完全相同 / 以……开头」三选一；比较前去掉首尾空白、统一大小写与全半角。群里的规则可设「必须同时 @ 机器人」，默认打开，避免机器人在群聊中频繁插话 |
| T3 | 新成员入群 | 企业、群机器人 | 在 `completeGroupJoin`（`ChatSession.cpp:6889` 起）发完入群提示之后判定 |
| T4 | 定时 | 企业、群机器人 | 每天 / 工作日 / 每周几 / 每月几号的某个时刻；第一版不支持任意 cron 表达式 |
| T5 | 收到单聊 | 个人机器人 | 别人发给主人的单聊消息，配合下面的附加条件 |
| T6 | 外部系统调用 | 企业、群机器人 | 接收外部系统的 Webhook（第一期第三段；群机器人须企业开关 `bot.groupexternal` 允许） |

**附加条件**（主要给个人机器人用；企业、群机器人可选用其中的时间段）

- 主人的在线状态属于所选的几种：离线、离开、忙碌。多个设备同时在线时取最在线的那个（在线 > 忙碌 > 离开）。`getUserStatusByUserId` 只返回找到的第一个会话的状态（`ChatServer.cpp:739-751`），合并各设备状态由新增的 `ChatServer::getMergedPresence` 负责。
- 时间段：每天 / 工作日 / 周末，HH:MM 至 HH:MM，可以跨零点；按服务器本地时间计算。
- 发送者范围：所有人 / 指定的人 / 指定的部门（含下级部门）。
- 冷却：同一个发送者在 N 分钟内只代答一次，默认 30 分钟。
- 主人最近 N 分钟内在这个会话里发过言则不代答（说明主人正在与对方交谈），默认 5 分钟。

**动作**

| 编号 | 动作 | 说明 |
| --- | --- | --- |
| A1 | 回复文字 | 纯文字或 Markdown（`content.format = "markdown"`），可使用变量 `{发送者}`、`{主人}`、`{日期}` |
| A2 | 用问答作答 | 群里取本群问答与企业问答（复用 `mergeForGroup`）；个人机器人取主人自己维护的问答（第三期，可选）。匹配规则见 §5.4 |
| A3 | 呼叫外部服务 | 把触发消息 POST 给外部地址，把应答作为回复发出（第一期第三段；群机器人须企业开关 `bot.groupexternal` 允许） |
| A4 | AI 对话（预留） | 调用大模型接口作答。本方案只预留动作编号，不排期 |

### 3.6 机器人的消息不再触发机器人

- 机器人的消息由服务端直接落库，不经过 `onSendMessage`，不会进入判定入口。
- 判定入口另外排除：发送者 `usertype != 0`、`content` 带机器人标记或 `autoreply = true`、系统提示（17）、服务端生成的卡片类消息。
- 客户端自动回复策略增加一条「带机器人标记的消息不自动回复」。个人机器人的代答本来就带 `autoreply = true`（§6.2），现有策略已能拦下；新增这一条是为了防止以后其它带机器人标记的单聊消息触发自动回复。

## 4. 交互设计

### 4.1 flamingoAdmin：企业机器人

- 左侧导航新增「机器人」页，与「企业问答」并列；平台超级管理员先选企业。
- 列表：名称、应用范围（「全部群」或「N 个群：甲、乙……」，写法同 `QaScopeText`）、群主能否在本群关闭、规则数、状态（启用 / 停用）、最近触发时间、操作（编辑、试一试、停用 / 启用、删除）。
- 编辑窗：
  - 基本信息：名称（最多 20 字）、简介（最多 100 字，显示在群成员页签的机器人资料卡上）、头像（字形加底色，与服务号的选法相同）。
  - 应用范围：全部群 / 所选的群（复用 `EnterpriseQaModal` 的下拉框与勾选列表）；「允许群主在本群关闭」勾选框。
  - 规则列表：每行一条规则，可上移、下移、删除；「添加规则」打开规则编辑窗，依次选择触发方式、填写条件、选择动作、填写回复内容。
  - 「试一试」：输入一段文字，服务端按规则判定，返回会命中哪条规则、会回复什么，不发出任何消息。
- 企业详情的「功能开关」子 tab（企业管理员与平台超级管理员共用，`Screens/FeatureSwitchesPage`）新增「机器人」卡片，排在含云端录像空间的「音视频」卡片之后（§11 Q18），四个开关都用现成的 `FeatureSwitchPanel`：
  - 「机器人」`bot.enabled`，默认打开，下发客户端。关闭后本企业所有机器人停止响应，客户端隐藏全部入口。
  - 「允许群主添加群机器人」`bot.groupbot`，默认打开，下发客户端。
  - 「允许员工配置个人机器人」`bot.personal`，默认打开，下发客户端。
  - 「允许群主给群机器人配置外部服务」`bot.groupexternal`，默认关闭，下发客户端（第二期）。打开后群主才能在群机器人上添加 T6、A3 两类规则（§5.6）。

### 4.2 群聊窗：群机器人

- 成员页签顶部新增「机器人 N」分组，列出本群可用的机器人；本群一个机器人都没有时整栏不显示（群主也一样，2026-10-08 用户确认，§11 Q21）。每个机器人一行，与成员行同一样式（2026-10-08 用户确认，§11 Q10）：左边头像，中间名字，
  右边小标签（企业机器人「企业」，停用的「已停用」，在本群关闭的「本群已关闭」；本群的群机器人没有标签）。点击打开机器人资料卡：应用风格的小窗
  （2026-10-08 用户确认，§11 Q11；标题栏带程序图标，宽度固定、高度按内容定），内容为头像、名字、「机器人」徽标与标签、简介、用法说明
  （例如「在群里 @我 并输入问题」，由服务端按规则生成）、来源（企业管理员配置 / 群主配置）。
- 添加与管理群机器人的入口在群管理窗口（群聊窗右上角齿轮）左侧导航「设置」组的「群机器人」页（2026-10-08 用户确认，§11 Q20；

## 5. 服务端

### 5.1 公开的发消息函数

与 `docs/仓库变动通知方案.md` §5.1 共用同一个 `ChatServer::postMessageAs`，由本方案第一期 1a 实现。机器人发出的消息额外带 `content.bot`（§6.2），clientmsgid 以 `bot-` 开头。

### 5.2 判定入口

| 入口 | 位置 | 说明 |
| --- | --- | --- |
| 单聊 | `ChatSession::onSendMessage` 推送完成之后（`ChatSession.cpp:2976`，`BotEngine::onSingleMessage`） | 判定收件人有没有启用的个人机器人 |
| 群聊 | `ChatSession::sendGroupMessage` 推送完成之后（`:3074`，`BotEngine::onGroupMessage`） | 判定本群可用的企业机器人与群机器人 |
| 入群 | `completeGroupJoin` 发完入群提示之后（`:6959`，`BotEngine::onMembersJoined`） | T3 |

- 重发去重时提前返回的分支不进入判定，同一条消息不会触发两次。
- 转发与群发（`deliverConversationMessage`）不进入判定（推荐），避免一次群发在多个群里同时引出机器人回复。
- 群消息 @ 了本群的某个机器人时，只让被 @ 的机器人判定，其他机器人（包括不要求 @ 的关键词规则）都不响应（2026-10-08 用户确认，§11 Q9；
  `bot::MentionsOtherBot`）。@ 的是普通成员、或没有 @ 任何人时照常判定。
- 入口只做两件事：查内存缓存判断「这个会话可能有机器人」，没有就直接返回；有就把消息的副本投递给机器人线程。I/O 线程上不做任何数据库查询。

### 5.3 机器人线程与调度

- `BotEngine`（服务器级单例）持有专用的 `EventLoopThread`（线程名 `bot-engine`）。所有判定在这个线程上按到达顺序执行，同一会话里机器人回复的顺序与触发消息的顺序一致。
- `BotManager`（服务器级单例）负责增删改查与缓存：「群 → 可用机器人」「用户 → 个人机器人」两张缓存表，配置变动时失效重建。应用到全部群的企业机器人按企业缓存；群所属企业按群主查询（`DepartmentManager::getUserEnterpriseId` 已有缓存）。
- 定时触发：机器人线程每 30 秒检查一次到点的规则。clientmsgid 为 `bot-<机器人id>-<规则id>-<yyyyMMddHHmm>-<群号>`，发送前用 `getMsgIdByClientId` 判重，进程重启后再检查同一时刻也不会重复发送。服务停机期间错过的定时消息不补发。
- 频率限制：每个机器人在每个会话里每分钟最多 20 条；每个企业的全部机器人合计每分钟最多 600 条（配置项可调）。超出部分丢弃并记日志。
- 关键路径日志（英文）：入口投递、命中的规则、发出的 msgid、因频率限制丢弃、因冷却跳过、配置变动。日志不打印消息正文。

### 5.4 「用问答作答」的匹配规则

1. 按 `content.at.users[].off / len` 剪掉 @ 片段，再去掉首尾空白，统一大小写与全半角。
2. 与某个问题（同样归一化）完全相同时，直接回复这条问答。
3. 否则按字符二元组的重合度给每个问题打分，最高分不低于阈值（默认 0.6）时回复得分最高的那条。
4. 都不满足时，回复「没有找到相关问答，你可以试试：」加得分最高的 3 个问题；一个候选也没有时回复规则里配置的兜底文字。

据推测这套打分对中文短问题够用；阈值在实施时用群问答的真实数据补单测核对。

### 5.6 防伪与安全

- 客户端发来的消息若带 `content.bot`，服务端在落库前删掉这个字段（做法与转发时去掉 `content.at` 相同，`MessageProtocol::buildForwardedContent`），保证只有服务端能产生带机器人标记的消息。
- 群主、员工填写的回复文字在保存时过企业敏感词（新增一个敏感词来源编号）；管理员填写的不检查（与 `docs/敏感词方案.md` §2.2 的口径一致）；Webhook 推来的内容与外部服务返回的内容在发送前检查。
- 个人机器人只读到别人发给主人本人的单聊消息，范围与主人自己能看到的相同。
- 密聊消息（2600 段，端到端加密，服务端读不到正文）与帖子群（没有聊天流）不触发机器人。
- 「呼叫外部服务」会把消息内容发出服务器：企业管理员可以配置；群主只有在企业开关 `bot.groupexternal` 打开时才能配置；个人机器人不提供；外部地址必须在企业管理员维护的域名白名单内；群里添加这类机器人时的系统提示要写明「@它的消息会发送到外部服务」。

### 6.2 机器人消息的内容

机器人在群里发的消息：

```json
{"msgtype": 1, "from": 5401, "content": {"text": "……", "format": "markdown", "bot": {"id": "12", "name": "值班提醒"}}}
```

个人机器人在单聊里的代答（`from` 为主人）：

```json
{"msgtype": 1, "from": 5308, "content": {"text": "[机器人] 我已下班，紧急事项请电话联系", "autoreply": true, "bot": {"id": "37", "name": "下班代答", "kind": "personal"}}}
```

- `autoreply = true` 让对方客户端现有的自动回复策略不回复它（`AutoReplyPolicy.cpp:143`）。
- 正文前缀「[机器人] 」只为老客户端准备；新客户端看到 `bot` 字段时去掉前缀，换成按界面语言翻译的「[机器人代答] 」。由「离开 / 忙碌自动回复」迁移来的预置规则代答时，前缀为「[自动回复] 」、`bot.kind` 为 `"autoreply"`，新客户端换成翻译后的「[自动回复] 」（服务端 `bot::BuildPersonalReplyContent`，`BotRules.cpp`；客户端 `balloonchatwnd::BotReplyDisplayText`，`GroupBotModel.cpp`）。
- 服务端不认识的字段原样存取，`format` 的处理与现有 Markdown 消息相同。

### 14.7 联调后的三项体验调整（2026-10-08，§11 Q9～Q11）

### 14.9 添加群机器人的入口合入群管理窗口（2026-10-08，§11 Q20～Q21）

- 群管理窗口（`UI/BalloonGroupManage`）左侧导航「设置」组「群权限」之后加「群机器人」页（`kPageBots` = 1010，图标 `kGmIconBot`）。
  可见性由 `IsBotsPageVisible(myRole, botsAvailable)` 决定：只有群主，且企业打开机器人（`features.bot`）、`FlamingoBot.dll` 已加载；
  管理员与普通成员一律看不到。页内是标题与说明、本群机器人的行（复用成员页签的 `BuildGroupBotRow`，行数据换算 `BuildBotSectionRows`
  两处共用）、没有机器人时的「本群还没有机器人」、2801 没到时的「正在加载」，以及「添加与管理机器人」按钮；按钮或某一行打开
  FlamingoBot.dll 的群机器人管理窗（所有者为群管理窗口）。
- 数据由主面板交给窗口：`CBalloonMainPanel::RefreshGroupManageBots` 在打开群管理窗口时、2801 到达时（`CacheGroupBots`，失败时显示
  「没有加载出来」）、2820 清掉缓存时（`ForgetGroupBots`，再拉一次 2801）、企业开关变化时调用；窗口的 `SetGroupBots` 在导航项出现或消失、

- 群聊窗成员页签的「机器人 N」一栏只用来查看：去掉「管理」（控件 622 与 `kGroupBotActionManage` 作废、不再复用），
  是否显示由 `ShouldShowBotSection` 决定，本群没有机器人时谁都看不到这一栏。
