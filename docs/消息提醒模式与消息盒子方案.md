# 消息提醒模式与「消息盒子」方案与开发计划

> 作者：balloonwj@qq.com　起草日期：2026-10-03
> 用途：记录把单聊、群聊的「消息免打扰」开关扩展为五种消息提醒模式（并入原「特别关注」），新增「消息盒子」聚合入口与窗口、批量管理窗口的整体方案、分期路线与开发步骤。后续每步开工前据此细化、收尾后回填实际结果。

---

## 1. 背景与目标

目前每个会话只有一个「消息免打扰」开关，开了就是「照收、不闪托盘、不响」。群一多，用户需要更细的分档：有的群要照常提醒，有的群只想偶尔看一眼、不想让它占着会话列表，有的群干脆不想再看到新消息；反过来，少数几个人和群又希望一来消息就立刻弹到眼前。

本方案把这些需求统一成**五种互斥的消息提醒模式**，单聊与群聊共用一套设置入口；被收起的会话汇总到会话列表里的一行「消息盒子」，点开是单独的「消息盒子」窗口；另提供一个批量管理窗口，一次设置很多个会话。原有的「特别关注」不再是独立的开关，而是并入提醒模式，成为其中一种。

以下口径均已与用户逐条确认（2026-10-03），实现时不再另行请示：

| 决策点 | 取值 | 详见 |
| --- | --- | --- |

## 3. 五种提醒模式

协议与库里的取值（`notifymode`）：

| 值 | 模式 | 单聊 | 群聊 |
| --- | --- | --- | --- |
| 0 | 允许消息提醒（默认） | 有 | 有 |
| 1 | 接收消息但不提醒 | 有 | 有 |
| 2 | 收进消息盒子且不提醒 | 有 | 有 |
| 3 | 屏蔽消息 | **无** | 有 |
| 4 | 特别关注 | 有 | 有 |

0、1 两个值与老的 `f_mute` 含义相同，迁移时直接沿用。特别关注取 4 而不是排在最前，是为了不打乱 0~3 与老数据的对应；界面上的排列顺序与取值无关（见 §4.1）。

### 3.1 收到一条他人消息时各模式的行为

「他人消息」指 `shouldCountAsUnread` 为真的消息：不是自己从别的设备同步回来的，也不是服务端生成的群系统消息。后两类在任何模式下都只更新摘要与时间、不计未读、不提醒（现状，不变）。

| 行为 | 0 允许 | 1 不提醒 | 2 消息盒子 | 3 屏蔽 | 4 特别关注 |
| --- | --- | --- | --- | --- | --- |
| 未读计数 | 计 | 计 | 计 | **不计** | 计 |
| 会话行摘要 / 时间 / 位置 | 更新 | 更新 | 更新「消息盒子」那一行与窗口里的行 | **都不更新**；会话不在列表里时也不新建 | 更新 |
| 未读胶囊颜色 | 红 | 灰 | 灰（汇总到消息盒子那一行） | 不显示 | 红 |
| 计入「消息」页签红色总数 | 是 | 否 | 否 | 否 | 是 |
| 闪托盘 | 是 | 否（群里被 @ 时例外，照常闪） | 否（被 @ 也不闪，只加「[有人@我]」） | 否 | 窗口没开时弹窗，不闪托盘 |
| 提示音 | 响 | 否（被 @ 时随托盘一起响） | 否 | 否 | 响 |
| 弹出聊天窗 | 否 | 否 | 否 | 否 | **窗口没开就创建并弹到前台**；已开着但最小化或被盖住时只闪任务栏、不提到前台 |
| 已打开的聊天窗里显示这条 | 是 | 是 | 是 | 是 | 是 |
| 存进本地库 | 是 | 是 | 是 | 是 | 是 |

补充规则：

- 提示音始终受全局「关闭所有声音」约束（现状，不变）。
- 正看着某个聊天窗时（`IsUserWatchingChatWindow`），无论哪种模式都不计未读、不提醒（现状，不变）。
- **单聊的窗口抖动**在 0、1、2、4 四种模式下都照常弹出并晃动聊天窗（现状，用户确认不变）。
- **文件夹传输邀请**按同一套判定：1、2 不提醒，4 视同新消息。
- 群里被 @ 的判断沿用 `IsMentioningMe`（包括 @所有人）。

### 3.2 屏蔽（模式 3）的细节

- 服务端照常推送，客户端只是不提醒、不计未读、不碰会话列表。消息照常存进本地库，用户从群列表或搜索打开群聊窗，能看到屏蔽期间的全部消息；群聊窗开着时新消息也照常显示。
- 会话行原地保留：摘要、时间、位置都停在屏蔽那一刻，不随新消息变化；行上显示禁止符，不显示未读。
- 解除屏蔽（3 → 其它）时，服务端把已读位点推进到该群当前最新一条（§5.6），屏蔽期间的消息不会在解除后一下子变成一大堆未读。
- 登录同步时，服务端对模式 3 的群照常算未读，客户端按模式忽略它；解除屏蔽时已读位点前移，之后的未读自然从零开始。

## 4. 交互设计

### 4.1 右键菜单

会话右键菜单、群列表右键菜单、联系人右键菜单三处，原来的「消息免打扰 / 取消免打扰」与「特别关注 / 取消特别关注」两项**合并成一个二级菜单**，放在原免打扰项的位置：

```
消息提醒设置  ▸
    特别关注
  ✓ 允许消息提醒
    接收消息但不提醒
    收进消息盒子且不提醒
    屏蔽消息              ← 只出现在群聊
    ────────
    批量管理消息提醒
```

- 当前模式那一项打勾（`AppendChecked`），其余不打勾；点已打勾的那一项不发请求。
- 三处菜单文字完全相同，`MENU-N1` 用例同步更新。
- 群聊窗成员列表、气泡 @ 片段、发送者头像共用的成员菜单（`BuildMentionMenuModel`）里的「特别关注 / 取消特别关注」保留为快捷项：对象是那个人的单聊会话，「特别关注」把模式设为 4，「取消特别关注」把模式设为 0。
- 「批量管理消息提醒」打开 §4.6 的窗口，并定位到当前会话所在的页签（群聊或单聊）。

### 4.2 资料窗

- 群资料窗的「消息免打扰」开关换成「消息提醒」下拉框（`DuiComboBox`），五个选项。
- 联系人资料窗的「消息免打扰」与「特别关注」两个开关合并成一个「消息提醒」下拉框，四个选项（没有屏蔽）。资料窗由此少一行，固定尺寸与布局单测（`ContactTests` C6 / C15、`BalloonGroupInfoLayoutTests` GI5）相应调整。
- 两个资料窗在模式被别处改动（本机其它入口、其它设备推送）时刷新下拉框的选中项。

### 4.3 徽章

定稿见 `snapshots/notifymode_badge_final.png` 的方案甲。

| 模式 | 徽章 | 颜色 | 位置 |
| --- | --- | --- | --- |
| 0 允许 | 无 | — | — |
| 1 不提醒 | 铃铛加斜线（新图标，替换现在的喇叭加叉） | 灰，与右侧时间文字同色 | 行右下角，未读胶囊左边 |
| 2 消息盒子 | 抽屉柜（新图标：外框 + 中间一道横线 + 上下两个拉手） | 灰 | 同上 |
| 3 屏蔽 | 禁止符（新图标：圆圈加斜线） | 灰 | 同上；该行不显示未读胶囊 |
| 4 特别关注 | 金色实心星（现有 `kIconStar`） | 金 `#F5A623` | 名字后面，沿用现在的位置 |

- 三处列表都画：会话列表、联系人列表（通讯录树）、群聊列表；消息盒子窗口里的会话也画（都是抽屉柜）。
- 尺寸 12 像素、描边 2（viewBox 24），与现有标记一致。三个新图标加进 `MainPanelIcons`（客户端代码，不涉及 balloonui）。
- 托盘菜单「关闭所有声音」仍用喇叭加叉，不受影响。

### 4.4 会话列表里的「消息盒子」一行

- 只要有模式 2 的会话出现在会话数据里，「消息」列表就多一行「消息盒子」；一个都没有时这一行不出现。
- 头像：蓝色圆底 + 白色抽屉柜。名字：「消息盒子」。
- 摘要：被收进的会话里最新一条的「会话名：摘要」；其中有被 @ 的会话时，摘要取那一条并在前面加「[有人@我]」。
- 时间：被收进的会话里最新一条消息的时间。
- 未读：被收进的各会话未读之和，灰色胶囊，不计入页签红色总数。
- 排序：与普通会话按时间混排，排在置顶会话之后；有新消息时上浮，但不闪不响。
- 被收进的会话（包括置顶的）不再单独出现在主列表里。
- 左键单击打开消息盒子窗口；右键菜单只有两项：「全部标为已读」「批量管理消息提醒」。

### 4.5 「消息盒子」窗口

- 单例、非模态的 `DuiFrameWindow`，可缩放；已经打开时再点那一行，只把窗口提到前台。
- 顶部一行：左边「全部标为已读」，右边「批量管理」。
- 下面是被收进的会话列表，外观与主面板会话列表相同（复用 `MainPanelTreeView` 及主面板填行的那套代码），置顶的排在前面，其余按时间倒序。
- 单击一行：打开聊天窗并清该会话未读，消息盒子窗口保持打开。
- 右键菜单与主面板会话右键菜单相同；在里面改成别的模式，该会话随即移出消息盒子。
- 窗口开着时，被收进的会话来了新消息实时刷新。
- 空状态：列表区居中显示「没有收进消息盒子的会话」。
- 窗口尺寸用具名常量（整窗尺寸，含标题栏，按开发约定文档 UI 约定第 7 条），配「按设计尺寸排得下」的布局单测。

### 4.6 批量管理窗口「消息提醒管理」

- 单例、非模态 `DuiFrameWindow`。两个页签：
  - **群聊**：我加入的全部群。
  - **单聊**：会话列表里的单聊，加上设置过非默认模式的同事；搜索框输入名字时在通讯录全体同事里搜，搜到的人也能直接设置。
- 每行：勾选框、头像、名字、当前模式（文字 + 对应徽章）。顶部搜索框，页签条下方一个「全选」勾选框。
- 底部：「将选中的设为 [下拉框]」+「应用」。下拉框里的选项按当前页签给出（单聊页没有屏蔽）。
- 点「应用」时一次请求提交全部改动（§5.4），成功后各行刷新；失败的条目在行上标红并保留勾选，便于重试。
- 也可以在某一行上右键，单独设置这一个。

### 4.7 原「消息盒子」改名「公告中心」

- 横幅底下那一行：没有新公告时的文字由「消息盒子」改为「公告中心」，有新公告时仍为「你有 N 条新公告」。
- 公告收件箱窗口标题改为「公告中心」。
- 代码注释、日志与文档里指公告收件箱的「消息盒子」一并改为「公告中心」，包括把公告收件箱的方案文档改名为 `docs/公告中心接入方案.md` 并更新引用它的地方（`协议设计-v2.md`、`客户端窗口消息号段规约与整改方案.md`）。相关单测里的期望文字同步更新（`AnnounceBoxLayoutTests`、`MainPanelUserDataTests`、`PanelDragZoneTests` 等）。

## 5. 协议设计

### 5.1 字段：`mute`（布尔）换成 `notifymode`（整数）

1501 应答的每个会话、1513 请求、1514 推送里的 `"mute"` 一律换成 `"notifymode"`（取值见 §3），**旧字段直接删除**，不保留兼容：只有 PC 客户端使用这个字段（安卓客户端没有用到），两端同时升级。

### 5.2 1501 应答新增 `notifymodes` 数组

```json
"notifymodes": [
  { "ctype": 2, "cid": "268435463", "mode": 3 },
  { "ctype": 1, "cid": "100007",    "mode": 4 }
]
```

列出本人全部**非默认模式**的会话，包括还没有消息、因而不在 `conversations` 里的群与联系人。客户端以它为准建立独立的模式表（§7.2），不再把模式挂在会话行上，「给还没有消息的会话设的模式重新登录后读不回」「新建会话行时丢设置」两个问题由此消失。`conversations` 里各会话的 `notifymode` 与本数组一致，便于调试时直接看。

### 5.3 1513 / 1514

- 请求：`{ "ctype": 2, "cid": "268435463", "notifymode": 2 }`（与 `pinned` / `deleted` 一样是可选字段）。
- 推送 1514：`{ "ctype": 2, "cid": "...", "pinned": false, "notifymode": 2, "deleted": false }`。

### 5.4 新增 `cmd_set_notify_modes = 1524`（批量设置）与 `cmd_notify_modes_changed_notify = 1525`

```
请求  { "items": [ { "ctype": 2, "cid": "268435463", "mode": 2 }, ... ] }
应答  { "code": 0, "msg": "ok",
        "results": [ { "ctype": 2, "cid": "268435463", "code": 0 }, ... ] }
推送  1525 → 本人全部在线设备：{ "items": [ 实际改成功的条目 ] }
```

- 单次最多 `kMaxNotifyModeBatch = 200` 条，超出整单回 3（请求非法）；客户端超过 200 条时自动分批。
- 每条单独校验，失败不影响其它条；整单在一个事务里写。
- 单条修改仍走 1513 / 1514；批量窗口与「全部标为已读」之外的入口都用 1513。

### 5.5 作废特别关注的独立协议

- `cmd_set_starred = 1216` 作废，`Protocol.h`（服务端与客户端两份）原处留注释，编号不得复用。
- 1201 应答里的 `starred` 数组删除，特别关注名单改由 §5.2 的 `notifymodes`（`mode = 4`）给出。
- `error_code_starred_limit = 210` 保留，改为「特别关注的会话数已达上限」，单聊与群聊合计。上限沿用 `kMaxStarredCount = 50`。

### 5.6 校验与错误码

| 校验 | 不通过时 |
| --- | --- |
| `notifymode` 在 0~4 之内 | 3（请求非法） |
| 单聊设 3（屏蔽） | 3（请求非法） |
| 群会话：操作者须是群成员（现有规则） | 现有错误码 |
| 单聊：对方须是同企业成员（沿用特别关注的校验） | `error_code_not_friend` |
| 设为 4 时，本人模式为 4 的会话已有 50 个 | 210 |

从 3 改成其它值时，在同一个事务里把该群的 `f_readmsgid` 推进到当前最大 msgid（`GREATEST`，只前进不后退）。

### 6.1 数据库

## 10. 风险与注意事项

- **协议不兼容**：`mute` 字段直接删除，新服务端与老客户端之间免打扰会失效，老客户端也收不到特别关注名单。服务端与客户端需要同时升级。
- **特别关注的群很活跃时**：窗口没开就弹出，用户关掉窗口后下一条消息又会弹出。这是选择「直接弹出聊天窗」的预期代价，联调时观察实际感受，必要时再议。
- **被收进消息盒子的会话被删除（从列表移除）后**：模式仍保留在模式表里，下次有消息时仍进消息盒子，不会回到主列表。

### 12.8 实施记录（2026-10-07）

按 §12.4 实现，测试用例见 §12.6。与方案不同或方案没写到的地方：

- **服务端校验集中在 `GroupFollowManager::checkTargets`**（本人须为群成员、不超过 20 人、不含自己、都是本群成员），会话层只负责调用与回包，这样 MF-S2 能直接对着临时库测。超限、填自己、填非成员都回 `error_code_bad_request`，没有另开错误码：客户端选人时已按同一个上限拦住，只有异常请求才会走到这里。
- **退群清理多删了一类行**：`GroupManager::removeMembers` 除了删当事人自己在本群的名单，也删别人名单里的当事人，否则这些名额一直被不在群里的人占着，当事人日后重新入群时关注还会意外恢复。被删的那些人不会收到 1331，名单要等下次登录（1501）才更新；他们的群成员菜单里本来也已看不到当事人，不影响使用。解散群把 `t_group_follow` 加进按群删除的表单。
- **1330 的协议代码放在 `GroupProtocol`**（结构 `GroupFollowList`、上限 `kGroupFollowMax`），1501 的 `groupfollows` 由 `MessageProtocol::buildSyncConversationsResponse` 新增的参数输出，`MessageProtocol.h` 因此包含了 `GroupProtocol.h`。

## 13. 会话列表行标记重排与头像在线状态角标（2026-10-07）

### 13.1 起因

- **时间不对齐**（据实证：`MainPanelTreeView.cpp` 原 1079-1082 行、`StatusIconReserve_`）：单聊会话行右端有在线状态徽标（基类 `DuiTreeView` 的行末状态位图，12 像素），本类画的时间与未读胶囊要整体让到它左边（徽标宽 12 + 间距 6），群行与「消息盒子」行没有徽标，于是两种行的时间差 18 像素，上下不成一列。

## 14. 特别关注：上下线提示与群成员菜单（原 `docs/特别关注接入方案.md`，2026-10-10 并入）

特别关注最初（2026-08-12）是一个独立功能，有自己的协议（1216）、表（`t_starred`）与名单模型；2026-10-03 并入本方案，成为提醒模式 4（`notify_mode_starred`，§3、§7.8），原协议与表已删除（§5.5、§11 的 1d、3c）。名单、协议、上限、主面板的设置入口与收到消息时弹出聊天窗的行为都以前面各节为准。本节收录原方案中仍然有效、前面各节没有写到的部分：命名约定、联系人上下线提示、群聊窗里的成员菜单入口与相关测试。上下线提示**只对联系人有效**，群没有上下线，只有 §3.1 所写的收到消息时弹出聊天窗。

### 14.1 命名约定

界面文字一律是「特别关注」，代码标识符一律用 `Starred`（`notify_mode_starred`、`CStarredPopupWindow`、`kMentionMenuStarred`、`FMG_MSG_QUERY_STARRED` 等）。不用直译的 `Focus`，因为它在本仓库已表示键盘 / 输入焦点（聊天窗的 `m_focusArea`、`CHAT_FOCUS_INPUT`）；也不用 `Watch`，它已被 `IsUserWatchingChatWindow` 用来表示「用户正看着这个聊天窗」。

特别关注与「收藏」（代码里是 `Favorite`）是两个独立标记：收藏是常用入口的书签，特别关注是提醒模式，两者互不影响、可以同时存在。

### 14.2 上下线推送的来源

- 服务端不为特别关注单独推送。上下线沿用 `cmd_presence_changed_notify`（1109）：`ChatServer::broadcastToEnterprise`（`chatserversrc/ChatServer.cpp`）取在线会话快照，发给同一企业的全部在线用户并跳过发起者本人。触发点有三处：登录成功（`ChatSession::onLogin`）、主动改状态（`ChatSession::onChangePresence`）、连接断开时补发离线（`ChatServer::onDisconnected`）。因此特别关注一个从没聊过的同事，同样收得到他的上下线。
- 推送不落库，本人离线期间别人的上下线不补发。这是有意接受的：上下线提示的价值在实时性，登录后补一批过时的提示没有意义（已与用户确认）。
- 登录时别人的当前状态随通讯录应答（1201 每个联系人的 `presence`）一次给出，不靠推送；但通讯录应答回来之前收到的推送会被误判为上线，所以仍需要 §14.3 的静默期。

### 14.3 判定与抑制

`CBalloonMainPanel::OnPresenceChanged`（处理 1109 推送）在播放上线提示音的逻辑之后调用 `MaybeShowStarredPresencePopup`，后者按下列顺序判定，任何一项不满足都不弹提示：

| 序 | 判定 | 说明 |
| --- | --- | --- |
| 0 | 不在锁屏期间 | 经 `balloonlock::DecideDuringLock(kLockEvtStarredPresence, ...)`，锁屏期间直接丢弃、解锁后不补弹（`Feature/Lock/LockSuppressPolicy.cpp`，`docs/锁屏方案.md` 第 4.9 节） |
| 1 | 对方是特别关注的联系人 | `IsContactStarred`：模式表里与他的单聊会话为 `notify_mode_starred` |
| 2 | 对方不是本人 | 服务端广播时已跳过本人的全部连接，客户端仍再排除一次，避免多设备登录等情况下给自己弹「我已上线」 |
| 3 | 确实是上线或下线 | `IsBuddyJustCameOnline` / `IsBuddyJustWentOffline`（`UI/BalloonMain/NotificationSound.h`），两者共用「可见在线」口径：在线、离开、忙碌算在线，其余（离线、已作废的取值）算不在线。在线、离开、忙碌之间的切换不提示，否则对方锁一次屏就会提示一次 |
| 4 | 不在静默期内 | 静默期 `kStarredSilenceMs` = 10 秒（`BalloonMainPanel.cpp`）。通讯录应答回来之前，`OnPresenceChanged` 对查不到的人按离线处理，此时收到的推送会被判成上线，不静默就会在登录瞬间把在线的同事全部提示一遍 |
| 5 | 本人不是「勿扰」 | 勿扰即用户自己选的在线状态 `presence_busy`，读 `MainPanelHeader::GetPresence()`（用户选的状态，不受掉线影响），不是「关闭所有声音」（`CUserConfig::IsEnableMute()`）那个设置 |

静默期的起算与相关处理：

- 主面板构造时与 `ResetForLogout` 时各起算一次。
- 断线重连（`ApplyConnectionState` 由非在线态回到 `kConnUiOnline`）时重新起算：重连后服务端会把在线的同事重推一遍，与刚登录时相同。连接态变为非在线时，同时收起已经弹出的提示（`HideAndClear`），那是断线前的状态。
- 比较写成 `(int)(::GetTickCount() - m_starredSilenceUntilTick) < 0`：`GetTickCount` 约 49.7 天回绕一次，直接比较大小会在回绕时判反。

### 14.4 提示窗 `CStarredPopupWindow`

`Source/UI/BalloonMain/StarredPopupWindow.{h,cpp}`，由主面板按值持有、单实例复用（成员 `m_starredPopup`），主面板销毁时一并销毁。

- **落点与置顶**：贴桌面工作区（排除任务栏）的右下角，边距 16 像素，按鼠标所在显示器定位；落点计算是 `UI/BalloonMain/CornerPopupPlacement.h` 的 `MoveWindowToWorkAreaCorner`，与新公告提示窗等右下角弹窗共用一份（开发约定文档 UI 约定第 3 条）。`HWND_TOPMOST` 置顶，`SW_SHOWNOACTIVATE` 显示、不抢前台焦点；以 `NULL` 为所有者创建，主面板最小化或隐藏到托盘时照常弹出。每次弹出都重新定位一次，以适应分辨率或任务栏位置的变化。
- **多条合并**：同一时刻多人上下线时并入同一个窗口、逐行列出（「张三 已上线」「李四 已离线」，显示名为空时为「用户<id>」），新事件追加进来并重新计时。行怎么排由纯函数 `BuildStarredPopupRows`（`UI/BalloonMain/StarredPopupModel.h`）决定：
  - 同一个人多次变化只保留最后一次的状态，但行的位置留在他第一次出现的地方，避免行在列表里跳动；
  - 按事件到达的先后排列；
  - 最多 `kStarredPopupMaxRows` = 5 行（含汇总行），去重后的人数超过 5 时前 4 行照常列出、第 5 行为「等 N 人」；
  - userid ≤ 0 的事件丢弃。
- **行控件**：balloonui 的 `DuiListBox`（悬停高亮、选中、滚动条都是现成的）。每行的 `lParam` 存该行的 userid，汇总行为 0。单击一行（`DUIN_VALUECHANGED`，连同 `ctrlId` 判断）时向主面板投递 `FMG_MSG_OPEN_CHAT` 打开与那个人的单聊，并收起提示窗；点汇总行不打开窗口。
- **自动关闭**：`kAutoCloseMs` = 6 秒无人理会后收起；标题后显示倒计时（「特别关注 · N 秒后关闭」，`CornerPopupCountdown.h`，屏幕共享第 15 期起）。鼠标停在窗口上时暂停计时，离开后从头重新计时（不是接着剩余时间）。离开通知靠 `TrackMouseEvent(TME_LEAVE)`，该登记是一次性的，每次鼠标进入都要重新登记，否则收不到 `WM_MOUSELEAVE`、窗口一直不消失。
- **关闭与尺寸**：标题栏只有关闭按钮；点关闭只隐藏并清空已攒下的事件，不销毁窗口。窗口有任务栏按钮，标题栏与任务栏都显示程序图标。窗口高度按行数计算，`SetMinSize` 与 `ResizeClient` 一起改，只有一条提示时不留空白。

### 14.5 群聊窗里的成员菜单入口

主面板的会话、联系人右键菜单经「消息提醒设置 ▸」设置特别关注（§4.1）。群聊窗里另有一个快捷项，作用对象是**那个群成员本人**（把与他的单聊会话设为特别关注或改回允许提醒），不是群：

- 群成员菜单的模型 `BuildMentionMenuModel`（`UI/BalloonChatWnd/GroupMentionMenu.h`）由三处共用：群聊窗右侧的成员列表（行与右键动作在 `GroupMemberPanelKit`，帖子群的成员面板也用它）、气泡里的 @某人 片段、气泡的发送者头像；帖子群详情里的 @某人 用 `BuildThreadMentionMenuModel`，经主面板的 `ShowThreadMemberMenu` 弹出。菜单项 `kMentionMenuStarred` 的文字由 `GetMemberStarredMenuLabel` 给出，为「设为特别关注联系人 / 取消特别关注联系人」（2026-10-06 起，与 §12 的「关注 TA 在本群的发言」区分开）；主面板联系人菜单里仍叫「特别关注」（`GetStarredMenuLabel`）。该项不受「成员是否还在群里」影响，对本人不出现。
- **查询**：提醒模式表只有主面板一份。气泡与成员行经查询钩子 `ChatMessageList::SetStarredQuery` / `GroupMemberItem::SetStarredQuery`（群聊窗建控件时装上）同步发送 `FMG_MSG_QUERY_STARRED` 问主面板，用于决定菜单文字。用钩子而不在行上存一个布尔值，是因为状态可能在别处（主面板菜单、资料窗、其它设备）被改掉，而成员列表不会因此重建，存下来的值会过期。
- **切换**：选中该项后投递 `FMG_MSG_TOGGLE_STARRED`（wParam 为 userid），主面板 `ToggleStarred` 按模式表现状取反（特别关注 ↔ 允许消息提醒），经 `SetConversationNotifyMode` 发 1513。群聊窗不保留任何状态副本。
- **发送者头像的右键**（`ChatBubble::TryPopupAvatarMenu`）：
  - 头像矩形不存成员，由 `AvatarRectInHost` 按绘制时的公式按需重算。文字气泡走渲染缓存，前提是绘制时不记录宿主坐标系里的命中矩形，存一份头像矩形会让所有文字气泡退出缓存。
  - 只在群聊里生效（判据为 `senderName` 非空，与绘制时显示发送者名字同一口径）；本人发的消息、`senderUserId` ≤ 0 的消息不弹。
  - 右键的判定顺序：先判 @片段，再判头像，都没命中才弹气泡自己的菜单（命中链接时在气泡菜单最前面加「在浏览器中打开」「复制链接地址」两项）。@片段与头像两个入口共用 `ChatBubble::PopupMemberMenu` 建菜单、弹出与投递。

### 14.6 上限

特别关注的会话（单聊与群聊合计）最多 50 个（服务端 `MessageProtocol.h` 的 `NOTIFY_MODE_STARRED_MAX`，客户端 `NotifyModeModel.h` 的 `kNotifyModeStarredMax`）。客户端设置前先按本地模式表检查（`NotifyModeModel::CanSetStarred`），满了直接提示「特别关注最多 50 个，请先取消一些再设置。」、不发请求；服务端再校验一次，超出回 `error_code_starred_limit`（210，§5.5、§5.6），客户端收到后重拉会话列表纠正并给出同一提示。
