# 消息记录窗：内容展示与交互增强方案

> 目标：让「消息记录」窗里的每一行从"一句摘要"变成"能看、能用的内容"——
> 长文能展开看全、表情画成表情、图片能看能存能复制、文件能定位能重下、文字能复制。
>
> 涉及子项目：`flamingoclient/`（PC 客户端）。不动服务端、不动 Android。
>
> 本文是**方案**，未开工。§10 列的待确认项需要先对齐。

---

## 1. 需求与范围

用户提出的五条：

| 编号 | 需求 |
| --- | --- |
| F1 | 支持看到完整的文字消息；太长时默认收起，点击可展开看完整内容 |
| F2 | 表情直接显示成表情，而不是文字占位 |
| F3 | 图片支持双击放大查看、复制、另存为 |
| F4 | 文件支持"打开所在位置"；文件不存在时支持下载，下载失败要给提示 |
| F5 | 文字消息（含表情）支持复制 |

不在本轮范围：语音消息的播放、链接消息的预览卡片、消息转发、多选批量操作。

## 2. 现状（据实证）

### 2.1 一行只画一行摘要

列表行的预览是一个**单行、定高**的标签：

- `HistoryWindowLayout.cpp:277-282` —— 预览控件是 `HistoryHighlightLabel`（`DuiLabel` 子类），
  对齐标志为 `DT_LEFT | DT_VCENTER | DT_SINGLELINE`，长文被 `DuiLabel` 自己的省略号截断。
- `HistoryWindowLayout.cpp:89` —— `const int kRowH = 56;`，
  `HistoryWindowLayout.cpp:466` 处每行以 `Hint().Fixed(kRowH)` 定高。

所以现在**没有任何一行能显示第二行文字**，行高也是编译期定死的。

### 2.2 表情现在是文字占位「[表情]」

`HistoryView.cpp:38-43`：文本消息走 `DigestFaceTokens(root["text"].asString())`，
把正文里的内联表情标记 `/f["<id>"]` 统一净化成字面量 `[表情]`。
这与会话列表的摘要口径一致，但在消息记录里就显得信息量太低。

真正把表情画出来的那套代码在气泡里：

- `ChatBubble.cpp:1069` `GetFaceGdiBitmapCached(int faceId)` —— 按 `Bin/Face/face<N>.png`
  载入并进程级缓存（保留 alpha，用 GDI+ `Bitmap`）。
- `ChatBubble.cpp:1290` `LayoutInlineContent(...)` —— 把「文字段 + 表情段」序列按最大宽度
  排版成若干 `InlinePlaced`，返回占用尺寸。
- `ChatBubble.cpp:1572` `DrawInlineContent(...)` —— 照排版结果画。
- `ChatBubble.cpp:1558` `MessageTextHasFace(...)` —— 是否含表情（决定走内联排版还是快路径）。
- `ChatBubble.cpp:1419` `BuildFlatText(...)` —— 拼"扁平文本"，每个表情占一个 U+FFFC。

**这五个函数全部位于 `ChatBubble.cpp:64` 起的匿名 `namespace` 内**（该匿名 namespace
一直延续到文件末尾 `ChatBubble.cpp:3153` 之前），外部编译单元<u>取不到</u>。
这是 F2 与 F5 最主要的一处结构性障碍，见 §4。

正文本身的分段解析倒是共用的：`balloonchat::ParseSendBody`（`BalloonChat/BalloonChatMsgFormat.h:118-133`）
已经能把 `/f["<id>"]` 解析成 `ChatSegment` 序列，且不依赖 UI。

### 2.3 图片：缩略图有，交互没有

- `HistoryRow.h:60-67` 明确写着：缩略图走 `ChatImageCache`，**本地缓存里没有原图时不下载**，
  只画占位块。
- 双击整行现在是**定位到聊天窗**：`HistoryRow` 覆写 `OnLButtonDblClk` 冒 `DUIN_DBLCLK`
  （`HistoryRow.h:141`），窗口侧在 `BalloonHistoryWindow.cpp:1099-1108` 收下并调 `LocateRow`。
- 可复用的现成件：
  - 看图窗有进程内共享入口 `CBalloonImageViewerWindow::ShowSharedImage(hOwner, imagePath)`
    （`BalloonImageViewer/BalloonImageViewerWindow.h:57-63`），单聊 / 群聊窗已在用。
  - 图片另存为 `SaveChatImageAs`（`BalloonChatWnd/ChatImageSaveAs.h`）。
  - 复制位图到剪贴板目前**没有**通用件：`ScreenCaptureOverlay.cpp:205-234` 里有一份
    `CF_BITMAP` 的实现，但它是截图浮层的私有成员函数；`ClipboardText.h` 只有文本那一路。

### 2.4 文件：只有类型色块，点不动

- 行内只画一块类型色块（`HistoryRow.h:68-101` 的 `HistoryRowThumb::kFile`），没有任何操作。
- 可复用的现成件：
  - `ResolveLocalFilePath(registeredPath, registeredExists, cachePath, cacheExists)`
    （`BalloonChatWnd/ChatFileLocation.h`）—— 纯逻辑，已有单测 Suite CFL。
  - `CFileLocalStore`（`BalloonHistory/FileLocalStore.h`）—— 按 md5 + 文件名查登记路径。
  - 下载入口 `net::FileTransfer::EnqueueDownload(msgid, fileid, filename, expectMd5, expectSize, selfUserId)`
    （`net/FileTransfer.h:276-278`）。
  - 结果经 `FMG_MSG_V2_FILE_DOWNLOAD_RESULT`（`UserSessionData.h:205`）回投，主面板在
    `BalloonMainPanel.cpp:2756` 的 `OnFileDownloadResult` 里落登记表并**广播给各聊天窗**——
    目前**不包含消息记录窗**，需要补一条扇出。

### 2.5 复制：气泡有一整套，消息记录一点没有

`ChatTextSelection.h` 是**纯逻辑**的选中 / 命中测试 / 提取模块（不依赖 GDI / HWND / balloonui），
字符口径为"一个表情占一个字符位、用 U+FFFC 占位"，提取时可把占位符换成可读文案
（`ExtractSelectedText(..., faceLabel)`，气泡传的是 `L"[表情]"`，见 `ChatBubble.cpp:725`）。
它本身可以直接被消息记录窗复用，缺的是"喂给它的排版结果"——而排版正是 §2.2 那个
被关在匿名 namespace 里的 `LayoutInlineContent`。

## 3. 总体设计

两件事撑起全部五条需求：

### 3.1 行从「单行标签」改成「内容块」

预览控件由 `HistoryHighlightLabel`（单行、定高）换成新的 **`HistoryContentView`**：

- 内部持有 `std::vector<balloonchat::ChatSegment>`（文字段 + 表情段），用抽出来的
  `LayoutInlineContent` 排版 —— 表情直接画成图（F2）。
- 支持**多行**与**折行**，并有"折叠 / 展开"两态：折叠态最多画 N 行、末行带省略号；
  展开态画全（F1）。
- 排版结果同时喂给 `ChatTextSelection`，支持拖选与复制（F5）。
- 关键字高亮（现有能力）继续保留：把 `HistoryHighlightLabel` 的高亮矩形逻辑并进来。

行高随之从"编译期常量"变成"按内容测量"：`BuildListContent` 里那句
`Hint().Fixed(kRowH)` 换成 `Hint().Fixed(MeasureRowHeight(row))`。

### 3.2 行上新增右键菜单

F3 的复制 / 另存为、F4 的打开所在位置 / 下载、F5 的复制，都挂在**行右键菜单**上。
菜单内容按该行的消息类型与本地文件状态变化，做法与气泡的 `ChatMessageMenu` 完全对齐：
**先做一个纯模型函数**算出"这个菜单该有哪几行"，再由窗口去弹真菜单。

> 菜单落点必须走 `balloonmain::ClampPopupMenuToWorkArea`（开发约定文档 UI 约定第 3 条）——
> 列表行靠近窗口底边时，不夹取的话菜单会跑到桌面外。

## 4. 先决改动：把内联表情排版从 ChatBubble.cpp 抽出来

**这是 F2 与 F5 的前置条件，也是本方案里唯一一处"改存量代码"的地方。**

新建 `BalloonChatWnd/ChatInlineText.{h,cpp}`，把下列函数从 `ChatBubble.cpp` 的匿名
namespace 平移过去，改为 `balloonchatwnd` 命名空间的公开函数：

| 函数 | 现位置 | 职责 |
| --- | --- | --- |
| `GetFaceGdiBitmapCached` | `ChatBubble.cpp:1069` | 按 faceId 取表情位图（进程级缓存） |
| `TokenizeForWrap` | `ChatBubble.cpp` 内 | 折行分词（近似 `DT_WORDBREAK`） |
| `struct InlinePlaced` | `ChatBubble.cpp:1167` | 一个排好位置的段 |
| `LayoutInlineContent` | `ChatBubble.cpp:1290` | 排版：段序列 + 最大宽度 → 位置表 + 尺寸 |
| `DrawInlineContent` | `ChatBubble.cpp:1572` | 照位置表绘制 |
| `MessageTextHasFace` | `ChatBubble.cpp:1558` | 是否含内联表情 |
| `BuildFlatText` | `ChatBubble.cpp:1419` | 拼扁平文本（表情占一个 U+FFFC） |

`ChatBubble.cpp` 改为 `#include "ChatInlineText.h"` 并删掉本地副本。

**这是纯搬迁，不改任何一行逻辑。** 按开发约定文档测试规范第 1 条（"不确定的行为，先测后改"），
搬迁前先给这几个函数补一组"当前行为"的单测（宽度给定时排出几行、每行占多宽、
扁平文本长度与表情占位是否对得上），搬完再跑同一组用例，保证气泡渲染没有任何变化。

另需给 `LayoutInlineContent` 加一个**行数上限**入参（折叠态用）：
达到上限即停止排版，并回报"还有内容没画完"。气泡侧传"无上限"，行为不变。

> 这不属于 balloonui，是 `Source/` 下的代码，按常规流程改即可（开发约定文档只对
> `third-party/balloonui/` 有事先批准的约束）。

## 5. 逐条设计

### F1 长文本折叠 / 展开

**折叠规则**：折叠态最多画 **5 行**（§10-1 已定），超出时末行以省略号收尾，
并在内容块右下角给一枚「展开」链接；展开态画全，链接变「收起」。
不足 5 行的消息不画链接 —— 它本来就是全的。

**展开状态存在哪**：存在 `HistoryModel` 里的一个 `std::set<int64_t> m_expandedMsgids`
（按 msgid 记，不是按行下标）。这样：

- 局部刷新（`RefreshContent`）不会把展开态冲掉；
- 翻页离开再翻回来，展开态还在；
- 换会话 / 改筛选条件时清空（那已经是另一批消息了）。

**行高**：`MeasureRowHeight` 用与绘制同一份 `LayoutInlineContent` 算，避免"量的和画的
不是一套"。滚动视口的内容高度本来就是各子控件高度累加，行高变了 `DuiScrollView`
会自然跟上；展开 / 收起后需要 `ForceLayout` 一次并刷新滚动条（与既有的
"提示带显隐后补布局"同一套路）。

**点哪里展开**：只点那枚「展开 / 收起」链接（§10-1 已定）。
不做"点正文任意处展开"—— 正文将来要支持拖选（F5 二级），点击语义会打架。

### F2 表情直接显示

有了 §4 的 `ChatInlineText` 之后，这条几乎是免费的：

1. `HistoryView` 新增 `std::string FullTextFromContent(int msgtype, const std::string& contentJson)`
   —— 与 `PreviewFromContent` 并列，但**不做** `DigestFaceTokens` 净化，原样返回正文
   （含 `/f["<id>"]` 标记）。`PreviewFromContent` 保持不动，会话列表那边继续用它。
2. `HistoryRowView` 增加 `CString m_fullText`（含表情标记的正文）。
3. `HistoryContentView` 拿到它，`ParseSendBody` 成段序列后交给 `LayoutInlineContent`。

非文本消息（图片 / 文件 / 语音…）仍走现在的 `[图片]` `[文件] xxx` 占位文案。

表情尺寸沿用气泡的 `kFaceDisplayPx = 28`（`ChatFaceTag.h`，§10-4 已定）——
`Bin/Face` 下的原图是 56×56，56→28 正好是 1/2 整数倍缩小，每个目标像素恰好对应源图
2×2 的方块，几乎无损；换成 20 之类的非整数倍会引入插值模糊。

### F3 图片：双击查看 / 复制 / 另存为

**双击查看。** **图片行的双击一律改成"看大图"**（§10-2 已定），该行的定位只留行内
那枚「定位」按钮。非图片行的双击行为不变，仍是定位到聊天窗。

实现上 `HistoryRow` 需要知道自己是不是图片行：现在它无差别地把双击冒成 `DUIN_DBLCLK`
（`HistoryRow.h:141`），窗口收到即 `LocateRow`（`BalloonHistoryWindow.cpp:1099-1108`）。
加一个"本行是图片消息"的标志，图片行改冒另一个通知码即可。

调 `CBalloonImageViewerWindow::ShowSharedImage(m_hWnd, path)` 即可，不必新建看图窗。

**本地没有原图时**：现在缩略图是个占位块。**双击即自动下载，完成后自动打开看图窗**
（§10-3 已定）。发 `net::ImageTransfer::EnqueueDownload`，缩略图切"下载中"态，结果经
`FMG_MSG_V2_IMAGE_DOWNLOAD_RESULT` → 主面板 → 消息记录窗，成功自动开看图窗、失败弹提示。

> 只在**用户明确双击**时触发，翻页 / 刷新一律不下载 —— 消息记录窗的轻量浏览定位
> （`HistoryRow.h:64-67`）在这一点上不变。

**复制 / 另存为**：走行右键菜单。

- 另存为直接调 `SaveChatImageAs`。
- 复制需要新建一个通用件 `ClipboardImage.h`（与 `ClipboardText.h` 并列）：把一个
  图片文件读成 `HBITMAP` 后以 `CF_BITMAP` 放进剪贴板。`ScreenCaptureOverlay.cpp:205-234`
  那段可作参考，但**不直接复用它**——它是截图浮层的成员函数、且源是已有的 `HBITMAP`
  而不是文件路径。新件同时给截图浮层留了日后归位的余地。

### F4 文件：打开所在位置 / 下载 / 失败提示

行右键菜单按**本地文件在不在**给不同的项：

| 本地状态 | 菜单项 |
| --- | --- |
| 在 | 打开文件 / 打开所在文件夹 / 另存为 |
| 不在 | 下载 |
| 正在下载 | 取消下载 |

"在不在"用现成的纯逻辑 `ResolveLocalFilePath` 判：登记路径（查 `CFileLocalStore`）优先，
失效则回退按 md5 推导的缓存路径，两处都没有即判定为"需要下载"。这套优先级与回退
已有单测（Suite CFL），不重造。

- **打开所在文件夹**：`ShellExecute(NULL, L"open", L"explorer.exe", L"/select,\"<路径>\"", ...)`，
  与气泡那条路同口径。
- **下载**：`net::FileTransfer::EnqueueDownload(msgid, fileid, filename, md5, size, selfUserId)`。
  fileid / md5 / size 从该行的 content JSON 取 —— `ParseContentBrief` 目前只取了
  `m_fileName` / `m_fileSize`（`HistoryView.h:145-152`），需要**扩展出 `m_fileId` 与 `m_fileMd5`**。
- **下载结果**：`CBalloonMainPanel::OnFileDownloadResult`（`BalloonMainPanel.cpp:2756`）
  现在只广播给各聊天窗，需补一条 `m_historyWindow.OnFileDownloadResult(...)` 的扇出。
  成功则刷新该行（现在能打开了）；失败弹提示。
- **失败提示**：用 `MessageBox` 弹窗（§10-5 已定）。下载是用户主动发起的操作，
  失败了就该明确告知；行内红字用户多半已经滚到别处、根本看不见，会误以为还在下。

### F5 文字（含表情）复制

分两级，**本轮只做第一级**（§10-6 已定）：

**一级：整条复制（本轮）。** 行右键菜单的「复制」把整条正文写进剪贴板。
表情写成 `[表情]`（§10-7 已定，与气泡 `ChatBubble.cpp:725` 同口径），
用现成的 `flamingo::CopyTextToClipboard`（`ClipboardText.h`）。
成本极低，覆盖绝大多数"我要把这句话贴到别处"的场景。

**二级：拖选复制（C5，另议）。** 在内容块里按下拖动选中一段，`Ctrl+C` 或右键复制。
`ChatTextSelection` 那套纯逻辑可以直接复用（喂 `LayoutInlineContent` 的排版结果即可），
但窗口侧要接鼠标按下 / 移动 / 抬起、跨行选区绘制、失焦清选、以及"选区在哪一行"的
归属管理 —— 这在一个**多行、可滚动、行会展开收起**的列表里比在单个气泡里复杂得多，
工作量约等于 F1~F4 之和。

## 9. 风险与注意

1. **`ChatInlineText` 抽取会碰到气泡的核心渲染路径。** 这是本方案里唯一有"改坏存量功能"
   风险的一步，所以单独排成 C0 并且先测后搬。
2. **行高不再固定**，凡是"按行下标算 y 坐标"的地方都要复查。已知一处：
   `BalloonHistoryWindow::UpdateRowHover` 按几何位置判鼠标在哪一行（`BalloonHistoryWindow.h:99-101`），
   它本来就是按各行实际矩形算的，据推测不受影响，但要实测确认。
3. **按需下载会让"浏览"变成"消耗流量"。** 消息记录窗的定位一直是轻量浏览界面
   （`HistoryRow.h:64-67` 特意写了"不为 36px 缩略图拉整张原图"）。加了按需下载后要注意
   只在**用户明确操作**时触发，不能因为翻页就批量拉。
4. **展开态与分页的交互**：一页 8 行，若几行都展开，一页会变得很长；加上表情按 28px
   画，折叠态单行最高就能到 190px 上下。日常消息绝大多数是一两行，只有长消息才触得到；
   本轮先按这个做，**实测后若确实难用，再议是否把每页条数调小**。

## 10. 已确认的决定（2026-08-05 与用户逐条对齐）

| # | 决定 | 说明 |
| --- | --- | --- |
| 1 | **折叠态最多 5 行**，靠右下角一枚「展开 / 收起」链接切换 | 不做"点正文任意处展开"——正文区域将来要留给拖选复制，点击语义会打架 |
| 2 | **图片行的双击一律改成"看大图"**，该行的定位只留行内那枚「定位」按钮 | 规则简单好记；代价是改掉了图片行既有的双击习惯 |
| 3 | 本地没有原图时，**双击即自动下载，完成后自动打开看图窗**，失败弹提示 | 只在用户明确操作时触发，翻页绝不批量拉 |
| 4 | 表情按 **28px** 画，与气泡的 `kFaceDisplayPx` 完全一致 | `Bin/Face` 原图 56×56，56→28 是 1/2 整数倍缩小、几乎无损；换成 20 会引入插值模糊 |
| 5 | 下载失败用**弹窗**提示 | 下载是用户主动发起的操作，失败了就该明确告知，与聊天窗其它失败提示同口径 |
| 6 | F5 本轮**只做整条复制**，拖选复制单独排一轮（C5） | 拖选在"多行 + 可滚动 + 行会展开收起"的列表里工作量约等于前四条之和 |
| 7 | 复制时表情写成 **`[表情]`** | 与气泡 `ChatBubble.cpp:725` 同口径，粘到哪里都可读 |

### 由这些决定带出的两处影响

**决定 2 要求行知道自己是不是图片行。** `HistoryRow` 现在无差别地把双击冒成
`DUIN_DBLCLK`，窗口收到就 `LocateRow`。改法是给 `HistoryRow` 加一个"本行是图片消息"
的标志，图片行的双击改冒另一个通知码（看大图），非图片行行为不变。

**决定 1 + 决定 4 会让含表情的长消息行明显变高。** 5 行 × 28px 表情行高 + 名字行 20px
+ 上下内边距，折叠态最高可到 190px 上下。日常消息绝大多数是一两行，只有长消息才会
触到这个高度；但这也意味着**一页 8 条的分页粒度在极端情况下会显得很长**。本轮先按
这个做，实测后若确实难用，再议是否把每页条数调小。

**三处实现时才想清楚的问题：**

1. **关键字高亮的字符口径变了。** 老代码在 `PreviewFromContent` 的输出上找关键字，
   那份文字里一个表情已被净化成 `[表情]` 四个字符；而内容块认的是<u>扁平文本</u>口径
   （一个表情占一个字符位）。直接接线的话，含表情的消息高亮会整体往后错位。
   改成在 `BuildFlatText(ParseSendBody(fullText))` 上找。
2. **行高要在构建时给出，可用宽度却要等布局才知道。** `DuiLayout` 的 `Fixed()` 是静态的，
   没有"按内容自适应"的 hint。解法是把列表实际宽度传进 `BuildListContent`，配一个
   `RowContentWidth` 精确扣掉头像 / 缩略图 / 两枚按钮槽 / 内边距 / gap / 滚动条。
   **这个函数必须与 `BuildRow` 里的实际布局严格对应** —— 少扣一列行高就算少，
   正文最后一行会被下一行压住。窗口侧传滚动视口的实际宽度，整窗首次构建与单元测试
   传 0 走兜底宽度。
3. **纯文字行不能按表情行高算。** 排版引擎的行高恒取 `max(字体行高, faceSize)`，

   好几条。内容块里 `EffectiveFaceSize()` 在正文确实没有表情时返回 0，行高退回字体
   行高。方案 §10 估算的"折叠态最高 190px"是按表情行算的，纯文字五行其实只有 95 上下。

**四处实现时才想清楚的问题：**

1. **右键够不到行容器。** `DuiHost::OnRButtonDown` 只把事件发给 `HitTopMost` 命中的<u>最深</u>
   控件 —— 右键点在正文或某枚按钮上时，行容器根本收不到。解法与悬停完全一样：在窗口层
   监听 `WM_RBUTTONUP`，按落点几何算出点在哪一行（`RowIndexAtPoint`）。**因此 `HistoryRow`
   一个字都没改。** 行下标由 `ctrlId` 反算而不是数"第几个子控件" —— 中间还夹着日期分组头。
2. **菜单不能在鼠标事件栈里弹。** `TrackPopupMenu` 是模态消息循环，直接在 `WM_RBUTTONUP`
   处理里跑会与 `DuiHost` 的鼠标捕获打架（菜单收起后整个界面点击失灵）。改为投递
   `WM_HISTORY_SHOW_ROW_MENU`，等事件解栈之后再弹 —— 与聊天窗弹发送模式菜单同一套路。
   打包屏幕坐标用了 `MAKELPARAM`，取出时**必须用 `GET_X_LPARAM` 按有符号还原**：多显示器
   布局下坐标可能为负，当无符号会把菜单弹到几万像素之外。
3. **图片没有取消下载的接口。** `net::FileTransfer` 有 `CancelDownload`，`net::ImageTransfer`
   没有。图片通常只有几百 KB、几秒就完，为它单开一条取消链路不划算；`CancelRowDownload`
   对图片只撤掉本窗口的跟踪状态，传输仍会跑完并落进缓存 —— 那份缓存下次看图还用得上。
4. **「打开所在文件夹」的路径必须带引号。** `explorer.exe /select,<路径>` 不加引号时，
   含空格的路径会被拆成多个参数，结果打开的是"我的文档"而不是定位到文件。

**下载的归属判定**：本窗口只认自己发起的那几笔（`m_downloadingMsgids`）。主面板收到
下载结果后向所有聊天窗 + 消息记录窗广播，消息记录窗按 msgid 判断这一笔是不是它要的，
不是就安静忽略 —— 否则聊天窗自己的下载失败会在消息记录窗里弹一个莫名其妙的提示框。

「下完自动开看图窗」只在**双击缩略图**时置上（`m_pendingViewMsgid`）：双击的意图就是
"我要看这张图"，下载只是手段；而从菜单点「下载」纯粹是把文件拿到本地，下完弹个窗
反而打断人。
