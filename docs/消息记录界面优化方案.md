# 「消息记录」窗口界面优化方案

> 作者：balloonwj@qq.com　起草日期：2026-08-04
> 用途：记录「消息记录」窗口（`flamingoclient/Source/BalloonHistory/`）这一轮界面优化的问题清单、设计与开发步骤。后续每步开工前据此细化、收尾后回填实际结果。

---

## 1. 背景与目标

「消息记录」窗口按设计稿搭起来之后，功能是齐的（类型筛选、时间筛选、关键字搜索、翻页、导出、定位、Pin），但用起来有三类问题：**有几处会在数据量大时真的出错**、列表信息密度低、检索结果不好读。

本轮把这三类一起处理。已与用户确认的范围：

| 决策点 | 取值 |
| --- | --- |
| 三个功能缺陷（见 §2.1） | **无条件修** |
| 列表观感与信息层次 | 做 |
| 检索体验（关键字高亮、日期分组） | 做 |
| 列表交互（悬停操作、行悬停、双击定位、Pin 标记） | 做 |
| 内容预览（图片缩略图、文件类型块） | 做 |
| 底部分页器 | **保留分页**，改成省略式页码 + 「跳至第 N 页」 |
| 关键字高亮的实现方式 | **子类化 `DuiLabel`**，不改 balloonui |

## 2. 现状盘点（据实证，均已核对代码位置）

### 2.1 三个会真的出错的缺陷

**(1) 页数超过 100 时，页码按钮与行内「定位」按钮串键。**

控件 id 基址是连着排的（`HistoryWindowLayout.h:54`~`56`）：

```
kIdHistoryPageNumBase = 600,  //第 p 页按钮 id = 600 + (p-1)
kIdHistoryLocateBase  = 700,  //第 i 行「定位」按钮 id = 700 + i
kIdHistoryPinBase     = 800,  //第 i 行「Pin / 取消」按钮 id = 800 + i
```

留给页码的只有 600~699 共 100 个。而分发处（`BalloonHistoryWindow.cpp:771`）判的是 `id >= kIdHistoryPageNumBase && id < kIdHistoryLocateBase`，第 101 页的按钮 id 恰好是 700 —— 它会被后面那条「定位」分支接走，点第 101 页变成「定位到本页第 0 行」。

每页 8 条（`BalloonHistoryWindow.cpp:61` `kHisPageSize = 8`），**800 条消息的会话就能触到**，一个聊了几个月的对话轻松超过。

**(2) 页码按钮全部平铺，没有省略。**

`PopulatePagerButtons`（`HistoryWindowLayout.cpp:267`）是 `for (int p = 1; p <= pageCount; ++p)` 一路建到底。5000 条消息 = 625 页 = 625 个按钮塞进一行，分页行直接失控。

**(3) 没有空状态。**

`BuildListContent`（`HistoryWindowLayout.cpp:241`）对空的 `rows` 就产出一个空 vbox。筛选或搜索到 0 条时，列表区是一整片白，只有底部一句「共 0 条 · 第 1/1 页」—— 用户看到的更像"卡住了"而不是"没有结果"。

### 2.2 列表观感

- **行高 64px、单行预览**（`HistoryWindowLayout.cpp:82` `kRowH = 64`），一屏只有 8 行，信息密度低。
- **时间列固定 96px 且右对齐**（`:87` `kTimeWidth = 96`），名字与时间之间空出几百像素，视线要横跨整行才能把"谁"和"什么时候"对上。
- **连续同一人的消息，头像与名字逐行重复**，纵向看过去全是同一个色块。
- **行内两枚按钮常驻**（`BuildRow`，`HistoryWindowLayout.cpp:134`）。一屏 8 行就是 16 枚按钮，右侧形成一道"按钮墙"，而它们绝大多数时候都不被点。

### 2.3 检索体验

- **命中的关键字不高亮**。搜「报告」出来一屏结果，还得自己在每行预览里找那两个字。
- **没有日期分组**，时间列每行重复「08-04」这一段。
- **搜索框没有提示文字**，也没有一键清空。

### 2.4 内容预览

图片、文件行只有 `PreviewFromContent`（`HistoryView.h`）产出的纯文字 —— `[图片]`、`[文件] 季度报告.xlsx`。而本地库里其实**有足够的信息**做得更好：`BuildContentJson` 落库时图片写了 `{image:{fileid,md5,w,h,size}}`、文件写了 `{file:{fileid,name,size,md5}}`（`V2MsgQuery.h:117`~`122`）。

### 2.5 可以直接复用的现成件

| 要用的能力 | 现成件 | 备注 |
| --- | --- | --- |
| 行悬停 / 按钮显隐 | `DuiControl::OnMouseEnter` / `OnMouseLeave`（`balloonui/DuiControl.h:154`~`156`）、`SetVisible`（`:111`） | 够用，**不必改 balloonui** |
| 图片缩略图解码与缓存 | `BalloonChatWnd/ChatImageCache.h:44` 的进程级单例，后台解码 + 按「路径 + 展示尺寸」缓存 + 完成回调 | 聊天气泡已在用，历史窗直接接 |
| 图片本地缓存路径 | `net/ImageTransfer.cpp:113` `buildImageCachePath` | **目前是文件内 `static`**，要用得先提出来，见 §7.1 |
| 文件类型色块配色 | `BalloonChatWnd/ChatBubble.cpp:140` `FileTypeColor` | **目前是文件内局部函数**，要用得先抽出来，见 §7.2 |

## 3. 缺陷修复

### 3.1 控件 id 分段重排

把三段基址拉开，并且**让分发处按各自的段判定，不再依赖"下一段的基址"当上界**：

```
kIdHistoryPageNumBase = 1000,  //页码按钮：1000 + (页号-1)，容量 1000 页
kIdHistoryLocateBase  = 3000,  //行内「定位」：3000 + 行下标
kIdHistoryPinBase     = 3200,  //行内「Pin / 取消」：3200 + 行下标
```

行下标的容量取每页条数上限即可（当前 8，留到 200 绰绰有余）。分发处三处判断改成 `id >= 基址 && id < 基址 + 容量`，容量写成具名常量，别再用"下一段基址"当上界 —— §2.1(1) 那个 bug 的根就是这个写法。

改完之后**页码按钮的数量本身也不再无限**：省略式页码一次最多渲染十来个（§3.2），1000 的容量只是兜底。

### 3.2 省略式页码 + 跳页

```
首页  <  1 … 7 [8] 9 … 250  >  末页          跳至 [    ] 页
```

规则（纯逻辑，抽成可单测的函数 `BuildPagerModel(currentPage, pageCount)` 放进 `HistoryView.h`）：

- 恒显示第 1 页与最后一页；
- 显示当前页及其前后各 1 页；
- 与两端不相邻时用省略号占位（省略号是**不可点的标签**，不是按钮，不占 id）；
- 总页数 ≤ 7 时全部平铺，不出现省略号。

「跳至第 N 页」用一个 `DuiEditHost` + 回车提交，越界夹到 `[1, pageCount]`。

### 3.3 空状态

列表为空时，`BuildListContent` 改为产出一块居中的空状态：一枚淡色图标 + 一行主文案 + 一行副文案。文案随**当前是什么把结果筛空了**变化，这比一句通用的"暂无内容"有用得多：

| 情形 | 主文案 | 副文案 |
| --- | --- | --- |
| 有关键字 | 没有找到「<关键字>」相关的消息 | 换个词，或把筛选条件放宽试试 |
| 无关键字、选了类型胶囊 | 这个会话还没有<类型>消息 | —— |
| 无关键字、选了 Pin 分类 | 还没有钉住任何消息 | 在聊天气泡上右键就能把重要消息钉在这里 |
| 什么都没选 | 这个会话还没有消息 | —— |

判定逻辑同样是纯函数（`BuildEmptyStateText(filter)`），进单测。

## 4. 列表观感与信息层次

### 4.1 行内重排

现状是「头像 ｜ 名字 ……大片空白…… 时间 ｜ 预览 ｜ Pin ｜ 定位」。改成：

```
┌────┬─────────────────────────────────────────────┬──────────┐
│ 头 │ 苏沐辰   21:31                              │ (悬停时  │
│ 像 │ 看下这个链接 https://example.com/p26        │  才出现) │
└────┴─────────────────────────────────────────────┴──────────┘
```

- **时间紧跟在名字右边**，小一号、淡一档，不再右对齐。名字与时间是同一件事的两半，拆到两端读起来要横扫整行。
- **时间只显示「HH:MM」**，日期交给分组头（§5.2）。
- 预览文字因此拿回整行宽度。
- 行高从 64 降到 **56**：两行文字（20 + 18）加上下内边距 9，头像同步 40 → 36。一屏能多出两三行。

### 4.2 连续同一人不重复头像与名字

同一分组内，**发送者与上一行相同**时省掉头像与名字，只留时间与预览，并把预览左缩进到与上一行对齐。这一判定是纯逻辑（在把 `HistoryRecord` 翻成 `HistoryRowView` 时算好，填一个 `m_compact` 标志），进单测。

注意判定要**在分组内**做：跨过日期分组头之后第一行必须重新显示头像，否则组头下面会突然冒出一条没有归属的孤儿行。

## 5. 检索体验

### 5.1 关键字高亮

新增 `BalloonHistory/HistoryHighlightLabel.{h,cpp}`：继承 `balloonui::DuiLabel`，增加一个「高亮区间」接口，绘制时先把命中那几段画成淡黄底再交给基类画字。

这一档正是仓库 UI 约定里的「次选：子类化扩展」——`DuiLabel` 能力接近但差一步，覆写最少的虚函数补齐，**不动 balloonui**。

配套纯逻辑 `FindHighlightRanges(text, keyword)` 放进 `HistoryView.h`：大小写不敏感、返回全部命中区间、空关键字返回空集。**要按 UTF-16 字符口径返回**，不是字节 —— 预览文字里有中文，按字节切会把汉字劈开。

### 5.2 按日期分组

列表里插入分组头行（`今天` / `昨天` / `2026-08-02`），分组内的行只显示「HH:MM」。

分组头是**不可点、无 id 的标签行**，高度 28。分页与分组的关系要说清楚：**分组在页内做**，不跨页合并 —— 翻到下一页时如果首行仍是同一天，那一页会再出现一次同样的组头。这是分页 + 分组的固有折中，比"跨页记住上一页最后一天"简单得多，也不会因为翻页顺序不同而出现组头忽有忽无。

日期文案的纯逻辑（`FormatDateGroupLabel(timestampMs, nowMs)`）进 `HistoryView.h` 与单测；`nowMs` 由调用方传入，便于测「今天 / 昨天」的边界。

### 5.3 搜索框

- 加提示文字：`搜索内容、文件名`
- 有内容时右侧出现清空按钮，点了清空并立即刷新

## 6. 列表交互

### 6.1 行内操作按钮改成悬停显示

新增 `BalloonHistory/HistoryRow.{h,cpp}`：继承 `DuiHBox`，覆写 `OnMouseEnter` / `OnMouseLeave`，进入时给整行铺一层极淡的悬停底色并把两枚操作按钮 `SetVisible(true)`，离开时反之。

两处要注意：

1. **按钮位置要预留**，不能靠"显示时才占位"——否则鼠标一进来预览文字就被挤短、看着抖一下。做法是按钮容器的宽度固定，只切按钮自身的可见性。
2. **已 Pin 的行例外**：那一行的「取消」按钮**常驻**。已经钉住是一个需要能一眼看见、且随时可撤的状态，藏起来反而找不到。

### 6.2 双击整行即定位

双击行的任意位置等同于点「定位」。悬停按钮之外多给一条更快的路，也照顾没注意到悬停按钮的用户。

### 6.3 已 Pin 的行在「全部」视图下也带标记

在时间右边画一枚小图钉（复用 §2.5 的 `kChatIconPin` 绘制函数）。现状只能从按钮文案是「取消」反推，等于没有标记。

## 7. 内容预览

### 7.1 图片行显示缩略图

行内左侧（头像与文字之间）加一块 40×40 的缩略图。

- 缓存路径由 `content.image.md5` 算出，走 `net/ImageTransfer.cpp:113` 的 `buildImageCachePath` —— **它现在是该 .cpp 内的 `static` 函数，要先提到 `ImageTransfer.h` 暴露出来**（纯路径拼接，不含 IO，提出来无副作用）。
- 解码与缩放走 `ChatImageCache`：命中直接画，未命中画占位方块并请求后台解码，完成回调里刷新该行。这套聊天气泡已经在用，历史窗接上即可。
- **缓存里没有原图时不下载**：历史窗是浏览界面，为了一个 40px 的缩略图去拉整张原图不划算。此时画占位方块 + `[图片]` 文字，与现状持平。

### 7.2 文件行显示类型色块与大小

把 `ChatBubble.cpp:140` 的 `FileTypeColor` 抽到共用模块（建议 `BalloonChatWnd/ChatFileVisual.{h,cpp}`，聊天气泡与历史窗共同引用），历史窗行内画 40×40 圆角色块 + 扩展名，预览文字改成「季度报告.xlsx · 1.8 MB」。

大小从 `content.file.size` 取，格式化函数复用现有的（`FileBubbleFormat.h`）。

| `Tests/HistoryViewTests.cpp` | 新增 8 个用例（V2Q-PAGER1~5、V2Q-EMPTY1~3） |

与方案的两处差异：

1. **跳页用了 `DuiSpinBox` 而不是裸 `DuiEditHost`。** 它是 balloonui 现成控件（仓库 UI 约定里的首选档），自带范围夹取与 ▲▼ 步进，越界不用自己校验。代价是手输入不会自动提交，得给内部 EDIT 单独一个 id、在它失焦时自己 `SetValue` —— 放在失焦而不是每键提交，是因为敲 "137" 的过程中会依次经过 1、13，每步都翻一次页毫无意义。
2. **空状态文案多了一档"时间范围"。** 方案 §3.3 的表只列了关键字 / 类型 / Pin / 无筛选四种，漏了时间。选了「近7天 + 图片」却搜空时，若说成"这个会话还没有图片消息"，而更早的图片其实有一堆，那就是误导。改成把时间作为"所选时间范围内"这个限定语并进类型那句。

**悬停这一件事踩了三层坑，最初的写法完全不工作，逐层记下来：**

1. **`OnMouseEnter` / `OnMouseLeave` 收不到。** `DuiHost::TrackHover` 用 `HitTopMost` 只把 enter/leave 发给<u>最深</u>的那个控件；鼠标停在行内的预览文字上时，收到事件的是那个 `DuiLabel`，行容器永远收不到。
   也**不能**靠覆写 `HitTest` 把整行截下来 —— 那样鼠标从文字移到按钮上时行会先收到 leave 把按钮藏起来，按钮就在光标底下消失了。
   最终改成**由窗口旁听 `WM_MOUSEMOVE`、按几何位置判"点在不在这一行里"**（`UpdateRowHover`），这样在同一行的各个子控件之间移动不受影响。两个消息处理器都置 `bHandled = FALSE` 只旁听不消费，否则整个界面的鼠标交互都会失灵。
2. **直接隐藏按钮会让旁边的文字撑开。** `DuiLayout` 布局时跳过不可见子控件，于是按钮那一列的宽度被预览文字吃掉，鼠标一进来文字被挤短、看着抖一下 —— 正是方案 §6.1 要避免的。改成给每枚按钮套一层固定宽度的容器：容器始终可见、占住宽度，只切里面按钮的可见性。
3. **按钮重新可见后画不出来。** `DuiControl::SetRect` 在矩形<u>没变</u>时会提前 return、连 `Layout` 都不调；而占位容器一直可见、宽度固定，它的矩形恰恰不变，于是"重新布局"的级联就断在这一层，里面刚变可见的按钮拿不到矩形。改成在切完可见性后直接对**占位容器**调 `ForceLayout`（它不做相等短路）。

## 10.7 第二轮反馈：下拉被截断 + 时间档位太少（2026-08-05）

用户按真实数据再次目检，提了两件事，都落在右上角那一块。

### 一、自定义时间区间的年 / 月 / 日下拉显示不全

现象是「2026年」被截成「202...」、「8月」被截成「8...」（`snapshots/112306.png`）。

根因是**写死像素宽度遇上高 DPI**：balloonui 的默认字体是按当前 DPI 算出来的
（`DuiResMgr`：`lfHeight = -MulDiv(9, dpi, 72)`），125% 缩放下比 100% 宽出四分之一；
而 `DuiLayout` 的 `Hint().Fixed()` 给的是**不随 DPI 变化**的像素。原先年下拉写死 76px、
月日写死 56px，在 100% 下勉强够，125% 下就不够了。`DuiComboBox` 画只读文字时还要从
控件宽度里扣掉 34px（左内边距 8 + 文字与箭头的间隙 4 + 箭头 14 + 箭头右边距 8），
剩给文字的其实只有 42px / 22px。

改法是**按实测字宽定宽**：新增 `MeasureDefaultFontWidth`（用与控件同一支默认字体量）
与 `IntComboWidth`（逐项量、取最宽的一项），再加回那 34px 与 8px 余量。「从」「到」
两个标签同样改为实测。时间下拉也一并改成实测，并保留 120px 作下限。

**过程中被单测抓出来一个真 bug**：最初写成"造下拉时顺带回填宽度、同一句里拿去
`Fixed()`"——
```cpp
row->AddChild(MakeIntCombo(..., &yearW), Hint().Fixed(yearW));   // 错
```
同一个函数调用的各实参求值次序在 C++ 里是**未指定**的，`Hint().Fixed(yearW)` 完全可能
先于回填 `yearW` 的那个实参求值，于是起始那三个下拉宽度取到 0（结束那三个因为复用已
填好的变量反而是对的）。新增的 V2L9 用例里"起止两组同名下拉应当一样宽"那两条断言当场
报出 `0 == 82`。改成**先把三个宽度全算好、再逐个 AddChild** 即可。

### 二、时间筛选增加「近 3 个月 / 近半年 / 近一年」

`HistoryTimeRange` 增加三档，并借这次把枚举值调整为**与下拉项下标一一对应**（0 起、
按界面上从上到下的顺序排，自定义排最后）。该值只在进程内使用、不落盘也不上网，改顺序
没有兼容负担；换来的是 `TimeRangeFromComboIndex` / `ComboIndexFromRange` 从两张 switch
表变成一次范围检查，再没有"下拉插了一项却忘了改 switch"这种静默筛错档的可能。

三档一律**按固定天数折算**（90 / 180 / 365 天），不做日历意义上的月份加减 —— 口径与
既有的「近 30 天」一致（30 天本来也 ≠ 一个自然月）；要精确到某年某月某日，界面上另有
「自定义」那一档。
