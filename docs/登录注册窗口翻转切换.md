# 登录窗与注册窗之间的翻转切换

> 2026-10-07。体例沿用 `docs/文件共享方案.md`：结论一律标注来源，「据实证」必附文件:行号或命令输出，「据推测」表示尚未验证。
> 每一帧怎么画、切换的先后顺序这两部分的细节写在源文件头里（`Source/UI/BalloonAuth/WindowFlipFrame.h`、`WindowFlipTransition.h`），本文汇总设计要点、接入位置与验证记录。

## 1. 需求

用户的需求清单（2026-10-06 晚至 10-07）里提出：在登录窗点「注册」弹出注册窗，或从注册窗回到登录窗时，改成翻转窗口的效果，不再是一个窗口直接消失、另一个直接出现。

## 2. 效果

- 绕竖直中线转半圈：前一半把起始窗口的画面水平压扁到 0，后一半把目标窗口的画面从 0 展开到原宽，共 350 毫秒（`kFlipDurationMs`）。
- 转动途中远离观看者的那条竖边略短，形成轻微的透视梯形（转到 90 度时短 12%，`kFlipPerspective`），画面略微压暗（最多 35%，`kFlipMaxShade`）。
- 两个窗口大小不同时，画面矩形（水平中心、上边缘、宽、高）在两者之间平滑插值：登录窗翻过去时逐渐变成注册窗的大小。注册窗摆在登录窗上边缘对齐、水平居中的位置，超出工作区时挪回工作区内。
- 打开注册窗为正向翻转，返回登录窗为反向翻转（梯形方向镜像）。

## 3. 切换顺序与退回直接切换

过渡由一个临时的分层弹出窗口完成（不进任务栏），它盖在两个窗口矩形的并集上，逐帧用 `UpdateLayeredWindow` 画出来。顺序保证任一时刻至少有一个窗口看得见、前台不会落到别的程序上：

1. 截取起始窗口与目标窗口的整窗画面（目标窗口事先在目标位置隐藏着建好、排好版）；
2. 显示并激活过渡窗口，第一帧与起始窗口一模一样，盖在它上面；
3. 隐藏起始窗口；
4. 播放翻转；
5. 显示并激活目标窗口；
6. 销毁过渡窗口。

以下情况退回直接切换（先显示目标窗口、再隐藏起始窗口）：系统关闭了「窗口内的动画」（`SPI_GETCLIENTAREAANIMATION` 为 FALSE）、起始窗口不可见或已最小化、截图或建过渡窗口失败；从注册窗返回时如果程序正在退出，也不播放。

截图的做法：balloonui 的 `DuiHost` 不处理 `WM_PRINTCLIENT`，隐藏窗口也没有屏幕内容可截，所以对窗口直接发一条 `WM_PAINT`，`DuiHost::OnPaint` 把整个客户区画进后台缓冲，再从 `DuiHost::GetBackBufferDC` 拷出。这一做法依赖 balloonui 当前的绘制实现，由用例 WF6 看住；取不到后台缓冲时只是退回直接切换，不影响功能。

## 7. 翻转结束时闪一下（2026-10-07 查实并修复）

**现象**：从登录窗翻到注册窗，翻转动画结束的一刻界面闪一下。

**原因**（据实证，`WindowFlipTests.cpp` 的 WFC 实验在用户的可见桌面上逐帧截屏，图片在 `tmp/verify7/flipcap3`～`flipcap5`）：注册窗每次都是新建的（`CBalloonRegisterWindow::RunModalFromLogin` 调 `BuildWindow`），第一次显示时系统（DWM）会播放约 300 毫秒的「打开」动画，从完全透明、略微缩小的状态淡入放大。而 `SwitchDuiWindows` 显示目标窗口之后 2～3 毫秒就销毁了过渡窗口，于是那块区域先露出后面的桌面（翻转后约 40 毫秒的截图里注册窗完全不可见），再慢慢浮现出注册窗。对照组排除了其它可能：

| 做法（每组新建一对窗口） | 目标窗口显示后与最终画面差异明显的帧数 |
| --- | --- |
| 现状（四轮共跑了四次） | 5～8 帧，最高差异约 205（0～255） |
| 只关掉过渡窗口的 DWM 动画 | 5 帧，照样闪 |
| 关掉登录窗与注册窗的 DWM 动画 | 0 |
| 同一对窗口的第二次翻转（窗口已显示过） | 0 |
| 销毁过渡窗口之前先等一次桌面合成（第一轮） | 与只关动画的结果相同，等合成本身没有作用 |
| 修法：盖上过渡窗口时关掉注册窗的动画，注册窗一显示就恢复（两次） | 0 |
| 翻回登录窗的方向（现状；登录窗此前显示过） | 0，本来就不闪 |

实验要点：测试程序从后台启动，系统不允许它抢前台，窗口会被压在终端后面，所以每组开始前先把起始窗口切到前台（`WfcBringToFront`）；DWM 的打开动画只在窗口第一次显示时播放，对照组必须每组新建窗口。

**修法**（2026-10-07 用户选定「只在切换时关掉动画」）：`SwitchDuiWindows` 在播放翻转时，`flip.Begin` 成功之后用 `DwmSetWindowAttribute(DWMWA_TRANSITIONS_FORCEDISABLED)` 关掉目标窗口的 DWM 窗口动画，`ShowAndActivate` 之后立即恢复；最小化、关闭等其它系统动画不受影响。直接切换（不播放翻转）没有过渡窗口，不改动画设置。开关函数可经 `SetFlipTransitionSwitchForTest` 替换，用例 WF9 断言调用时机。

**修后实机复核**（2026-10-07）：用户在本机显示器上仍觉得翻转结束时闪一下。以 `tmp/verify7/fliprec.py` 每秒约 60 次录下真实客户端的正反两次翻转（范围含窗口四周 60 像素），过渡窗口销毁之后画面与最终画面完全相同，打开动画的问题已消除；用户看到的是翻转过程中卡片四周露出后面的画面，记为 `bugs.md` BUG-123，用户决定暂不处理。
