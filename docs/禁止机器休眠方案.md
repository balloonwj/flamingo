# 「禁止机器休眠」技术方案

> 作者：balloonwj@qq.com　功能开发日期：2026-08-12　本文撰写日期：2026-09-30
> 用途：记录 PC 客户端「系统设置 → 通用 → 禁止机器休眠」的需求范围、实现机制、生命周期、与「自动离开」的互斥关系、代码位置与验证方法。

---

## 1. 需求与范围

开启后，在客户端保持登录期间，本机做到三件事：

1. **不自动休眠**（系统睡眠）；
2. **不自动关闭显示器**；
3. **不自动启动屏幕保护程序、不自动锁屏**。

典型场景是演示、长时间传输文件等需要本机一直亮着的临时情形，因此**默认关闭**。

范围约定：

- **只在已登录时生效。** 停留在登录界面的客户端没有理由阻止整台机器休眠，即使开关是开着的也不生效。
- **只阻止"自动"发生的休眠、关屏与锁屏。** 用户手动锁屏（Win+L）不受影响；已经启动的屏保或已经锁定的屏幕也不会被唤醒。
- 断线重连期间仍然保持：判断依据是「本进程已登录」，而不是「连接是否就绪」（见 3.3 节）。

---

## 2. 为什么需要两套机制（据实证）

Windows 上"不休眠 / 不关屏"与"不锁屏"由两套互不相干的机制控制。2026-08-12 用 `tools/keepawake_probe.ps1` 在本机实测（判读方法见 `tools/README.md`），结论记录在 `KeepAwakePolicy.h` 头注释中：

| 实测项 | 结果 |
| --- | --- |
| 持有系统电源请求期间，`GetLastInputInfo` 报出的输入空闲时长 | 仍从 0 递增到 15 秒，**电源请求不影响输入空闲计时器** |
| 屏保超时设为 60 秒，静置 90 秒 | 屏保如期启动 |
| 同样设置下，每 20 秒合成一次零位移鼠标移动，观察 100 秒 | 空闲时长始终不超过 15 秒，屏保一次都没有启动 |
| 屏保已经启动之后再合成输入事件 | 屏保仍在运行，合成输入不会唤醒屏幕 |

屏幕保护程序与自动锁屏依据的正是输入空闲计时器，所以只申请电源请求挡不住锁屏。本功能因此由两部分组成：

- **系统电源请求**：阻止休眠与关闭显示器；
- **周期性合成输入事件**：把输入空闲计时器清零，阻止屏保与自动锁屏。

## 3. 实现

### 3.1 阻止休眠与关屏：系统电源请求

实现在 `CKeepAwakeSession::Acquire` / `Release`（`flamingoclient/Source/UI/BalloonMain/KeepAwakeSession.cpp`）。

- **首选 `PowerCreateRequest` + `PowerSetRequest`**（Windows 7 起提供），分别设置 `PowerRequestSystemRequired`（阻止休眠）与 `PowerRequestDisplayRequired`（阻止关屏），两项缺一不可：只设置前者时显示器仍会关闭。
  - 它是进程级的，不绑定调用线程；
  - 管理员执行 `powercfg /requests` 时能看到是哪个程序、以什么理由阻止休眠。理由字符串为「FlamingoIM：用户开启了「禁止机器休眠」」，便于企业环境排查"这台机器为什么不休眠"。
  - 两项中只要有一项设置成功就视为持有，并在日志中分别记录两项的结果。
- **回落到 `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED | ES_DISPLAY_REQUIRED)`**：当 `PowerCreateRequest` 失败，或两项 `PowerSetRequest` 都失败时使用。它绑定在调用线程上，因此 `CKeepAwakeSession` 只能在主线程使用（定时器与消息处理都在主线程）。
- **释放**：`PowerClearRequest` 两项后关闭句柄；回落路径则调用 `SetThreadExecutionState(ES_CONTINUOUS)` 撤销。析构函数也会释放一次，作为最后保障。

### 3.2 阻止屏保与自动锁屏：合成零位移鼠标移动

实现在 `CKeepAwakeSession::Nudge`。

- 用 `SendInput` 合成一个 `MOUSEEVENTF_MOVE`、`dx = dy = 0` 的鼠标移动事件：光标不会移动，不会投递到任何窗口，也不会被识别为点击，但足以把 `GetLastInputInfo` 的空闲时长清零。
- **不合成按键**：按键会真实投递给前台窗口，可能触发其它程序的快捷键。
- **合成间隔 25 秒**（`kKeepAwakeNudgeIntervalMs`，`KeepAwakePolicy.h`）。间隔的上限受屏保与锁屏超时约束：Windows 界面上可设置的最短超时是 1 分钟，间隔必须明显小于它。驱动它的定时器是 30 秒一次，所以实际上每次定时器触发都会合成一次；保留独立的间隔常量，是为了让合成频率与定时器周期解耦，将来定时器改成更短周期时合成频率不会随之升高。

### 3.3 触发时机与生命周期

本功能没有自己的定时器，复用「自动离开」控制器每 30 秒一次的定时器（`kAutoAwayPollIntervalMs`，`MainPanelAutoAwayController.h`）。每次触发时 `CAutoAwayController::CheckKeepAwake` 装配输入，交给纯函数 `DecideKeepAwake`（`KeepAwakePolicy.cpp`）判定，再按结果执行：

| 条件 | 判定结果 | 执行的动作 |
| --- | --- | --- |
| 开关关闭或未登录，且当前未持有 | `kKeepAwakeNone` | 不做任何事（默认状态，绝大多数时候走这里） |
| 开关关闭或未登录，且当前持有 | `kKeepAwakeRelease` | 释放电源请求 |
| 开关开启且已登录，当前未持有 | `kKeepAwakeAcquire` | 输出一次系统空闲策略快照，获取电源请求，成功后**立即合成一次输入** |
| 已持有，从未合成过或距上次合成满 25 秒 | `kKeepAwakeNudge` | 合成一次输入 |
| 已持有，距上次合成不足 25 秒 | `kKeepAwakeNone` | 不做任何事 |

几个细节：

- **获取后立即合成一次**：否则首次合成要等满一个间隔，这段时间足以让超时较短的锁屏策略生效。
- **经过时长用 `ComputeIdleMs` 计算**（`AutoAwayPolicy.h`），它已处理好 tick 回绕（开机约 49.7 天后 `GetTickCount` 归零）。
- **"已登录"取 `ISessionStateHost::IsLoggedIn`**，即会话控制器的 `m_bAlreadyLogin`：登录成功置真，退出登录或被踢下线回到登录窗时置假（`MainPanelSessionController.cpp` 的 `ReturnToLoginWindow`）。没有用 `IsSessionEstablished`，因此网络断开、自动重连期间仍然保持，不会因为一次掉线就让演示中的机器进入休眠。
- **生效时延**：设置里拨动开关只改配置，不直接调用 Win32 API；控制器每次触发都重新读取配置，所以开启或关闭后**最多 30 秒**生效。退出登录后同理，下一次触发时释放。主面板在退出登录时不销毁，只是隐藏，定时器仍在运行；登录窗的模态循环用 `GetMessage(&msg, NULL, 0, 0)` 派发本线程的全部消息（`BalloonLoginDlg.cpp`），定时器消息照常送达。
- **退出程序时立即释放**：主面板销毁时调用 `CAutoAwayController::Shutdown`，其中释放电源请求；`CKeepAwakeSession` 析构时也会再释放一次。

## 4. 与「自动离开」互斥

合成输入会把全系统的输入空闲计时器清零，而「自动离开」正是依据这个计时器判定"电脑多久没人操作"，两者不可能同时成立。2026-08-12 与用户确认的处理方式：

- **开启禁止休眠期间，自动离开一律不生效。** `CAutoAwayController::BuildAutoAwayInput` 把 `m_enabled` 取为「自动离开开关为开 且 禁止休眠开关为关」。空闲轮询和锁屏 / 解锁两条触发路径都经过这里，因此都不会切换在线状态。
- **设置页把「自动离开」两行置为禁用**（开关与等待时长下拉框），副标题换成「已开启「禁止机器休眠」，自动离开暂不生效」（`CBalloonSystemSettingDlg::ApplyKeepAwakeExclusion`）。打开设置窗时按当前配置设置一次，拨动禁止休眠开关时再设置一次。
- **不修改自动离开的配置值**，开关也停在原位置，仅整行变淡。关闭禁止休眠后自动离开原样恢复，不丢失用户此前的选择。
- **互斥是单向的**：只有禁止休眠会禁用自动离开，反过来不限制。自动离开默认开启，若反向也加限制，用户要使用禁止休眠就得先去关掉自动离开。

## 7. 日志

日志一律用英文（开发约定文档「代码规范」第 15 条），`CKeepAwakeSession` 的日志以 `keep-awake:` 开头，可用 `findstr keep-awake Logs\*.log` 一次检索。开启后应当依次看到：

```
keep-awake: idle policy snapshot - screensaverActive=1, screensaverTimeout=600 sec, screensaverSecure=1, inactivityPolicy=-1 sec (-1 means not configured).
keep-awake: power request acquired (handle 0x..., systemRequired=1, displayRequired=1).
keep-awake: synthesized a mouse move, system idle 12 sec before it, SendInput returned 1.
keep-awake: synthesized a mouse move, system idle 30 sec before it, SendInput returned 1.
...
keep-awake: power request released.
```

（上面的数值为示意。）

- **策略快照**只在获取时输出一次，记录屏保是否启用、屏保超时、屏保恢复是否要求密码，以及组策略「交互式登录: 计算机不活动限制」（`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\InactivityTimeoutSecs`）。有了它，事后看日志就知道被测机器当时几分钟会锁屏。
- **合成日志**每次都输出，其中"合成前空闲秒数"应当稳定在一个定时器周期左右；若持续增长，说明合成没有生效。开启期间约每 30 秒一条，即每小时约 120 条。
- **锁屏是否真的发生过**看自动离开控制器输出的会话事件日志：`session event: code=0x7, ... keepAwake=1, holdingPowerRequest=1, ...`。`0x7` 是 `WTS_SESSION_LOCK`。开启本功能静置一段时间后，日志中没有出现这一条，就是锁屏被阻止的直接证据。

2026-09-30 之前，`CKeepAwakeSession` 的日志是用 `_T("中文")` 写的，落盘为 GBK 编码，与同一文件里其它 UTF-8 日志混在一起；当天已改为英文。

## 8. 测试与验证

**单元测试**（`Tests/KeepAwakePolicyTests.cpp`，标签 `[keepawake]`）：

| 编号 | 场景 |
| --- | --- |
| KA1 | 开关关闭且未持有时不执行任何动作 |
| KA2 | 开关关闭后释放电源请求 |
| KA3 | 未登录时不占用电源请求 |
| KA4 | 开关开启且已登录时获取电源请求 |
| KA5 | 距上次合成不足一个间隔时不重复合成 |
| KA6 | 距上次合成满一个间隔即再次合成 |
| KA7 | 从未合成过时立即合成 |
| KA8 | tick 回绕时仍能算出正确的经过时长 |

**Win32 行为**：没有单元测试，用 `tools/keepawake_probe.ps1` 验收（第 2 节的实测数据即来自它）。

**真实客户端端到端验证**：

1. 登录后在「系统设置 → 通用」打开「禁止机器休眠」，等待 30 秒左右；
2. 以管理员身份执行 `powercfg /requests`，SYSTEM 与 DISPLAY 两项下都应出现本程序，理由为「用户开启了「禁止机器休眠」」；
3. 客户端日志中应有 `keep-awake: power request acquired`，之后约每 30 秒一条 `keep-awake: synthesized a mouse move`；
4. 静置超过系统的屏保 / 锁屏超时，不应锁屏，日志中也不应出现 `session event: code=0x7`；
5. 关闭开关，等待 30 秒左右，日志中应有 `keep-awake: power request released`，再执行 `powercfg /requests`，本程序应已消失；
6. 再打开开关后退出登录，同样应在 30 秒左右内看到释放日志。

截至 2026-09-30，`flamingoclient/Bin/Logs` 下的日志中没有任何一次获取电源请求的记录，即上述端到端流程尚未在这台机器的真实客户端里走过。

## 9. 已知边界

- **手动锁屏不受影响**：Win+L 照常锁屏；此时自动离开也不会因为锁屏切到离开（见第 4 节）。
- **不唤醒已经启动的屏保或已锁定的屏幕**（据实证，见第 2 节）。
- **合成输入是全系统的**：本机其它依据输入空闲时长工作的程序（例如其它软件的"无操作自动离开"）在此期间也会认为有人在操作。这是该机制本身的副作用，无法只对本程序生效。
- **据推测**，电源请求只阻止系统"自动"进入休眠，用户合上笔记本盖子、按电源键或选择"睡眠"时仍会休眠（这是 Windows 电源请求的设计，未在本项目中实测）。
- **据推测**，合成输入也能推迟组策略「计算机不活动限制」触发的锁屏，因为它同样依据输入空闲计时器；尚未在配置了该组策略的机器上实测。策略快照日志会记录该组策略的取值，便于日后排查。
- **据推测**，前台是以更高权限运行的程序（例如以管理员身份运行的窗口）时，`SendInput` 可能被 Windows 的界面权限隔离拦截，而且此时返回值不一定报告失败；若真实环境中出现"开着禁止休眠仍然锁屏"，可以先从合成日志里的空闲秒数是否持续增长来判断是不是这个原因。未实测。
- **进程异常退出**：据推测，系统会随进程结束回收电源请求句柄与线程执行状态，不会让机器一直无法休眠；未实测。
