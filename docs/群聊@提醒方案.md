# 群聊 @提醒 方案与开发计划

> 作者：balloonwj@qq.com　起草日期：2026-07-31
> 用途：记录给 flamingoclient 群聊接入「@某人 / @所有人」的整体方案、展示规格、分期路线与开发步骤。后续每步开工前据此细化、收尾后回填实际结果。

---

## 1. 背景与目标

群聊里点名某人时，需要一个能被对方明确感知的提醒机制：发送方在输入框里选人插入 `@昵称`，接收方在气泡里看到高亮的 `@昵称`，被点名的人还要在托盘和会话列表上被单独提示。

最终形态包含 @某人、@所有人、离线期间的「有人@我」补标、以及跳转到被 @ 那条消息。按风险从低到高分期推进，第一期只做「@某人」的完整闭环，且不改服务端。

## 2. 现状盘点（据实证，均已核对代码位置）

本节记的是 2026-07-31 起草时的代码现状，行号只对当时的代码成立。

### 2.1 服务端把 content 当成不透明 JSON —— 第一期不用改服务端

`flamingoserver/chatserversrc/MessageProtocol.cpp:117-119` 只校验 `content` 是个 JSON 对象，随后 `req.content = writeCompact(root["content"])` 整块收下；存库（`:196`）与推送（`:167`、`:178`）都原样回填。服务端唯一会往 `content` 里看一眼的地方是 `buildMessageDigest`（`:252-291`），且只取 `text` 字段做会话预览。

**结论：把 @ 信息放进 `content` 的新字段，消息的收发、存储、多端同步全部无需服务端改动。** 只有「离线期间的 @我 标记」这一项才真正需要动服务端（见 §7.3）。

### 2.2 群聊输入框是富文本，可直接着色

群聊输入框是 `ChatInputRichEdit`（`UI/BalloonChatWnd/ChatInputRichEdit.h`），即 balloonui 无窗口富文本控件 `DuiRichEdit` 的聊天定制子类，构建位置在 `UI/BalloonChatWnd/BalloonGroupChatWindow.cpp`。它支持按选区设字符格式：`EM_SETCHARFORMAT` 这类编辑命令由控件转发给排版引擎，参数含义与直接向真子窗口发消息时完全一致。回车发送、「正在输入」通知、以及 @ 提醒的键盘与滚轮转发也都由这个子类自己处理，**着色不需要改 balloonui**。

### 2.3 「@提醒」按钮已经存在

`UI/BalloonChatWnd/GroupMentionButton.h` —— 群聊输入工具栏右侧的白底圆角描边小按钮，对照设计稿 08 的 Composer。入口是现成的，缺的是点击后的行为。

### 2.4 群成员数据是现成的

群聊窗持有 `m_memberInfo`（`std::map<int64_t, MemberInfo>`，`BalloonGroupChatWindow.h:525`），由 `OnGroupMembersArrived` 从 `cmd_get_group_members` 应答填入。成员项结构见 `net/GroupProtocolClient.h:69-85`：`m_userid` / `m_role`（0 成员 1 管理员 2 群主）/ `m_card`（群名片）/ `m_nickname` / `m_facetype` / `m_customface`。

显示名规则：优先群名片 `m_card`，为空则退到 `m_nickname`。

### 2.6 现有气泡配色

`ChatBubble.cpp` 的气泡配色常量：

| 常量 | 值 | 用途 |
| --- | --- | --- |
| `kBubbleOther` | `#F3F2EF` | 对方气泡底（浅灰） |
| `kBubbleSelf` | `#FFE6D8` | 自己气泡底（浅橙） |
| `kAccent` | `#FF7A45` | 主题橙 |
| `kBubbleText` | `#2A2A2A` | 气泡文字 |

两种气泡底都是浅色，文字都是深灰。这意味着 @ 底色块两种情形都做得了，只是自己气泡（浅橙底）上的橙色块要压深一档才拉得开层次。

### 2.7 会话预览由服务端计算

`cmd_sync_conversations` 应答里每条会话的 `lastmsg.digest` 由服务端 `buildMessageDigest` 生成（`MessageProtocol.cpp:317`）。因此**离线期间收到的 @ 消息，重新登录同步会话列表时拿不到「@我」标记**，需要客户端在拉历史时自行补，或改服务端（§7.3）。

## 3. 协议设计

文本消息的 `msgtype` 保持 `message_type_text`（1）不变，在 `content` 里新增可选的 `at` 对象：

```json
{
  "text": "@张三 @李四 明天十点开会",
  "at": {
    "all": 0,
    "users": [
      { "uid": "10001", "off": 0, "len": 7 },
      { "uid": "10002", "off": 8, "len": 7 }
    ]
  }
}
```

字段含义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `at.all` | int | 1 = @所有人；0 或缺省 = 否 |
| `at.users[].uid` | string | 被 @ 的 userid，字符串编码（与 `cid` / `msgid` 的既有约定一致，避免大整数精度问题） |
| `at.users[].off` | int | 该 `@显示名` 片段在 `text` 里的起始偏移，**UTF-8 字节** |
| `at.users[].len` | int | 该片段的长度，**UTF-8 字节** |

三条约定：

1. **偏移用 UTF-8 字节**，因为 `text` 在协议里就是 UTF-8，字节口径跨端最稳，不依赖任何一端的字符串内部表示。
2. **`@` 符号计入片段，其后的分隔空格不计入。** 即 `@张三` 是片段，`@张三 ` 的尾随空格在片段之外。
3. **「是否被 @」只看 `uid`，不看文本。** 这样群名片改了、群里有同名成员，判定都不受影响；`off` / `len` 只服务于显示高亮。

`at` 字段缺省时表示本条不含 @，与老版本客户端完全兼容（老客户端不认识 `at`，只显示纯文本，功能降级但不出错）。

## 4. 客户端数据流

```
收到 cmd_message_notify
  → MessageProtocolClient::parseMessageNotify 解析出 MessageNotify::m_ats（UTF-8 字节偏移）
  → 群聊窗组装 ChatMessage 时换算成 ChatMessage::AtSpan（UTF-16 字符下标）并算好 isMe
  → ChatBubble 只管按 AtSpan 画高亮，不再关心身份
```

`ChatMessage`（`UI/BalloonChatWnd/ChatMockData.h`）新增字段：

```cpp
// 本条文本消息里的 @ 片段（按出现顺序）。空 = 本条不含 @，气泡走原有的整段
// DrawText 快路径与渲染缓存，一行都不变。
struct AtSpan
{
    int64_t uid;    // 被 @ 的人 userid；0 表示 @所有人
    int     off;    // 片段起始位置（UTF-16 字符下标）
    int     len;    // 片段长度（UTF-16 字符数）
    bool    isMe;   // 被 @ 的是不是本人 —— 决定用橙色还是蓝色
};
std::vector<AtSpan> ats;
```

**两套偏移口径的分工**：协议侧用 UTF-8 字节（跨端稳定），渲染侧用 UTF-16 字符下标（气泡的字符级排版按 `WCHAR` 计数）。换算只在「协议结构 → ChatMessage」这一处做，是纯函数，可单测。

`isMe` 也在组装时算好，气泡拿到的是纯展示数据，符合 `ChatMessage` 现有定位。

## 5. 展示规格

### 5.2 配色（两种气泡底 × 两种 @ 类型）

| | @我 | @别人 |
| --- | --- | --- |
| **对方气泡**（`#F3F2EF` 浅灰底） | 底 `#FFDDCB`，字 `#D9531E` | 底 `#E4EEFB`，字 `#2F6FD0` |
| **自己气泡**（`#FFE6D8` 浅橙底） | 底 `#FFC9AE`，字 `#B8431A` | 底 `#E4EEFB`，字 `#2F6FD0` |

设计意图：**@我 走主题橙系**，与品牌色一脉相承、最醒目；在浅橙气泡上把底色压到 `#FFC9AE`、文字压到 `#B8431A`，才能从 `#FFE6D8` 的底上浮出来。**@别人 走中性蓝**，明确是个 mention 但不抢戏，两种气泡底共用同一套——蓝块落在浅橙底上略跳，但正因为跳才一眼能与「@我」区分。

> 这几个值由 `kAccent` 与两个气泡底派生，S3 出四格对照图目视后按此定稿，实机效果与对照图一致，未再调值。

### 5.3 几何

- 底色块为圆角矩形，圆角半径 **3px**。
- 相对文字区域上下各外扩 **1px**、左右各外扩 **2px**。
- 高亮区间是 `@显示名` 本身，尾随分隔空格不计入。
- **底色块不参与折行计算** —— 只叠在文字下方并向外溢出 2px，不改变文字排布。因此 `Measure()` 的折行测量与缓存逻辑一行都不用动。气泡本身有内边距，2px 溢出不会顶到边。
- 绘制顺序：先铺所有底色块，再画文字。

## 6. 输入侧交互

**触发**：在输入框键入 `@` 时弹出成员选择浮层。检测由输入框控件 `ChatInputRichEdit` 在自己的字符与按键处理函数里完成，命中后按既有约定投一条自定义消息给聊天窗，不改 balloonui。「@提醒」按钮（`GroupMentionButton`）点击时等价于插入一个 `@` 并弹浮层。

**浮层**：仿 `UI/BalloonSearch/SearchDropdown` 做一个 `GroupAtDropdown` —— 它已经是成熟的独立顶层浮窗（`WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`、通知自路由、失焦收起），这些坑都趟过了。落点必须经 `balloonmain::ClampPopupMenuToWorkArea` 夹取（开发约定文档的菜单不越屏规则）。

**数据源**：`m_memberInfo`。列表顶部按需插入「@所有人」：谁能看到由群设置「谁能 @ 全体成员」（`atallscope`，0 仅群主和管理员、1 所有人，见 `docs/群管理接入方案.md`）决定，客户端判定 `CanMentionAll(role, atAllScope)`，服务端 `GroupProtocol::canMentionAll` 按同一口径校验。支持键入前缀过滤。

**插入**：往 RichEdit 插 `@显示名 `（含尾随空格），选中该段发 `EM_SETCHARFORMAT` 设成主题橙，随后**把插入点之后的格式恢复成默认**——否则用户接着打字会一路继承橙色。同时在窗口侧记一条 @ 记录（uid + 显示名）。

**发送前重扫**：以输入框最终文本为准，重新扫描 `@显示名` 片段、重算偏移，扫不到的记录直接作废。这样即使用户把 `@张三` 删掉一半、或在中间插了字，发出去的数据也不会错。第一期因此**不做退格原子删除**，靠重扫兜底。

## 7. 提醒链路

### 7.1 在线收到

`BalloonGroupChatWindow::OnRecvGroupMessage` 解析出 `m_ats`，判定是否含本人 uid（或 `at.all` 为真）。命中则：

- 托盘闪发送方头像 —— 复用现有 `PostTrayFlash`。
- 会话列表该行预览文字前加 `[有人@我]`。
- 未读角标照常。

### 7.2 会话列表的展示

会话列表的预览文字前加纯文本前缀 `[有人@我] `（S5 实现，前缀由 `AtMeDigestPrefix()` 生成），不做局部染色。

### 7.3 离线补标（二期）

因 §2.7，离线期间的 @ 消息在会话列表同步时拿不到标记。两条路：

- **客户端补**（一期采用）：拉历史消息（`cmd_sync_messages`）时自行扫描 `at` 列表。够用，前提是拉到了那条消息。
- **服务端补**（二期）：在 `ConversationBrief` 里加 `atme` 字段，服务端按 `lastcontent` 扫或在库表里记。需要改服务端与库表。

## 8. 分期

**第一期（不动服务端）**：协议 `content.at` 的构造与解析、气泡高亮展示、输入框 @ 触发与成员浮层、发送前重扫、在线「@我」的托盘与会话列表提示。

**第二期**：@所有人（含服务端权限校验，已完成，权限按群设置 `atallscope`，见 §6）、离线「@我」标记（服务端 `atme`）、退格整体删除一个 @ 片段、「有人@我」的聚合跳转胶囊。

**实现期踩到的坑（本功能自身引入，已修复）**

1. **本进程没有全局 `GdiplusStartup`，Measure 阶段 GDI+ 尚未初始化。** 各模块按仓库既有
   做法各自惰性初始化（`ChatImageCache.cpp` / `AvatarImageUtil.cpp` / `BalloonAboutDlg.cpp`）。
   `ChatBubble.cpp` 此前用 GDI+ 只发生在<u>绘制阶段</u>，那时别的模块已经初始化过了；而
   @提醒 的排版在 `Measure()`（<u>布局阶段</u>）就要用 GDI+，比任何绘制都早。此时
   `Graphics` / `FontFamily` 状态为 `GdiplusNotInitialized(18)`，且 **`new Gdiplus::Font`
   会返回空指针而不是抛异常**（`GdiplusBase::operator new` 内部调 `GdipAlloc`，失败即返回
   NULL，构造函数根本不执行），表现为气泡尺寸为 0、一个字都画不出来。修法是在本文件加
   一份同款惰性初始化 `EnsureGdiplusForBubble()`，在用 GDI+ 画 @ 的入口调用（现为 `DrawMentionBlocks`）。

   > 这一条对后续在<u>布局阶段</u>使用 GDI+ 的代码都成立，不限于 @提醒。

  之后的格式恢复默认**（否则用户接着打的字会一路继承橙色），再记一条候选。

**「@提醒」按钮已接线**

点击等价于在光标处敲一个 `@`：往输入框插入 `@` 再投一条 `kMentionChangedMsg`，之后
完全走手敲 `@` 的同一条路径 —— 不让按钮和键盘各自演化出一套逻辑。

**实现期踩到的三个坑（均为本功能自身引入，已修复）**

1. **`DuiListBox::SetCurSel` 的 `notify` 默认是 true。** 浮层弹出时程序化设默认高亮
   会发出 `DUIN_VALUECHANGED`，被当成"用户选中"当场提交，插入又改动文本、触发重算、
   再弹浮层……绕成死循环，表现为"输入 @ 直接选中一个名字 + 列表闪烁"。
   修法：本类所有程序化 `SetCurSel` 一律传 `notify=false`。
2. **`DuiListBox::SetCurSel` 只在选中项<u>变化</u>时才发通知**（`DuiListBox.cpp:269`）。
   默认高亮第一项后，用户点的正是第一项 → 选中没变 → 一条通知都不发 → 点了没反应。
   修法：按开发约定文档「次选：子类化扩展」子类化出 `AtMemberList`，只覆写 `OnLButtonUp`
   一个虚函数，在鼠标抬起时<u>无条件</u>补发一条自定义码 `DUIN_AT_ROW_PICKED`。
   行号直接读基类已设好的 `GetCurSel()`（`IndexFromPoint` 与滚动偏移都是私有的）；
   选在<u>抬起</u>时提交，因为提交后浮层立刻隐藏，若在按下时提交，这次点击的抬起会落到
   浮层底下的窗口上造成误触。
3. **`WS_EX_NOACTIVATE` 只阻止窗口被"激活"，<u>不阻止它在被点击时拿走键盘焦点</u>。**
   实测点浮层时 `GetFocus()` 从输入框变成浮层窗口，宿主随即收到
   `WM_ACTIVATE(WA_INACTIVE)`，"失活就收起浮层"的逻辑在鼠标<u>按下</u>那一刻把浮层藏掉，
   抬起自然落空 —— 表现为"列表点不动"。
   修法：浮层处理 `WM_MOUSEACTIVATE` 返回 `MA_NOACTIVATE`（下拉 / 工具条类窗口的标准
   做法），焦点始终留在输入框；`WM_ACTIVATE` 的收起逻辑再补一条"对方窗口是本浮层则
   不收起"作兜底。

   > 这三条里第 3 条最值得记：查它的过程说明**这类交互问题必须用真实鼠标复现**。
   > 用 `SendMessage` 投递鼠标消息不会引起焦点变化，整条链路看着完全正常。

**为便于自测所做的改动**

`--groupchatwindow` 调试入口现在会用 `MockGroupMembers()` 填 `m_memberInfo`（uid 用
1000+ 下标占位），使 @ 浮层在无服务器、未登录时也能弹出、可点、可插入。否则这条交互
只能登录进真实群才验得了，每改一次都要手工重来一遍。

### S5 收尾回填（2026-07-31）

`UI/BalloonMain/BalloonMainPanel` 收到群消息（`OnRecvChatMessage` 的 `ctype==2` 分支）时判定是否 @ 到本人：
`IsMentioningMe(notify.m_ats, notify.m_atAll, selfId)`，并排除"自己在别端发出、同步回来"的消息。

命中时做两件事：会话列表的预览文字加 `[有人@我] ` 前缀；托盘照常闪该群头像，**且突破
消息免打扰**。后者是有意为之 —— 群消息免打扰的本意是"别为每条群聊都打扰我"，而点名到
我头上的那条恰恰是设了免打扰也想知道的。提示音仍受全局静音位约束，未放开。

**第一期到此闭环**：输入 → 发送 → 接收 → 气泡高亮 → 托盘与会话列表提醒全部打通，且
一行服务端代码都没改。

### 第二期：@所有人 的协议与纯逻辑（2026-07-31，UI 未接）

协议层其实在 S2 就已经带上了 `at.all`，本轮补的是纯逻辑与语义。UI 侧（浮层里那一项、
按角色显隐）后来已接上：群聊窗按 `CanMentionAll` 决定浮层里是否出现「@所有人」。

- `kMentionAllNameUtf8` = "所有人"（写成显式 UTF-8 转义，理由见常量注释：它要参与
  文本匹配，源文件编码一旦被改写会静默失配）。`kMentionUidAll` 沿用 0。
- `CanMentionAll`：当时只有群主与管理员可用。@所有人 会给全群每人推一次提醒，
  放开给普通成员等于把打扰全群的权力交给任何人。**这是客户端侧的先行拦截，不能作为
  唯一防线**。现在的签名是 `CanMentionAll(role, atAllScope)`，按群设置 `atallscope`
  决定（见 §6）；服务端 `GroupProtocol::canMentionAll` 已按同一口径校验。
- **修正了一处语义**：`ConvertSpansForRender` 原来"整条带 atAll 就把所有片段都标成
  @我色"，这是错的 —— "@所有人 @张三 辛苦了"里那句 `@张三` 说的是张三、不是我。
  改为**逐片段独立判定**：该片段 uid 等于本人、或它就是「@所有人」那一段，才算 @ 到我。
  `atAll` 参数随之从该函数移除（消息级的判定仍由 `IsMentioningMe` 承担）。
- `IsMentioningMe` 增加一条防御：片段里出现 uid=0（@所有人）即命中，不依赖对端一定把
  `all` 标志位写对。

测试补到 30 个用例、108 条断言（`[mention]`），含角色权限、`@所有人` 的重扫、与具体成员
并存、逐片段 isMe 判定、标志漏写的兜底、以及 `all=1` 的协议往返。全量 839 个用例通过。

## 10. 测试用例清单（S1 / S2）

**偏移换算**

1. 纯 ASCII 文本，UTF-8 字节偏移与 UTF-16 字符下标一致。
2. 纯中文文本，1 汉字 = 3 UTF-8 字节 = 1 UTF-16 字符，换算正确。
3. 中英混排，`@张三` 出现在中文之后，偏移正确。
4. 含 emoji（BMP 外字符，UTF-8 4 字节 = UTF-16 2 个代理项）时换算正确。
5. 偏移越界 / 长度越界时安全返回，不崩、不越界读。

**文本扫描**

6. `@张三 你好` 扫出 1 个片段，偏移 0、长度为 `@张三` 的字节数。
7. `@张三 @李四 开会` 扫出 2 个片段，偏移各自正确。
8. 文本被改成 `@张 你好`（名字被删了一半）时，原记录扫不到、应作废。
9. 同名成员各自的记录按 uid 区分，不互相串。
10. 文本中出现邮箱等含 `@` 但非 mention 的内容时不误判。

**是否@我**

11. `users` 含本人 uid → 命中。
12. `users` 不含本人 uid → 不命中。
13. `all=1` → 命中（无论 users 是否含本人）。
14. `users` 为空且 `all=0` → 不命中。
15. 本人 uid 为 0（未登录态）时不命中，不崩。

**协议往返**

16. 构造带 2 个 @ 的 content，解析回来字段一致。
17. 不带 `at` 字段的 content 解析后 `m_ats` 为空，不报错（老版本兼容）。
18. `at` 字段类型异常（`users` 不是数组、`uid` 不是字符串）时安全降级为空，不崩。
