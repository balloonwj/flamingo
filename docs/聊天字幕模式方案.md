# 聊天字幕模式方案

PC 客户端的单聊窗、群聊窗各加一个「字幕模式」按钮。开启后，桌面上出现一条类似「桌面歌词」的字幕，对方每发来一条消息，字幕就显示「某某说：内容」。外观参照 `snapshots/t1.png`（锁定：透明底、带描边的文字、鼠标点击穿透）与 `snapshots/t2.png`（解锁并悬停：半透明深色底、上方一排工具按钮）。

- 提出与方案确认：2026-10-05。
- 开发状态：见第 6 节「开发进度」（随进度更新）；接手说明见第 7 节。

---

## 1. 已确认的决定

以下七项由用户逐项确认（2026-10-05），实现时不要更改。

| # | 事项 | 决定 |
| --- | --- | --- |
| 1 | 进入字幕模式时聊天窗怎么办 | **聊天窗保持不动**。字幕上的「回到聊天窗」只把聊天窗提到前台（最小化时先还原）；「退出」只退出字幕模式，不碰聊天窗。主面板的 `OpenSingleChat` / `OpenGroupChat` 不用改。窗口抖动沿用现有行为（照常把聊天窗调到前台） |
| 2 | 字幕上显示过的消息算不算已读 | **显示过就算已读**：聊天窗处于字幕模式时，新消息不记未读，并照常上报已读位点（单聊对方会看到「已读」） |
| 3 | 共享屏幕、录屏时字幕的去留 | 做成 ⚙ 菜单里的开关「共享屏幕或录屏时隐藏字幕」，**默认关闭（默认不排除）** |
| 4 | 多个会话同时开字幕 | **每个会话各一条字幕**。位置、宽度、锁定状态按会话记；字号、行数、上述开关按账号记一份。新开的字幕若该会话没有记过位置，排在已有字幕上方、不重叠 |
| 5 | 一条字幕里显示几条消息 | 用户原话：「从开启字幕开始的时刻，来一条新消息显示一条字幕，再来一条，字幕更新」。**只显示最新一条**，开启前的旧消息不显示，**不做翻看功能**。开启后第一条消息到达前显示暗色的「等待新消息…」 |
| 6 | 自己发的消息 | **不上字幕**，从别的设备同步回来的也不上 |
| 7 | 文字最多几行 | **默认 2 行**，⚙ 菜单里可改为 1~3 行；超出部分在最后一行末尾截断并加「…」 |

实机联调之后，用户 2026-10-05 又确认了下面几项（**第 1 项「关闭聊天窗时字幕随之关闭」的做法据此作废**）：

| # | 事项 | 决定 |
| --- | --- | --- |
| 8 | 单聊字幕说话人前缀用什么名字 | **有备注只用备注**，没有备注用真名（`balloonmain::ResolveContactSpeakerName`）；聊天窗标题与字幕工具条上的会话名仍是「真名（备注）」 |
| 9 | ⚙ 菜单关闭后的前台 | **交还给弹菜单前的窗口**（只在菜单关闭后前台仍是字幕自己时交还，用户点别的窗口关菜单时不动） |
| 10 | 字幕与聊天窗的关系 | **字幕不随聊天窗关闭而关闭**，改由主面板统一持有；聊天窗关掉后点「回到聊天窗」重新打开聊天窗；只剩字幕开着时收到的消息**同样算已读**；退出或注销时全部关闭，**重登后不自动恢复**（位置、宽度、锁定与外观照旧恢复） |
| 11 | 聊天窗头部按钮 | 字幕开着时**高亮**：图标蓝色 #3B82F6，不加底色（起初另加浅蓝圆角底，已按第 15 条去掉） |
| 12 | 主面板入口 | 「联系人」「最近会话」「群组」三个页签的右键菜单都加一项，字幕没开时为「开启字幕模式」、开着时为「关闭字幕模式」；从菜单开启时只弹出字幕，不打开聊天窗 |
| 13 | 主面板徽章 | 「最近会话」「联系人」「群组」三个页签里正在显示字幕的会话行，在名字后面画字幕图标徽章，蓝色 #3B82F6（选中行上改为白色，否则与选中底色分不清） |
| 14 | 群聊字幕的来源标注 | 第一行行首用浅蓝色写「【群名】」，后面是「某某说：」；群名过长时截短加「…」，最多占一行的四分之一；等待提示与撤回提示也带群名。「某某」**群名片优先**，没有群名片用联系人短名，因此主面板要缓存开着字幕的群的群名片 |
| 15 | 头部按钮的高亮样式与悬停提示（2026-10-05 第二轮复验后） | 字幕开着时**只把图标画成蓝色，不要背景**；鼠标悬停时与其它按钮一样显示浅灰底。悬停提示随状态切换：开着时「字幕已开启」，关着时「字幕已关闭」（替代原来固定的「字幕模式」）。单聊窗、群聊窗相同 |

另外两项：

- **字幕窗口不用 balloonui、自行绘制**：用户已批准（下达「开始吧 全部做完告诉我」即视为批准整个方案）。原因是 balloonui 的窗口都是不透明的普通窗口、在 `BeginPaint` 里绘制，做不到逐像素透明、整窗点击穿透和描边大字。字幕窗口只画字幕和工具按钮、处理拖动与锁定；⚙ 菜单仍用 balloonui 的 `DuiMenu`。
- 硬性约束不变：修改 balloonui、git 提交、在共用桌面上启动测试客户端或模拟点击，都须先问用户。本项目没有改 balloonui 的计划。

## 2. 交互设计

### 2.1 入口

单聊窗、群聊窗头部那排图标里各加一个「字幕模式」按钮（图标 `kChatIconSubtitle`：圆角框内下部一短一长两行横线），放在「消息记录」左边：

| 窗口 | 控件编号 | XML 位置 |
| --- | --- | --- |
| 单聊窗 | `kIdHdrSubtitle = 441`（`ChatWindowLayout.h` 的 `CtrlId`） | `kChatWindowBodyXml` 里 `id="414"`（history）那一行之前，`kind="subtitle"` |
| 群聊窗 | `kGIdHdrSubtitle = 536`（`GroupChatWindowLayout.h`；516 是作废的号，不复用） | `kGroupChatWindowBodyXml` 里 `id="512"`（history）那一行之前 |

悬停提示随状态切换：字幕关着时「字幕已关闭」，开着时「字幕已开启」（第 1 节第 15 条；`ChatIconButton::SetToggleTips`）。点一下进入，再点一下退出（经主面板的 `CSubtitleRegistry::Toggle`）。字幕开着时按钮图标为蓝色，不加底色。

### 2.2 字幕的三种状态

| 状态 | 外观 | 鼠标 |
| --- | --- | --- |
| 解锁，鼠标不在上面 | 只有带描边的文字，背景透明 | 按住可以拖动 |
| 解锁，鼠标停在上面 | 圆角半透明深色底淡入（150 ms），上方工具条显示会话名与四个按钮；鼠标离开后等 400 ms 再淡出（250 ms） | 按住空白或文字处拖动；按住左右边缘（8 像素）调宽度 |
| 锁定 | 只有文字（同 t1），整窗点击穿透 | 鼠标在字幕上停留 500 ms 后，工具条锁定按钮的位置浮出一个带圆形深色底的「打开的锁」小按钮，点它解锁 |

工具条（「会话名 + 四个按钮」整组水平居中）：会话名（单聊为对方名字，群聊为群名）、⚙ 设置、🔒 锁定、↗ 回到聊天窗、✕ 退出字幕模式。

⚙ 菜单（`DuiMenu`）：字号（小 22 / 中 28 / 大 34 / 特大 42，96 DPI 下的像素，默认中）、最多显示行数（1 / 2 / 3 行，默认 2）、「共享屏幕或录屏时隐藏字幕」（勾选项，默认不勾；不支持排除采集时置灰）。

### 2.3 字幕内容

- 格式「张三说：内容」：说话人前缀用模板 `TR(L"{0}说：")`（英文译成「{0}: 」），名字金黄 `RGB(255,214,74)`、内容白色，等待提示与撤回提示浅灰 `RGB(205,205,205)`。文字粗体，先画半透明阴影、再画深色描边、最后填色。每行水平居中。
- 名字来源与气泡一致：单聊取 `m_peerName`；群聊取 `ResolveSender(notify.m_from).m_name`（`BalloonGroupChatWindow.h`，优先群名片）。
- 内容：`net::MessageProtocolClient::digestForNotify`（会话列表预览的同一口径：文本取正文、内联表情换成「[表情]」，其余类型为 [图片]、[聊天记录]、[接龙] 标题、[共享] 名称、[语音通话] 等占位文字），文件补文件名（「[文件] 报价单.xlsx」），语音补时长（「[语音] 8″」）。换行与连续空白合并成一个空格；超过 1000 个字符先截掉。
- 折行：中日韩文字逐字折行，拉丁单词不拆（比整行还宽时才按字符拆），不拆代理对；说话人前缀整体放第一行，名字过长时截短，保证前缀不超过行宽一半。
- 正在显示的那条被撤回时，换成撤回提示（聊天窗 `OnMessageRecalled` 收到的 `tipText`）。
- 系统提示（`message_type_system`）不上字幕。同一条消息（同 msgid）只显示一次。

### 2.4 位置的保存与恢复

- 每个会话的字幕位置（左、上、宽，屏幕物理像素）与锁定状态，在拖动、调宽结束和锁定 / 解锁后立刻存进账号配置。
- 恢复：保存的矩形与某个工作区重叠足够多（`winplace::kMinVisibleWidthPx` × `kMinVisibleHeightPx`）时，平移到整个落在重叠最多的工作区里；否则（如那台显示器已拔掉）按默认位置放：主显示器工作区底部居中，离底边留工作区高度的 10%，宽度取工作区宽度一半（限制在 320～1100 逻辑像素之间）。
- 窗口高度只由字号与行数决定，不随消息长短变化；改字号或行数时保持底边不动、向上长高。

### 2.5 配置文件格式（账号 ini，全 ASCII）

```ini
[Subtitle]
FontSize=28
MaxLines=2
HideFromCapture=0
[SubtitlePlacement]
1_10023=120,860,960,1        ; 键「会话类型_会话ID」，值「左,上,宽,是否锁定」
```

## 3. 技术方案

### 3.1 模块划分

新代码在 `flamingoclient/Source/UI/BalloonSubtitle/`（命名空间 `subtitle`），偏好在 `Source/Session/`：

| 文件 | 职责 | 能否单测 |
| --- | --- | --- |
| `Session/SubtitlePrefs.h/.cpp` | 外观与各会话位置的数据模型、配置文本编解码；由 `CUserConfig::Subtitles()` 持有 | 可以（SUBP） |
| `SubtitleModel.h/.cpp` | 当前显示哪一条：来一条换一条、过滤本人与系统提示、按 msgid 去重、撤回替换；`BuildSubtitleContent` / `MakeSubtitleIncoming` 把推送换算成字幕内容；`SubtitleLine::m_origin` 是群聊行首的群名标注（`CSubtitleModel::SetOrigin`）；`CGroupCardCache` 是主面板为开着字幕的群记下的群名片 | 可以（SUBM、SUBGC1） |
| `SubtitleTextFit.h/.cpp` | 折行与截断，测量函数由调用方传入；带群名标注的重载把「【群名】」与说话人前缀一起放在第一行，`FitLine::m_originLen` 给出群名标注的长度 | 可以（SUBF） |
| `SubtitleState.h/.cpp` | 锁定 / 解锁 / 悬停 / 淡入淡出 / 小锁按钮的状态机，给出此刻是否穿透、底色与小锁按钮的不透明度 | 可以（SUBS） |
| `SubtitleLayout.h/.cpp` | 尺寸随字号与 DPI 缩放、工具条位置、命中测试、放置与限制到工作区 | 可以（SUBL、SUBPL） |
| `SubtitleRenderer.h/.cpp` | 画进预乘透明度的 BGRA 位图；`CSubtitleTextMeasurer` 用 GDI+ 测量文字（与绘制同一字体、同一排版格式） | 可以（SUBR） |
| `SubtitleView.h` | `ISubtitleView`（会话 → 窗口）与 `ISubtitleViewHost`（窗口 → 会话）两个接口 | — |
| `SubtitleSession.h/.cpp` | `CSubtitleSession`：一个会话的字幕模式（进入 / 退出、转交消息与撤回、保存位置与外观、多条字幕的避让与外观同步、通知持有者）；`CSubtitleRegistry`：按（会话类型, 会话ID）管全部字幕，由主面板持有，「回到聊天窗」与状态变化经回调通知主面板 | 可以，用假视图（SUBC、SUBG） |
| `SubtitleWindow.h/.cpp` | 真正的窗口，实现 `ISubtitleView` | 隐藏用例（SUBW） |
| `Common/Graphics/CompositionLayer.h/.cpp` | DirectComposition 逐像素透明图层（由 `FlamingoMedia/Share/ShareCompositionLayer` 挪来，类名 `graphics::CCompositionLayer`） | 由原 SSAA 用例覆盖 |

### 3.2 显示方式与「共享时隐藏」

- 字幕窗口优先建成「不要重定向位图」（`WS_EX_NOREDIRECTIONBITMAP`，常量 `graphics::kExStyleNoRedirectionBitmap`）的分层窗口，`SetLayeredWindowAttributes(255, LWA_ALPHA)`，内容经 `CCompositionLayer::Present` 交给 DWM 合成。
- 「共享时隐藏」只切换 `SetWindowDisplayAffinity`：`WDA_EXCLUDEFROMCAPTURE`（0x11，常量 `kDisplayAffinityExclude`）或 `WDA_NONE`，运行中切换不用重建窗口。
- 据实证（`Source/Tests/ShareCompositionLayerTests.cpp` 的 SSAA1）：DirectComposition 窗口不排除时能被屏幕读取采集到，排除后读不到。而 `UpdateLayeredWindow` 的逐像素透明窗口设置排除会失败（屏幕共享第 2h 期实测错误 8），所以不能只用它。
- 退回：`CCompositionLayer::Attach` 失败（Windows 7、建不出设备）时，重建一个不带 `WS_EX_NOREDIRECTIONBITMAP` 的窗口，改用 `UpdateLayeredWindow` 显示，⚙ 菜单里「共享时隐藏」置灰（`IsCaptureExclusionSupported()` 返回 false）。
- 解锁时渲染器给整窗铺一层透明度 1/255 的底（`m_hitTestable`），使 `UpdateLayeredWindow` 方式下整个矩形都能收到鼠标消息。

### 3.3 窗口行为（`SubtitleWindow.cpp`）

- 样式：`WS_POPUP`，扩展样式 `WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE | WS_EX_LAYERED`（再加上上面的不重定向位图）；不设所有者窗口；`WM_MOUSEACTIVATE` 返回 `MA_NOACTIVATE`。
- 锁定时窗口带 `WS_EX_TRANSPARENT`，收不到鼠标消息，所以用定时器（`kSubtitleTimerId`：渐变中 30 ms、平时 120 ms）查询 `GetCursorPos`，经 `HitTestSubtitle` 得到部位后调 `CSubtitleState::OnCursor`，再 `Tick` 得到 `SubtitleVisual`；按 `m_clickThrough` 增删 `WS_EX_TRANSPARENT`（光标正落在浮出的小锁按钮上时暂时去掉，那次点击才能落到按钮上），样子有变化才重画。
- 拖动与调宽：按下时 `SetCapture`，自己跟踪鼠标移动（不用 `HTCAPTION`），宽度不小于 `m_minWidth`；松开时 `ClampSubtitleRect` 限制到工作区，再调 `ISubtitleViewHost::OnSubtitleMoved`。拖动期间 `CSubtitleState::SetDragging(true)`。
- 工具按钮：按下记 `m_pressedPart`，在同一按钮上松开才执行；执行时向自己 `PostMessage(kMsgSubtitleCommand, part, 0)`，等鼠标消息处理完再做（弹菜单、退出字幕模式时销毁窗口都不在鼠标消息的调用栈里）。`kPartClose` 调 `OnSubtitleClose` 后不得再访问自己的成员（会话会 delete 窗口对象）。
- ⚙ 菜单：弹出前记下当时的前台窗口，再 `SetForegroundWindow(m_hwnd)`（用户刚点过本窗口，本进程有设前台的权限；据实证，2026-10-05 实机联调时点到菜单外面菜单能正常关闭），`CSubtitleState::SetMenuOpen(true)`，`DuiMenu::TrackPopup` 同步返回后，按 `ShouldRestoreForegroundAfterMenu` 把前台交还给弹菜单前的窗口（只在前台仍是字幕自己时交还，SUBFG1~3），再按选择组装新外观，调 `OnSubtitleAppearanceChanged`。
- 悬停提示：原生 `TOOLTIPS_CLASS`，按钮可点时才启用（`m_tooltipsActive`）。文字：设置、锁定字幕、解锁字幕、回到聊天窗、退出字幕模式。
- DPI：按窗口所在显示器的 DPI（`balloonwjui::DuiDpi::GetWindowDpi`）重算 `ComputeSubtitleMetrics`；处理 `WM_DPICHANGED`、`WM_DISPLAYCHANGE`、`WM_SETTINGCHANGE`（工作区变化）时重新布局并限制到工作区。
- `SetAppearance`：按新字号、行数重算高度，保持底边不动；按 `m_hideFromCapture` 设置显示亲和性。
- 窗口私有消息 `kMsgSubtitleCommand = WM_APP + 0xE0`，已登记进开发约定文档 UI 约定第 6 条的 WM_APP 偏移清单。
- 群聊字幕行首的群名标注：`relayout` 里用 `FitSpeakerPrefix(TR(L"【{0}】"), 群名, 行宽 × kOriginMaxWidthPercent%)` 截短，再交给带群名标注的 `FitSubtitleText`；渲染器按 `m_originLen`、`m_speakerLen` 把第一行分成浅蓝 `kOriginColor`、金黄、白色三段。

### 3.4 字幕由主面板持有（2026-10-05 第二轮起）

最初由两个聊天窗各持有一个 `CSubtitleSession`、关窗时随之关闭。用户在实机联调后确认字幕不随聊天窗关闭（第 1 节第 10 条），改为主面板 `CBalloonMainPanel` 持有 `subtitle::CSubtitleRegistry m_subtitles`，聊天窗里不再有字幕会话。

| 环节 | 做法 |
| --- | --- |
| 初始化 | `EnsureSubtitles()` 第一次用到时 `m_subtitles.Init(&m_UserConfig.Subtitles(), 存盘回调, this, 事件回调, this)`；注销（`ResetForLogout`）时 `ExitAll()` 并把 `m_subtitlesReady` 置回 false，重新登录后按新账号重新初始化；主面板销毁（`OnPanelDestroyMsg`）时也 `ExitAll()`，不留到析构 |
| 开关 | `ToggleSubtitle(ctype, cid)`：会话名单聊取 `ContactDisplayName`、群聊取 `GroupDisplayName`。入口有三：聊天窗头部按钮经 `FMG_MSG_TOGGLE_SUBTITLE`（`WM_USER + 4510`，同步 `SendMessage`，`wParam` 为 ctype，`lParam` 为调用方栈上的 `int64_t*` cid，返回 1 开着 / 0 关着）请主面板切换；会话、联系人、群组三个右键菜单的「开启字幕模式 / 关闭字幕模式」（命令号 19 / 19 / 15） |
| 收消息 | `OnRecvChatMessage` 里按 `IsSubtitleOn` 把消息交给字幕：单聊说话人用 `ContactSpeakerName`（有备注只用备注）；群聊先查 `m_subtitleGroupCards`（群名片），没有时用 `ContactSpeakerName` |

## 7. 接手指南

- 先读第 1 节的决定与第 6.2 节的待办。
- 往源文件追加含反斜杠的代码时用 Write / Edit 工具，不要用 Bash heredoc：本机的 Bash 工具会把 `\\` 折成 `\`（2026-10-05 踩过，SUBSNAP2 的路径因此写错）。
- 所有新增代码遵守仓库开发约定文档的代码规范：Allman 花括号、`m_` 成员加中文注释、不用魔数、注释中文、日志英文、C++11、少用 lambda 与 `auto`；界面文字一律 `TR`。
- 群聊窗里 `WindowAttention.h` 必须排在 `<windowsx.h>` 之前：后者定义了函数式宏 `IsMinimized(hwnd)`，排在它之后时接口方法 `IsMinimized` 被改写成 `IsIconic`，链接报「无法解析的外部符号 Win32WindowRaiseOps::IsIconic」（2026-10-05 踩过，已在包含处写明原因）。
- 本项目没有改动 balloonui，也不需要改；若实现中发现需要，先问用户。
- 增量编译的一个坑（2026-10-05 踩过）：别的会话在你编译期间改了头文件时，先开始编译、读到旧头文件的 .cpp 会留下时间戳更新的 .obj，下一次增量编译不会重编它，运行时表现为说不通的访问违例（当时客户端 B 崩在 `CBalloonMainPanel::OnAutoReplyAck` 查 `m_pendingAutoReplies` 上）。做法：记下编译起止时间，编完按中间目录里的 `CL.read.*.tlog` / `CL.write.*.tlog` 找出真正读过「编译期间被改过的头文件」的 .obj，删掉后再增量编一次，直到找不出这样的 .obj（2026-10-05 晚上别的会话改头文件很频繁，连续编了三次才干净）。只看时间段整段删 .obj 也行，但会多编很多无关文件。崩溃时抓调用栈的做法：等「程序出错」框弹出后用 cdb 非侵入挂上去。
- 联调时的两个坑（2026-10-05 第二轮复验时遇到）：
  - 关闭客户端的提示框用投递消息：「是 / 否」框投 `WM_COMMAND`、`wParam=6`（IDYES）有效；只有「确定」的信息框投 `WM_COMMAND IDOK` 没有反应，投 `WM_CLOSE`（0x10）有效。
  - **用真实鼠标点击之前，先确认那个点落在测试窗口上**（`WindowFromPoint` 取到的窗口类名）。测试客户端的提示框不是置顶窗口，可能被用户自己的窗口挡住：这次就有一次点到了用户的终端窗口上。
- 提交须由用户决定，不要自行 commit。
