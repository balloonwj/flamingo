# 「聊天消息时间显示」方案与实现记录

> 作者：balloonwj@qq.com　起草日期：2026-08-12
> 用途：记录 PC 客户端聊天窗里显示消息时间这一特性的形态选择、口径约定、代码落点与进度。

---

## 1. 背景

改版前聊天界面完全不显示消息时间。翻聊天记录时无从判断某条消息是刚才说的还是昨天说的，
只能去消息记录窗里对。

数据源本来就有：气泡这边能拿到消息时间（`UI/BalloonChatWnd/ChatBubble.h` 的
`BackfillServerIds(msgid, timestampMs)`），消息列表的接口也带 `timestampMs`。

---

## 2. 形态：时间分隔行（2026-08-12 与用户确认）

在消息流中间插入一行居中的灰色小字，**只在两条消息间隔较久时才插**，而不是给每条消息
都标时间。

当时摆出的三个选项与取舍：

| 形态 | 优点 | 代价 |
| --- | --- | --- |
| **A 时间分隔行**（已选） | 界面干净，长对话不被时间刷屏，贴合国内 IM 的普遍习惯 | 消息列表要引入一种"非气泡行"，测量与命中测试都要认它 |
| B 每条气泡带时间 | 改动集中在气泡，不动列表结构 | 满屏时间；短消息会被时间撑宽——回一个"好"字，气泡却有时间那么宽 |
| C 两者结合 | 信息最全 | 改动最大 |

真需要精确到每条的时间，鼠标悬停显示提示是更轻的补充手段，本期不做。

---

## 3. 口径约定

**插入阈值 5 分钟。** 连续对话时（间隔通常几秒到几十秒）一行都不插；聊着聊着停下再
回来，才会有一行标出"这是隔了一会儿之后的消息"。判定用 `>=`，正好满阈值就插。

**三种特殊情形**（都由纯逻辑函数定死，有用例守着）：

- **没有上一条** —— 消息流的第一条，一律插。开头总该有个时间。
- **本条时间未知**（时间戳 <= 0）—— 不插。插了也写不出文案。
- **时间倒挂**（本条早于上一条）—— **插**。服务器时间回拨或消息乱序时会出现；时间倒着
  走本身就该让用户看见，闷着不显示只会更费解。

**文案分档**，与公告列表的口径一致，避免同一个时间在两处显示成不同样子：

| 情形 | 显示 |
| --- | --- |
| 今天 | `09:05` |
| 昨天 | `昨天 22:10` |
| 今年更早 | `08-10 14:03` |
| 往年 | `2025-12-31 23:50` |

"当前时刻"由调用方传入而不是函数自己读时钟——这样"今天 / 昨天"的判定才能被测试固定住。
"昨天"的判法是把当前时刻往前推一天再比同一天，月末、年末与闰年的边界自动成立。

## 4. 代码落点

| 文件 | 职责 |
| --- | --- |
| `UI/BalloonChatWnd/ChatTimeSeparator.{h,cpp}` | 纯逻辑：`ShouldInsertTimeSeparator` 与 `FormatChatSeparatorTime`。不碰控件、不读时钟 |
| `Tests/ChatTimeSeparatorTests.cpp`（CTS1–CTS8） | 上述两支的全部边界 |
| `ChatMessageList::AppendMessage` | 判定并插入分隔行 |
| `ChatMessageList::Begin/EndPrependBatch` | 翻页时的基准进出与新旧交界补行 |

测试里的时间戳一律用 `mktime` 按本地时间构造，使被测代码与用例处在同一时区，换机器不会飘。

### 4.1 为什么插在 AppendMessage 这个漏斗里

实时收发、向上翻页（批次期间照常调它）、单聊窗与群聊窗，全都从 `AppendMessage` 过。
插一处即可覆盖全部路径，不会出现"某条路径忘了插"。两个细节：

- **分隔行自身（`kMsgTime`）不参与判定**，否则会被自己的时间反复触发。
- **时间未知（`timestampMs` 为 0）的消息不更新基准**，否则后面一条正常消息会与 0 相比、
  被判成"没有上一条"而多插一行。
- 文案为空（时间戳不可用）时干脆不插 —— 插一行空白比不插更费解。

### 4.2 翻页时的三件事

向上翻页的流程是 `BeginPrependBatch()` → 照常 `AppendMessage` 灌入本页 → `EndPrependBatch()`
把本批整体旋转到列表头部。围绕分隔行要处理三处：

1. **进批次时把基准清零并寄存原值。** 本批第一条最终是整个消息流的开头，理应带一行时间；
   若沿用实时消息那条基准，会拿它去和末尾最新消息的时间相比，判出来没有意义。
2. **交界补行。** 本批消息之间的分隔行在 `AppendMessage` 里已逐条判过，唯独"本批最后一条"
   与"翻页前原本的第一条"之间没人判过——那两条在旋转后才相邻，不补的话翻上去会看到交界处
   凭空缺一行。补的时机是**旋转之前**：此刻本批还挂在末尾，追加的行旋转后正好落在整批的
   最后、也就是原第一条之前，位置天然正确。原第一条本身若已是分隔行则跳过。
3. **收尾还原基准**，让后续实时消息仍与消息流末尾比。空页（服务端返回 0 条）那条早退路径上
   也要还原，否则基准会被永久清零。

## 6. 已查实：渲染那一侧本来就有（2026-08-12）

原本担心要给消息列表引入一种新的"非气泡行"，实际不必——**时间分隔行这个类型早就存在**：

- `ChatMockData.h:52` 的 `kMsgTime = 0`，注释原话就是「居中时间分隔」；文案放在
  `ChatMessage::text`，`fromMe` 对它无意义（`ChatMockData.h:90,92`）。
- 气泡对它有完整支持：`ChatBubble.cpp` 的 `GetRowHeight` 给它单独的行高（`kTimeRowHeight`）、
  `IsRealMessage` 判定它不是真实消息（不参与撤回、引用一类操作）、`RenderContent` 有专门的绘制分支。
- 窗口那边已经在用它渲染居中系统提示：窗口抖动等提示由 `CBalloonChatWindow::AppendSystemTip`
  经 `MakeSystemTipMessage`（`ChatEarlyTips.h`）造一条 `kind = kMsgTime` 的消息。

**所以本特性缺的从来不是"能不能画这行字"，而是"什么时候插、插什么字"** —— 正是
`ChatTimeSeparator` 那两支纯函数。剩下的接入不需要动行模型、测量与命中测试。

## 7. 回显消息没有时间行、跨天与跨午夜（2026-10-14）

### 7.1 现象与原因

用户实测：前一天晚上的消息与第二天上午新发的消息之间没有时间行。

据实证（读代码所得，实施时先写用例复现）：本人发出的消息在本地先回显，回显气泡的时间戳是 0，要等服务端回执才回填。
单聊发送文字、Markdown、代码片段时传 0（`BalloonChatWindow.cpp` 5363、5416、5645 行），群聊同样（`BalloonGroupChatWindow.cpp`
3795 行注释「此刻 msgid / timestampMs 还未知，留 0 待回执回填」）。而第 4.1 节定下「时间未知的消息不插行、不更新基准」，
`ShouldInsertTimeSeparator` 遇到 0 直接返回不插（`ChatTimeSeparator.cpp` 45～48 行）；回执到达后
`ChatMessageList::BackfillSentMessage` → `ChatBubble::BackfillServerIds` 只补 msgid 与时间戳，不补行、也不更新基准。
结果是：本人隔夜后发的第一条消息前面没有时间行；对方随后的回复与昨晚的消息比较，时间行插在本人消息之后、回复之前。
关掉重开聊天窗后正常（历史消息从本地库加载时带时间戳）。第 5 节的「目视核对」一直没做，CTS1～8 只测纯函数，覆盖不到这条路径。

同时查出两处相关问题：

- **跨天不一定插**：判定只看间隔是否满 5 分钟，23:58 与次日 00:01 之间没有时间行。
- **跨午夜后文案不更新**：分隔行的文字在插入时按当时的「现在」算好后不再变（`ChatMessageList.cpp` 492～503 行），
  聊天窗开着过了零点，昨晚的「21:30」不会变成「昨天 21:30」。

### 7.2 已定事项（2026-10-14 逐项确认）

1. **回显消息只在消息列表里按本机时间判定**：`AppendMessage` 遇到本人发出、时间戳为 0 的消息，按本机当前时间判定与格式化，
   并记为基准；`BackfillSentMessage` 回填后，若这条是列表里最后一条真实消息，把基准换成服务端时间。消息本身的时间戳语义不变
   （仍为 0 直到回执），撤回时限、引用、备忘预填等不受影响。另一个做法「回显时直接写入本机时间」未采用：两条现有用例断言回显时为 0，
   各发送路径都要改。
2. **跨天必插**：前后两条消息不在同一个本地日期时一律插行，不论间隔长短。
3. **跨午夜刷新文案**：分隔行记下对应的消息时间；消息列表绘制时发现本地日期与上次不同，就把所有分隔行的文字重新格式化。不加定时器。
4. **「回显」以带客户端消息 ID 为准**（实施中查出，2026-10-14 确认）：只有带 `clientMsgId` 或 `fileClientMsgId` 的本人消息按本机时间判定。
   密聊邀请卡片、文件夹行等本地行没有这个 ID，也不会有回执，照旧不插时间行；否则这类卡片单独移除时
   （`RemoveSecretInviteMessage` 只移除卡片本身），它前面的时间行会留在原处。
5. **删除后清理时间行、重算基准**（同上）：发送失败的消息在本窗口删除（右键删除 `RequestDeleteBubble`、多选删除
   `DeleteSelected`）时，因此孤立的时间行一并移除；判定基准按列表里剩下的行重新确定（最后一条时间已知的真实消息，
   或最后一行时间行所标注的时间），否则紧接着重发的消息与被删的那条比较，前面会缺时间行。按服务器 msgid 删除
   （`RemoveMessagesByMsgid`）原本就清理孤立行，也一并重算基准。

为了让用例能固定「现在」，消息列表取当前时刻改为经一个可替换的函数（只供测试替换），不再直接调 `::time`。

### 7.3 测试用例（2026-10-14 确认，CTL5、CTL6 为实施中补充并确认）

- **CTS9** 跨天必插：23:58 → 次日 00:01（间隔 3 分钟）插；同一天间隔 4 分钟不插；原有的「时间未知不插」「倒挂插」不变。
- **CTS10** 跨天按本地日期判定，跨月、跨年边界同样成立（时间戳用 `mktime` 按本地时间构造）。
- **CTL1** 列表级：昨晚 21:30 对方一条 → 今早本人回显（时间戳 0，「现在」为 09:05）→ 本人那条之前有且只有一行「09:05」。
- **CTL2** 回执回填后基准换成服务端时间：回显 → 回填 09:05 → 09:08 对方回复 → 不再插行。
- **CTL3** 本人连发三条回显（都为 0、相隔不到 5 分钟）→ 只在第一条前插一行。
- **CTL4** 跨午夜刷新：「现在」为昨晚时插入的「21:30」，把「现在」换到今天后绘制一次 → 变为「昨天 21:30」；日期没变时绘制不改文字。
- **CTL5** 昨晚 21:30 对方一条 → 今早 09:05 本人发送失败后删除（右键删除、多选删除两个分支）→ 列表里不再有「09:05」这一行；
  09:06 重发 → 前面重新插一行「09:06」。
- **CTL6** 本人发出的密聊邀请卡片（没有客户端消息 ID、时间戳为 0）前面不插时间行。

另有五个测试文件按子控件下标取气泡（`BubbleAt(list, 0)`），本人回显前面多了时间行后取到的是时间行，改为按「第几条真实消息」取、
跳过 kMsgTime 行，用例原意不变：`ChatBubbleBackfillRepaintTests.cpp`、`ChatReadReceiptTests.cpp`、`SensitiveSendFailTests.cpp`、
`ChatPinClickTests.cpp`、`GroupMentionInteractionTests.cpp`。
