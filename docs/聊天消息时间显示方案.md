# 「聊天消息时间显示」方案与实现记录

> 作者：balloonwj@qq.com　起草日期：2026-08-12
> 用途：记录 PC 客户端聊天窗里显示消息时间这一特性的形态选择、口径约定、代码落点与进度。

---

## 1. 背景

改版前聊天界面完全不显示消息时间。翻聊天记录时无从判断某条消息是刚才说的还是昨天说的，
只能去消息记录窗里对。

数据源本来就有：气泡这边能拿到消息时间（`UI/BalloonChatWnd/ChatBubble.h` 的
`BackfillServerIds(msgid, timestampMs)`），消息列表的接口也带 `timestampMs`。

---

## 2. 形态：时间分隔行（2026-08-12 与用户确认）

在消息流中间插入一行居中的灰色小字，**只在两条消息间隔较久时才插**，而不是给每条消息
都标时间。

当时摆出的三个选项与取舍：

| 形态 | 优点 | 代价 |
| --- | --- | --- |
| **A 时间分隔行**（已选） | 界面干净，长对话不被时间刷屏，贴合国内 IM 的普遍习惯 | 消息列表要引入一种"非气泡行"，测量与命中测试都要认它 |
| B 每条气泡带时间 | 改动集中在气泡，不动列表结构 | 满屏时间；短消息会被时间撑宽——回一个"好"字，气泡却有时间那么宽 |
| C 两者结合 | 信息最全 | 改动最大 |

真需要精确到每条的时间，鼠标悬停显示提示是更轻的补充手段，本期不做。

---

## 3. 口径约定

**插入阈值 5 分钟。** 连续对话时（间隔通常几秒到几十秒）一行都不插；聊着聊着停下再
回来，才会有一行标出"这是隔了一会儿之后的消息"。判定用 `>=`，正好满阈值就插。

**三种特殊情形**（都由纯逻辑函数定死，有用例守着）：

- **没有上一条** —— 消息流的第一条，一律插。开头总该有个时间。
- **本条时间未知**（时间戳 <= 0）—— 不插。插了也写不出文案。
- **时间倒挂**（本条早于上一条）—— **插**。服务器时间回拨或消息乱序时会出现；时间倒着
  走本身就该让用户看见，闷着不显示只会更费解。

**文案分档**，与公告列表的口径一致，避免同一个时间在两处显示成不同样子：

| 情形 | 显示 |
| --- | --- |
| 今天 | `09:05` |
| 昨天 | `昨天 22:10` |
| 今年更早 | `08-10 14:03` |
| 往年 | `2025-12-31 23:50` |

"当前时刻"由调用方传入而不是函数自己读时钟——这样"今天 / 昨天"的判定才能被测试固定住。
"昨天"的判法是把当前时刻往前推一天再比同一天，月末、年末与闰年的边界自动成立。

## 4. 代码落点

| 文件 | 职责 |
| --- | --- |
| `UI/BalloonChatWnd/ChatTimeSeparator.{h,cpp}` | 纯逻辑：`ShouldInsertTimeSeparator` 与 `FormatChatSeparatorTime`。不碰控件、不读时钟 |
| `Tests/ChatTimeSeparatorTests.cpp`（CTS1–CTS8） | 上述两支的全部边界 |
| `ChatMessageList::AppendMessage` | 判定并插入分隔行 |
| `ChatMessageList::Begin/EndPrependBatch` | 翻页时的基准进出与新旧交界补行 |

测试里的时间戳一律用 `mktime` 按本地时间构造，使被测代码与用例处在同一时区，换机器不会飘。

### 4.1 为什么插在 AppendMessage 这个漏斗里

实时收发、向上翻页（批次期间照常调它）、单聊窗与群聊窗，全都从 `AppendMessage` 过。
插一处即可覆盖全部路径，不会出现"某条路径忘了插"。两个细节：

- **分隔行自身（`kMsgTime`）不参与判定**，否则会被自己的时间反复触发。
- **时间未知（`timestampMs` 为 0）的消息不更新基准**，否则后面一条正常消息会与 0 相比、
  被判成"没有上一条"而多插一行。
- 文案为空（时间戳不可用）时干脆不插 —— 插一行空白比不插更费解。

### 4.2 翻页时的三件事

向上翻页的流程是 `BeginPrependBatch()` → 照常 `AppendMessage` 灌入本页 → `EndPrependBatch()`
把本批整体旋转到列表头部。围绕分隔行要处理三处：

1. **进批次时把基准清零并寄存原值。** 本批第一条最终是整个消息流的开头，理应带一行时间；
   若沿用实时消息那条基准，会拿它去和末尾最新消息的时间相比，判出来没有意义。
2. **交界补行。** 本批消息之间的分隔行在 `AppendMessage` 里已逐条判过，唯独"本批最后一条"
   与"翻页前原本的第一条"之间没人判过——那两条在旋转后才相邻，不补的话翻上去会看到交界处
   凭空缺一行。补的时机是**旋转之前**：此刻本批还挂在末尾，追加的行旋转后正好落在整批的
   最后、也就是原第一条之前，位置天然正确。原第一条本身若已是分隔行则跳过。
3. **收尾还原基准**，让后续实时消息仍与消息流末尾比。空页（服务端返回 0 条）那条早退路径上
   也要还原，否则基准会被永久清零。

## 6. 已查实：渲染那一侧本来就有（2026-08-12）

原本担心要给消息列表引入一种新的"非气泡行"，实际不必——**时间分隔行这个类型早就存在**：

- `ChatMockData.h:52` 的 `kMsgTime = 0`，注释原话就是「居中时间分隔」；文案放在
  `ChatMessage::text`，`fromMe` 对它无意义（`ChatMockData.h:90,92`）。
- 气泡对它有完整支持：`ChatBubble.cpp` 的 `GetRowHeight` 给它单独的行高（`kTimeRowHeight`）、
  `IsRealMessage` 判定它不是真实消息（不参与撤回、引用一类操作）、`RenderContent` 有专门的绘制分支。
- 窗口那边已经在用它渲染居中系统提示：窗口抖动等提示由 `CBalloonChatWindow::AppendSystemTip`
  经 `MakeSystemTipMessage`（`ChatEarlyTips.h`）造一条 `kind = kMsgTime` 的消息。

**所以本特性缺的从来不是"能不能画这行字"，而是"什么时候插、插什么字"** —— 正是
`ChatTimeSeparator` 那两支纯函数。剩下的接入不需要动行模型、测量与命中测试。
