# 聊天消息转发方案与开发计划

> 作者：balloonwj@qq.com　起草日期：2026-10-01
> 用途：记录 PC 客户端单聊窗、群聊窗「逐条转发」与「合并转发」两种模式的整体方案与开发步骤，以及为此需要的服务端修补。后续每步开工前据此细化，收尾后回填实际结果。

---

## 1. 需求

1. 单聊窗与群聊窗支持把一条或多条消息转发到其它会话，目标可以是单聊，也可以是群，一次可以选多个目标。
2. 支持两种模式：逐条转发（每条源消息在目标会话里各生成一条）与合并转发（所有源消息打包成一条「聊天记录」消息）。
3. 收到合并转发的一方能在聊天窗里看到一张「聊天记录」卡片，点开后按时间查看其中每一条消息。

以下口径均已与用户确认（2026-10-01），实现时不再另行请示：

| 决策点 | 取值 | 详见 |
| --- | --- | --- |
| 气泡右键「转发」 | 不直接打开目标选择窗，改为进入多选模式并预先勾选该条，由用户在底栏选逐条或合并 | §3.1 |
| 多选底栏 | 由三段改为四段：取消 / 逐条转发 N / 合并转发 N / 删除 N | §3.1 |
| 服务端修补 | S1～S7 全部实施 | §4 |
| 单次转发上限 | 最多 100 条消息、最多 9 个目标 | §3.2、§4 |
| 合并卡片 | 在 `ChatBubble` 内自绘，与现有文件卡片、文件夹卡片同一做法 | §5.5 |
| 聊天记录查看窗 | 平铺行样式，复用消息记录窗的行构建函数，不用聊天气泡 | §5.6 |
| 转发到群的文件 | 补上群聊窗对普通文件消息（类型 3）的渲染，不禁止 | §5.5 |
| 「给对方留言」 | 放到第二期，本期不做 | §8 |
| 内容体积上限（S7，2026-10-01 追加确认） | 三项都做：合并记录 content 上限 256 KiB；转发应答的消息体上限 512 KiB；同步、搜索、Pin 列表应答按 768 KiB 截断（顺带解决应答超过客户端单帧上限的大部分情形） | §4 |

## 2. 调查结论

以下各条均有代码依据（2026-10-01 的状态）。

### 2.1 服务端

1. **转发已经实现。** `ChatSession::onForwardMessage`（`chatserversrc/ChatSession.cpp`）支持逐条与合并两种模式，目标可为单聊或群。源消息经 `MessageManager::getMessagesByIds` 取出，按 `f_msgid` 升序排列，已撤回的、以及本人看不到的会话里的消息被跳过。合并转发生成一条 `msgtype=15` 的消息，content 为 `{title, messages:[完整消息体...]}`（`MessageProtocol.cpp`），标题缺省为「聊天记录」。
2. **转发到群时只校验群成员身份。** 普通群发在 `sendGroupMessage` 里还要检查禁言、「仅群主和管理员可 @全体」、敏感词，并按 `clientmsgid` 做幂等去重；转发路径经 `deliverConversationMessage` 直接落库，这几项都没有做。被禁言的成员可以借转发往群里发消息。
3. **逐条转发把源 content 原样复制，其中的 `at` 与 `quote` 也一并复制。** 这两项位于 content 内部；`deliverConversationMessage` 只清空服务端自己的顶层 mentions 与 quote。客户端判断「是否 @ 到我」只看 content 里的 `at`（`BalloonMainPanel.cpp`），因此把一条 @ 过某人的群消息转发到另一个群时，此人若也是目标群成员，会收到「[有人@我]」提醒。引用块指向另一个会话里的消息，点击后无法定位。
4. **应答只有新 msgid。** 应答为 `{code, msg, msgids}`，不带 `clientmsgid`、时间戳与内容。目标为单聊时，服务端只把新消息推给对方，转发人拿不到可以显示和落库的数据；目标为群时，fan-out 包括发送者本人。
5. **一次转发的条数没有上限。** 每条消息都在 EventLoop 线程上同步写库。`cmd_mass_send` 出于同样原因限制了 50 个目标（`MessageProtocol.h` 的 `MASS_SEND_MAX_TARGETS`）。
6. **已删除的消息仍可转发。**
7. **合并子消息里只有发送者 userid，没有名字**（`MessageProtocol.cpp` 的 `messageBodyValue`）。
8. **chatserver 单帧包体上限为 1 MiB**（`chatserversrc/Protocol.h:28`）。

### 2.2 客户端

1. **转发入口只有占位。** 气泡右键「转发」（`ChatMessageMenu.h:47` 的 `kChatMsgMenuForward`）与多选底栏「转发 N」（`ChatMessageList.cpp`）都调用 `ChatMessageList::RequestForwardBubble`，该函数只弹出「转发功能正在开发中」。
2. **多选模式已可用。** `EnterMultiSelectWith` 进入多选并预选一行（`ChatMessageList.cpp`）；底栏在 `OnPaint` 里用 GDI 直接绘制、按横坐标三等分判断命中；「删除 N」已真实可用。
3. **网络层只有命令号。** `cmd_forward_message = 1511` 与 `message_type_merged = 15` 定义在 `net/Protocol.h:201`、`:855`，没有发送函数与应答解析；1511 的应答落入 `HandleV2Frame` 的 `default` 分支，只记一行日志（`IUSocket.cpp`）。
4. **类型 15 在客户端全链路都不认识。**
   - 解析时 content 被丢弃，`fillMessageFromObject` 只按图片、文件、文件夹、文字四种形状取字段（`MessageProtocolClient.cpp`）。
   - 本地库只存 `{}`（`V2MsgQuery.cpp`）。
   - 实时消息不显示（单聊 `BalloonChatWindow.cpp`，群聊 `BalloonGroupChatWindow.cpp`）；历史消息显示为「[消息]」占位。
   - `digestForMsgType` 没有「[聊天记录]」（`MessageProtocolClient.cpp`）。
5. **群聊窗丢弃自己发出的回显**（图片与文字两处，`BalloonGroupChatWindow.cpp`），依据是普通发送已有乐观气泡。转发没有乐观气泡，转发到群的消息因此不会出现在本端已打开的群窗里。
6. **单聊收到的文件与历史文件气泡 `msgid` 为 0**，服务端 msgid 放在 `fileMsgid` 里（`ChatMockData.cpp` 的 `MakeIncomingFileMessage`）。照 `ChatMessageList::DeleteSelected` 的写法收集 msgid 会漏掉这些文件。
7. **群聊窗不渲染普通文件消息（类型 3）**：实时收到的不显示，历史里显示为「[文件]」占位（`BalloonGroupChatWindow.cpp`）。
8. **单聊窗与群聊窗没有公共基类**（`BalloonChatWindow.h:75`、`BalloonGroupChatWindow.h:88`），消息映射与处理函数各写一份。
9. **可复用的部件**：
   - 选人：`CCreateGroupDlg`（`UI/BalloonMain/CreateGroupDlg.h:64`）及 `MemberPickerTreeView` / `MemberPickerRow` / `BuildMemberPickerTree`；
   - 带真实头像的行与拼音搜索：`CSearchDropdown`（`UI/BalloonSearch/SearchDropdown.h:91`）的 `ApplyRowAvatar` 与 `contactsearch::Match`；
   - 平铺消息行：消息记录窗的 `balloonhistory::BuildListContent`（`UI/BalloonHistory/HistoryWindowLayout.h:541`）；
   - 会话、联系人、群的内存数据都在 `CBalloonMainPanel` 的私有成员里（`m_conversations`、`m_contacts`、`m_myGroups` 等，`BalloonMainPanel.h`），新对话框只能由主面板打开并传入数据。

## 3. 交互设计

### 3.1 入口

- **气泡右键「转发」**：进入多选模式并预先勾选这一条（调用现有的 `EnterMultiSelectWith`），与点「多选」效果相同。菜单项文字仍为「转发」。
- **多选底栏**：改为四段，依次为「取消 / 逐条转发 N / 合并转发 N / 删除 N」，选中条数为 0 时后三段置灰。点「逐条转发」或「合并转发」后打开目标选择窗，并退出多选模式。
- **哪些消息能转发**：
  - 能转发：文字（含内嵌表情）、图片、文件、合并记录。
  - 不能转发：发送中或发送失败的消息（没有服务端 msgid）、文件夹传输记录、系统提示与时间分隔行（已撤回的消息会变成提示行，也在此列）。
  - 右键菜单对不能转发的气泡不显示「转发」。
  - 多选中混有不能转发的行时，发送时跳过它们，并提示「已跳过 N 条不能转发的消息」；全部都不能转发时，两个转发按钮置灰。

### 3.2 目标选择窗

- 左侧为搜索框与三个页签：最近会话、联系人（组织架构树）、群组。搜索同时匹配三类数据，支持拼音。
- 右侧为已选目标列表；上方一行说明本次转发的内容，如「逐条转发 3 条消息」「[聊天记录] 张三和李四的聊天记录」；底部为「取消 / 发送」。
- 可多选，最多 9 个目标；不列出自己。同一个人在「最近会话」与「联系人」里各勾一次，只算一个目标。

### 3.3 合并转发的标题

由客户端生成后随请求发给服务端：单聊为「<本人名字>和<对方名字>的聊天记录」，群聊为「<群名>的聊天记录」。超过上限时截断。

### 3.4 结果反馈

- 全部目标成功：在发起转发的聊天窗弹出 `DuiToast`「已转发」。
- 有失败的目标：弹出提示框，列出失败的目标与原因（被对方拉黑、不是群成员、已被禁言、含敏感词、消息不存在等）。

### 3.5 合并消息的显示

- 聊天窗里显示为卡片：第一行是标题，其下最多 4 行「发送者：摘要」，底部为「聊天记录（共 N 条）」。
- 卡片的右键菜单保留「引用回复 / 转发 / Pin / 撤回 / 删除 / 多选」，不提供「复制」。
- 点击卡片打开聊天记录查看窗：只读，按时间列出每条子消息的头像、名字、时间与内容，带日期分组。子消息本身是合并记录时显示为小卡片，点击再打开一层。

## 4. 服务端改动

| 编号 | 内容 |
| --- | --- |
| S1 | **条数与标题上限。** `msgids` 超过 100 条时在解析阶段拒绝（回 `error_code_bad_request`），常量写法参照 `MASS_SEND_MAX_TARGETS`，并注明必须与客户端的同名常量保持一致。标题超长时截断。 |
| S2 | **排除本人已删除的消息**，已删除的消息不能再被转发。 |
| S3 | **逐条转发时去掉文字消息 content 里的 `at` 与 `quote`。** 合并转发不改动子消息：查看窗只读，也不参与「@我」判断。 |
| S4 | **转发时执行与普通发送相同的校验。** 转发到群时，禁言校验与普通群发共用 `ChatSession::checkGroupSpeakAllowed`。敏感词按企业级词库检查（`docs/敏感词方案.md` 第 2a 步），转发到单聊与群聊都检查，检查的是实际要新建的内容：逐条转发为去掉引用后的内容，合并转发为含标题的整条合并记录；取文字用 `MessageProtocol::collectSensitiveTexts`，命中任意一处即整体拒绝（507，客户端提示「内容包含敏感词」）。转发请求本身不带 @，「仅管理员可 @全体」一项不涉及。 |
| S5 | **应答增加 `clientmsgid` 与 `messages`。** `messages` 为新建消息的完整消息体，结构与 `cmd_message_notify` 相同。老客户端忽略这两个字段，不受影响。 |
| S6 | **合并子消息增加 `fromname`**，取转发当时发送者的昵称，使这份记录不依赖接收方的通讯录；发送者离职、被移出组织架构后照样能显示名字。 |
| S7 | **内容体积上限。** 客户端要求 chatserver 发来的单帧原始长度不超过 1 MiB，超过即断开连接（`flamingoclient/Source/net/FrameCodec.cpp:144`、`IUSocket.cpp:1451-1456`）；聊天输入框不限长度，拉取历史一页最多 100 条，所以单靠限制合并记录无法保证整页不超限。经用户确认采用三项措施：合并记录 content 超过 256 KiB 回 `error_code_msg_too_large`；转发应答的 `messages` 累计超过 512 KiB 后只给 msgid；同步、搜索、Pin 列表应答的消息体累计超过 768 KiB 时截掉远离锚点的一端并把 `hasmore` 置为真。 |
| S8 | 同步更新 `docs/协议设计-v2.md` 中 1511 一节。 |

## 5. 客户端改动

### 5.1 网络层

- `MessageProtocolClient` 新增 `buildForwardMessageRequest` 与 `parseForwardMessageResponse`；`CIUSocket` 新增 `ForwardMessage`，返回帧序号，应答按序号匹配（参照 `CIUSocket::SendFolderInvite`）。
- 新增应答消息 `FMG_MSG_V2_FORWARD_RESULT = WM_USER + 4404`（A 段「消息」档的下一个空号），wParam 为帧序号，lParam 为堆上的解析结果。四层接线：`UserSessionData.h` 定义、`HandleV2Frame` 投递、`ProxyWndProc` 转发、主面板消息映射与处理函数。完成后运行 `FlamingoUnit.exe "[msgid]"`。
- 客户端单次转发上限常量（100 条、9 个目标）与服务端 S1 保持一致。

### 5.2 类型 15 的解析、摘要与本地库

- 解析时保留原 content 字符串，供合并卡片与查看窗使用。
- `BuildContentJson` 增加类型 15 分支，存为 `{"merged": 原 content}`；`search_text` 写入标题与各条子消息的文字，使消息记录窗能搜到。
- `digestForMsgType` 增加「[聊天记录]」，与服务端 `buildMessageDigest` 一致。

### 5.3 聊天窗入口

- `ChatMessageMenu` 的「转发」按「能否转发」决定是否显示；点击后调用 `EnterMultiSelectWith`。同步修改 `ChatImageMenuTests.cpp` 中目前「总是显示转发」的断言。
- `ChatMessageList` 新增 `GetSelectedForwardMsgids()`：按 msgid 升序返回；取 `msgid`，为 0 时改取 `fileMsgid`；跳过不能转发的行，并返回跳过的条数。
- 多选底栏改为四段，命中判断同步调整。
- 列表向宿主窗口投递 `WM_CHAT_FORWARD_REQUEST = WM_APP + 0x62`（紧挨删除请求 0x61，定义在 `ChatMessageList.h`），wParam 表示是否合并，lParam 为堆上的 msgid 列表。开发约定文档「UI 约定」第 6 条的 WM_APP 已占用列表同步补上 0x62。
- 单聊窗与群聊窗各加一个处理函数：补上源会话类型与 id、合并标题，以 `FMG_MSG_OPEN_FORWARD_PICKER = WM_USER + 4502`（B 段）投给主面板，lParam 为堆上的转发请求。

### 5.4 目标选择窗与转发调度

- 新建 `CForwardTargetDlg`，由主面板持有（写法照 `m_createGroupDlg`），窗口骨架沿用 `CCreateGroupDlg` 的布局。
  - 联系人页直接使用 `MemberPickerTreeView` 与 `BuildMemberPickerTree`；页签使用 `SearchFilterTab`；最近会话与群组两页使用 `MainPanelListItem` 行并显示真实头像（参照 `ApplyRowAvatar`）；搜索使用 `contactsearch::Match`。
  - 不给 `CCreateGroupDlg` 增加第五种 Purpose：选中项的键不同（转发为会话类型加会话 id，建群为 userid），且转发窗需要把结果交回主面板，而不是自行发送协议。
  - 方案设想在客户端一侧补两处扩展：`MemberPickerRow` 支持位图头像，`MemberPickerTreeView` 支持点击整行勾选。两处都没有做：联系人页的行仍按 `DecodeAvatar` 画首字头像（`MemberPickerRow::SetRowData` 只收头像文字与底色），只有最近会话与群组两页的行用 `DuiAvatar`、有借来的位图就画位图（`ForwardTargetDlg.cpp` 的 `MakeAvatar`）；点击整行勾选见下一条。
  - **「点击整行勾选」未实现**（见 §9 第 3 步）：转发窗与新建群聊对话框一致，三个页签都只有点复选框才切换勾选（联系人页认 `MemberPickerTreeView` 的 `DUIN_PICKER_CHECK_TOGGLE`，最近会话与群组两页认各行复选框的 `DUIN_CLICK`，见 `CForwardTargetDlg::OnDuiNotify`）。`MemberPickerTreeView` 后来（2026-10-08，「选择部门」小窗）加了 `SetToggleOnRowClick`，转发窗没有打开它。
  - 选择逻辑（去重、上限、跨页签搜索）抽成纯逻辑的模型类，便于单测。
  - 新增调试入口 `--forwardpicker`，用 `BuildStressData` 造数据。
- 新建纯逻辑类 `ForwardDispatcher`，由主面板持有：
  - 对每个目标发一次请求，登记「帧序号 → 目标」；
  - 汇总全部目标的结果，全部返回后统一给出 §3.4 的反馈；
  - 序号对不上的应答忽略。
- 应答成功后，用应答里的 `messages` 写本地库、推给已打开的目标窗口（按 msgid 去重）、刷新会话列表。
- 群聊窗对「自己发出的回显」改为按 `clientmsgid` 或 `msgid` 去重：列表里已有同一条就跳过，没有就按「本人发送」显示。普通发送的乐观气泡仍不会重复，转发到群的消息也能显示。

### 5.5 合并卡片与群聊文件气泡

- `ChatMsgKind` 增加合并记录类型，在 `ChatBubble` 里自绘卡片。
- 单聊窗、群聊窗的实时渲染与历史渲染共四个分支都加上类型 15。
- 群聊窗补上类型 3 的文件气泡（实时与历史），逻辑参照单聊窗的 `RenderIncomingFile`。群聊的文件消息没有「接收 / 拒绝」流程（服务端 `onFileTransferAck` 只处理单聊，`ChatSession.cpp` 该函数开头），气泡直接提供下载。

### 5.6 聊天记录查看窗

- 新建 `CMergedRecordWindow`，行内容复用 `balloonhistory::BuildListContent`：不设 `m_pinned`、不驱动悬停状态，行上的「Pin / 定位」按钮就不会出现。
- 名字优先取子消息的 `fromname`，没有时用主面板的 `ResolveSenderName`。
- 图片经 `ChatImageCache` 的监听机制加载。子消息的 msgid 是原消息的 id，直接用它发起下载即可，主面板按 msgid 分发下载结果的逻辑不需要调整（核实经过见 §9 第 6 步）。
- 新增调试入口 `--mergedviewer`，用构造的合并内容打开。

### 5.7 消息记录窗

识别类型 15：预览显示「[聊天记录] 标题」，点击打开查看窗。

## 6. 开发步骤

每一小步完成后向用户汇报一次。涉及 `ChatBubble.cpp`、两个聊天窗、`BalloonMainPanel` 的步骤，开工前先与同时在做聊天窗性能优化的会话确认对方已改完，避免两边同时修改同一文件。

| 步 | 内容 |
| --- | --- |
| 0a | S1 条数与标题上限、S2 已删除过滤 |
| 0b | S3 逐条转发去掉 `at` 与 `quote` |
| 0c | S4 转发的禁言与敏感词校验 |
| 0d | S5 应答补字段、S6 子消息补 `fromname` |
| 0e | S7 合并内容体积：测量后定上限 |
| 0f | S8 协议文档 |
