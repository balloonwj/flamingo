# 聊天记录管理器方案与开发计划

> 作者：balloonwj@qq.com　起草日期：2026-10-03
> 用途：记录把 PC 客户端「消息记录」窗口升级为「聊天记录管理器」（左侧会话列表、右侧聊天记录）的整体方案、分期路线与开发步骤。每步开工前据此细化测试用例并与用户确认，收尾后在第 10 节回填实际结果。第 11 节是 2026-10-05 起的增强（文件与图片汇总、时间轴模式、通配符搜索），进展回填在 §11.9。

---

## 1. 背景与目标

现在的「消息记录」窗口一次只看一个会话，要看另一个会话的记录，得回到主面板或聊天窗再点一次入口；想知道"某句话是在哪个会话里说的"，只能一个会话一个会话地搜。本方案在这个窗口左边加一栏会话列表，把所有会话的聊天记录集中到一个窗口里浏览、搜索和管理。

最终形态：从主面板系统菜单的「聊天记录管理」，或任何一个「消息记录」入口打开同一个窗口。左栏列出所有有聊天记录的会话，点哪个右侧就显示哪个会话的记录，右侧的筛选、分页、导出、Pin、多选转发、清空等功能与现在完全相同。左栏顶部的搜索框既能按名字找会话，也能跨会话搜聊天内容，并且可以勾选若干会话限定搜索范围。左栏宽度可以拖动调整，也可以整栏折叠。

以下口径均已与用户逐条确认（2026-10-03），实现时不再另行请示：

| 决策点 | 取值 | 详见 |
| --- | --- | --- |
| 窗口形态 | **升级现有的消息记录窗**，不另起新窗口；所有「消息记录」入口都打开它并在左栏选中对应会话 | §3.1 |
| 「全部会话」混排视图 | **不做**。右侧始终只显示一个会话，跨会话的需求由搜索满足 | §3.1 |
| 左栏数据来源 | 主面板会话缓存（服务端会话列表）与本地库里有记录的会话**取并集**；服务端不改 | §4.1 |
| 搜索范围 | 默认搜所有会话；可以在范围弹层里**勾选多个会话**，只在这些会话里搜 | §5.2 |
| 搜本机还是服务器 | **只搜本机已保存的记录**，结果处注明 | §5.3 |
| 左栏宽度 | **可以拖动调整，也可以折叠**；宽度与折叠状态存进账号配置 | §3.3 |

## 2. 现状

以下结论均已核对代码（据实证）。

### 2.1 消息记录窗

- `CBalloonHistoryWindow`（`flamingoclient/Source/UI/BalloonHistory/BalloonHistoryWindow.h`）是主面板的成员 `m_historyWindow`，整个进程只有一个实例。
- 它一次只显示一个会话，但开着时可以直接切换到另一个会话：`OpenForConversation` 在窗口已存在时走"重定向到新会话"的分支，重置筛选条件、重新统计并刷新，不重建窗口。
- 右侧功能：类型胶囊（全部 / 文字 / 图片 / 文件 / 语音 / 链接 / Pin）、时间下拉与「选日期」、发送人下拉、关键字、分页与跳页、导出（文本 / 网页）、图片网格、行右键菜单、多选后合并转发 / 逐条转发 / 删除、「清空聊天记录」、翻到末页时向服务端往前拉取更早的消息。
- 客户区控件树由 `HistoryWindowLayout.cpp` 的 `BuildHistoryWindowBody` 构造，根是一个 `DuiVBox`。窗口默认 898×737、最小 640×460（`BalloonHistoryWindow.cpp` 的 `kHisWindowWidth` 等常量）。

### 2.2 主面板与消息记录窗之间的交互

`CBalloonMainPanel::OpenHistory` 打开窗口后，向服务端补拉该会话最新 100 条消息（`RequestSyncMessages`）和该会话的 Pin 全集（`GetPinnedMessages`）。此后主面板发给窗口的所有回调都按"窗口当前显示的那个会话"判断是否与它有关：

| 调用 | 场合 |
| --- | --- |
| `RefreshIfConversation` | 同步应答落库、实时收到新消息、撤回、Pin 变化、删除消息之后 |
| `RefreshIfOpen` | 按时间范围清理本地库之后 |
| `IsOwnOlderFetch` | 判断一页同步应答是不是本窗口往前拉取发出的 |
| `OnImageDownloadFinished` / `OnFileDownloadFinished` | 本窗口发起的下载有结果了 |
| `IsShowingConversation` + `DestroyWindow` | 本人离开某群后，如果窗口正显示这个群就**直接关掉整个窗口** |
| `ShowToast` | 从本窗口发起的转发全部成功 |

这套机制以"只有一个窗口、一次只显示一个会话"为前提。升级后这个前提不变，这些调用都不用改，只有离开群那一处要改成"删掉左栏那一行并选中下一个会话"。

### 2.3 本地库

- `CV2MsgStore` 把消息存进每个用户一份的 `ChatLog\msgv2.db`。表 `t_msg` 主键 `(ctype,cid,msgid)`，另有索引 `idx_conv_time (ctype,cid,timestamp)` 与 `idx_conv_type (ctype,cid,msgtype)`。全部读写在界面线程上同步执行。
- 每个会话在 `t_cover` 里记一段覆盖区间（`HistoryCoverage.h`）。消息记录窗只显示区间内的消息；没有区间（刚登录、断网）时不限制。
- 跨会话的关键字汇总查询 `CV2MsgStore::SearchConversations` 已经写好，单测在 `Tests/GlobalSearchStoreTests.cpp`（标签 `[globalsearch]`），主面板搜索下拉经后台查询线程 `CV2MsgSearchWorker` 调用它。它的可见口径与消息记录窗相同（`V2MsgQuery.cpp` 的 `kSearchFromWhere`）：未撤回，且该会话没有区间、已拉到最早一条或 msgid 不小于区间下界。它不计文件、文件夹传输、文件共享卡片三类（这三类由同文件的 `SearchFileMessages` 负责）。

### 2.4 服务端

- `cmd_sync_conversations`（1501）返回本人的全部会话，不限条数，但会把用户「从列表删除」的会话隐藏起来（`t_conversation.f_deleted` / `f_deleted_msgid`，见 `MessageManager::getConversationBriefs`）。被隐藏的只是列表项，服务端的聊天记录仍在，之后来了新消息会话会重新出现。
- 群会话要有消息才会出现在会话列表里。
- `cmd_search_messages`（1515）是按单个会话的服务端搜索，客户端目前没有用。本方案不用它（§5.3）。

### 2.5 可复用的 balloonui 控件

- **会话列表**：主面板的会话列表就是 `DuiTreeView`，头像、名字、摘要、右侧时间分别用 `SetItemLabel`、`SetItemSubLabel`、`SetItemRightStacked` 等现成接口（见 `CBalloonMainPanel::AddConversationNode`）。
- **左右分栏**：`DuiSplitter`。客户端聊天窗的消息区与输入区之间已经在用（`Tests/ChatWindowLayoutTests.cpp` 的 `kIdInputSplitter`）。它没有折叠接口，只有 `SetSplitPx`、`SetMinSizes`、`SetSplitFraction`；balloonui 测试里它有一条既有失败用例 `HitTestBarRegion`（开发约定文档记录的基线），不影响聊天窗的实际拖动。
- **勾选列表**：转发目标选择窗（`UI/BalloonMain/ForwardTargetDlg.h`）「最近会话」页的行是 `DuiButton`（复选框）+ `DuiAvatar` + `DuiLabel`，勾选集合在纯逻辑模型 `ForwardTargetSelection` 里。范围弹层照这个形式做。

## 3. 界面

### 3.1 整体布局

```
┌────────────────────────┬────────────────────────────────────────────┐
│ 🔍 搜索会话或聊天内容   «│ 消息记录 · 张三                          ✕ │
│ 范围：全部会话 ▾        │ 共 1,234 条消息                            │
│ [全部] [单聊] [群聊]    │ 🔍 搜索…                  [全部成员 ▾]     │
│────────────────────────│ [全部][文字][图片][文件][语音][链接][Pin]  │
│ (头像) 张三       10/02 │ [全部时间 ▾] [选日期]                      │
│        好的，明天见      ┃ ────────────────────────────────────────── │
│ (头像) 产品群     09/30 ┃   消息列表（与现在完全相同）               │
│        [图片]            ┃                                            │
│ …                      ┃                                            │
│                        │ 共 N 条 · 第 x/y 页   [分页]   清空  导出   │
└────────────────────────┴────────────────────────────────────────────┘
                         ↑ 分隔条，可左右拖动
```

- 客户区根容器由现在的 `DuiVBox` 改为一个竖向分隔的 `DuiSplitter`：pane 0 是新的左栏，pane 1 是现在 `BuildHistoryWindowBody` 构造的整套右侧界面，原样放进去。
- 右侧标题仍是「消息记录 · <会话名>」；窗口标题（任务栏上显示的）改为「聊天记录管理」。
- 只有一个窗口，不做「全部会话」混排视图。

### 3.2 左栏组成

自上而下：

1. **搜索框**，提示文字「搜索会话或聊天内容」，右侧是折叠按钮「«」。
2. **范围按钮**「范围：全部会话 ▾」，勾选了会话后显示「范围：已选 N 个会话」，旁边出现「×」可一键恢复为全部（§5.2）。
3. **类型筛选**：全部 / 单聊 / 群聊，形式与右侧的类型胶囊一致。
4. **会话列表**（`DuiTreeView`，只有一层）。每行：头像、会话名、右侧最后一条消息的日期、第二行摘要。不显示未读数、不显示置顶标记——这里不是收消息的地方。

搜索框里有字时，第 4 项换成搜索结果（§5.1）。

### 3.3 拖动与折叠

- 左栏宽度用 `DuiSplitter` 拖动调整，松手时（`DUIN_VALUECHANGED`）记下宽度。
- 折叠：点左栏顶部的「«」后，左栏宽度变为 0，右侧标题左边出现「»」按钮，点它恢复。`DuiSplitter` 没有折叠接口，计划**不改 balloonui**，在客户端这样实现：折叠时把左栏的最小宽度设为 0 并 `SetSplitPx(0)`，展开时恢复最小宽度和折叠前的宽度。折叠期间分隔条仍可拖动，拖出来即视为展开。这一做法已由第 2a 步的布局单测验证（含"折叠后再展开"，见第 10 节），没有改 balloonui。
- 宽度与折叠状态存进账号配置，与窗口位置、大小放在一起（现在关窗时已经保存窗口矩形，见 `OnDestroyMsg`）。
- 尺寸（`HistoryWindowLayout.h` 的 `kMgr*` 常量，均为像素，balloonui 的布局尺寸不随 DPI 缩放，与原来消息记录窗的写法一致）：左栏默认宽 260、最小 200；分隔条宽 5，折叠后为 1；右侧最小宽度 640（原来消息记录窗的最小窗口宽度，底部一行的取舍已按它验证过）。窗口默认宽度 = 原来的 898 + 左栏宽度 + 分隔条；最小宽度展开时为 200 + 5 + 640，折叠时为 640 + 1。展开左栏时窗口比最小宽度窄，就把窗口向右加宽到最小宽度。布局单测见 `Tests/HistoryManagerLayoutTests.cpp`（HML2 核对默认宽度下右侧仍是 898 宽，HML4 核对两侧最小宽度）。

### 3.4 入口

| 入口 | 行为 |
| --- | --- |
| 主面板系统菜单新增「聊天记录管理」（`kSysMenu` 新增编号 11） | 打开管理器；上次查看的会话仍在左栏里就选中它，否则选中最近的那个会话；左栏为空时右侧显示空状态 |
| 单聊窗 / 群聊窗的「消息记录」按钮、「已 Pin N 条」提示带 | 打开管理器并在左栏选中该会话、滚动到可见；Pin 提示带仍预选 Pin 胶囊 |
| 会话右键「消息记录」、通讯录右键「查看消息记录」、群资料里的入口 | 同上 |

这些入口都经 `FMG_MSG_OPEN_HISTORY` / `CBalloonMainPanel::OpenHistory` 进来，接口不变，调用方不用改。左栏折叠着时从这些入口打开，保持折叠，不自动展开。

## 4. 左栏会话列表

### 4.1 数据来源与合并

两份数据取并集：

- **服务端列表**：主面板的 `m_conversations`（`net::ConversationItem`），有名字所需的 ctype/cid、最后一条的时间与服务端拼好的摘要。
- **本地列表**：本地库里有可见记录的会话（第 1a 步新增的查询，§7）。它的作用是把「从列表删除」、但本机缓存着记录的会话也列出来。

合并规则（第 1b 步的纯逻辑，有单测）：

1. 按 `(ctype, cid)` 去重。两边都有时，最后时间取较晚的一份，摘要跟着取那一份。
2. 只在本地有的群会话，如果群列表已经加载、而本人不在这个群里，就不列出——离开群时本地记录理应已被删除，这一条用来兜住旧版本留下的残余数据。群列表还没加载时照常列出。
3. 按最后时间倒序；时间相同按最后一条的 msgid 倒序，再相同按会话类型、cid 升序，保证顺序稳定。不把置顶会话排在前面。
4. 摘要：服务端那份直接用 `m_digest`（撤回的按主面板现有规则改写）；只在本地有的，用 `HistoryView.h` 的 `PreviewFromContent` 由最后一条记录生成，口径与会话列表摘要一致。
5. 名字和头像沿用主面板的规则（`ResolveSenderName`、`GroupDisplayName`、头像缓存），不另写一份。

### 4.2 筛选

- 类型：全部 / 单聊 / 群聊。
- 名字：搜索框里的文字按会话名匹配，支持拼音全拼与首字母，复用 `UI/BalloonSearch/ContactMatch` 与拼音表。

### 4.3 实时更新

| 事件 | 左栏的反应 |
| --- | --- |
| 收到或发出新消息 | 对应那一行刷新时间与摘要并移到正确位置；没有这一行时插入。短时间内多次变化合并成一次刷新 |
| 服务端会话列表重新同步（重连后） | 按 §4.1 重新合并 |
| 会话被清空 | 行保留（会话仍在），右侧照常刷新为空 |
| 本人离开群、被移出、群被解散 | 删掉那一行；正在显示它时自动选中下一行，没有下一行就显示空状态。不再关闭整个窗口 |
| 别处「从列表删除」了某个会话 | 行保留（聊天记录还在） |

### 4.4 右键菜单

打开聊天窗口、导出聊天记录、清空聊天记录。后两项与右侧底部的按钮走同一套流程（导出时先切到该会话）。

## 5. 跨会话搜索

### 5.1 搜索结果的组成

搜索框里有字时，左栏列表换成两段：

1. **会话**：会话名匹配的会话（§4.2），点击即切换。
2. **聊天记录**：用 `SearchConversations` 列出命中的会话，每行显示会话名和「N 条相关聊天记录」；只命中一条时直接显示那条的文字。点击后右侧切到该会话，并把关键字填进右侧搜索框，右侧列表即按关键字筛选。

输入停止一小段时间后再查询，与右侧搜索框的延迟查询做法一致。

### 5.2 指定搜索范围

- 点「范围：全部会话 ▾」弹出一个带搜索框的勾选列表，列出左栏的全部会话，形式与转发目标选择窗的「最近会话」页相同（复选框 + 头像 + 名字）。
- 勾选后搜索只在这些会话里进行，「会话」与「聊天记录」两段都受它限制。没有搜索词时左栏列表同样只列出范围里的会话——范围按钮就在列表上方，列表与它显示的范围一致，不会出现「范围显示已选 3 个、列表却列着全部会话」的情况。
- 与主面板搜索下拉的「消息」标签（`SearchConversations`）不同，这里**不排除**文件、文件夹传输记录、文件共享卡片三类：管理器只有一份结果，文件名也要能搜到；这样「N 条相关聊天记录」也与点进去之后右侧按同一个词筛出的条数一致。数据层为此另写了 `CV2MsgStore::SearchConversationsForManager`，没有改动 `SearchConversations`。
- 范围只在本窗口打开期间有效，不存盘；关窗后重新打开恢复为全部会话。
- 数据层要给 `SearchConversations` 增加一个"限定会话集合"的参数（第 1c 步）。集合为空表示不限。

### 5.3 只搜本机

只查本地库，不向服务器发请求。本机从没同步过的老消息搜不到，所以「聊天记录」那一段的标题注明「仅搜索本机已保存的记录」。

## 6. 切换会话

- 左栏点击一行，走 `OpenForConversation` 现成的切换路径（重置筛选条件、刷新右侧），并由主面板补拉该会话最新 100 条与 Pin 全集——与现在从入口打开时做的事相同。主面板把 `OpenHistory` 里发这两个请求的部分拆成单独的函数，供切换时调用。
- 快速连续点击时不能每次都发请求：切换后先等 300 毫秒（`kMgrBackfillDelayMs`），期间又切换了就只给最后停下来的那个会话发。
- 左栏刷新也做了合并：主面板每收到一条消息都会通知一次，窗口收到第一次通知后计时 400 毫秒（`kMgrRebuildDelayMs`），期间的通知不再重新计时，到点重建一次左栏。被动刷新不改动左栏的滚动位置，只有用户切换会话、或刚打开窗口时才把选中行滚进可见区域。
- 正在往前拉取、或正在为导出加载全部消息时切换会话，沿用现在 `OpenForConversation` 的处理：放弃在途的拉取，作废待导出的任务。

## 7. 本地库的会话列表查询（第 1a 步）

```cpp
//本地库里一个会话的汇总：最后一条可见消息的概况
struct LocalConversationBrief
{
    int         m_ctype;          //会话类型：1单聊 2群聊
    int64_t     m_cid;            //会话ID（我方视角）
    int64_t     m_lastMsgid;      //最后一条可见消息的 msgid
    int64_t     m_lastTimestamp;  //它的时间（Unix毫秒）
    int64_t     m_lastFromid;     //它的发送人
    int         m_lastMsgtype;    //它的内容类型
    std::string m_lastContent;    //它的归一化内容JSON，供生成摘要
};

bool CV2MsgStore::QueryConversationList(std::vector<LocalConversationBrief>& out);
```

口径：

- 每个会话取 msgid 最大的一条**未撤回**消息作为最后一条（msgid 由服务端全局单调分配，与服务端会话摘要取 `MAX(f_msgid)` 一致）。
- 这一条必须按覆盖区间可见（与 `kSearchFromWhere` 同一口径）。它不可见时，比它更早的也都不可见，整个会话不列出。
- 结果按最后时间倒序，时间相同按 msgid 倒序。

性能：查询在界面线程上执行。写法上逐个会话沿主键索引跳到下一个会话（先在同一会话类型里找下一个 cid，找不到再跳到下一个类型），再按主键倒序取它第一条未撤回的行，避免对全表按会话分组；整轮查询放在一个读事务里。实测结果与两处优化的来历见第 10 节 1a。

### 11.4 通配符搜索

规则：

- 勾选「通配符」后：`*` 匹配任意个字符（含零个），`?` 匹配恰好一个字符（Unicode 字符，汉字、表情都算一个）；匹配方式仍是「包含」，相当于两端各有一个 `*`。不勾时 `*`、`?` 按普通字符。
- 大小写规则与现在相同：只忽略 ASCII 字母的大小写。
- 输入里去掉 `*` 之后什么都不剩（如只输了 `*` 或 `**`）时，按「没有关键字」处理。
- 适用范围：管理器里的全部搜索，即右侧会话内搜索、左栏跨会话搜索、文件 / 图片页的文件名搜索、时间轴搜索。主面板搜索下拉与服务端搜索不在本期范围内。

做法：

- **转成 `LIKE` 串**：先在 `\ % _` 前加反斜杠，再把 `*` 换成 `%`、`?` 换成 `_`，前后加 `%`，配 `ESCAPE '\'`。不勾时用现有的 `MakeLikePattern`。
- **全文索引加速**：按 `*`、`?` 把输入切成几段普通文字，取不少于 3 个字的段，各自按 `MakeFtsPhrase` 加引号后用 ` AND ` 连起来交给 `MATCH` 找候选行，再用 `LIKE` 复核。每段文字都出现在命中行里，候选行一定包含 `LIKE` 的全部命中，结果与只用 `LIKE` 相同。没有一段够 3 个字时整表 `LIKE`。
- **高亮**：按通配符找出命中区间，取最左、最短的匹配（不让一个 `*` 把整行标黄），命中之间不重叠。`?` 在 UTF-16 里把代理对算作一个字符，与 SQLite 的 `_` 一致。
- **据实证**（第 5a 步 `[wildcard]` 的 WC 组用例）：SQLite 的 `LIKE` 里 `_` 按 UTF-8 字符而不是按字节匹配，一个汉字算一个。
- **悬停说明**（2026-10-07 用户要求）：「通配符」复选框挂多行悬停提示（`MakeWildcardCheckbox` 里 `DuiToolTipMgr::Register`，左栏范围行、右侧搜索行与文件页三处同一份文字），讲清 `*`、`?` 的含义，给出 `会议*纪要`、`张?`、`202?年`、`报告*.pdf` 四个示例，并说明仍按「包含」查找、不区分英文大小写、不勾选时按普通字符查找。用例 HML11。

### 12.3 搜索语法

- **适用范围**：右侧会话内搜索（含时间轴模式）、左栏跨会话搜索、「与我有关」页与链接页的搜索。文件页的文件名搜索只认多个词、排除词与引号，其余限定词不适用（文件名里没有这些信息），写了也忽略。
- **规则**：按空白（含全角空格）切分；`"…"` 或 `“…”` 括起的部分是一个词；`-词` 排除（单独一个 `-` 按普通字符）；`from:` / `发送人:`、`type:` / `类型:`（文字、图片、文件、语音、链接、Pin 及对应英文）、`after:` / `before:`（`YYYY-MM-DD`、`YYYY/MM/DD`、`YYYYMMDD`，`before` 含当天）是限定词，限定词名不区分大小写，认不出的 `xxx:` 按普通词处理（`http://…` 不受影响）。勾选通配符时每个词各自按通配符解释。
- **与界面筛选的关系**：限定词与类型胶囊、时间下拉、发送人下拉同时生效（取交集），不回写到界面控件。
- **`from:` 的解析**：本地库只有 userid。会话内搜索按本会话发过言的人的显示名匹配（包含即可，ASCII 不分大小写）；跨会话搜索（以及链接页、与我有关页）按本地库里发过言的所有人（`CV2MsgStore::QueryAllSenders`，窗口打开期间缓存一份）经主面板解析出的显示名匹配。一个都匹配不上时这次搜索没有结果。
- **做法**：纯函数 `ParseHistorySearch` 把输入切成正向词、排除词与限定条件；`BuildWhereClause` 为每个正向词加一个 `LIKE ?`、每个排除词加一个 `NOT LIKE ?`，限定条件直接写进语句；绑定按同一顺序进行。全文索引加速取各正向词里不少于 3 个字的段用 AND 连接。高亮把各正向词的命中区间合并。搜索框悬停时显示语法说明。
- **兼容性**：以前「季度 报告」（中间有空格）按整串匹配，现在是两个词同时包含，结果是原来的超集；要按原样匹配请加引号。

### 12.7 导出增强

- 导出浮层：范围（当前会话 / 选择会话：浮层里直接列出全部会话供勾选，每行沿用搜索范围浮层的行样式；浮层里不能再弹出第二个浮层，弹出时第一个会因失去焦点关闭）、时间（全部 / 近 7 天 / 近 30 天 / 近 3 个月 / 近半年 / 近一年 / 按当前筛选条件，最后一项只对当前会话有意义，其它会话按全部时间）、格式（网页 / 纯文本）、附件（包含图片、包含本机已有的文件）、打包为 zip。纯文本格式带附件时，附件同样放进 `_files`，文本里在那一行末尾注明相对路径。
- 单个会话且不打包时与原来相同：选保存位置，生成网页（图片放在 `_files` 文件夹）或纯文本。多个会话或打包时选一个文件夹（或 zip 文件），每个会话一个子文件夹 `<会话名>/`，里面是网页或文本与附件。
- zip 用程序自带的 zlib 写（deflate 压缩、CRC32），不依赖系统组件；路径按 UTF-8 编码并置 UTF-8 标志位，Windows 资源管理器与常见解压工具都能正确显示中文名。单个 zip 超过 4 GB 时提示改为导出到文件夹（不写 ZIP64）。
- 导出在后台线程进行，右侧显示进度提示条，完成后提示「已导出 N 个会话」并可打开所在文件夹。
