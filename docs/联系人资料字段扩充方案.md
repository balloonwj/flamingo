# 联系人资料字段扩充方案

> 作者：balloonwj@qq.com　起草日期：2026-10-04
> 用途：记录联系人资料窗新增个性签名、性别、生日、所在地、邮箱、岗位、手机号、座机八个字段（当前登录人可就地编辑其中七个）的需求结论、现状盘点、协议与界面设计、分期步骤与测试用例；第 9 节为 2026-10-06 追加的「手机号、座机对同事的公开范围」。后续每步开工前据此细化、收尾后回填实际结果。

## 1. 需求与已定决定（2026-10-04 与用户逐项确认）

| 事项 | 决定 |
| --- | --- |
| 编辑入口 | 联系人资料窗打开的是本人时，字段可直接在窗里编辑（2026-10-07 起本人资料只由联系人资料窗承担，见第 10 节） |
| 可改字段 | 个性签名、性别、生日、所在地、邮箱、岗位、座机，共 7 个本人可改；**手机号只显示、不允许本人修改**（它是注册时唯一、找回密码时按它发验证码的凭据） |
| 岗位 | 本人填写的自由文本，与部门无关；界面上叫「岗位」。管理员按部门设的「职位」（`t_department_member.f_position`）原样保留 |
| 头部括号 | 联系人资料窗头部姓名旁的括号仍显示部门职位，不变 |
| 窗口布局 | 窗口加宽（420 → 600），新增「个人资料」区块：个性签名独占一整行，其余 7 个两列排列，小字标签在上、值在下（卡片式），见第 4.2 节示意 |
| 性别编码 | 统一为 **0 = 未设置（界面显示「保密」）、1 = 男、2 = 女**，与管理后台一致；客户端改用这套编码，下拉框增加「保密」 |
| 他人与本人 | 看别人时 8 个字段只读、对方没填的不显示；看本人时 8 个都显示，没填的显示灰色「未填写」，7 个可改字段旁有编辑入口 |
| 编辑方式 | 与同一窗口里「备注名」一致，逐格就地编辑：回车或点到别处保存，Esc 取消；性别用下拉框，生日按 YYYY-MM-DD 输入并在保存前校验 |
| 校验 | 长度上限按库里列宽（签名、所在地、邮箱 256 字，岗位、座机 64 字）；邮箱只查含「@」；座机只允许数字、空格与 `+ - ( )`；新增的岗位纳入敏感词检查 |
| 看本人时的其余部分 | 隐藏语音 / 视频通话、发消息、备注名、分组、标签、消息提醒、收藏；只留头部、「历史消息」「组织架构」快捷按钮、「个人资料」区块与关闭按钮，窗口相应变矮 |
| 本人的入口 | 通讯录双击自己、右键「查看资料」、搜索选中自己，改为打开联系人资料窗（本人可编辑），与群聊 @ 菜单、群管理成员菜单一致；2026-10-07 起主面板头部与系统菜单「个人信息」也打开联系人资料窗（第 10 节） |
| 不做的 | 管理后台（flamingoAdmin）的员工编辑这次不加「岗位」；手机号更换（短信验证）不做 |

## 3. 协议与数据（服务端）

### 3.1 表结构

`t_user` 新增 `f_post varchar(64) DEFAULT NULL COMMENT '岗位：本人填写的自由文本，与部门职位无关'`。改 `table_mysql.sql` 后运行 `python tools/gen_table_sqlite.py` 重新生成 SQLite 架构，并在 `MysqlManager.cpp` 的列清单里加一行。

### 3.2 下发字段

通讯录列表 `contacts[]`、登录应答的本人资料、资料 JSON（1103 应答与 1108 推送）都新增：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `landline` | 字符串 | 座机，未填为空串 |
| `post` | 字符串 | 岗位，未填为空串 |

`gender` 的取值在协议文档里写明：0 = 未设置、1 = 男、2 = 女。

### 3.3 改资料请求（1104）

新增两个可选字段 `landline`、`post`，与已有字段一样「带了才改」。服务端新增校验，不合法时回 `error_code_bad_request`：

- 长度按 UTF-8 字符数：签名、所在地、邮箱不超过 256，岗位、座机、昵称不超过 64；
- `gender` 只接受 0、1、2；`birthday` 只接受 0（清空）或合法的 YYYYMMDD；
- 请求里即使带了 `phonenumber` 也忽略（手机号不允许本人修改）。

敏感词检查增加岗位（座机是号码，不查）。`updateUserInfoInDb` 的全部文字字段改为经 `dbapi::EscapeString` 转义后再拼 SQL，并补写座机与岗位。

## 4. 客户端

### 4.1 数据层

- `net::ContactItem` 增加 `m_gender`、`m_birthday`、`m_phone`、`m_mail`、`m_landline`、`m_post`，解析通讯录列表时读取；1108 推送解析全部资料字段，`OnUserInfoChanged` 全部回写（目前所在地也没有回写）。
- `CBuddyInfo` 增加座机、岗位，登录应答解析时读取。
- 性别：新增一组纯函数在编码与界面文字之间转换（0「保密」、1「男」、2「女」，经 `TR`），联系人资料窗使用；其余取值按「保密」显示。
- 改资料请求只带改动过的字段（`buildUpdateProfileRequest` 现在每次全发六项），新增座机、岗位，不带手机号。

### 4.2 联系人资料窗

窗口宽 420 → 600，其余区块随之加宽、排版不变。新增「个人资料」区块，位置在快捷操作行之下、备注名等设置行之上：

```
│── 个人资料 ────────────────────────────────────────│
│ 个性签名                                         ✎ │
│ 在出差路上，有事留言                                 │
│ 性别                     ✎  生日                  ✎ │
│ 女                           1996-08-12              │
│ 所在地                   ✎  岗位                  ✎ │
│ 北京                         交互设计师              │
│ 邮箱                     ✎  座机                  ✎ │
│ jiang@flamingo.im            010-8888 6666           │
│ 手机号                                              │
│ 138 0000 0000                                       │
```

- 看别人：只读，没有铅笔；没填的格子不显示，后面的格子按顺序前移补位；八个都没填时整个区块不显示。
  多于两行时默认只显示前两行，小标题右侧出现「展开全部」链接，点开后显示全部并变为「收起」（2026-10-04 用户确定：
  资料填全的人全部展开时窗口约 950 像素高，1366×768 或 125% 缩放的屏幕放不下）。每次打开资料窗都从收起开始，
  资料变更推送引起的刷新保持当前的展开状态。
- 看本人：八格都显示，没填的显示灰色「未填写」；七个可改字段有铅笔，手机号没有。语音 / 视频通话、发消息、备注名、分组、标签、消息提醒、收藏都隐藏，窗口相应变矮。
- 本人的入口：主面板里通讯录双击、右键「查看资料」、搜索选中本人这三处，原先改道到本人资料对话框，改为打开联系人资料窗，并由主面板把「是本人」传给窗口（窗口自身不做判定，与现有分层一致）。
- 就地编辑：同一时间只有一格处于编辑态；回车或失焦保存、Esc 取消；保存经主面板发改资料请求，先乐观更新本人资料，失败按原值回滚并提示（含敏感词失败）。成功后主面板头部一并刷新。
- 高度：区块高度随可见行数变化，`ContactBodyHeight` 增加可见行数参数；显隐变化后对父容器 `ForceLayout`（UI 约定第 5 条）。
- 实现：区块只用现有控件拼成。内嵌 XML 里放占位标记 `<contact-profile-block/>`，构建时替换成代码生成的片段：
  0 号槽位是昵称格（只在看本人时有内容，2026-10-07 起，见第 10.3 节）、1 号槽位是签名格，各独占一行，2～8 号槽位每行两个；格子数据（`BuildContactProfileCells`，在 `ContactModel.h`）按顺序
  填进槽位，控件 id 占 1100–1199 一段。

### 4.3 本人资料对话框

> 2026-10-07 起本人资料对话框（`CBalloonProfileDlg`）已删除，本人资料统一由联系人资料窗承担，见第 10 节。本节保留为当时的记录。

- 性别下拉框改为「保密 / 男 / 女」三项，按新编码读写。
- 新增「岗位」「座机」两行（可编辑）与「手机号」一行（只读）；窗口相应加高，`kMaxContainers` 调大，配一条按设计尺寸排得下的布局单测（UI 约定第 7 条）。

### 4.4 多语言

新增界面文字（「个人资料」「岗位」「座机」「手机号」「未填写」「保密」、各条校验提示）都包进 `TR`，运行提取脚本并补齐四种语言的译文；英文下两列的格宽按「只增不减」检查。

## 7. 风险

- **性别历史数据**：此前经客户端保存过性别的人，「男」（0）会显示成「保密」、「女」（1）会显示成「男」，需要本人重新选一次。库里的值无法区分是谁写的，不做迁移。
- **窗口变宽**：600 宽在 1366×768 的屏幕上仍放得下，但字段、部门行、标签行都取最多时整窗较高，PFX12 会给出具体上限，届时如超出工作区再与用户商量。
  已商量（2026-10-04）：看别人时区块默认收起成两行（见 4.2 节），部门一行、标签一行时整窗约 774 像素；
  展开全部后仍可能超出小屏幕的工作区，由用户自行收起。

## 9. 手机号、座机对同事的公开范围（2026-10-06 用户追加）

### 9.1 需求与已定决定（2026-10-06 与用户确认）

| 事项 | 决定 |
| --- | --- |
| 需求 | 每个人可以在自己的资料里分别设置手机号、座机是否对同事公开 |
| 默认值 | 手机号不公开（仅自己可见），座机公开（对同事可见）。老账号升级后同样取这个默认值，即升级后所有人的手机号先对同事隐藏 |
| 不公开时同事看到什么 | 这一格不出现，与没填写相同，不显示「未公开」之类的提示 |
| 本人看到什么 | 号码照常显示，同时显示当前设置「仅自己可见 ▾」或「对同事可见 ▾」 |
| 开关形式 | 文字加下拉菜单：点状态文字弹出两项菜单（「仅自己可见」「对同事可见」，当前项打勾），选中即保存 |
| 入口 | 联系人资料窗看本人时的手机号、座机两格（2026-10-07 本人资料对话框删除后只剩这一处） |
| 在哪里过滤 | 服务端。不公开时发给同事的数据里不带号码，而不是由客户端隐藏——只在客户端隐藏的话，抓包或旧版客户端仍能看到 |
| 管理后台 | 不受开关限制：flamingoAdmin 的员工管理与 monitor 端口照常能看到、编辑手机号与座机 |

### 9.2 现状（据实证）

- **号码下发给他人的路径有三条**（改动前都原样带出 `phonenumber` 与 `landline`）：
  - 通讯录列表：`ChatSession.cpp` 的 `fillContactInfo`；
  - 取资料 1103：`ChatSession.cpp` 的 `onGetUserInfo`；
  - 资料变更推送 1108：改资料与改头像两处，资料 JSON 由 `ProfileProtocol.cpp` 的 `makeProfileJson` 生成。

  登录应答只发给本人。管理后台走 `HttpSession` / `EmployeeManager`，monitor 走 `MonitorSession.cpp:134`，不在本次范围。群成员列表、搜索等其它下发不带这两个字段（全目录检索 `phonenumber|landline` 只命中上述几处）。
- **按人推送已有现成接口**：`broadcastToEnterprise` 带 `excludeUserId` 参数（`ChatServer.h:145-148`），`pushToUsers` 只推给指定 userid（`ChatServer.h:170`）。
- **同事端不用改显示逻辑**：客户端收到 1108 后 `applyUserInfoChanged` 无条件覆盖手机号与座机（`ContactsProtocolClient.cpp:249-251`），看别人时空字段不显示（`ContactModel.cpp` 的 `BuildContactProfileCells`）。所以推送里号码为空串时，同事端资料窗里这一格按「没填写」消失。
- **本人一侧的界面**：联系人资料窗的格子数据在 `BuildContactProfileCells`（`ContactModel.cpp`），手机号格本人也没有编辑按钮。

### 9.7 风险与不做的

- **升级后手机号对同事全部隐藏**：这是按默认值有意为之，但部署后同事会看不到原来能看到的手机号，上线时需要告知用户可以自行打开。

## 10. 资料窗多窗口、本人资料统一与行内编辑按键（2026-10-07 用户追加）

### 10.1 需求与已定决定（2026-10-07 用户确认）

1. **多个资料窗口并存**：一人一窗。再次打开同一个人时激活已有窗口（还原、前置，不重建界面、不冲掉正在编辑的内容）；「修改备注」入口激活已有窗口时只让备注名进入编辑态。新窗口相对上一个错开 24 像素摆放，超出工作区时回到起点（工作区居中的位置），并保证落在工作区内。本人只有一个资料窗。群成员侧栏、@ 菜单、群管理等入口对自己点「查看资料」时走看本人的入口。
2. **本人资料统一用联系人资料窗，删除本人资料对话框**：主面板头部点昵称区、系统菜单「个人信息」也打开资料窗看本人。资料窗看本人时补「昵称」可编辑格（区块第一格，回车提交、Esc 取消、失焦提交、本地校验不合格时提示并留在编辑态），提交走原有的 `FMG_MSG_CONTACT_PROFILE_EDIT`。头像显示真实头像，看本人时可点击打开修改头像对话框（离线拦截照旧），改头像成功后资料窗头像随之刷新。部门、职位原本就在资料窗头部（职务行与部门路径区块），整页「编辑 → 保存」的交互不再保留。
3. **行内编辑回车提交、Esc 取消**：资料窗「备注名」与群资料「我在本群的昵称」两处补上（Esc 恢复原值并退出编辑、不提交）；新增的昵称格同样支持；`InitUi` 不复位备注编辑态的问题一并修复。

- **2026-10-07 晚修正：资料格进入编辑时输入框里的文字下半截被裁掉**（用户截图 `snapshots/201141.png`，昵称格，其他格子一样）。
  原因（据实证）：资料格的输入框与性别下拉框固定 22 像素高；`DuiEdit` 只在「一行的高度 < 控件高 - 上下边框」时把单行文字垂直居中（`DuiEdit::ApplyTextInsets`），一行的高度按 `DuiRichEdit::GetLineHeight` 为默认字体的 `tmHeight + tmExternalLeading`。本机显示器为 120 DPI（125% 缩放），客户端按显示器感知 DPI，9 磅默认字体一行高 20 像素，正好等于 22 像素输入框去掉边框后的 20 像素，不满足「小于」，文字从顶部排、底部被裁掉。单元测试程序没有声明 DPI 感知，系统对它报告 96 DPI，一行只有约 17 像素，所以原有用例看不到这个问题。
  修法：`ContactLayout.cpp` 新增 `ContactProfileValueHeightForDpi` / `ContactProfileValueHeight` / `ContactProfileRowHeight`，值一行的高度取 22 与「该 DPI 下默认字体一行的高度 + 上下边框 + 上下各 2 像素余量」中的较大者，按本机所有显示器中最高的 DPI 计算（`i18n::MaxMonitorDpi`）；显示值的文字、输入框、性别下拉框三者同高，切换到编辑时排版不跳动，区块与窗口高度随之计算。120 DPI 下为 26 像素。
  用例 CWS8（`[contactwin][contactprofile]`）：在按显示器感知 DPI 的线程上下文里（`SetThreadDpiAwarenessContext`，与真实客户端一致）建资料窗控件树，逐个资料格进入编辑，检查输入框的行高小于控件高减上下边框、性别下拉框放得下一行，并检查群资料的群昵称输入框；另检查 96～192 各档 DPI 下算出的高度都放得下。修改前在本机失败（宿主 DPI 120，8 个输入框都是「高 22、行高 20」，`tmp/verify7/cws8_before.log`），修改后 `[contactwin],[contactprofile],[profilefields],[contact],[groupinfo]` 96 个用例全部通过，窗口用例 `[contact-wnd]` 5 个通过（`cws8_after.log`、`cww_after.log`）。待人工核对：实机上编辑昵称、签名等格子，文字完整显示。
