# 自动登录：可取消的自动登录与设置开关方案

> 目标：让用户在自动登录进行中能随时取消，并且登录之后也能随时打开或关闭自动登录。
>
> 涉及子项目：`flamingoclient/`（PC 客户端）。不动服务端、不动 Android。
>
> 本文是**方案**，§5 的决定已于 2026-09-30 与用户确认，按 §7 的步骤推进。

---

## 1. 需求与范围

| 编号 | 需求 |
| --- | --- |
| A | 自动登录时弹出登录窗并直接进入「登录中」，用户可以点「取消登录」中止；中止时顺带取消「自动登录」的勾选 |
| B | 系统设置「账号安全」页增加「自动登录」开关，登录后可随时打开或关闭 |

不在本轮范围：开机自启动（系统设置里已有，与自动登录是两回事）、多账号各自的自动登录策略（仍只看上次登录的那个账号）。

---

## 2. 现状（据实证）

### 2.1 自动登录的数据与入口

- 每个历史账号的「记住密码」「自动登录」两个标志与保存的密码存在 `Users\LoginAccountList.dat`
  （`Session/LoginAccountList.h` 的 `LOGIN_ACCOUNT_INFO`）。

### 2.2 登录窗里的两个复选框

- 勾「自动登录」会连带勾上「记住密码」，取消「记住密码」会连带取消「自动登录」；点一下即调
  `PersistCheckStateForCurrentAccount` 落盘，不必等登录成功（`UI/BalloonAuth/BalloonLoginDlg.cpp` 的
  `CBalloonLoginDlg::OnDuiNotify`，`DUIN_VALUECHANGED` 分支）。

### 2.3 现有的「取消自动登录」途径

1. 登录窗里取消勾选（§2.2）；
2. 主动登出：`ShouldClearAutoLoginOnExit` 对 `kLoginExitUserLogout` 返回 true（`UI/BalloonMain/KickoutNotice.cpp`）；
3. 被踢下线且原因为密码已修改、密码被管理员重置、企业已删除或账号已删除（同上）；
4. 登录时服务端报密码错误：`CSessionController::ForgetSavedPasswordForCurrentAccount` 清掉保存的密码与两个标志
   （`UI/BalloonMain/MainPanelSessionController.cpp`）；
5. 在登录窗的账号下拉框里删掉该账号。

2026-10-06 补充：账号与手机号都能登录之后，历史列表的键是登录窗里输入的原文（可能是手机号），而登录后本人资料里的账号是服务端返回的规范账号。第 2～4 条原先拿后者查列表，用手机号登录时查不到、标志清不掉；现在一律用输入的原文查（`PickLoginAccountListKey`），详见 `docs/登录账号与手机号登录方案.md` 第 5 节。

## 3. 方案 A：自动登录也弹出登录窗，可取消

### 3.1 流程

1. 会话控制器不再走「后台静默登录」那条路。自动登录时与手动登录一样弹出登录窗（模态），并事先告诉
   登录窗「这次要自动开始」。
2. 登录窗显示出来后，若要求自动开始、且账号与密码都已填好，就给自己投递一条窗口私有消息，在消息
   处理里调用 `OnLoginClicked()` —— 与用户手动点「登录」完全同一条路：先做登录前的更新检查，再切到
   「登录中」，主按钮变为「取消登录」。
   - 投递而不是在建窗过程中直接调用：此时窗口还没进入模态消息循环，界面尚未显示出来。
   - 本地没有保存密码（例如刚因密码错误被清掉）时不自动开始，停在登录窗等用户输入。
3. 用户点「取消登录」：本轮作废、界面回到可输入。若这一轮是自动发起的，**同时取消「自动登录」的勾选
   并立即落盘**（用户已确认，见 §5），下次启动不再自动登录。手动发起的一轮被取消时勾选不变。
4. 登录失败一律在登录窗里就地显示，不再先弹 MessageBox 再重新弹登录窗。密码错误时照旧清掉保存的密码
   与两个勾选。
5. 登录中点托盘图标可以把登录窗调到前台（此时登录窗已存在，`ShowLoginOrMainPanel` 能找到它）。

### 3.2 代价

- 网络好的时候登录窗会一闪而过（登录一般零点几秒完成）。
- 托盘的登录动画原本只服务于「没有登录窗」的自动登录路径；两条路合并后不再需要，随之删除。

## 4. 方案 B：系统设置里的「自动登录」开关

- 位置：系统设置「账号安全」页，与「修改密码」「二次验证」同一组。
- 本地账号列表由主面板的会话控制器持有（内存里一份，之后整份写回文件），设置窗口**不能**自己读写
  `LoginAccountList.dat`，否则会被会话控制器那份覆盖。故：
  - 打开设置窗时由主面板把当前账号的自动登录状态传进来，开关据此显示；
  - 拨动开关时，设置窗口向主面板投递一条消息（与「修改密码」按钮转发 `FMG_MSG_OPEN_CHANGEPWD` 同一做法），
    由会话控制器修改账号列表并落盘。新消息号按《客户端窗口消息号段规约与整改方案》取 B 段 4520 档
    （资料与设置类对话框 → 主面板），加完跑 `FlamingoUnit.exe "[msgid]"`。
- 关闭：只取消「自动登录」，不动已保存的密码与「记住密码」。
- 打开：同时打开「记住密码」，并把本次登录所用的密码存下，否则下次启动没有密码可用。

实现要点：

- 开关控件 id 为 `kIdAutoLogin = 606`（`BalloonSystemSettingDlg.cpp`，604 已被「登录日志」占用）。
- 消息为 `FMG_MSG_SET_AUTO_LOGIN`（`WM_USER + 4525`，`Session/UserSessionData.h`），wParam 为目标状态
  （1 开 / 0 关），无堆负载。它投给主面板，由挂在主面板消息链上的会话控制器
  `CSessionController::OnSetAutoLogin` 处理。
- 初始状态由主面板在 `OpenSystemSettingDlg` 里经 `CSessionController::IsAutoLoginEnabledForCurrentAccount`
  取得，再通过 `CBalloonSystemSettingDlg::SetAutoLoginSwitchState` 传入。
- 会话控制器除了修改历史账号列表，还必须同步修改自己的 `m_stAccountInfo`。每次登录成功（包括断线自动
  重连成功）时，`OnLoginResult` 会按 `m_stAccountInfo`（经 `CLoginAccountList::RecordLoginSuccess`）更新
  历史列表里该账号的密码与两个勾选项，只改列表的话，下一次重连就会把开关的修改恢复成旧值。

## 5. 已确认的决定（2026-09-30）

| 问题 | 决定 |
| --- | --- |
| A 与 B 做哪个 | 两个都做 |
| 自动发起的一轮被「取消登录」后，要不要顺带取消「自动登录」的勾选 | 要，并立即落盘 |

## 6. 测试用例

### 6.1 登录进度状态机（`Tests/LoginProgressStateTests.cpp` 追加）

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| LPA1 | 自动发起的一轮在「登录中」被取消 | 取消成功，并报告这一轮是自动发起的 |
| LPA2 | 手动发起的一轮被取消 | 报告不是自动发起的 |
| LPA3 | 自动发起的一轮结束（成功或失败）后，再手动发起一轮并取消 | 报告不是自动发起的，不沿用上一轮的标记 |

### 6.2 是否自动开始（新增纯函数）

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| ALS1 | 要求自动开始，账号与密码都有 | 自动开始 |
| ALS2 | 要求自动开始，但密码为空 | 不自动开始 |
| ALS3 | 没有要求自动开始 | 不自动开始 |

### 6.3 设置开关修改账号列表（新增纯函数 `ApplyAutoLoginSetting`，`Tests/LoginAccountListTests.cpp` 追加）

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| ALB1 | 关闭 | 自动登录变为关；记住密码与已存的密码不变 |
| ALB2 | 打开并传入当前密码 | 自动登录、记住密码都变为开，密码被存下 |
| ALB3 | 账号不在列表里 | 返回失败，列表不变 |
| ALB4 | 修改后写文件再读回 | 各标志保持修改后的值 |
| ALB5 | 关闭后查询启动时是否自动登录 | 返回否 |

### 6.4 人工验证（真实客户端）

自动登录会用本机保存的账号去登录，可能把正在使用的客户端挤下线，故以下几项由用户在真实客户端里验证：

1. 勾选自动登录后重启：弹出登录窗并自动进入「登录中」；点「取消登录」后回到可输入状态，「自动登录」
   的勾已去掉；再重启不再自动登录。
2. 系统设置里打开 / 关闭「自动登录」，分别重启确认。
3. 停掉服务端后自动登录：错误直接显示在登录窗里。
