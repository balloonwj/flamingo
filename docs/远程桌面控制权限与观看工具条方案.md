balloonwj@qq.com　2026-10-12

## 1. 需求

用户 2026-10-12 提出以下要求：

1. 远程桌面被控端顶部的提示条（「您的桌面正在被 XXX 远程控制」+ P2P 徽标 +「结束控制」）改成与屏幕共享控制条一致的样式。
2. 远程桌面**默认不允许控制**，开启之后才能控制。控制者和被控者都可以开启：控制者要申请，由被控者同意；被控者可以直接开启。

## 3. 现状（调查结论，2026-10-12）

### 3.1 远程桌面的控制权限

- 唯一的授权是被控端接受邀请（1712 accept=1）。接受之后控制端只要解码器就绪就发送键鼠帧（`FlamingoMedia/RemoteDesktop/RdViewerWindow.cpp` 456-515），被控端收到就注入，没有任何判断（`RdControlledStreamer.cpp` 112-131）。
- 没有「仅查看」状态，也没有任何开关能禁止注入。imgserver 对 1854 只按命令号放行（`flamingoserver/imgserversrc/RelayHelloPolicy.cpp` 80-84），P2P 链路端到端透传，所以真正能把关的只有被控端客户端。
- 服务端会话表在接受之后从不调用 `setState`，会话一直记为响铃中（`RemoteDesktopManager`）。
- 被控端顶部条 `CRdControlledBar` 没有排除在截屏外，会被抓进推给控制端的画面。
- 远程桌面没有「输入落在 Flamingo 自己窗口上就丢弃」的过滤；屏幕共享有（`Share/ShareControllerControl.cpp` 386-397）。

### 3.2 屏幕尺寸、分辨率不同时

两个功能都采集物理像素：exe 启动时声明了按显示器感知 DPI（`Source/App/Startup.cpp` 220）。

| 项 | 远程桌面 | 屏幕共享 |
| --- | --- | --- |
| 采集范围 | 只抓主显示器（0 号显卡），不可选 | 可选任意显示器或单个窗口 |
| 编码 | 自研 16 位色差分编码，不缩放、无分辨率上限，5 fps | H.264，长边不超过 1920、宽高取偶数，最高 15 fps |
| 观看端显示 | **拉伸铺满窗口，不保持宽高比**（`RdScreenDecoder.cpp` 127-131） | 等比缩放、四周留黑边，默认全屏 |
| 鼠标坐标 | 按控件与画面的比例逐轴换成被控端绝对像素，`SetCursorPos` 注入 | 归一化到 0~65535、扣除黑边，被控端按显示器矩形换回物理坐标 |
| 远端指针 | **帧里不含指针，帧里带了位置但观看窗不画** | 画进视频帧 |
| 中途改分辨率 | **推流端不主动补发完整画面**（`ScreenFrameEncoder.cpp` 84-90，`RdControlledStreamer.cpp` 209）；走 P2P 时不定时发关键帧，画面一直错乱直到重连；GDI 降级路径感知不到分辨率变化 | 编码器重建并发关键帧；但**显示器矩形是开始共享时的快照**（`DxgiOutputCapturer.cpp` 45），控制、指针、标注都按旧矩形算；**采集重建失败后不再重试**（`ShareHostStreamer.cpp` 587-593），画面永久冻结 |

本次不处理、写进 `bugs.md` 的：两个功能都没处理屏幕旋转；远程桌面只抓 0 号显卡上的主屏；屏幕共享整屏没有 GDI 降级；屏幕共享观看端没有「1:1 原始大小」。（原列在这里的「非主持人的共享者被控制时共享者条上没有『收回控制』按钮」已在第 2.1 节 B 中修复。）

## 4. 设计

### 4.1 协议：1718 / 1719

两个号是 1700 段的空号（1717 是 `cmd_call_card_notify`，1720 起是屏幕共享）。

**1718 `cmd_rd_control`**（客户端 → 服务端）

```json
{"sessionid": "…", "action": 1}
```

应答 `{"code": 0, "msg": "ok", "sessionid": "…", "action": 1, "control": 1}`，`control` 是动作之后的控制状态。

| action | 名称 | 谁能做 | 前提 | 之后的状态 | 推 1719 给谁 |
| --- | --- | --- | --- | --- | --- |
| 1 | 申请 request | 控制端 | 未授权 | 申请中 | 被控端 |
| 2 | 撤回申请 cancel | 控制端 | 申请中 | 未授权 | 被控端 |
| 3 | 授予 grant | 被控端 | 未授权或申请中 | 已授权 | 控制端 |
| 4 | 拒绝 deny | 被控端 | 申请中 | 未授权 | 控制端 |
| 5 | 收回 revoke | 被控端 | 已授权 | 未授权 | 控制端 |
| 6 | 放弃控制 release | 控制端 | 已授权 | 未授权 | 被控端 |

重复的动作按成功处理、状态不变、不推送：申请中或已授权时控制端再申请，已授权时被控端再授予，都不打扰对方。

**1719 `cmd_rd_control_notify`**（推送）

```json
{"sessionid": "…", "action": 3, "control": 2, "fromid": "10001", "fromname": "tom"}
```

`control` 取值：0 未授权、1 申请中、2 已授权。

**错误码**（700 段的 740 起是空号）

| 码 | 名称 | 含义 |
| --- | --- | --- |
| 740 | `error_code_rd_not_exist` | 远程桌面会话不存在（已结束或 sessionid 无效） |
| 741 | `error_code_rd_not_participant` | 不是会话参与方，或角色不对（如控制端想授予） |
| 742 | `error_code_rd_control_state` | 当前状态不允许这个动作（会话还没接通、没有待处理的申请、没有在控制） |

**服务端**：`RemoteDesktopSessionInfo` 加「是否已接通」与「控制状态」两个字段。接受邀请时记为已接通，控制状态为未授权；控制动作只在已接通后有效。规则写成 `RemoteDesktopManager::applyControl` 纯逻辑，返回新状态与要通知的人；`ChatSession::onRemoteDesktopControl` 只负责编解码、发应答、推送和打日志。

**客户端**：`RemoteDesktopProtocolClient` 加编解码；exe 的信令白名单（`Source/net/MediaSignalPolicy.cpp`）与 DLL 的 `CRdController::IsRdSignal` 都扩到 1719。

### 4.2 被控端

- **把关**：新建纯逻辑类 `RdControlGate`（`RemoteDesktop/RdControlGate.h/.cpp`）。默认关闭；关闭时鼠标、键盘帧一律丢弃；记录仍按下的键与鼠标按钮，关闭时补发松开，避免按键卡住；落在本进程窗口上的输入不注入（判定复用屏幕共享的做法）。注入发生在中转或 P2P 接收线程上，开关用原子量。
- **开关时机**：被控者点「允许控制」或在申请提示上点「同意」后发 grant，应答成功才打开；点「收回控制」时**先在本地关闭**再发 revoke；收到控制端的 release（1719）时关闭；会话结束、锁屏、登出时关闭。
- **顶部条**：`CRdControlledBar` 重写成屏幕共享控制条的样式：深色底 RGB(44,48,56)、状态点 + 状态文字 + P2P 徽标、30×30 图标按钮（`ShareBarButtonArt`）、「隐藏」「收起」（`TopBarCollapse`），并排除在截屏外（`WDA_EXCLUDEFROMCAPTURE`）。状态文字分三种：「XXX 正在查看你的桌面」「XXX 申请控制你的电脑」「XXX 正在控制你的电脑」。按钮：允许控制 / 收回控制（同一个按钮，已授权时蓝底）、结束远程桌面（红）、隐藏、收起。
- **申请提示**：复用屏幕共享的右下角提示 `CShareCornerToast`：标题「控制申请」，正文「XXX 申请控制你的电脑」，按钮「同意 / 拒绝」，60 秒无操作按拒绝处理。控制端撤回申请时提示自动关闭。
- **授权对话框**：文案由「XXX 请求远程控制你的电脑」改为说明接受后对方只能查看，操作键鼠需要另行同意（具体措辞在实现时给出）。

### 4.3 共用的浮动观看工具条

新建 `CViewerFloatBar`（`Share/ViewerFloatBar.h/.cpp`，`DuiFrameWindow` 子类），屏幕共享观看窗与远程桌面观看窗共用。

- **外观与共享者控制条一致**：深色底、30×30 图标按钮、悬停提示、开关打开时蓝底、申请中橙色、录制中红色，左侧可放状态文字；「隐藏」「收起」沿用 `TopBarCollapse`。
- **位置**：窗口模式下浮在观看窗画面区域的顶部居中，跟随观看窗移动、缩放，观看窗最小化时隐藏；全屏时贴在显示器顶部居中。
- **窗口关系**：以观看窗为所有者，所以始终在观看窗之上、随它最小化，不在任务栏出现、不抢焦点（键盘焦点留在观看窗，远程桌面的按键转发不受影响）。按 UI 约定第 11 条，有所有者的 `DuiFrameWindow` 不能用 `WS_POPUP`，否则按钮通知会发给所有者。实现时（2026-10-12）用的是重叠窗口，建好后去掉系统自动加上的 `WS_CAPTION`；另外非弹出的顶层窗口改变大小时，`DefWindowProc` 会按最小跟踪尺寸把高度夹到至少 `SM_CYMIN`，收起时缩不成 18 像素高的小把手，所以工具条自己处理 `WM_WINDOWPOSCHANGING`、不交给 `DefWindowProc`（VB5 实测发现）。2026-10-14（8n）balloonui 改为只把 `WS_CHILD` 宿主的通知发给父窗口之后，工具条改回有所有者的 `WS_POPUP` 窗口，上述两处处理与 `WM_NCACTIVATE` 的处理一并删除（`WM_MOUSEACTIVATE` 的处理保留）。
- **按钮由使用方配置**：每个按钮给出种类、提示文字、外观（普通 / 打开 / 申请中 / 录制中 / 危险）、是否显示；点击时向通知窗口投消息，带按钮编号。条件按钮显隐变化后整条重排。
- `ShareBarButtonArt` 补图标：白板、共享说明、主持人（皇冠）、全屏、退出全屏、离开 / 断开，以及「申请中」的橙色外观。

### 4.4 屏幕共享观看窗

- 撤掉标题栏上全部自定义图标（`refreshMicIcon` 里的 `AddCaptionIcon`、`OnDuiNotify` 里的图标分支、那批 `make*Icon` 与 `HBITMAP` 成员），标题栏只留标题和最小化、还原、关闭。
- 浮动条按钮依次为：麦克风、摄像头、标注、录制、字幕（可用时）、申请控制、共享我的屏幕、新建白板、N 人观看 ▾、共享说明（有描述时）、主持人 ▾（经移交成为主持人时）、全屏 / 退出全屏、离开（非强制模式）、隐藏、收起。命令沿用现有的 `Command` 与 `kMsgShareViewerCommand`，控制器 `OnViewerCommandMsg` 基本不改。
- 窗口模式与全屏用同一条，原来借用的 `CRdViewerToolbar` 不再使用。字幕菜单、主持人菜单、观看者名单、共享说明浮窗改为弹在对应按钮下方。
- 顺带修掉「全屏状态下成为主持人后，『主持人 ▾』要等重建工具条才出现」的问题。

### 4.5 远程桌面观看窗（控制端）

- 浮动条按钮：申请控制（灰）/ 取消申请（橙）/ 结束控制（蓝）、全屏 / 退出全屏、断开（红）、隐藏、收起；状态文字「仅查看」「申请中」「控制中」。标题栏上原有的「全屏」图标移进浮动条。
- 控制端状态写成纯逻辑类 `RdViewerControlState`：未授权时不发送任何键鼠帧；收到授予后才发送；收到收回、拒绝或会话结束时停止。
- 两个观看窗都换掉之后删除 `CRdViewerToolbar`。

### 4.6 分辨率相关修复

1. **远程桌面等比显示**：画面按宽高比放进画面控件、四周黑边；鼠标坐标扣除黑边后再换算成被控端绝对像素，黑边上的移动不发送，按下在画面内、松开在画面外时夹到画面边缘照发。帧格式不变。
2. **远程桌面改分辨率后补发画面**：推流线程发现采集尺寸变化就立即发 BITMAPINFO + 首屏（P2P 路径也发）；GDI 降级采集器每次抓帧前比较屏幕尺寸，变了就重建。
3. **远程桌面显示远端指针**：观看端按帧里带的指针位置（被控端主屏坐标）换算到画面矩形里画出系统指针，指针形状按帧里的类型取。
4. **屏幕共享改分辨率后的两处**：采集器重建时重新读取显示器矩形，控制、指针、标注、边框都跟着更新；重建失败后按固定间隔持续重试，并把「画面暂停」状态告诉观看端，重建成功后恢复。

### 4.7 兼容性

- 新被控端 + 旧控制端：旧控制端不会申请，只能查看；它发来的键鼠帧被新被控端丢弃。
- 旧被控端 + 新控制端：新控制端未授权时不发键鼠，而旧被控端不会授予，所以只能查看。
- 旧服务端：不认识 1718，申请得不到应答，控制端申请状态一直停在「申请中」，可以手动撤回。部署时服务端与客户端一起升级。

- 发现并修复三处（均先写用例复现、修复后通过，`[viewerbar]`、`[rdctl]`、`[rdres]`、`[sharemulti]` 等 9 组 83 个用例全过）：
  1. 浮动工具条虽带 `WS_EX_NOACTIVATE`，点击时默认处理仍返回 `MA_ACTIVATE`，工具条变成前台窗口：观看窗失去键盘焦点，远程桌面控制中按键不再转发（据实证：被控端日志里的输入帧计数不变）；
