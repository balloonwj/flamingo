# 锁屏方案与开发计划

2026-10-05 ~ 10-06 与用户逐项确认。适用于 PC 客户端（`flamingoclient/`），新增可选模块 `FlamingoLock.dll`。动画样式以本地网页样稿为准（2026-10-06 用户确认五种动画的效果；汉字数字雨 2026-10-07 改为大红配色，与样稿不再一致，见第 12 节）。

## 1. 背景与目标

用户离开座位时，用客户端自己的锁屏把整块屏幕盖住：旁人看不到桌面上的内容、也操作不了电脑，只有输入密码才能解锁；锁屏期间播放客户端自己的动画，其中一种是「八荣八耻」的文案展示。

锁屏是「防旁人随手查看和操作」的隐私锁，**不能代替 Windows 自己的锁屏**：Ctrl+Alt+Del 是系统保留的组合键，普通程序拦不住，从任务管理器结束客户端进程即可解除锁屏（2026-10-05 已向用户说明，用户认可）。

## 2. 已确认的产品选择

| 事项 | 结论 |
| --- | --- |
| 入口 | 托盘右键菜单新增「锁屏」，登录前、登录后的菜单里都有，锁屏不依赖登录状态 |
| 模块形态 | 独立的 `FlamingoLock.dll`；加载失败时托盘菜单不显示「锁屏」，客户端其余功能不受影响 |
| 锁定方式 | 每块显示器盖一个置顶的全屏窗口；用低级键盘钩子屏蔽 Win 键、Alt+Tab、Alt+F4、Alt+Esc、Ctrl+Esc 等组合键；其它程序弹出的窗口压在锁屏之下 |
| 解锁密码 | 每次锁屏前临时设一个，解锁后即作废，不写入磁盘 |
| 锁屏界面 | 平时只有动画；鼠标单击任意处，屏幕下方淡入「解锁」「重启」「关机」三个按钮；点「解锁」后出现密码框，回车或点箭头解锁；15 秒无操作淡出，回到只有动画的状态；按钮出现之前键盘按键唤不出任何东西 |
| 关机、重启 | 点了之后在锁屏界面上二次确认（「确定要关机吗？其他程序里未保存的内容可能会丢失。」），确认后执行，不需要密码 |
| 防休眠 | 锁屏期间系统不睡眠、显示器常亮、屏幕保护程序不启动 |
| 锁屏期间的客户端 | 照常在线、照常收消息；本程序不弹任何窗口、不放任何提示音；备忘提醒、公告弹窗等提醒类弹窗延到解锁后再弹；锁屏界面不显示任何与消息有关的信息。来电原定「自动回绝并告诉对方暂时无法接听」，2026-10-06 按推荐改为本机静默、不回绝，原因见第 6 节第 4 项 |
| 动画 | 五种：八荣八耻、火烈鸟漫步、粒子时钟、弹跳标志与烟花、汉字数字雨，样式见样稿 |
| 绘制方式（2026-10-06） | 锁屏画面（动画，以及画面上的按钮、密码框、确认框）全部用 Windows 自带的 Direct2D / DirectWrite 绘制，与样稿效果一致；不引入新库，只多链接系统导入库 `d2d1.lib`、`dwrite.lib`。密码框的按键处理在锁屏模块内自行实现，只在锁屏模块内部使用。锁屏前设置临时密码的窗口照常用 balloonui |

## 3. 现状盘点（据实证）

### 3.1 插件 DLL 的加载方式

- 通用加载器 `Source/App/PluginModuleLoader.h`（`CPluginModuleLoader<T>`）：用 `quietload::LoadLibraryQuietly` 静默加载（损坏的 DLL 不弹系统错误框），按名字取工厂函数 `TModule* (__cdecl*)(uint32_t apiVersion)`，工厂返回 NULL 视为版本不符（`plugin_load_version_mismatch`）。加载器本身不打日志、不调 Init / Shutdown。已有用户：`CP2PHost`（`Feature/P2P/P2PHost.cpp:36-68`）、`CFileShareHost`。
- `FlamingoP2P.dll` 是最接近的范例：`CAppShell::Startup` 在启动阶段调用 `LoadP2PModule()`（`App/AppShell.cpp`），宿主是单例，`Init` 失败就卸载；`CAppShell::Shutdown` 最后卸载。DLL 工厂对版本做精确比较；日志经宿主接口 `Log(level, utf8)` 转给 exe 的日志器（`FlamingoP2P/Host/HostLogBridge.cpp`）。
- 带界面的 DLL（`FlamingoMedia`、`FlamingoFileShare`）各自静态链接一份 balloonui，持有自己的 `CAppModule _Module`；界面文字经宿主接口 `Translate` / `GetUiLanguage` 交给 exe 翻译（`i18n::InitFromHost`，API 版本 10、11 起），并给自己那份 balloonui 设置默认字体与文字解析器（`FlamingoMedia/Host/MediaModule.cpp:185-188`）。
- 加载失败时界面按「模块指针为 NULL」隐藏相应入口，例如托盘的屏幕共享、录制项（`IsModuleReady()`）。
- 工程文件由脚本生成（`tools/gen_p2p_vcxproj.py`、`gen_media_vcxproj.py`）：四个配置、`/utf-8`、静态 CRT、定义 `WIN32`、`.def` 导出工厂函数；生成后还要把新工程加进 `tools/gen_vcxproj_filters.py` 的 `TARGETS`，把新目录加进 `tools/i18n_extract.py` 的 `SCAN_ROOTS`。

### 3.2 托盘菜单

- 菜单模型是纯函数 `BuildTrayMenuModel(kind, muted, presence, connUiState, recordState, withScreenShare)`（`UI/BalloonMain/MainPanelTrayMenu.h`），exe 与单元测试工程共用；登录前的菜单是「打开主面板 / 分隔线 / 退出」，登录后是四个在线状态、静音、打开主面板、屏幕共享与录制（可选）、登出、退出。
- 菜单项编号 `TrayMenuId` 的 3 号 `kTrayMenuLock` 是旧主窗口的「锁定主面板」，已随旧主窗口删除、只保留占位，与本功能无关；下一个空号是 12。`TrayMenuKind` 里也有一个运行时从未用到的 `kTrayLocked`。
- 用例 `Tests/MainPanelTrayMenuTests.cpp`（TRAY1~TRAY18，标签 `[traymenu]`）按行数断言两种菜单的形态，新增菜单项须走带缺省值的新参数，不能改变现有调用的结果。
- 托盘图标由常驻的主面板持有（`CTrayController`），登录前就已挂上（提示「未登录」）。登录前界面线程运行的是登录框的模态循环（`m_LoginDlg.DoModal`）。

### 3.3 全局快捷键

三个全局快捷键都注册在主面板上：打开主面板 Ctrl+Alt+D（id 1001）、录屏 Ctrl+Alt+R（1002）只在登录成功后注册（`MainPanelSessionController.cpp`），截图 Alt+Z（1003，可设置）2026-10-07 起程序启动即注册（`docs/截图独立模块方案.md` 3.5 节）。`Feature/Screenshot/ScreenshotEntry.h` 已有 `SuspendAppHotkeys` / `ResumeAppHotkeys`。登出时没有注销它们。

### 3.4 防休眠与屏保

- `UI/BalloonMain/KeepAwakeSession.*`：首选 `PowerCreateRequest` + `PowerSetRequest(SystemRequired / DisplayRequired)`，失败时退回 `SetThreadExecutionState`；`Nudge()` 合成零位移鼠标移动，把输入空闲计时器清零。
- 据实证（`docs/禁止机器休眠方案.md` 第 2 节）：电源请求只能阻止休眠与关屏，**挡不住屏保与自动锁屏**，必须每 25 秒合成一次输入。
- `SetThreadExecutionState` 的退路按线程生效，与主面板上现有的实例放在同一线程会互相覆盖；放在锁屏自己的线程上则互不影响。

### 3.5 登录前可用的配置

没有程序级的配置类；登录前能用的只有 `config/flamingo.ini`（`CIniFile` 读写，见 `Common/Util/IniFile.h`）。该文件须保持 ASCII（`[ui]` 的四个品牌项除外）。按账号的 `CUserConfig` 登录后才加载。

### 3.6 窗口消息号

DLL 私有消息走 `WM_APP + n`，由 DLL 自己的消息窗口接收，不经代理窗；守卫用例 `[msgid]` 不解析 DLL 的头文件，占用的偏移登记在开发约定文档的列表里。空闲段如 `0x100~0x10F`。

### 3.7 弹窗、提示音与来电

**提示音**

- 统一入口是 `balloonmain::PlayNotifySound` / `StartLoopSound` / `StopLoopSound`（`UI/BalloonMain/NotificationSoundPlayer.cpp`），静音与否由调用方算好传入。这份源文件**同时编进了 exe 与 FlamingoMedia.dll**（`FlamingoMedia.vcxproj`），两边各有一份状态；FlamingoMedia 里的来电铃声、回铃、接通、挂断等提示音经宿主接口 `IMediaHost::IsSoundMuted()` 取静音状态（`App/MediaHostAdapter.cpp` 的 `CMediaHostAdapter::IsSoundMuted`）。
- 绕过它们的声音：托盘气泡提示（`CTrayIcon::ShowBalloonTip` 没有设 `NIIF_NOSOUND`，断线重连时每次都弹）；带图标的 `::MessageBox` 会放系统提示音；语音消息播放（WASAPI，不受静音控制，播完一条会自动播下一条）；通话与屏幕共享房间里的实时声音。

**来电的回绝**

- 单聊来电：被叫回绝发 `cmd_call_response`（1703），消息体只有 `sessionid` 与 `accept:0`，**没有原因字段**；服务端（`ChatSession.cpp` 的 `ChatSession::onCallResponse`）一律给主叫推「已拒绝」（`call_state_rejected` = 2）。`call_state_busy` = 8 有定义、主叫端也会显示「对方正在通话中」并放忙音，但服务端从未发送过。要让主叫看到「对方暂时无法接听」，须改服务端与协议。
- 回绝必须在 FlamingoMedia 里做：通话占用的 P2P 链路由 DLL 申请与放弃（`ClaimCallSlot`），只在 exe 里拦截信令并发 1703，链路不会被放弃。
- 群通话谢绝（`cmd_groupcall_decline`）同样没有原因字段。
- 据推测（未核实服务端 `sendToUser`），来电邀请推给本人所有在线设备，任一设备回绝即结束整个呼叫，本机锁屏时自动回绝会让手机上的响铃也一起结束。

| --- | --- | --- |

## 4. 总体设计

### 4.1 模块划分

| 位置 | 内容 |
| --- | --- |
| `flamingoclient/FlamingoLock/`（新，`FlamingoLock.dll`） | 临时密码窗口、锁屏线程、每块显示器的锁屏窗口、Direct2D 绘制与五种动画、锁屏界面交互、键盘钩子与置顶守护、防休眠、关机与重启。静态链接自己的一份 balloonui（临时密码窗口用），日志与界面文字经宿主转给 exe |
| `Source/Feature/Lock/`（新，exe） | `CLockHost`：加载 / 卸载 DLL、实现宿主接口；锁屏状态的全局查询入口；锁屏开始与结束时通知主面板 |
| exe 其它位置（改动） | 托盘菜单加「锁屏」；锁屏期间暂停全局快捷键、静音、延后提醒类弹窗；锁屏开始与结束时调用 FlamingoMedia 的 `SetScreenLocked` |
| `FlamingoMedia.dll`（改动） | `IMediaModule` 新增 `SetScreenLocked(bool)`（API 版本 12 → 13）：锁屏开始时结束远程桌面受控、结束本人主持的屏幕共享、停止录屏并保存、停止语音消息播放与循环提示音；锁屏期间来电与群通话邀请静默（不弹窗、不响铃、不回绝），远程桌面请求自动拒绝，屏幕共享开始的角落提示不弹、不自动加入；宿主的 `IsSoundMuted()` 在锁屏期间返回「静音」 |

### 4.2 线程模型

锁屏的全部界面（临时密码窗口、锁屏窗口）都在 DLL 自己的**锁屏线程**上运行，该线程有自己的消息循环，锁屏结束后退出。理由：

- 低级键盘钩子的回调在安装它的线程上执行，系统要求在超时（默认约 300 毫秒～1 秒）内返回，否则跳过该钩子、按键照常放行，多次超时后还可能被静默摘除。exe 的界面线程偶有较长的同步操作（例如聊天记录统计 0.3～0.5 秒），钩子放在那里会漏键。
- 动画按帧绘制，放在独立线程上不受 exe 界面线程卡顿影响。
- 登录前 exe 界面线程运行的是登录框的模态循环，独立线程不依赖它。

exe 调 `RequestLock()` 后立即返回；锁屏线程弹出临时密码窗口，设好密码后进入锁屏。锁屏开始、结束时，DLL 在锁屏线程上回调宿主的 `OnLockStateChanged`，宿主只置标志并 `PostMessage` 给主面板，其余处理都回到 exe 界面线程上进行。`IsLocked()` 用原子变量，任意线程可调。

### 4.3 锁屏窗口与绘制

- 锁屏线程临时切到 Per-Monitor-V2 的 DPI 上下文（与截图界面相同的做法，`flamingoclient/FlamingoScreenshot/Capture/ScreenCaptureOverlay.cpp`），每块显示器建一个无边框、置顶、覆盖该显示器整个矩形（含任务栏）的窗口，按物理像素绘制。
- 绘制用 Direct2D + DirectWrite（Windows 7 起提供），每个窗口一个 `ID2D1HwndRenderTarget`。多个窗口在同一线程上：各窗口不等垂直同步（`D2D1_PRESENT_OPTIONS_IMMEDIATELY`），每帧画完后调一次 `DwmFlush()` 对齐桌面合成节拍。需要逐帧叠加拖尾的场景（粒子时钟、汉字数字雨）先画到离屏位图，再贴到窗口。
- 字体：书法字优先华文行楷，没有时依次退回华文楷体、楷体；界面文字用 `i18n::UiFontName()`。
- 显示器增减或分辨率变化（`WM_DISPLAYCHANGE`）时按新的显示器布局重建窗口，锁屏状态与密码不变。
- 设备丢失（`D2DERR_RECREATE_TARGET`）时重建绘制目标。

### 4.4 锁屏界面的交互

状态机（纯逻辑，可单测）：

| 状态 | 进入条件 | 界面 | 离开 |
| --- | --- | --- | --- |
| 只有动画 | 刚锁屏；按钮淡出后 | 动画 | 单击任意处 → 按钮 |
| 按钮 | 单击 | 屏幕下方淡入「解锁」「重启」「关机」 | 点「解锁」→ 密码；点「重启」「关机」→ 确认；15 秒无操作 → 只有动画 |
| 密码 | 点「解锁」 | 按钮上方出现密码框并取得焦点 | 密码正确 → 解锁；错误 → 抖动、提示「密码不正确，请重试」、清空；15 秒无操作 → 只有动画 |
| 确认 | 点「重启」或「关机」 | 居中的确认框 | 取消 → 按钮；确认 → 执行；确认框打开时不计空闲 |

- 键盘只在「密码」状态下送进密码框；其余状态下按键一律忽略。
- 按钮栏出现在单击所在的那块显示器上。
- 密码框关闭输入法（`ImmAssociateContext(hwnd, NULL)`），只接受可打印的 ASCII 字符。

### 4.5 屏蔽键盘与保持最上层

- 锁屏线程安装 `WH_KEYBOARD_LL`。锁屏期间吞掉：左右 Win 键（及一切带 Win 的组合）、Apps 键、Alt+Tab、Alt+Esc、Ctrl+Esc、Alt+F4、Alt+Space、Ctrl+Shift+Esc（打开任务管理器）。其余按键只在前台窗口是本模块的锁屏窗口、且处于「密码」状态时放行，否则一律吞掉。
- 拦不住的：Ctrl+Alt+Del（以及其中的任务管理器、注销、切换用户）、Win+L。据推测 Win+L 由系统登录进程处理，键盘钩子拦不住；用户按了也只是叠加一层 Windows 锁屏，无害。
- 据推测，钩子吞掉的按键不会再触发其它程序用 `RegisterHotKey` 注册的全局快捷键；第 2c 期实测验证。
- 置顶守护：`SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` 监视前台窗口变化，前台不是锁屏窗口时把锁屏窗口重新置顶；另有 500 毫秒一次的定时器补充（应对别的置顶窗口后来居上）。锁屏窗口忽略 `WM_CLOSE` 与 `SC_CLOSE`。

### 4.6 临时密码

- 临时密码窗口（balloonui 的 `DuiFrameWindow`）：两个密码框（输入、再输一次）、「锁屏画面」下拉框（见第 6 节第 2 项）、「锁屏」「取消」按钮。规则：4~32 个可打印的 ASCII 字符，两次一致；不合规时在窗口内给出原因。
- 密码只以「随机盐 + SHA-256 摘要」保存在内存里（Windows CNG，`bcrypt.lib`），明文用完立即 `SecureZeroMemory`；解锁时按同样方式计算后做定长比较；解锁后摘要与盐一并清除。不写入磁盘与日志。
- 连续输错 5 次后需等 30 秒才能再试，密码框下方显示倒计时。

### 4.7 防休眠与屏保

锁屏线程上用一个 `CKeepAwakeSession`（DLL 直接编译 `KeepAwakeSession.cpp`）：锁屏开始时 `Acquire()`，每 25 秒 `Nudge()` 一次，解锁时 `Release()`。合成的零位移鼠标移动不算「用户操作」，不会唤出按钮。

### 4.8 关机与重启

确认后在锁屏线程上启用 `SE_SHUTDOWN_NAME` 特权，调用 `ExitWindowsEx(EWX_POWEROFF 或 EWX_REBOOT | EWX_FORCEIFHUNG, SHTDN_REASON_MAJOR_OTHER | SHTDN_REASON_FLAG_PLANNED)`。系统随后向各程序发 `WM_QUERYENDSESSION`，本进程照常放行。据推测，有程序阻止关机时 Windows 显示的「这些应用阻止关机」画面不在用户桌面上，不会被锁屏挡住；实机核对时确认。

### 4.9 锁屏期间客户端的表现

**实现方式**：exe 侧提供 `balloonlock::IsScreenLocked()`（任意线程可调，`Source/Feature/Lock/LockHost.h`）；各来源的处理办法集中在一个纯函数 `balloonlock::DecideDuringLock(kind, locked)`（`Source/Feature/Lock/LockSuppressPolicy.h`，返回「照常 / 延后到解锁 / 丢弃」，可单测），各接入点只调它，不各自判断。延后的事项按到达顺序记下，解锁时由主面板在界面线程上依次补做（实现见第 10 节）。置顶守护（第 4.5 节）是兜底：漏网的窗口也会被压在锁屏之下。

**提示音**：exe 那份 `PlayNotifySound` / `StartLoopSound` 在锁屏期间直接返回（由 exe 在启动时给它登记一个判定函数，FlamingoMedia 那份不登记）；FlamingoMedia 那份经 `IMediaHost::IsSoundMuted()` 取静音状态，宿主在锁屏期间返回「静音」。锁屏开始时停掉两边正在循环的提示音、停止语音消息播放。托盘气泡不弹。

| 来源 | 锁屏期间 |
| --- | --- |
| 单聊 / 群聊新消息、文件夹传输邀请 | 不打开聊天窗、不闪任务栏、不响；照常更新会话行、未读数与托盘闪烁（`DecideArrival` 增加锁屏输入） |
| 已打开的聊天窗收到消息 | 消息照常显示，窗口不抖动、不抢前台 |
| 桌面字幕 | 锁屏开始时隐藏全部字幕窗口，期间收到的消息不进字幕；解锁后恢复显示 |
| 平台公告、群公告 | 延后；群公告的「已弹过」记录推迟到真正弹出时再写 |
| 特别关注的上线提醒 | 丢弃（时效性提醒，解锁后再弹已无意义） |
| 备忘提醒 | 延后；解锁后按各自的样式补弹（全屏的仍全屏，右下角的仍右下角） |
| 文件共享的右下角通知（别人操作了本人的共享、本人的传输结束，2026-10-07 起，`kLockEvtFileShareNotice`） | 延后；FlamingoFileShare.dll 经宿主的 `QueryNoticePolicy` 得知后先记下，每秒再问一次，解锁后补弹（`docs/文件共享方案.md` 第 14 节） |
| 单聊来电、群通话邀请 | 本机静默：不弹来电窗、不响铃、不回绝（第 6 节第 4 项） |
| 远程桌面请求 | 自动拒绝（受控需要本人在场确认） |
| 屏幕共享开始的角落提示、通话对方发起的共享自动加入 | 不弹、不自动加入 |
| 强制观看模式下自动加入共享 | 延后到解锁 |
| 自动升级提示 | 延后 |
| 强制升级 | 下载照常；「启动更新程序并退出」这一步延后到解锁 |
| 被挤下线 | 连接照常断开；提示框延后到解锁后再弹，之后照原流程回到登录窗 |
| 断线重连成功 | 不显示主面板、不抢前台；解锁后再显示（这一步同时用本次登录的资料刷新主面板顶部，不能丢，2026-10-06 由「丢弃」改为「延后」） |
| 停靠在屏幕边缘的主面板 | 不滑出（锁屏期间不轮询光标位置） |
| 托盘气泡 | 「掉线重连中」只换图标不弹气泡；「已最小化到托盘」不弹（气泡带系统提示音） |
| 其它偶发的 `MessageBox`（网络错误提示等） | 不逐个处理，由置顶守护压在锁屏之下 |

**全局快捷键**：锁屏开始时不论是否登录都调用 `SuspendAppHotkeys` 全部注销；解锁时截图快捷键总是恢复（2026-10-07 起截图快捷键程序启动即注册，见 `docs/截图独立模块方案.md` 3.5 节），「打开主面板」与录屏两个只在解锁时已登录才恢复（`balloonlock::ShouldResumeHotkeysAfterUnlock`，`UI/BalloonMain/BalloonMainPanelLock.cpp`）。

**锁屏时正在进行的会话**：见第 6 节第 5 项。

## 5. 接口

### 5.1 DLL 导出（`FlamingoLock/FlamingoLockApi.h`）

```cpp
namespace flamingolock {

const uint32_t kApiVersion = 1;   // 宿主与 DLL 必须一致，不一致时工厂返回 NULL

struct LockInitParams
{
    uint32_t       m_cbSize;      // sizeof(LockInitParams)
    const wchar_t* m_appDir;      // 程序目录，不带末尾反斜杠
};

class ILockHost                    // exe 实现
{
public:
    virtual void Log(int level, const char* utf8) = 0;
    virtual const wchar_t* Translate(const wchar_t* context, const wchar_t* source) = 0;
    virtual bool GetUiLanguage(wchar_t* langBuf, uint32_t langChars, wchar_t* fontBuf, uint32_t fontChars) = 0;
    virtual bool ReadAnimationChoice(char* buf, uint32_t chars) = 0;   // [lock] animation
    virtual void WriteAnimationChoice(const char* token) = 0;
    virtual void OnLockStateChanged(bool locked) = 0;                  // 在锁屏线程上调用，宿主须自行转到界面线程
};

class ILockModule                  // DLL 实现
{
public:
    virtual bool Init(ILockHost* host, const LockInitParams* params) = 0;
    virtual void Shutdown() = 0;                  // 进程退出前调用；锁屏中也会结束锁屏线程
    virtual uint32_t GetApiVersion() const = 0;
    virtual bool RequestLock() = 0;               // 弹出临时密码窗口；已在设置密码或已锁屏时返回 false
    virtual bool IsLocked() const = 0;            // 任意线程可调
};

} // namespace flamingolock

extern "C" flamingolock::ILockModule* __cdecl FlamingoLock_Create(uint32_t apiVersion);
```

### 5.2 exe 侧

- `CLockHost`（单例，仿 `CP2PHost`）在 `CAppShell::Startup` 里 `LoadMediaModule()` 之后加载，`Shutdown` 里最先卸载（锁屏中退出时先结束锁屏线程）。
- `balloonlock::IsScreenLocked()` 供各处查询；锁屏开始与结束时 `CLockHost` 给主面板投 `kMsgLockStateChanged`（`WM_APP + 0x104`，wParam 1 开始、0 解锁）。
- 托盘：`BuildTrayMenuModel` 新增缺省参数 `bool withLock = false`，为 true 时在登录前、登录后两种菜单的「打开主面板」下面各加一项「锁屏」（`kTrayMenuLockScreen = 12`）。
- 主面板系统菜单（2026-10-07 起，用户要求）：`BuildSystemMenuModel` 末尾新增缺省参数 `bool withLock = false`，主面板传 `CLockHost::IsModuleReady()`；为 true 时在「账号」组「修改密码」之后加一项「锁屏」（`kSysMenuLockScreen = 20`，挂锁图标，与托盘一致），点击调 `CLockHost::RequestLock()`。「修改密码」改用新画的钥匙图标 `kIconKey`，两项不再同一个图标。同一次改动把最后一组改为「登出与关于」，「关于」放在整张菜单的最后一行。用例 SYSL1~SYSL3（`MainPanelSystemMenuTests.cpp`）。

## 7.1 Direct2D 版本

只用 Direct2D 1.0（`ID2D1HwndRenderTarget`，Windows 7 即可）。1.0 没有模糊、阴影等特效，也没有加色混合，样稿与实现的差异如下：

- 发光、文字阴影：在字或图形背后画一团径向渐变光晕近似（`Scene/SceneUtil` 的 `DrawGlowAt`）。
- 「从模糊到清晰」：改为由大到小、由淡到实。
- 粒子与火花的加色混合（canvas 的 `lighter`）：改为普通透明度叠加，重叠处不会更亮。
- 粒子时钟与汉字数字雨靠「不清屏、每帧盖一层半透明底色」留下拖尾，而窗口渲染目标每帧内容不保留，所以先画在与窗口同样大小的离屏位图（`CreateCompatibleRenderTarget`）上再整张贴到窗口；每帧盖的底色按帧时长折算，帧率不同时拖尾长度大致相同。

## 9. 实机核对清单

锁屏会盖住整个桌面、拦截键盘，按 `docs/界面自动化验证原理.md` 第 12 节「隐藏桌面与可见桌面的规矩」，由用户本人核对：

1. 托盘右键菜单：登录前、登录后都在「打开主面板」下面有「锁屏」；把 `FlamingoLock.dll` 改名后重启客户端，菜单里不再有「锁屏」，其余功能正常。
2. 点「锁屏」弹出设置窗口：两次密码、「锁屏画面」下拉框（五种动画、随机、轮流播放），上次的选择被记住；密码太短、两次不一致时窗口内提示原因。
3. 锁屏后每块显示器都被盖住并播放所选动画；任务栏看不到；Win 键、Alt+Tab、Alt+F4、Ctrl+Esc、Ctrl+Shift+Esc 都没有反应。
4. 单击出现三个按钮，15 秒不动淡出；点「解锁」出现密码框，输错抖动提示，输对解锁；连续输错 5 次后需等 30 秒。
5. 点「关机」「重启」先出确认框，取消回到按钮；（可选）确认后真的关机 / 重启。
6. 锁屏 2 分钟以上（大于系统屏保与关屏时间），屏保不启动、显示器不关、电脑不睡眠。
7. 登录后锁屏，用另一个账号给本账号发消息、发公告、触发备忘提醒、拨打电话：锁屏期间不弹窗、不响，会话列表的未读数照常增加；解锁后公告与备忘补弹；来电若仍在响铃时限内（45 秒）解锁后弹出来电窗，已超时或对方已挂断则不弹。
8. 锁屏期间按 Alt+Z、Ctrl+Alt+D 没有反应；解锁后恢复。
9. 用 Ctrl+Alt+Del 打开任务管理器能看到并结束客户端，锁屏随之消失（预期行为，说明这不是系统级锁屏）。
10. 开着某个会话的桌面字幕时锁屏：字幕消失，锁屏期间来的消息不出现在字幕上；解锁后字幕恢复。
11. 锁屏前开始录屏、主持屏幕共享、被远程控制：锁屏后录像照常保存，共享结束，远程控制结束；通话不受影响。
12. 锁屏期间拔网线再插回：托盘图标变化但不弹气泡；重连成功后主面板不弹出，解锁后才显示。

### 10.2 延后事项的补做方式

- **平台公告、群公告**：主面板按到达顺序记下（同一条公告只记一次，同一个群只留最新的一条，锁屏期间被撤回或删除的从队列移除），解锁时逐条补弹。群公告的「已弹过」记录在真正弹出时才写，锁屏期间退出程序的话下次登录还会弹。
- **备忘提醒**：`CMemoCenter` 记下锁屏期间到点的提醒（调度器已把它们记为已提醒，不会重复触发），解锁时按各自的样式补弹；锁屏期间被删除的不弹。右下角弹窗的刷新同样压到解锁后。
- **被挤下线**：断开连接、停止自动重连、界面转为离线这几步立即执行（否则掉线会触发自动重连，与另一端来回顶号）；提示框与回到登录窗延后，解锁时把原消息重新投递一次。重复到达的只保留最后一条。
- **升级提示、强制升级退出**：原消息连同堆对象记下，解锁时原样重新投递，处理函数照常执行。
- **重连成功后显示主面板**：解锁时补做。
- **来电**：锁屏期间占住通话槽位、记下邀请；解锁时仍在响铃时限内（默认 45 秒）就弹来电窗并响铃，期间对方挂断（收到状态推送）则清掉。
- **强制观看的共享**：解锁时双方都空闲则补加入。

## 11. 设置窗口的「预览」与标题栏图标（2026-10-07）

### 11.1 需求

- 设置临时密码的窗口里，「锁屏画面」下拉框右侧加一个「预览」按钮：按下拉框当前的选择全屏播放动画，让用户锁屏之前先看到效果。
- 设置窗口的标题栏左侧显示程序图标（开发约定文档 UI 约定第 10 条）。

### 11.2 设计

- **只在一块显示器上播放**：设置窗口所在的那块（`MonitorFromWindow`），用现成的锁屏窗口 `CLockWindow` 盖住它。不复用 `CLockSession`：后者要求已设好密码，并且会装低级键盘、鼠标钩子与前台钩子、申请防休眠、每 500 毫秒重新置顶、Esc 只逐级退回，这些预览都不需要。
- **预览会话 `Session/LockPreviewSession`**（实现 `ILockWindowSink`）：建窗期间把线程临时切到 Per-Monitor-V2（与锁屏相同，窗口按物理像素建在显示器上；DPI 小工具从 `LockSession.cpp` 提到 `Session/LockDpi` 共用），建好后恢复。何时结束、何时换片、先播哪一种由纯逻辑 `Core/LockPreviewState`（`CLockPreviewState`）判定：
  - 固定方式播所选的那种；「随机」任取一种（随机数取自 `BCryptGenRandom`）；「轮流播放」从八荣八耻开始、**每 5 秒**换一种（真正锁屏时是每分钟）。
  - 单击（左、右、中键）、按任意键（含 Esc、Alt 一类的系统键）结束预览；**第一帧画出来之后的 400 毫秒内**不理会单击与按键，避免双击「预览」按钮的第二下立刻把预览关掉。保护时间从第一帧画出来时算起，而不是从建窗时算起：不可见桌面上调试版的第一帧要 0.5~0.9 秒。
  - 预览窗口失去激活（Alt+Tab、点了别的显示器上的窗口）、显示器变化、系统注销时任何时候都立即结束。
  - 结束推迟到下一帧开始时进行（输入是在预览窗口自己的消息处理里收到的，那里不能销毁窗口）；先回调设置窗口恢复可用、取回前台，再销毁预览窗口，免得前台落到别的程序上。
- **`CLockWindow` 的补充**：`ILockWindowSink` 加三个有空默认实现的虚函数 `OnLockSysKeyDown`、`OnLockOtherButtonDown`、`OnLockDeactivate`，锁屏会话不覆写，行为不变；`WM_SYSKEYDOWN` 照旧不交给系统默认处理（Alt+F4 不会变成关闭命令）。
- **画面上方的提示**：`OverlayFrame` 加 `m_hint`，非空时 `CLockOverlayRenderer` 在画面上方居中画一个半透明深色胶囊，内写「按 Esc 或单击退出预览」；胶囊位置由纯函数 `ComputePreviewHintRect` 计算（顶边在 6% 高度，宽度为文字宽度加两侧留白，过长时截到屏幕之内）。只用 Direct2D / DirectWrite。锁屏会话不填 `m_hint`，锁屏画面不变。
- **帧驱动**：并入锁屏线程现有的逐帧循环——`CLockThread::Run` 在没有锁屏、但设置窗口正在预览时，每轮调用 `CLockSetupDialog::RenderPreviewFrame` 并用 `DwmFlush` 对齐节拍，与锁屏相同。
- **设置窗口**：下拉框与「预览」按钮同一行（按钮宽 64，译文更长时按 `i18n::DefaultButtonWidthForText` 只增不减），行高不变，窗口高度 `kDlgContentH` 的公式不变。点「预览」先给自己投 `WM_APP + 0x105`，等按钮的点击通知处理完再开始预览；预览期间设置窗口被禁用（不能再点「预览」「锁屏」，回车也不会触发），代码里另有判断兜底。预览打不开（Direct2D 不可用、建窗失败）时在错误提示行显示「无法打开预览。」。
- **程序图标**：`gen_lock_vcxproj.py` 把 `Source/UI/BalloonMain/TitleBarIcon.cpp` 编进本 DLL（只依赖 `<windows.h>` 与 `Source/resource.h`，不触发 LG4）；设置窗口建窗后 `SetIcon(m_programIcons.TitleBitmap(16, kOpaqueTitleBarColor))`，它没有所有者窗口、会出现在任务栏上，再调 `ApplyTaskIcons`。图标资源从 exe 模块加载。
- 不改 `ILockModule`，`kApiVersion` 仍为 1。

## 12. 汉字数字雨改为大红配色（2026-10-07）

### 12.1 需求与决定

用户认为汉字数字雨原来的配色（黑底、绿字，《黑客帝国》风格）不好看，要求改成大红色、偏喜庆的风格。2026-10-07 逐项确认的决定：

1. **方向：大红底、金色字雨**（另一个备选是「暗红底、大红字雨」，只换常量、改动最小，但喜庆程度不如前者，未采用）。整屏不用单一的纯红，而是中心大红、四角压暗的径向渐变，避免整屏纯红刺眼、像出错画面。与八荣八耻场景（同为红底金字，`HonorScene.cpp`）色调接近，但一个逐字书写、一个满屏下落，形态差别大，可以接受。

| 「荣」半句与光晕 | 金 `0xFFD54A` / `0xFFC83C` | 不变 |
| 「耻」半句与光晕 | 红 `0xFF7070` / `0xFF5050` | 米白 `0xFFF1E0` / 暖橙 `0xFFA64D`（红色在红底上看不清） |
| 字的底衬 | 黑色，82% 不透明，相邻两字的底衬连成一条 | 深红 `0x5C060A`，85% 不透明，加金色 `0xF0C45A` 细边；宽度从字号的 1.12 倍收到 1.0 倍，一字一方、彼此留缝，像一张张斗方红纸（连成一条时相邻金边会重叠成粗线） |

实现要点：

- 离屏位图（拖尾所在，第 7.1 节）用**纯色**大红底，每帧盖的、擦除旧头部所在格子用的都是这一种颜色；四角压暗是离屏位图贴到窗口之后，在窗口渲染目标上另盖的一层径向渐变（中心透明、四角 45% 不透明的黑，横纵半径为画面宽高的一半乘以 √2），每帧只画一次、不累积。
- **不能把渐变直接当离屏位图的底色每帧叠加**（最初就是这样实现的，截图后发现问题）。据实证：按 60 帧 / 秒模拟 20 秒，画面上出现一圈圈明显的椭圆环；按到中心的距离统计红色分量与理想渐变之差，中位数呈锯齿状 −1 → +10 级周期变化，30 帧 / 秒时周期为归一化半径 0.08，60 帧 / 秒时为 0.16。原因是每帧叠加的半透明渐变在 8 位预乘精度下被量化：底色每变化 255 ÷ (每帧不透明度 × 255) 级（60 帧时约 14 级）叠加色才变一档，拖尾残留停下来的亮度随之分档。改为纯色底加压暗层后，同样条件下残差在 +2 ~ +5 级之间、与半径无关，环消失。
- 残留字形：每帧只盖约 7%（60 帧 / 秒）的底色，8 位精度下与底色相差不到 7 级左右时就不再变化，满屏留有一层很淡、均匀的字形纹理（红色分量平均高出底色约 3~4 级）；定格句子淡出后，深红底衬的位置会留下比底色略暗的方块，直到被字符雨覆盖。旧版黑底上同样有残留，只是更不易察觉。截图核对时可以接受，实机预览后如嫌明显再处理。
