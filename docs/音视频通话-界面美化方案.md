# 音视频通话：界面美化方案

本文承接 [音视频通话-媒体切换方案.md](音视频通话-媒体切换方案.md)。媒体切换功能落地后，
通话窗在**功能**上已经完整（语音 / 视频共用一个窗口、可双向切换、有时长、有任务栏图标），
但**观感**仍是骨架状态。本文描述美化改造。

编写日期：2026-07-31

---

## 1. 现状问题（据实证）

### 1.1 语音态的画面区几乎是空白

接通态统一用视频窗基座之后，语音态复用了同一块大画面区，但里面**只有一行居中的对端昵称**
（`BalloonCallDlg.cpp` 的 `ApplyCanvasPlaceholders` 在 `!m_videoCall` 分支只 `SetPlaceholderText`），
其余全是空白底色。这是当前最突兀的一处：一个占据大半屏的区域只放了一行小字。

### 1.2 底部只有三个文字按钮，且缺静音

全文件搜 `mute` 与"静音"命中数为 **0** —— 静音按钮**根本不存在**。
（注：媒体切换方案文档 5.3 节的按钮表里写了"静音"，那是设想、不是现状，本文以代码为准。）

实际按钮集合，取自 `BalloonCallDlg.cpp` 的 `SetText` 调用：

| 形态 | 按钮 |
| --- | --- |
| 通话中（视频） | 切回语音、关闭摄像头、挂断 |
| 通话中（语音） | 切到视频、挂断 |
| 来电 | 拒绝、接听 |
| 呼叫中 | 取消 |

全部是 `DuiButton` 的矩形文字按钮（`StylePushButton` + `Variant::Default`），**挂断没有危险色**，
四个并排时既占宽又分不出主次。

### 1.3 呼叫中 / 来电态与接通态风格割裂

这两态仍是 340×128 的小窗（`kDlgWidth` / `kDlgHeight`），接通后突然变成大窗，
尺寸与视觉语言都断档。

## 2. 已定基调

以下三项在方案讨论中由开发者拍板，若要推翻请在动工前提出。

**配色走深色。** 主流视频通话界面都是深色——画面是主角，深色底不与画面抢注意力，也更
显专业。代价是与 FlamingoIM 其它窗口的浅色主题不统一，但通话窗本就是个独立的沉浸式窗口，
这种不统一可以接受。

**头像先做字形回退。** 通话窗目前没有任何取头像的逻辑（搜 `avatar` 只有 3 处注释）。
第一步只做"昵称首字 + 主题色底"的字形头像，不接真图下载链路；真图留作后续，接入时复用
主面板那套 `AvatarImageUtil`。这样美化不被头像下载的复杂度拖住。

**圆形图标按钮放在 `Source/Call/` 下自建。** 按开发约定文档的 UI 约定应优先复用 balloonui，
但 `DuiButton` 是矩形文字按钮，做圆形图标按钮需要覆写绘制。故子类化 `DuiButton` 成
`call::CallRoundButton`，放在 `Source/Call/`，**不动 balloonui**。若日后别处也要用这种按钮，
再按约定向用户提议把它上收进 balloonui。

## 3. 改造内容

### 3.1 语音态画面区：头像 + 昵称 + 状态

画面区改成竖向居中的一组元素：

- **大圆形头像**，直径约 96px。字形头像取昵称首字，底色按 userid 稳定取色（与联系人列表
  同一套取色规则，保证同一个人到哪儿都是同一个颜色）。
- **昵称**，16px 半粗。
- **状态行**，小号浅色：接通前显示"正在呼叫…"/"邀请你语音通话"，接通后显示通话时长。

背景用深色竖向渐变，而不是纯色块。

### 3.2 底部操作条：圆形图标按钮

一排等间距的圆形图标按钮，图标复用 `ChatIcons` 那套线性图标（已有摄像机与听筒，需补
麦克风及其"斜杠禁用"变体）。

| 按钮 | 直径 | 常态 | 激活 / 强调态 |
| --- | --- | --- | --- |
| 静音 | 48 | 半透明白底 + 麦克风 | 实心白底 + 麦克风划斜杠 |
| 摄像头（仅视频态） | 48 | 半透明白底 + 摄像机 | 实心白底 + 摄像机划斜杠 |
| 切换媒体 | 48 | 半透明白底 + 听筒 / 摄像机（图标随目标态） | — |
| 挂断 | 56 | **红底白图标** | — |

文字不再占按钮宽度，改为悬停 tooltip（复用 `DuiToolTipMgr`）。挂断直径更大 + 红底，
确立视觉主次。

**这一条顺带把缺失的静音补上**——它是通话界面里用户最常找的按钮，现在完全没有。

### 3.3 三态统一视觉

呼叫中 / 来电态沿用同一套深色背景、同样的圆形头像 + 昵称居中、同样的圆形按钮
（来电=绿色接听 + 红色拒绝，呼叫中=红色取消）。尺寸不必与接通态相同，但配色、圆角、
按钮样式必须一致，让三态看着是同一个产品。

### 3.4 视频态操作条悬浮自动隐藏

操作条改为浮在画面底部、鼠标静止数秒后淡出，鼠标移动或悬停其上时淡入。时序对齐
开发约定文档「UI 约定」第 1 条对滚动条 auto-hide 定的思路（滚动淡入、约 800ms idle 后淡出），
区别仅在触发源是鼠标移动而非滚动。

通话时长同时在画面区右上角显示一个小胶囊，视线不必上移到标题栏。

## 4. 测试用例

### 4.1 可自动化（纯逻辑）

美化的绝大部分是绘制，测不了。可测的是抽出来的纯函数：

- **头像字形与底色**：昵称取首字（含中英文、emoji、空昵称的退化）；同一 userid 恒得同一
  底色；不同 userid 的底色分布不集中。
- **操作条按钮集合**：按 (形态, 媒体类型, 摄像头开关) 组合产出的按钮 id 序列与顺序正确；
  语音态不出现摄像头按钮；非接通态不出现切换与静音按钮。
- **自动隐藏时序判定**：给定"上次鼠标活动时刻"与"当前时刻"，判定操作条应显示还是隐藏；
  悬停其上时恒显示。

### 4.2 不可自动化

配色、渐变、圆角、图标观感、淡入淡出的实际效果、三态切换时的视觉连贯性——只能靠截图
比对与目视检查，如实标注为无自动化覆盖。

## 5. 开工顺序

1. 抽纯函数（头像字形取色、按钮集合、自动隐藏时序判定）并写测试，**与用户确认用例后**
   再写产品代码。
2. `call::CallRoundButton` 子类化 `DuiButton`，实现圆形图标绘制与三态配色。
3. 语音态画面区改造（头像 + 昵称 + 状态）。
4. 底部操作条换成圆形按钮，补上静音。
5. 呼叫中 / 来电态统一视觉。
6. 操作条悬浮 + 自动隐藏。

---

## 6. 已顺手清理的技术债

接通态改为一律走视频基座后，旧的小窗布局分支里那段 `if (m_mode == kModeConnected)`
（构造「切到视频」按钮）已不可达 —— `m_mode` 在该分支恒为呼叫中或来电。已删除。

---

## 7. 风险

- **静音是新功能，不只是美化**：它要接音频引擎的采集静音开关，不是纯绘制改动，工作量与
  风险都高于其余各条，建议单独一步做完并验证。
- **深色基调与其余窗口不统一**：若日后产品要求全局风格一致，这套配色可能要返工。
- **自动隐藏可能挡操作**：操作条淡出后用户找不到按钮是常见抱怨，须保证鼠标一动即刻淡入，
  且淡出延时不宜过短。
