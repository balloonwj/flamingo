本目录放的是<u>不参与产品构建</u>的辅助脚本：生成代码 / 数据表的工具，以及用来实测某项
系统行为的探针。产品代码不依赖它们，删掉不影响编译，但它们承载着一些"为什么这么写"
的实测依据，请勿随手清理。

## keepawake_probe.ps1

### 它验证什么

客户端「系统设置 → 通用 → 禁止机器休眠」开启后要做到三件事：不休眠、不关闭显示器、
不锁屏。这三件事在 Windows 上分属两套互不相干的机制，本脚本就是用来确认这个分工的：

1. **系统电源请求可用** —— `PowerCreateRequest` / `PowerSetRequest` 能否成功创建并设置，
   以及回落方案 `SetThreadExecutionState` 是否可用。
2. **电源请求不影响输入空闲计时器** —— 持有电源请求期间，`GetLastInputInfo` 报出的空闲
   时长是否照常增长。这一条决定了"防休眠"与"防锁屏"必须分别处理。
3. **合成输入事件能重置输入空闲计时器** —— 发送一个位移量为 0 的鼠标移动事件后，空闲
   时长是否归零。屏幕保护程序与自动锁屏依据的正是这个计时器。
4. **（可选）持续合成输入时屏保确实不启动** —— 需要显式加 `-LiveScreenSaver`，见下文。

产品代码中对应的实现在 `flamingoclient/Source/UI/BalloonMain/KeepAwakeSession.{h,cpp}`，
判定逻辑在 `KeepAwakePolicy.{h,cpp}`（有单元测试 `Source/Tests/KeepAwakePolicyTests.cpp`）。
Win32 API 那一层没有单元测试，本脚本就是它的验收手段。完整的技术方案见
`docs/禁止机器休眠方案.md`。

### 怎么运行

```powershell
# 基础三项，约 40 秒，普通权限即可
powershell -ExecutionPolicy Bypass -File tools\keepawake_probe.ps1

# 追加屏保实测，约 2 分钟，会临时改动屏保设置（见下方"注意事项"）
powershell -ExecutionPolicy Bypass -File tools\keepawake_probe.ps1 -LiveScreenSaver
```

可选参数：

- `-NudgeIntervalSec`（默认 20）：屏保实测中每隔多少秒合成一次输入事件。
- `-ObserveSec`（默认 100）：屏保实测的观察时长，须明显大于临时设置的 60 秒屏保超时。

### 怎么判读结果

- **第 2 节**：空闲时长应当从 0 单调增长到接近 20 秒。若它中途归零，说明期间有真人输入，
  该轮数据无效，重跑即可。**这一节的结论是"电源请求管不到锁屏"**，是整个设计的前提。
- **第 3 节**：每次合成之后空闲时长应当立即回到 0。
- **第 4 节**：`屏保是否启动过 = 0` 且 `最大空闲` 接近合成间隔，才算通过。若最大空闲远
  小于合成间隔，说明观察期间有真人输入干扰，本轮作废。

运行期间不要触碰键盘和鼠标 —— 真人输入同样会重置空闲计时器，会让脚本无法区分"是合成
输入起了作用"还是"是你在动鼠标"。

### 改这个脚本时的注意事项

**保存为带 BOM 的 UTF-8。** PowerShell 5.1 读取 `.ps1` 时若文件没有 BOM，会按系统 ANSI
代码页解码，脚本里的中文会变成乱码，其中某些字节还会让解析器直接报语法错误、整个脚本
跑不起来。同理，`Add-Type` 那段 C# 代码块内一律只写英文注释 —— 万一 BOM 丢了，中文注释
被误解码后可能让 C# 的行注释吞掉下一行真实代码，这类故障非常难查。

### 注意事项

- `-LiveScreenSaver` 会**临时**把屏幕保护程序改为系统自带的空白屏保、超时改为 60 秒，
  脚本结束时（含中途报错）在 `finally` 中还原原设置，并把还原结果打印出来。若脚本被
  强行中断，请手动检查「设置 → 个性化 → 锁屏界面 → 屏幕保护程序」。
- `powercfg /requests` 需要管理员权限。非管理员运行时该节会打印一行提示并跳过，不影响
  其余各节。
- 脚本会向系统合成鼠标输入事件（位移量为 0，光标不动）。它不会点击、不会投递到任何窗口。

### 已知的实测结论（2026-08-12，Windows 10 Pro 19045）

- `PowerCreateRequest` 与两项 `PowerSetRequest` 均成功；`SetThreadExecutionState` 回落
  方案同样可用。
- 持有电源请求期间空闲时长从 0 增长到 15.3 秒，**电源请求确实不影响输入空闲计时器**。
- 每 4 秒合成一次位移量为 0 的鼠标移动事件，每次之后空闲时长立即归零。
- 屏保超时设为 60 秒时：静置 90 秒屏保如期启动；每 20 秒合成一次输入事件时，100 秒内
  空闲时长始终不超过 15 秒、屏保一次都没有启动。
- **尚未验证**：真正的锁屏（屏保勾选"恢复时显示登录屏幕"，或组策略下发计算机不活动
  限制）是否同样被推迟。测试用的这台机器两项都未配置，无法观察。在有锁屏策略的机器上
  复验时，除本脚本外还应查看客户端日志中 `会话事件` 那一行 —— 出现 `状态码=0x7`
  （`WTS_SESSION_LOCK`）即表示确实发生过锁屏。
